# Earthquake Show 版本记录

## 维护规则

本文档长期记录每个版本实际完成的小功能，是判断某个版本“已经具备什么能力”的唯一版本清单。

- 每次新增、修改或移除用户可见功能时更新本文档。
- 每个版本必须记录实现内容、明确未包含内容、验证结果和已知问题。
- 正式原生版本号统一维护于 `Directory.Build.props`，并由各 `.csproj` 和界面版本信息读取。
- 尚未实现或尚未验证的能力不得写入“已实现”。
- Bug 修复除记录在这里外，还要在[工程实现文档](./工程实现文档.md)的故障记录中说明原因和验证方法。

## 0.9.0 - 2026-08-20

### 已实现

- 新增随应用复制的 `Assets/japan-overview.geojson` 离线日本示意轮廓，并在资源元数据中明确其不是官方 JMA 边界。
- 新增 `OfflineMapGeometry`，解析 GeoJSON `Polygon`/`MultiPolygon` 外环和 `EPSG:4326` 经纬度坐标，拒绝不支持的几何类型。
- 新增 `EarthquakeMapViewModel`，将当前事件最新有效报文投影为震度区域、震源和观测点图层；区域按 `areaCode` 匹配，坐标未知的点不绘制。
- 新增 WPF 原生 `EarthquakeMapView`，使用 `Canvas`、`Polygon` 和 `Ellipse` 绘制轮廓、震度颜色和事件点，不依赖浏览器、在线底图或地图 SDK。
- 地图工具支持放大、缩小、日本全图、定位所选事件和跟随选择；没有事件时仍显示离线轮廓。
- 地图状态继续复用 `EarthquakePageState.Map`，未创建第二份事件选择；底部状态显示“地图：离线示意”。
- 新增 5 个 App 地图测试，覆盖 GeoJSON 元数据、几何校验、区域/震源/观测点图层、无坐标过滤、地图命令和空状态；全套测试增至 89 个。

### 本版本未包含

- `japan-overview.geojson` 是 UI 示意轮廓，不是 JMA 官方行政或预报区域边界，不能用于空间查询或区域归属判断。
- 尚未接入 Mapsui、SkiaSharp、在线底图、真实 GIS Shapefile 或地图空间分析。
- 运行时内存仓储仍为空，固定 JMAXML 尚未解析，因此正常启动时只有离线轮廓，没有事件图层。
- 地图平移、全屏、重叠点选择和正式图例细分留到后续地图增强阶段。

### 验证结果

- `dotnet build EarthquakeShow.sln --configuration Release --no-restore --no-incremental`：App、Core 和两个测试工程全部通过，`0` 个警告、`0` 个错误。
- `dotnet test EarthquakeShow.sln --configuration Release --no-restore --no-build`：Core 50 个、App 39 个，共 89 个测试全部通过。
- `python -X utf8 tools\validate_test_data.py`：固定测试数据完整性校验继续通过。
- 原生窗口在 `1440 × 900` 和 `1180 × 720` 下验证离线轮廓、地图工具栏、状态文字和紧凑详情入口；窗口可正常关闭。
- App 和 Core Release 程序集的产品版本前缀、文件版本分别为 `0.9.0` / `0.9.0.0`。

### 已知限制

- 当前投影使用固定日本范围和等比例经纬度绘制，未进行 Web Mercator 或地理投影校正；正式 GIS 阶段需要重新评估。
- 区域图层只绘制能在本地 GeoJSON 中找到相同 `areaCode` 的区域；缺失几何不会阻塞事件详情显示。

## 0.8.0 - 2026-08-19

### 已实现

- 新增 `EarthquakeEventListView`、列表 ViewModel 和事件卡片显示投影，左栏由状态占位升级为可操作的原生 WPF 事件列表。
- 事件卡片显示最大震度、震源、震级、发生/发布时间、报文状态、海啸摘要和新事件标记；未知震级显示为“`M 不明`”。
- 列表默认按最新发布时间排序，可切换最新发生时间和最大震度；未知时间/震度排在已知值之后，并使用 `EventId` 确保稳定顺序。
- 搜索支持事件 ID、震源名称/代码、报文代码和来源 ID；搜索文字输入后即时更新结果。
- 新增最近 24 小时/7 天/30 天、最低震度、最低震级、区域和来源筛选；空仓储与筛选无结果使用不同提示。

- 仓储更新时保持当前历史事件选择，新事件显示“新”标记但不抢走选择；用户选择新事件后清除标记。
- 刷新按钮接入现有仓储刷新边界，刷新进行中禁止重复触发。
- 列表启用回收式 WPF 虚拟化，更新时同步同一个可观察集合并保留未变化卡片实例；新增 19 个 App 测试，覆盖排序、搜索、筛选、未知值、选择、新事件、100 条数据和刷新防重入，全套测试增至 84 个。

- 运行时内存仓储仍为空，固定 JMAXML 尚未解析成领域事件；正常启动时仍显示空列表，不注入合成数据。
- 当前仓储返回完整事件快照，没有更早缓存的分页游标；“加载更早记录”随 SQLite 缓存契约实现。

- 地图、详情内容、缓存、报文解析和网络数据源仍未实现。

- `python -X utf8 tools\validate_test_data.py`：固定数据完整性校验继续通过。
- 原生窗口在 `1440 × 900` 和 `1180 × 720` 下完成空列表、筛选控件和紧凑详情布局检查。

## 0.5.0 - 2026-08-19

### 已实现

- 新增纯领域服务 `EarthquakeEventMerger`，按 `EventId` 将多份报文合并为不可变事件时间线。
- 使用 `SourceId + SourceMessageId` 去除同一来源消息的重复输入；重复到达时保留最早 `ReceivedAt` 的记录。
- 事件内报文按 `IssuedAt`、报次、`ReceivedAt`、来源 ID 和来源消息 ID 升序稳定排列；无报次排在数字报次之前。
- 多事件按最后报文发布时间降序排列，发布时间相同时使用 `EventId` 确定顺序。
- `EarthquakeEvent` 提供当前 `LatestReport` 和只包含发布/订正状态的 `LatestEffectiveReport`。
- 新增 `EarthquakeEventSummary`，当前状态来自最后一报；震源、震级和最大震度来自最后有效报文。
- 订正报更新摘要但保留原报；取消报决定当前状态，同时沿用最后有效报文的数据摘要。
- 合并入口拒绝空 `EventId`、`SourceId` 和 `SourceMessageId`，避免无法追踪的报文被错误合并。
- 新增 15 个测试用例，覆盖乱序输入、去重、最早接收记录、完整排序键、多事件排序、旧报、订正、取消、空输入、空时间线和无效标识。

### 本版本未包含

- 尚未解析固定 JMAXML；测试使用直接构造的领域报文验证合并规则。
- WPF App 尚未引用 Core，事件列表仍未显示固定或实时地震数据。
- 尚未建立页面状态、数据仓库接口、SQLite 缓存或网络数据源。

### 验证结果

- `dotnet build EarthquakeShow.sln --configuration Release --no-restore --no-incremental`：App、Core 和测试工程全部通过，`0` 个警告、`0` 个错误。
- `dotnet test EarthquakeShow.sln --configuration Release --no-restore --no-build`：46 个测试全部通过，`0` 个失败、`0` 个跳过。
- `python -X utf8 tools\validate_test_data.py`：固定数据完整性校验继续通过。
- App 和 Core Release 程序集的产品版本前缀、文件版本分别为 `0.5.0` / `0.5.0.0`。

### 已知限制

- 去重身份依赖数据适配器提供稳定的 `SourceId` 和 `SourceMessageId`；跨来源内容相同的报文不会在本步骤中合并为同一时间线节点。
- 当前摘要按最后有效报文整体取值，不在多来源之间逐字段仲裁；来源优先级和冲突保留在真实数据源接入阶段实现。

## 0.4.0 - 2026-08-19

### 已实现

- 新建无 WPF、数据库和网络依赖的 `EarthquakeShow.Core` 项目，并加入解决方案。
- 定义 `EarthquakeEvent`、`EarthquakeReport`、`Hypocenter`、`IntensityArea`、`IntensityMunicipality`、`IntensityStation`、`SourceReference` 和 `SourceStatus`。
- 定义报文类型、发布/订正/取消状态、正常/训练/测试上下文和数据源在线、延迟、断开、限流、解析失败、停用状态。
- 使用 `JmaIntensity` 明确表示 `unknown/1/2/3/4/5-lower/5-upper/6-lower/6-upper/7`，提供稳定代码的双向转换。
- 使用 `GeoCoordinate` 拒绝非有限或越界坐标；观测点和震源仍可显式没有坐标。
- 使用可空震源深度区分 `0 km` 和未知；使用 `Magnitude` 拒绝 `NaN/Infinity`，未知震级使用 `null`。
- 所有领域时间使用 `DateTimeOffset` 保留来源偏移量；持久化约定为 ISO 8601 `O` 格式。
- `EarthquakeReport` 保留原始报文代码、来源 ID、来源消息 ID、原文 URL 和 `SourcePayload`，避免标准化丢失来源字段。
- 报文时间线、区域、市町村和观测点集合使用 `ImmutableArray<T>`，避免构建后被外部列表修改。
- 新建 `EarthquakeShow.Core.Tests`，引入 xUnit 2.9.2、xunit.runner.visualstudio 2.8.2 和 Microsoft.NET.Test.Sdk 17.12.0。

### 本版本未包含

- 尚未实现 JMAXML 解析器，固定 XML 还没有转换成领域对象。
- 尚未实现按 `EventID` 合并、报文去重、排序、订正或取消处理。
- WPF App 尚未引用 Core，页面没有新增用户可见地震数据。
- 尚未创建 Infrastructure、SQLite 仓储或数据源接口。

### 验证结果

- `dotnet build EarthquakeShow.sln --configuration Release --no-restore --no-incremental`：App、Core 和测试工程全部通过，`0` 个警告、`0` 个错误。
- `dotnet test tests\EarthquakeShow.Core.Tests\EarthquakeShow.Core.Tests.csproj --configuration Release --no-restore`：31 个测试全部通过，`0` 个失败、`0` 个跳过。
- 测试覆盖震度代码往返、未知震度、`0 km`/未知深度、非有限震级、合法/越界坐标、JST 偏移量、来源原文和不可变报文集合。
- `python -X utf8 tools\validate_test_data.py`：固定数据完整性校验继续通过。

### 已知限制

- 模型只约束单个值和单份报文，不验证一个 `EarthquakeEvent` 内所有报文是否具有相同 `EventID`；该规则在步骤 4 的合并服务中实现。
- `DateTimeOffset` 只保证内存中保留偏移量，SQLite 和 JSON 的 ISO 8601 序列化需要在后续持久化实现中继续测试。
