# Earthquake Show 版本记录

## 维护规则

本文档长期记录每个版本实际完成的小功能，是判断某个版本“已经具备什么能力”的唯一版本清单。

- 每次新增、修改或移除用户可见功能时更新本文档。
- 每个版本必须记录实现内容、明确未包含内容、验证结果和已知问题。
- 正式原生版本号统一维护于 `Directory.Build.props`，并由各 `.csproj` 和界面版本信息读取。
- 尚未实现或尚未验证的能力不得写入“已实现”。
- Bug 修复除记录在这里外，还要在[工程实现文档](./工程实现文档.md)的故障记录中说明原因和验证方法。

## 0.6.0 - 2026-08-19

### 已实现

- 新增 `IEarthquakeEventRepository`，统一定义事件列表、按 ID 查询、完整快照更新通知和主动刷新入口。
- 新增线程安全的 `InMemoryEarthquakeEventRepository`，接收标准化报文并复用 `EarthquakeEventMerger` 完成合并、去重和排序。
- 内存仓储发布不可变事件快照，支持取消令牌；主动刷新保持为空操作，因为当前没有外部数据源。
- WPF App 首次引用 Core，但只通过仓储接口消费事件，不直接访问 HTTP、SQLite 或 XML。
- 新增不可变 `EarthquakePageState`，分离事件列表、选中事件、当前报文、搜索、排序、地图、来源、加载、刷新、离线和错误状态。
- 新增 `EarthquakePageViewModel`，支持首次加载、主动刷新、事件选择、报文版本选择和返回最新报。
- 仓储更新后使用 `EventId` 和来源消息身份保持当前浏览位置；新事件不会抢走用户正在查看的历史事件。
- 主窗口首次显示后异步初始化空内存仓储，关闭时解除更新订阅；现有空状态界面行为不变。
- 新增[数据契约与格式文档](./数据契约与格式.md)，长期记录领域字段、枚举、未知值、时间、身份、排序、仓储、页面状态和固定数据格式。
- 新增 4 个 Core 仓储测试和 6 个 App 页面状态测试；加上原有测试共 56 个。

### 本版本未包含

- 内存仓储默认为空，尚未把固定 JMAXML 解析成事件或显示到现有列表。
- 搜索、排序和地图状态目前只保存条件，不执行筛选、排序切换或地图渲染。
- 尚未实现 SQLite、网络数据源、后台订阅或来源优先级；`RefreshAsync` 在内存实现中不访问外部系统。
- 主窗口布局和事件控件没有在本版本调整。

### 验证结果

- `dotnet build EarthquakeShow.sln --configuration Release --no-restore --no-incremental`：App、Core 和两个测试工程全部通过，`0` 个警告、`0` 个错误。
- `dotnet test EarthquakeShow.sln --configuration Release --no-restore --no-build`：Core 50 个、App 6 个，共 56 个测试全部通过。
- `python -X utf8 tools\validate_test_data.py`：固定数据完整性校验继续通过。
- App 和 Core Release 程序集的产品版本前缀、文件版本分别为 `0.6.0` / `0.6.0.0`。

### 已知限制

- 仓储更新事件携带完整快照，适合当前事件规模；真实缓存接入后需要测量大量历史记录下的分配和更新时间，再决定是否增加增量消息。
- 页面 ViewModel 只保存搜索、排序和地图条件，步骤 7/8 实现具体行为时必须继续遵守当前选择保持规则。

## 0.5.0 - 2026-08-19

### 已实现

- 新增纯领域服务 `EarthquakeEventMerger`，按 `EventId` 将多份报文合并为不可变事件时间线。
- 使用 `SourceId + SourceMessageId` 去除同一来源消息的重复输入；重复到达时保留最早 `ReceivedAt` 的记录。
- 事件内报文按 `IssuedAt`、报次、`ReceivedAt`、来源 ID 和来源消息 ID 升序稳定排列；无报次排在数字报次之前。
- 多事件按最后报文发布时间降序排列，发布时间相同时使用 `EventId` 确定顺序。
- `EarthquakeEvent` 提供当前 `LatestReport` 和只包含发布/订正状态的 `LatestEffectiveReport`。
- 新增 `EarthquakeEventSummary`，当前状态来自最后一报；震源、震级和最大震度来自最后有效报文。
- 订正报更新摘要但保留原报；取消报决定当前状态，同时沿用最后有效报文的数据摘要。
- 合并入口拒绝空 `EventId`、`SourceId` 和 `SourceMessageId`，避免无法追踪的报文被错误合并。
- 新增 15 个测试用例，覆盖乱序输入、去重、最早接收记录、完整排序键、多事件排序、旧报、订正、取消、空输入、空时间线和无效标识。

### 本版本未包含

- 尚未解析固定 JMAXML；测试使用直接构造的领域报文验证合并规则。
- WPF App 尚未引用 Core，事件列表仍未显示固定或实时地震数据。
- 尚未建立页面状态、数据仓库接口、SQLite 缓存或网络数据源。

### 验证结果

- `dotnet build EarthquakeShow.sln --configuration Release --no-restore --no-incremental`：App、Core 和测试工程全部通过，`0` 个警告、`0` 个错误。
- `dotnet test EarthquakeShow.sln --configuration Release --no-restore --no-build`：46 个测试全部通过，`0` 个失败、`0` 个跳过。
- `python -X utf8 tools\validate_test_data.py`：固定数据完整性校验继续通过。
- App 和 Core Release 程序集的产品版本前缀、文件版本分别为 `0.5.0` / `0.5.0.0`。

### 已知限制

- 去重身份依赖数据适配器提供稳定的 `SourceId` 和 `SourceMessageId`；跨来源内容相同的报文不会在本步骤中合并为同一时间线节点。
- 当前摘要按最后有效报文整体取值，不在多来源之间逐字段仲裁；来源优先级和冲突保留在真实数据源接入阶段实现。

## 0.4.0 - 2026-08-19

### 已实现

- 新建无 WPF、数据库和网络依赖的 `EarthquakeShow.Core` 项目，并加入解决方案。
- 定义 `EarthquakeEvent`、`EarthquakeReport`、`Hypocenter`、`IntensityArea`、`IntensityMunicipality`、`IntensityStation`、`SourceReference` 和 `SourceStatus`。
- 定义报文类型、发布/订正/取消状态、正常/训练/测试上下文和数据源在线、延迟、断开、限流、解析失败、停用状态。
- 使用 `JmaIntensity` 明确表示 `unknown/1/2/3/4/5-lower/5-upper/6-lower/6-upper/7`，提供稳定代码的双向转换。
- 使用 `GeoCoordinate` 拒绝非有限或越界坐标；观测点和震源仍可显式没有坐标。
- 使用可空震源深度区分 `0 km` 和未知；使用 `Magnitude` 拒绝 `NaN/Infinity`，未知震级使用 `null`。
- 所有领域时间使用 `DateTimeOffset` 保留来源偏移量；持久化约定为 ISO 8601 `O` 格式。
- `EarthquakeReport` 保留原始报文代码、来源 ID、来源消息 ID、原文 URL 和 `SourcePayload`，避免标准化丢失来源字段。
- 报文时间线、区域、市町村和观测点集合使用 `ImmutableArray<T>`，避免构建后被外部列表修改。
- 新建 `EarthquakeShow.Core.Tests`，引入 xUnit 2.9.2、xunit.runner.visualstudio 2.8.2 和 Microsoft.NET.Test.Sdk 17.12.0。

### 本版本未包含

- 尚未实现 JMAXML 解析器，固定 XML 还没有转换成领域对象。
- 尚未实现按 `EventID` 合并、报文去重、排序、订正或取消处理。
- WPF App 尚未引用 Core，页面没有新增用户可见地震数据。
- 尚未创建 Infrastructure、SQLite 仓储或数据源接口。

### 验证结果

- `dotnet build EarthquakeShow.sln --configuration Release --no-restore --no-incremental`：App、Core 和测试工程全部通过，`0` 个警告、`0` 个错误。
- `dotnet test tests\EarthquakeShow.Core.Tests\EarthquakeShow.Core.Tests.csproj --configuration Release --no-restore`：31 个测试全部通过，`0` 个失败、`0` 个跳过。
- 测试覆盖震度代码往返、未知震度、`0 km`/未知深度、非有限震级、合法/越界坐标、JST 偏移量、来源原文和不可变报文集合。
- `python -X utf8 tools\validate_test_data.py`：固定数据完整性校验继续通过。

### 已知限制

- 模型只约束单个值和单份报文，不验证一个 `EarthquakeEvent` 内所有报文是否具有相同 `EventID`；该规则在步骤 4 的合并服务中实现。
- `DateTimeOffset` 只保证内存中保留偏移量，SQLite 和 JSON 的 ISO 8601 序列化需要在后续持久化实现中继续测试。

## 0.3.0 - 2026-08-19

### 已实现

- 保存同一 JMA 事件 `20260819071048` 的官方 `VXSE51`、`VXSE52` 和 `VXSE53` XML 原文，覆盖震度速報、震源情报和震源/震度详情链路。
- 官方 `VXSE53` 样本包含 4 个都道府县、7 个细分区域、41 个市町村和 75 个观测点，可用于多区域及多观测点解析测试。
- 增加基于官方 `VXSE53` 的订正夹具，保留同一 `EventID`，使用 `InfoType=訂正`、`Serial=2` 和修正后的震级。
- 增加字段缺失夹具，覆盖震级 `NaN`、震源无坐标、可选字段缺失和观测点坐标无法补齐。
- 从 JMA 官方震度观测点坐标 JSON 筛选并关联详情报中的 75 个观测点编码，生成离线 `JmaStations.csv`。
- 根据官方观测点坐标生成 7 个区域测试包络 GeoJSON，用于区域编码匹配和离线图层加载验证；文件明确标记为非官方边界。
- 增加 `unknown` 到震度 `7` 的标准化、排序和应用显示颜色定义；颜色只作为辅助编码。
- 增加数据清单，记录官方/合成来源、下载日期、SHA-256 和每份报文的预期结果。
- 增加无第三方依赖的离线校验脚本，检查哈希、XML 事件链、订正状态、缺失字段、观测点、GeoJSON 和震度定义。
- 修复校验器将 XML `NaN` 保留为浮点值的问题，详见工程实现文档 `BUG-002`。

### 本版本未包含

- 固定数据尚未接入 WPF 页面，没有新增用户可见的地震事件。
- 尚未实现 JMAXML 解析器、统一领域模型、事件合并或报文排序。
- 区域 GeoJSON 是测试包络，不是 JMA 官方细分区域边界，不得用于正式地图或区域归属判断。
- 未加入 xUnit 工程；本步骤验证的是静态数据契约和完整性，使用独立离线校验脚本更直接。

### 验证结果

- `python tools\validate_test_data.py`：通过，验证 5 份 XML、75 个观测点、7 个区域测试包络和 10 个震度定义。
- 三份官方报文具有同一 `EventID`；订正夹具归属于同一事件；缺坐标观测点未出现在坐标表中。
- 所有固定文件的 SHA-256 与 `manifest.json` 一致，校验过程未访问网络。
- `dotnet build EarthquakeShow.sln --configuration Release --no-restore`：通过，`0` 个警告、`0` 个错误。

### 已知限制

- JMA 官方细分区域 Shapefile 约 110 MB，本版本没有将其纳入测试数据；正式地图阶段只提交经简化和许可核验的派生资源。
- 合成夹具用于边界行为测试，不代表 JMA 实际发布事件，也不替代完整 JMAXML Schema 验证。

## 0.2.0 - 2026-08-19

### 已实现

- 建立 `EarthquakeShow.sln` 和 `EarthquakeShow.App` WPF 工程，目标框架为 `.NET 8 Windows`，输出类型为 `WinExe`。
- 使用 WPF 原生 `Window`、`Grid`、`RadioButton`、`TabControl` 等控件实现地震情报页面外壳，不启动浏览器、WebView 或本地 Web 服务。
- 主窗口包含顶部应用状态、左侧地震导航、事件列表空状态、地图占位区、摘要/观测点/时间线/原始数据四个详情标签和底部状态栏。
- 默认窗口尺寸为 `1440 × 900`，最小尺寸为 `1180 × 720`。
- `MainWindowViewModel` 每秒更新一次 JST 时间，并显示网络、缓存和程序版本占位状态；窗口关闭时停止计时器。
- 使用 `Directory.Build.props` 统一维护 `0.2.0` 程序版本、可空引用、隐式 using、警告即错误和确定性构建设置。
- 修复启动时版本文本绑定到只读属性导致的异常，详见工程实现文档 `BUG-001`。

### 本版本未包含

- 未加入固定或实时地震报文、事件领域模型、合并逻辑和历史数据。
- 未引入 Mapsui/SkiaSharp、SQLite、CommunityToolkit.Mvvm 或其他外部 NuGet 依赖。
- 地图按钮为禁用占位控件；EEW、海啸、搜索、设置和历史回放入口尚未显示。
- 当前没有适合单元测试的领域或数据逻辑，因此未建立测试工程；将在固定报文解析和事件合并逻辑出现时加入 xUnit 测试。

### 验证结果

- `dotnet build EarthquakeShow.sln --configuration Release`：通过，`0` 个警告、`0` 个错误。
- 原生进程 `EarthquakeShow.App.exe` 成功启动，窗口标题为 `Earthquake Show`，未启动浏览器或服务器。
- 实测默认窗口为 `1440 × 900`；请求缩小至 `800 × 600` 时，WPF 正确限制为 `1180 × 720`。
- 通过 Windows UI Automation 验证四个详情标签均存在，可切换至“时间线”并恢复“摘要”。
- 主窗口正常关闭，进程在 5 秒内退出，`dotnet run` 返回代码 `0`。
- 已检查 `1440 × 900` 截图，未发现空白渲染、文字裁切、控件重叠或越界。

### 已知限制

- 当前页面只展示无数据状态，尚不能加载或查看真实地震事件。
- UI 响应式收缩、地图渲染和高 DPI 场景将在对应实现步骤单独验证。
