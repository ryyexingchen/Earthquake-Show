# Earthquake Show 工程实现文档

当前版本：`0.67.19`。

`0.67.19` 在海啸详情页局部恢复原有 WPF 浅灰边框标签样式，保留内容 Stretch；VTSE `Magnitude@description` 贯通领域模型、解析器和 SQLite，未知数值时摘要显示规范化描述；固定附加文移动到摘要末尾；观测表将首波和高潮拆成独立列。

`0.67.18` 在地震和海啸详情的 `TabItem` 上统一设置内容 Stretch，确保子栏内容占满所属栏宽；海啸页面将详情时间统一转换为 JST。预报注意报缺少高度时显示“——”，摘要显示 VTSE `固定付加文`，震源名为“不明/未知”时回退到报文描述。此前海啸预报/时间线样式错误绑定 `ObservationStatusText` 的 WPF `BindingExpression` 日志已通过拆分观测高度样式修复；地图 LOD 取消旧请求产生的 `TaskCanceledException` 属于正常取消路径。

`0.67.17` 支持同一海啸事件在时间线中切换不同报文，并按当前报文以前的事件历史构建累计预报区、观测点、推定区域和信息项快照；重复 code 使用下一报文更新，未重复 code 的既有情报继续保留。

`0.67.16` 将观测状态“欠测”“观测中”“微弱”投影到实测高度列，其中前两者使用黑色背景，后者使用海啸预报浅蓝背景；状态列不再显示“观测到海啸”。海啸报文列表按 `EventId` 聚合为事件代表报文，代表报文取发布时间最新的一条；完整报文仍保留在时间线和原始数据中，刷新时继续按来源报文身份保持当前详情选择。

`0.67.15` 将海啸警报/预报表从摘要页分离到独立的“警报 / 预报”标签；观测点表的状态列改为纯文本，实测高度使用 `TsunamiLevel` 对应的浅蓝、黄色、红色或紫色背景显示。

`0.67.14` 将海啸右栏改为原生 `TabControl`，提供“摘要”“观测点”“时间线”“原始数据”四个可切换页面。摘要页展示震源和海啸警报/预报表，观测点页展示可选观测站和海啸情报/实际观测表，时间线页展示报文时间线、差异和信息项，原始数据页保留 XML 查看与复制。新控件独立声明 WPF 资源，避免独立 BAML 加载时无法解析父控件资源。

`0.67.13` 将海啸右侧详情拆成独立的“海啸警报 / 预报”和“海啸情报 / 实际观测”子栏。预报子栏使用等级、预报区、预计首波、最大高度四列表格；观测子栏使用区域、观测点、首波、高潮、实测高度、状态六列表格，并保持观测行选择与地图/站点详情联动。两块的可见性继续分别由 `HasForecastAreas` 和 `HasObservationStations` 控制，因此“仅观测无预报”可以正常显示。

`0.67.12` 修复海啸报文刷新时 WPF `ListBox` 因替换 `ItemsSource` 将瞬时 `null` 反向写入 ViewModel、导致报文取消选中和详情/地图消失的问题。报文列表改为 ViewModel 到视图的单向选中同步，用户选择通过 `SelectionChanged` 显式提交；海啸页主体调整为左侧报文列表、中间地图、右侧报文详情与数据表的三栏布局。

`0.67.11` 修复用户查看海啸页面时被新地震报文自动导航打断的问题：海啸页面可见时保留当前页面和地图，仍在后台更新地震数据；只有地震页面可见时才执行新报文自动聚焦。

`0.67.10` 将海啸地图最大缩放从 `24` 收紧为 `16`，仍保留 `13–16` 的高精度海岸线查看范围。App 启动时会把三份固定 VTSE 训练样例（`VTSE41/51/52`）写入独立的 `sample-jma-tsunami` 来源，便于无网络、无缓存时验证报文列表、预报区、观测和地图显示；后续可移除该 seed 调用和资源链接。

`0.67.9` 优化海啸地图放大后的尖刺和卡顿：`TsunamiMapView` 按屏幕空间最小点距（普通几何 `0.65px`、点数达到 `10000` 时 `1px`）过滤连续近点并始终保留每条线的末点；路径使用圆角连接和圆端点，避免 WPF 默认斜接线在锐角处外扩；线宽按当前缩放倍率反向补偿，保持放大后视觉宽度稳定；连续属性/滚轮变化通过 32ms 后台定时器合并重绘。原始 GeoJSON 和 LOD 层级不变。

`0.67.8` 将海啸地图调整为三级本地 LOD：`MapZoomLevel <= 2` 使用低精度沿岸线，`2 < MapZoomLevel <= 12` 使用中精度沿岸线，`MapZoomLevel > 12` 使用详细沿岸线；缩放范围为 `0.5–16`。中精度和详细资源在首次进入对应倍率后通过后台任务按需加载，加载期间保留当前已显示层，完成后通知地图重绘；缩回概览倍率会取消过期请求。低精度资源由详细沿岸线按步长 `2` 抽稀并去除连续重复点，中精度资源保留全部点但统一为运行时 LOD 格式，三层保持相同预报区 code。新增 `tools/generate_tsunami_lod.py` 用于可重复生成派生资源。

`0.67.7` 修复高精度地图按视口裁剪后跨事件自动缩放过度放大的问题：`TryGetSelectedEventBounds()` 现在按当前报文的区域/市町村代码从稳定的概览几何取完整包络，再叠加当前图层和震源/观测点坐标。高精度图层切换或缓存仍在旧事件范围时，自动适配不会再因当前裁剪结果为空而退化为震源单点；高精度视口裁剪和手动交互规则保持不变。

`0.67.6` 修复海啸地图被选中报文容器一并折叠的问题：地图组件现在独立于 `HasSelectedReport` 详情容器，只要低精度沿岸线资源可用，即使没有选中报文也显示中性的预报区地图；选中报文后仍按“摘要 → 地图 → 观测详情”的顺序显示。

`0.67.5` 在海啸地图中加入选中观测点的自动居中：只有状态为“观测到海啸”或“微弱”且坐标完整的站点会触发平移，欠测、无坐标和未观测记录仍只保留表格/详情展示。观测表选择变化会在界面线程空闲时滚动到选中行，地图点点击沿用同一 code 选择状态。

`0.67.4` 重排海啸页面详情顺序，增加海啸地图缩放和概览/详细 LOD；低倍率只读取约 58 KB 的低精度沿岸线，达到 `2.0×` 后按需读取约 6 MB 的详细沿岸线。观测表改为可选列表，地图只显示有实际测量意义且有坐标的 `观测到海啸`/`微弱` 站点；站点详情仅在表格或地图选中后显示。

`0.67.3` 修复报文切换自动缩放竞态：报告变化时由 ViewModel 重建图层并发布 `ViewedReportKey`，视图使用当前画布和新事件包络一次性计算最终 Zoom；ViewModel 不再先写入隐藏的默认缩放值。`0.66.62` 的统一视口筛选、`0.66.61` 的边界筛选、`0.66.60` 的 LRU 范围缓存、`0.66.59` 的边界有效性检查及更早版本的重绘抑制策略仍然有效。

## 2. 当前工程状态

- 正式实现目标：C# + .NET 8 + WPF 原生 Windows 桌面应用。
- 本机环境：已安装 `.NET SDK 8.0.412` 和 `Microsoft.WindowsDesktop.App 8.0.18`。
- 当前版本：`0.67.11`。报告切换自动缩放由视图统一计算：ViewModel 仅重建新报文图层并发布 `ViewedReportKey`，视图按当前画布尺寸、事件包络和震源坐标一次性提交目标 Zoom，避免旧事件手动缩放值与隐藏默认值之间的异步竞争；地图只为有明确震度且有坐标的观测点创建 `EarthquakeMapMarker`，未知震度观测点仍保留在详情报文数据中；有震度观测点在标签模式下显示震度文本；观测点圆圈、震度标签和观测点高亮统一绘制到单个 `DrawingVisual`，减少高精度重绘时的 WPF 控件创建和布局开销；高倍率观测点标签排版按震度和 DPI 缓存 `FormattedText`，观测点圆圈和标签模板按当前报文实际 marker 类型懒加载并复用，避免每个观测点重复创建绘制对象；完全相同投影状态下的区域、市町村、边界和区域高亮静态几何宿主直接复用，缓存键对远小于一个像素的浮点反算误差使用容差比较，减少重复坐标投影和 `StreamGeometry` 构建；高精度资源按约 1° 网格扩大视口并缓存最多 3 个已解析范围，来回移动时优先复用 `MapGeometrySet`；拖拽高精度地图使用持久位图缓存，视图卸载时释放；同一精度且内容稳定、当前视野仍位于最近绘制覆盖范围内时，拖动提交复用现有视觉层，只更新平移后的地理中心。观测点标签字体使用单独的 `StationLabelFont` 字段并在圆圈内容区域垂直居中，低倍率恢复小圆点；高精度重绘复用冻结画刷，震源在所有观测点标签之后绘制并输出重绘耗时及图层计数；连续高精度加载请求在视口仍处于当前缓冲范围时复用进行中的解析任务，只更新待应用中心，减少重复 JSON 解析和 GC 峰值；完整重绘使用后台调度，拖动中的高精度结果暂存到交互结束后再按视口校验应用；滚轮缩回较低精度时提交当前中心并保留预览画面，等待目标 LOD 应用后只重绘一次；地图状态变化不再重建详情观测树，避免首次选择观测点后高亮被自动清除；几何替换静止时锁定替换前画布中心，拖动时保留已提交中心和像素位移，避免高精度加载完成后视角跳动；拖动期间延迟 LOD 检查并合并最新请求，松开后再执行最新视口检查；高精度静态图层仅构建当前视野及 25% 缓冲范围内的区域、市町村和边界，累计拖动超出覆盖范围时松手补绘；中精度 LOD 取消在文件边界非异常返回，过期请求不会提交几何；高精度索引读取取消也使用非异常式返回，避免过期请求报告异常；HTTP 在线来源默认每 5 秒并行检查，P2P WebSocket 报文收到即入库；失败和限流继续指数退避。地震页面状态栏现在区分 XML 覆盖延迟、来源限流和来源解析失败；新增 `tools\audit_jma_xml_feed.ps1` 用于核验 JMA 短/长期 Feed 覆盖窗口；新增报文会通知主窗口自动定位左侧事件列表并切换详情摘要；震源情报根据前序详细观测点决定区域绘法；自动地图精度完全由全局 ZoomLevel 决定；远地 P2P 重复归并会先保守归并再与 JMA XML 合并；设置页已提供本地 JMA XML 目录选择、导入和统计提示，SQLite schema 4 保留最近导入批次及跳过/失败明细，报文与导入明细现在使用同一事务；报文切换期间属性通知触发的 LOD 检查通过后台调度合并为单次执行，显式用户交互仍即时检查；高精度视野边界密集时改用 `1px` 屏幕空间简化阈值，低密度仍用 `0.65px`，不改变边界范围和首尾点；高精度静态重绘的轮廓、区域、市町村和选中高亮视口筛选统一使用单次索引循环，减少 LINQ 迭代器与中间集合分配；海啸地图新增三级 LOD、按需后台加载和 `0.5–16` 缩放范围；海啸沿岸线新增屏幕空间简化、圆角连接、缩放线宽补偿和重绘节流。

## 3. 正式技术栈

`0.66.43` 性能修复：高精度视口统一按缓存瓦片判定，同一瓦片内拖动复用视觉层；同级别在途 LOD 请求合并，中精度资源只解析一次，高精度换瓦片期间保留已有视觉层。

| 层级 | 技术 | 职责 |
| --- | --- | --- |
| 桌面界面 | .NET 8 + WPF | 原生窗口、控件、布局、键盘和可访问性 |
| 应用语言 | C# | 界面、领域模型、数据源、缓存和后台任务 |
| 架构 | MVVM | 分离 View、页面状态和业务逻辑 |
| MVVM 辅助 | CommunityToolkit.Mvvm | 后续减少通知属性和命令样板代码 |
| 地图 | Mapsui WPF + SkiaSharp | 不依赖 WebView 的地图、区域和点图层渲染 |
| GIS | NetTopologySuite | GeoJSON、几何计算和空间数据处理 |
| 数据库 | Microsoft.Data.Sqlite | 事件、报文版本、原始响应和来源状态缓存 |
| 网络 | HttpClient | JMA、P2PQuake 和其他 HTTP 数据源 |
| JSON/XML | System.Text.Json + System.Xml | 数据解析和固定样本契约 |
| 日志 | Microsoft.Extensions.Logging | 结构化运行日志和故障诊断 |
| 测试 | xUnit 2.9.2 + Microsoft.NET.Test.Sdk 17.12.0 | 领域逻辑、解析器、仓储和回归测试 |
| 开发脚本 | Python | 仅用于 GIS 和固定样本的离线预处理 |

正式运行时不得依赖 Node.js、npm、Rust、浏览器、WebView、HTML/CSS 或本地 HTTP 服务。

## 4. 环境要求

- Windows 10/11 x64。
- .NET SDK 8.x。
- Microsoft Windows Desktop Runtime 8.x。
- 不需要单独安装 SQLite；`Microsoft.Data.Sqlite` 随应用依赖提供托管和原生运行库。
- 实时刷新需要访问 `https://www.jma.go.jp/`，不需要 API Key；无网络时仍可读取 SQLite 缓存。

检查命令：

```powershell
dotnet --info
dotnet --list-sdks
dotnet --list-runtimes
```

当前环境已经满足建立和运行基础 WPF 工程的条件。

### 5.1 外部资源目录

根目录 `resources/` 保存待评估、待转换或许可证尚未核对的原始素材，不会自动进入 WPF 输出。音频沿用现有 `resources/sounds/`；普通图片放入 `resources/images/`；需要区别采样、平铺或地图渲染用途的贴图放入 `resources/textures/`；大型文本、速度模型和查找表放入 `resources/data/`；`resources/lib/` 只保存确实需要且完成来源、架构和许可证核验的原生 DLL。

确认要随应用发布的资源再复制或链接到 `src/EarthquakeShow.App/Assets/Audio/`、`Assets/Images/`、`Assets/Textures/` 或 `Assets/Data/`。App `.csproj` 已为这四类目录配置 `CopyToOutputDirectory=PreserveNewest` 和 `CopyToPublishDirectory=PreserveNewest`；不要直接把整个 `resources/` 复制进发布包，避免把未使用的大文件、第三方 DLL 或授权不明素材带入正式版本。

## 7. 原生窗口实现

### 7.1 启动流程

```text
EarthquakeShow.App.exe
  → App.xaml 启动
  → 创建 MainWindow
  → MainWindow 创建 MainWindowViewModel 并设为 DataContext
  → FixedJmaXmlDataLoader 读取正式站点目录，并以固定 CSV 作为代码补充/损坏回退
  → 同一站点目录解析四份固定 JMAXML 和七份 JMA 详细 JSON，并注入实时 JMA XML 来源
  → 创建 SQLite 仓储并初始化地震 schema v3（旧 v1/v2 缓存自动迁移并清理 jma-json）
  → 优先读取缓存；缓存为空时写入固定 seed，已有缓存时补入缺失的固定官方样例
  → 写回失败时尝试只读连接，保留已读取的缓存事件并显示只读状态
  → SqliteEarthquakeEventRepository 使用 EarthquakeEventMerger 合并事件
  → 设置离线来源状态并加载页面快照
  → 依次请求 JMA list.json 摘要、JMA XML Atom Feed 详情和 P2PQuake JSON 补充源
  → 成功报文写入 SQLite；失败来源只更新来源状态
  → ViewModel 初始化版本、页面状态、地图和 JST 时钟
  → 窗口首次显示后异步加载仓储事件快照
  → 关闭窗口时先取消并等待初始化、HTTP 刷新和 WebSocket 循环
  → 释放会话取消源、HttpClient、DispatcherTimer 和页面事件订阅后完成关闭
```

`0.15.0` 仍没有依赖注入容器或长期轮询任务。固定样本在 ViewModel 创建阶段解析，SQLite 缓存先加载到页面，随后用同一个 `HttpClient` 以 15 秒超时依次请求 JMA JSON、JMA XML 和 P2PQuake；用户点击刷新时复用相同路径。HTTP、XML/JSON 处理和 SQLite 操作均在异步流程中执行，不阻塞 WPF Dispatcher。

### 7.2 主窗口区域

`MainWindow.xaml` 使用 WPF `Grid` 建立以下固定区域：

- 顶部状态栏：带状态点的数据状态卡片、最后接收时间、搜索/设置按钮和 JST 当前时间卡片。
- 左侧导航：首版只显示已经实现的地震入口。
- 事件列表：最近事件和历史地震共用一个列表。
- 地图区域：承载 WPF 原生 `EarthquakeMapView`，绘制离线轮廓和当前事件图层。
- 右侧详情：摘要、观测点、时间线和原始数据标签。
- 底部状态栏：网络、缓存、来源、地图数据、WebSocket 错误详情、自动刷新和版本；错误详情使用弹性列，自动刷新与版本使用稳定宽度。

默认窗口为 `1440 × 900`，最小窗口为 `1180 × 720`。宽度不低于 `1280 px` 时，右侧详情栏固定为 `380 px`；低于该阈值时详情列宽归零，详情面板覆盖在地图右侧并可开关。顶部搜索按钮聚焦事件搜索框；设置按钮切换原生设置页，地图工具提供缩放、复位、定位和跟随选择。所有区域均由 WPF 原生控件构成，不通过浏览器或托管网页实现。

### 7.3 UI 线程规则

- 当前 JST 时钟使用 UI 线程上的 `DispatcherTimer`，每秒只更新一个文本属性，并在窗口关闭时停止和解除事件订阅。
- 网络、XML/JSON 解析和 SQLite 操作不得阻塞 WPF Dispatcher。
- 后台结果通过 ViewModel 更新，必要时使用 Dispatcher 切回 UI 线程。
- 不使用 `async void`，事件处理器和 WPF 生命周期入口除外。
- 所有长期任务必须支持取消，应用退出时停止连接和定时器。
- 主窗口使用两阶段关闭：第一次 `Closing` 取消关闭并等待 `DisposeAsync()`；资源释放完成后再次关闭，由 `OnMainWindowClose` 结束应用进程。

### 7.4 地震情报页面状态

`EarthquakePageViewModel` 只依赖 `IEarthquakeEventRepository`，通过不可变 `EarthquakePageState` 快照统一发布页面状态。主窗口只负责在首次显示时调用 `LoadAsync()`，不直接读取事件或管理选择。

```text
IEarthquakeEventRepository
  → ListEventsAsync / EventsChanged
  → EarthquakePageViewModel
  → EarthquakePageState
  → 后续事件列表、地图和详情绑定
```

首次非空加载选择事件列表第一项及其最后一报。仓储发布新快照时，先按 `EventId` 恢复当前事件，再按 `SourceId + SourceMessageId` 恢复当前报文；只有原选择已不存在时才回退到第一项或最后一报。因此新事件到达不会强制打断历史浏览。

页面状态同时保存搜索文字、筛选快照、排序选项、地图焦点、来源状态、加载、刷新、离线和错误状态。`0.11.0` 由列表 ViewModel 执行搜索、筛选和排序，由详情 ViewModel 投影 `ViewedReport`，由地图 ViewModel 消费同一快照并投影当前报文图层。

`EarthquakeDetailsViewModel` 不创建第二份事件选择。摘要字段、区域/市町村/观测点列表、时间线和原始负载均从 `EarthquakePageState.ViewedReport` 重建；时间线选择通过 `EarthquakePageViewModel.SelectReport()` 修改页面快照。时间线只投影与当前报文 `SourceId` 相同的节点，来源切换选择目标来源的最新报文；上一报、下一报和返回最新均在当前来源内导航，不会穿越到另一来源。观测点选择有坐标时调用地图 `FocusLocation()`，无坐标项仍可选但不会生成地图标记。

详情显示使用 `ReportDisplaySnapshot` 按报文顺序累计字段：只有非空震源、震级、发生时间、海啸说明和非 `Unknown` 最大震度才覆盖已有值，后续报文缺少字段不会回退为“不明”。摘要关键字段按最大震度、震源地、震级、深度、海啸逐行显示；震度速报在缺少震源和震级时增加“震源・规模 调查中”。时间线关键字段按最大震度一行、震级/震源地/深度一行、海啸一行显示。时间线变化摘要只比较当前报文实际提供的字段；从未知首次收到时显示当前值，已知值改变时显示 `旧值 → 新值`，相同值和缺失值继续显示累计原值；从未收到的非海啸字段不显示，海啸始终显示当前累计状态或“津波 调查中”。

摘要页把海啸从普通字段列表中独立出来。无海啸说明显示“津波 调查中”；来源文字归一化为“津波の心配なし”“若干の海面変動”“津波注意報”“津波警報”或“大津波警報”，对应灰、蓝、黄、红、紫色背景。未识别的非空原文保留原文并使用中性背景。

仓储更新可能来自后台线程。ViewModel 在创建时捕获 `SynchronizationContext`，收到更新后切回该上下文再替换状态；测试环境没有同步上下文时同步执行。主 ViewModel 保存初始化、自动刷新和 WebSocket 循环任务；窗口关闭时由 `DisposeAsync()` 取消并依次等待这些任务，再解除仓储事件订阅和释放连接资源。同步 `Dispose()` 复用同一清理任务，不建立第二条释放路径。

### 7.5 显示投影与响应式布局

`EarthquakePageDisplayState.Create()` 将领域和页面状态转换为可直接绑定的界面文字和布尔状态。加载、错误、空数据、来源连接、最后接收和当前选择的判断集中在该投影中；XAML 只使用绑定和 `BooleanToVisibilityConverter`，不重复业务判断。

`WindowLayoutViewModel` 只管理窗口宽度等级和详情抽屉开关。`MainWindow` 的 `SizeChanged` code-behind 属于纯显示行为：它把实际宽度交给布局 ViewModel，并在紧凑模式把 `DetailsColumn` 设置为 `0`。详情面板跨越地图与详情列并右对齐，因此桌面模式占用预留列，紧凑模式则覆盖地图右侧。

顶部状态字段使用固定列宽，数据状态卡片采用状态点、小标题和状态文字的两行结构，当前时间卡片保持固定高度；底部来源和 WebSocket 错误字段使用最大宽度和文字省略，自动刷新列固定为 `190 px`、版本列固定为 `88 px`，防止动态文字互相覆盖或影响地图区域。响应阈值和抽屉状态有独立单元测试；窗口尺寸、标签切换和抽屉操作使用原生窗口截图与 UI Automation 验证。

### 7.6 事件列表投影与选择

`EarthquakeEventListViewModel` 订阅 `EarthquakePageViewModel.PropertyChanged`，只把页面事件快照投影为当前可见卡片，不持有第二份仓储或独立选择。筛选或排序改变后计算目标顺序，再按 `EventId` 对同一个 `ObservableCollection` 执行插入、移动、替换和删除；未变化卡片保留实例，避免重置整个数据源和滚动位置。100 条事件场景由单元测试验证，WPF `ListBox` 使用回收式 `VirtualizingStackPanel` 创建可见容器。

搜索覆盖事件 ID、震源名称/代码、报文代码和来源 ID。时间筛选使用最新发布时间；震度和震级未知值不会被当作零值参与最低值比较；区域筛选检查最新有效报文的震源、区域、市町村和观测点。确定性排序和字段细节维护于[数据契约与格式](./数据契约与格式.md)。

列表 `SelectedItem` 调用页面 `SelectEvent()`，因此地图和详情后续可复用同一选择状态。仓储快照变化时列表按 `EventId` 恢复卡片选择，并比较前后事件 ID 标记新事件；首次加载的数据不标为新事件。刷新入口调用页面已有仓储边界，并在任务完成前拒绝第二次刷新。

筛选区域当前在固定 `280 px` 左栏内折叠并即时应用，没有引入筛选草稿对象或独立抽屉 ViewModel。当前仓储一次返回全部事件，不存在分页游标；“加载更早记录”将在 SQLite 仓储定义分页契约后实现。

### 7.7 地图状态与图层

`EarthquakeMapViewModel` 只依赖现有 `EarthquakePageViewModel` 和不可变 `OfflineMapGeometry`。页面状态变化时重新投影 `ViewedReport`：区域通过 `areaCode` 匹配本地概览 GeoJSON，同一代码的多个几何部件合并为一个事件区域；没有匹配几何的区域累计到 `UnmappedAreaCount`，不静默丢弃。震源只在存在合法坐标时生成一个标记，观测点只为有坐标的记录生成标记。无坐标观测点不丢失，详情页仍可显示。没有手动报文快照时，页面首次选择事件仍把 `ViewedReport` 设置为最新报文。

`EarthquakeMapView` 使用 WPF `Canvas`、`Path`/`StreamGeometry` 和 `Ellipse` 原生图形。每个 GeoJSON Feature 合并成一个路径，使用 EvenOdd 填充规则保留内环；投影中心从真实几何和事件焦点计算，缩放比例统一以全国概览自动适配比例为基准。全局 `ZoomLevel=1.0` 表示全国概览，事件自动适配按事件包络相对全国包络换算级别，每级使用约 `1.25x` 像素比例；震源坐标作为严格中心，震源、已解析观测点和区域/市町村几何组成事件包络，视口保留约 10% 留白；无震源时回退到事件图层包络中心，点事件使用最小包络避免过度放大。缩放范围为 `0.5` 到 `24.0`，点击日本全图会关闭跟随，跟随按钮会重新启用并定位当前事件。

观测树的当前选中对象由 `EarthquakeMapSelection` 保存，使用都道府县、区域、市町村或观测点的稳定代码区分，不按名称猜测。选中都道府县时，地图查找其 `PrefectureCode` 对应的所有区域面；选中区域或市町村时按几何代码查找单个面；选中观测点时按站点代码查找点标记。选中后按完整几何包络计算中心和全局 ZoomLevel：观测点定位到点，区域/市町村/都道府县确保完整面落入视口。区域和市町村坐标优先从当前几何按代码查找，当前精度未包含时回退到概览几何；选中高亮也会从概览几何重建，避免节点暂时没有震度图层对象而显示位置未知。渲染层在普通边界之后叠加高对比外层描边和与震度对应的内层描边，区域面保留原震度填色，观测点使用同样的双层圆环；重复点击同一观测树节点清除选择，地图手动拖动或缩放只更新投影，不清除选择。观测树项容器直接处理预览点击，保证文本点击也能取消当前选择，并固定拉伸观测点栏内容到详情栏宽度；空或不完整轮廓会跳过高亮绘制。该层不使用模糊特效或持续动画，并会随中/高精度几何替换自动重建。

自动刷新或流式来源产生新报文时，页面比较新旧快照中的报文身份；只有发现新增报文才自动跳转。目标按 `IssuedAt`、`ReceivedAt` 降序选择，发布时间相同则 JMA XML 优先；没有新增报文时保留用户当前事件和报文选择。

查看震度速報时，如果当前报文之前已经出现过震源情报或震源・震度情报，地图层从前序报文继承最近震源坐标并绘制震源标记；震源情报之前的震度速報不继承震源，震源・震度情报之后不会再按此规则出现新的震度速報。

真实地图资源通过 `Assets\\Data\\**\\*` 规则复制到输出和发布目录。运行时默认读取 `Assets/Data/Map/jma-earthquake-areas-overview.geojson`：使用 `0.015` 度简化容差和 `0.0002` 平方度最小多边形面积过滤，元数据记录 JMA 来源、版本、坐标顺序和过滤参数。高精度 `jma-earthquake-areas.geojson` 保留作后续按需加载输入；`Assets/japan-overview.geojson` 保留作历史示意资源但不再作为运行时入口，应用不下载在线底图。

启动性能约束：全国概览不得在启动阶段解析高精度 66 MB 图层。概览资源约 3.2 MB、435 个多边形部件；地图视图对 ViewModel 通知和窗口尺寸变化使用合并重绘，避免初始化期间重复创建 `StreamGeometry`。直接启动 Release 可执行文件实测工作集约 200 MB（测量包含 .NET/WPF 和固定数据基线，不作为硬性上限）。海洋背景使用 `#B7D4E2`，陆地使用 `#F3EFE4`，边界使用 `#798F99`，用于建立清晰的海陆视觉层次。

## 8. 地图方案

步骤 8 使用 WPF 原生 `Canvas`、`Polygon` 和 `Ellipse` 绘制，不使用浏览器、WebView、在线底图或 Mapsui 运行时依赖；Mapsui/SkiaSharp 仍保留为后续大规模 GIS 场景的评估选项。

当前图层：

#### 8.2 地图精度与内存优化调研及第一阶段实现

当前资源统计（2026-08-24，文件大小为 UTF-8 GeoJSON 文件大小，坐标数按位置数组统计）：

| 资源 | 文件大小 | Feature | 坐标数 | 简化容差 |
| --- | ---: | ---: | ---: | ---: |
| 区域概览 | 3.20 MB | 194 | 127,463 | 0.015° |
| 市町村概览 | 4.58 MB | 1,910 | 165,083 | 0.015° |
| 区域拓扑边界概览 | 3.35 MB | 1,069 | 130,039 | 0.015° |
| 区域中精度 | 1.03 MB | 194 | 42,246 | 0.003° |
| 市町村中精度 | 2.77 MB | 1,910 | 97,589 | 0.003° |
| 区域拓扑边界中精度 | 0.86 MB | 1,069 | 31,101 | 0.003° |
| 区域高精度 | 62.94 MB | 194 | 2,640,712 | 0.0005° |
| 市町村高精度 | 69.31 MB | 1,910 | 2,891,840 | 0.0005° |

高精度资源的坐标量约为概览层的 17 至 21 倍；运行时还会把 JSON 数组转换为托管对象和冻结的 `StreamGeometry`，所以不能仅按文件大小估算内存。推荐的实施顺序是：

方案对比：

| 方案 | 细节改善 | 内存风险 | 结论 |
| --- | --- | --- | --- |
| 直接替换高精度 GeoJSON | 最大 | 高，启动解析和几何峰值同时增加 | 不采用 |
| 单一中精度 GeoJSON | 中等 | 可控，但全国视图仍承担全部几何 | 可作为第一阶段 |
| 多级 LOD 按缩放加载 | 高，按视图需要提升 | 低到中，切换时只保留当前级别 | 推荐 |
| 按区域/瓦片分块 | 高，可进一步限制工作集 | 实现复杂，需要缓存和边界拼接 | LOD 不足时再采用 |
| 压缩 JSON 或二进制坐标 | 不改变几何细节 | 可降低磁盘和读取分配，但不能消除 `StreamGeometry` 内存 | 作为后续传输优化 |

压缩文件本身不能解决 WPF 绘制内存：应用最终仍要把坐标转换为 `StreamGeometry`。因此优先减少当前视图需要的坐标数，再考虑压缩存储。

1. `0.39.0` 保留概览层作为启动和全国视图；`ZoomLevel > 2` 时按需加载 `0.003°` 中精度，`ZoomLevel <= 2` 恢复概览。
2. 资源读取在后台任务完成后替换三类几何，同一时刻只让当前几何继续参与地图渲染；取消或异常时保留上一层。
3. `0.60.0` 在 `ZoomLevel > 12` 按当前视野及 20% 缓冲解析 `0.0005°` 高精度区域和市町村；区域轮廓由同一批高精度 Polygon 派生，不再加载全国高精度边界对象。
4. 每个级别仍需记录首次绘制耗时、LOD 切换耗时、工作集峰值和缩放到 4/8/12/24 倍的视觉缝隙；高精度平移重载还需记录包络命中率和单次解析峰值。

本阶段中精度三件套合计约 `4.66 MB`、约 `170,936` 个坐标，按当前对象和 WPF 绘制方式暂估地图新增工作集约 `15–40 MB`；这是工程区间，不替代 Release 实测。高精度区域和市町村仍约 `132.25 MB` 文件、`5,532,552` 个坐标，不应在启动时同时解析。

公开地图实现调研（访问日期：2026-08-21）：

- [Mapbox GL JS 性能指南](https://docs.mapbox.com/help/troubleshooting/mapbox-gl-js-performance/) 将渲染成本拆为 source 数、layer 数和顶点数，并建议合并相似图层、减少不可见要素、优化表达式、使用矢量瓦片和 feature state。对本项目的直接启发是：按震度分组后保持少量 `StreamGeometry`，并按 LOD/视口减少顶点，不为每条边创建 WPF 控件。
- [Mapbox source 规范](https://docs.mapbox.com/mapbox-gl-js/style-spec/sources/) 说明 GeoJSON 适合小型或动态数据，矢量瓦片适合按瓦片加载的大型静态数据。项目当前没有网页瓦片运行时，后续若 LOD 仍不足，可以采用离线分块几何，而不是引入 WebView。
- [OpenStreetMap 瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/) 要求遵守缓存头、保留本地缓存、避免批量预取，并使用明确的应用标识。项目使用 JMA 离线资源，因此不请求 OSM 瓦片；这些原则仍适用于未来任何在线底图适配器。
- [Google Maps JavaScript API 概览](https://developers.google.com/maps/documentation/javascript/overview) 将栅格/矢量渲染、缩放、平移、视口和标记碰撞作为独立能力。项目不采用网页 API，但会保留“视口状态与图层加载状态分离”的设计原则。

内存估算方法：当前 `GeoCoordinate` 是两个 `double`，仅按坐标值计算约为 `16 bytes/点`；数组、集合、字符串、JSON 解析中间对象和 WPF `StreamGeometry` 还会产生额外开销。按 `16–32 bytes/点` 的托管几何、`16–48 bytes/点` 的绘制几何和解析峰值叠加估算，得到以下工程区间：

| 场景 | 坐标数 | 资源文件 | 地图新增工作集粗估 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 当前概览（区域+市町村+边界） | 422,585 | 10.62 MB | 25–55 MB | 启动默认方案 |
| `0.005°` 候选（区域+市町村，未含边界） | 97,482 | 2.80 MB | 12–35 MB | 临时探针结果，需拓扑和截图验证 |
| 高精度区域+市町村 | 5,532,552 | 132.25 MB | 180–420 MB | 不应启动时同时解析 |

这些数字不是 Windows 工作集承诺；WPF、字体、SQLite、固定数据和 .NET CLR 基线还要另行计入。正式实现必须在同一台机器、同一 Release 配置下测量启动后、首次绘制、LOD 切换和缩放到 4/8/12 倍的 Private Working Set，并记录峰值和 GC 后稳定值。

## 10. 领域模型

Core 只表达跨来源公共语义和纯领域计算，不引用 WPF、HttpClient、SQLite 或具体 XML 类型。

### 10.1 核心对象

| 类型 | 约定 |
| --- | --- |
| `EarthquakeEvent` | 使用来源事件 ID 标识事件，保存不可变报文时间线，并派生当前报文、最后有效报文和事件摘要 |
| `EarthquakeReport` | 保存报文代码、类型、状态、上下文、时间、震源、震级、震度集合和来源 |
| `Hypocenter` | 名称、代码和坐标可未知；深度为 `int?`，`0` 与 `null` 含义不同 |
| `Magnitude` | 值可未知；拒绝 `NaN` 和正负无穷，保留类型和来源条件文字 |
| `IntensityArea` | 保存都道府县、细分区域和该区域最大观测震度 |
| `IntensityMunicipality` | 使用 `AreaCode` 关联区域，保存市町村最大观测震度 |
| `IntensityStation` | 使用 `MunicipalityCode` 关联市町村，坐标可未知 |
| `SourceReference` | 保留来源 ID、原始消息 ID、原文 URL 和来源原始负载 |
| `SourceStatus` | 表达在线、延迟、断开、限流、解析失败和停用等适配器状态 |

### 10.2 未知值与时间

- 震度未知统一使用 `JmaIntensity.Unknown`；枚举顺序只用于稳定排序，不能把底层数值直接显示给用户。
- 标准震度代码由 `ToCode`/`TryParseCode` 转换，未知输入返回失败和 `Unknown`，不静默映射为普通震度。
- 震源深度未知使用 `null`，地表或极浅震源可使用 `0`。
- 震级未知使用 `Magnitude.Value = null`；非有限浮点数在构造时拒绝。
- 领域时间使用 `DateTimeOffset`。写入 JSON 或 SQLite 时使用 `ToString("O")` 等价的 ISO 8601 往返格式，读取后必须保留原偏移量。

### 10.3 集合与来源字段

报文的区域、市町村、观测点以及事件的报文时间线使用 `ImmutableArray<T>`。Core 不把 XML 节点直接暴露给 UI；无法统一的源字段保存在 `SourceReference.SourcePayload`，同时保留原始报文代码和消息 ID，便于排查标准化差异。

### 10.4 事件合并与摘要

`EarthquakeEventMerger.Merge()` 接受已标准化的报文集合并返回不可变事件集合。它不保存状态、不读取数据库，也不依赖输入顺序，后续内存仓储和 SQLite 仓储应复用这一入口，不能在各数据源适配器中复制合并规则。

`0.40.0` 在按 `EventId` 初始分组后增加 JMA 同源临时身份归并。只有两个 `jma-xml` 事件组分别包含 `VXSE51` 和 `VXSE52`/`VXSE53`，EventID 按 `yyyyMMddHHmmss` 解析后的时间差不超过 60 秒、组内最新发布时间差不超过 180 秒，且双方已知最大震度不冲突时才合并。合并后的 `EarthquakeEvent.EventId` 选择包含震源信息的正式 EventID；报文对象的原始 EventId、SourceMessageId、SourcePayload 和 SQLite 主键不改写。P2PQuake、JMA JSON 以及不满足条件的 JMA 组保持独立事件。

```text
标准化报文
  → 校验 EventId / SourceId / SourceMessageId
  → 按 EventId 分组
  → 按 SourceId + SourceMessageId 去重并保留最早接收记录
  → 事件内稳定排序
  → 按最新发布时间排列事件
  → EarthquakeEvent 派生当前状态和最后有效报文摘要
```

事件内排序键依次为 `IssuedAt`、`Serial`、`ReceivedAt`、`SourceId`、`SourceMessageId`，其中 `Serial = null` 排在数字报次之前。事件集合按各事件最后报文的 `IssuedAt` 降序排列，时间相同使用 `EventId` 升序兜底。

`LatestReport` 是时间线最后一份报文，包含取消状态；`PreferredReport` 按 XML、P2PQuake 的来源优先级选择默认展示报文；`LatestEffectiveReport` 只接受 `Issued` 或 `Correction`。`EarthquakeEventSummary.Status`、`Context` 和 `UpdatedAt` 来自 `PreferredReport`，报文代码、发生时间、震源、震级和最大震度来自 `LatestEffectiveReport`。因此时间线可以保留 P2PQuake 的较新节点，同时默认摘要仍优先使用 XML。

输入标识为空时合并服务抛出 `ArgumentException`。该检查只保护归并身份；字段级合法性仍由值对象和后续解析器负责。

### 10.5 固定 JMAXML 解析与应用装配

`JmaXmlParser` 使用禁用 DTD 和外部解析器的 `XmlReader` 加载 XML，再按节点本地名称读取 JMAXML 命名空间中的固定字段。解析器只依赖 Core 领域模型，不知道 WPF、输出目录或测试路径；报文代码、稳定来源消息 ID 和可选接收时间由调用方通过 `JmaXmlParseOptions` 提供。

```text
App 输出 Assets/JmaXml + Data/Stations 目录 + JmaStations.csv 回退
  → FixedJmaXmlDataLoader 组装文件路径和稳定消息 ID
  → JmaStationCoordinateCatalog 建立代码/唯一名称索引和资源诊断
  → JmaXmlParser.LoadFixtures 读取并标准化四份报文
  → EarthquakeEventMerger 按 EventID 合并时间线
  → InMemoryEarthquakeEventRepository
  → EarthquakePageViewModel → 列表和地图
```

App 的 `.csproj` 从 `tests/TestData` 链接三份官方报文、订正夹具和站点 CSV，并配置输出、发布复制。字段缺失夹具不复制到 App，防止测试事件出现在用户界面。`SourceId` 固定为 `jma-xml`，`SourceMessageId` 使用文件名，原始 XML 保存于 `SourcePayload`，便于解析差异排查。

解析失败不会生成部分事件：文件访问、权限或格式异常由 App 装配器包装为带资源提示的 `InvalidOperationException`，当前固定资源缺失会阻止窗口创建。网络适配器接入后不得沿用这个启动失败策略，应把单份报文失败映射为来源状态并继续显示缓存。

完整字段映射、未知值和错误边界维护于[数据契约与格式](./数据契约与格式.md)。Core 测试直接使用仓库固定夹具，覆盖官方三报文、订正、字段缺失、坐标补齐、事件合并和 XML 安全边界。

### 10.6 仓储边界与内存实现

`IEarthquakeEventRepository` 定义异步事件列表、按 ID 查询、完整快照更新通知和主动刷新。WPF 页面不能绕过该接口直接访问 HTTP、XML 或 SQLite。具体字段和方法契约长期维护于[数据契约与格式](./数据契约与格式.md)。

`InMemoryEarthquakeEventRepository` 用于开发和单元测试。它在线程锁内保存原始标准化报文和合并后的事件快照，`ApplyReports()` 追加报文后统一调用 `EarthquakeEventMerger`，在锁外发布不可变完整快照，避免订阅者回调阻塞仓储锁。当前没有外部来源，所以 `RefreshAsync()` 只检查取消令牌，不产生数据。

### 10.7 SQLite 缓存实现

`SqliteEarthquakeEventRepository` 位于 `EarthquakeShow.Infrastructure/Persistence`，只依赖 Core。它使用 `Microsoft.Data.Sqlite`，连接字符串关闭连接池以避免 Windows 进程退出后残留数据库文件句柄。默认路径为 `%LOCALAPPDATA%\\EarthquakeShow\\earthquake-cache.db`，测试通过构造函数传入临时路径隔离文件。

数据流固定为：

```text
seed 报文 → 初始化地震 schema v3（兼容 v1/v2 迁移并清理 jma-json）→ 读取 earthquake_reports
                         ↘ 空缓存时写入 seed
                         ↘ 非空缓存时按报文身份补入缺失 seed
所有报文 → EarthquakeEventMerger → 事件快照 → EventsChanged / 页面
source_status → 离线 Disabled 状态 → EarthquakePageState.SourceStatuses
```

每份报文的标准列用于查询和审计，完整领域字段保存在显式 `ReportPayloadDto` JSON 中；DTO 明确映射时间、枚举、坐标、震度集合和来源原文，不直接序列化领域 record。写入使用事件 ID、来源 ID和来源消息 ID作为主键，重复初始化通过 upsert 保持幂等。初始化发现已有缓存时，只补入传入 seed 中尚不存在该三元身份的报文；当前 App 传入的四份 seed 是官方熊本三报文和订正报文，因此旧缓存升级后也能显示该事件，不覆盖已有实时来源内容。

数据库无法打开、schema 版本不支持、JSON 损坏或权限/格式异常时，仓储捕获可预期持久化异常，使用传入的固定 seed 构建内存事件快照，并把失败原因写入 `CacheStatus`；不会让 WPF 启动直接退出，也不会清空已有内存事件。取消令牌仍按异步 API 约定向上抛出。

`0.46.0` 新增 `tsunami_reports` 后将 schema 提升到 `v2`。初始化发现 `schema_version=1` 时先创建海啸表和索引，再将版本更新为 `2`；其他未知版本仍按既有策略回退 seed。v1→v2 是一次性向前迁移，不删除或重写已有 `earthquake_reports` 和 `source_status` 数据；迁移行为由 Infrastructure 回归测试覆盖。

### 10.8 JMA JSON 实时摘要

`JmaJsonEarthquakeSource` 实现 `IRealtimeEarthquakeSource`，默认读取 `https://www.jma.go.jp/bosai/quake/data/list.json`。适配器只负责 HTTP 获取、真实字段解析和标准化，不引用 SQLite 或 WPF。`MainWindowViewModel` 持有应用生命周期 `HttpClient`，设置 15 秒超时和应用 User-Agent，并把适配器注入 SQLite 仓储。

启动和刷新数据流：

```text
页面先加载 SQLite 缓存
  → JmaJsonEarthquakeSource.FetchAsync
  → EarthquakeSourceFetchResult（报文 + SourceStatus）
  → SqliteEarthquakeEventRepository upsert
  → EarthquakeEventMerger 重新派生快照
  → 页面同步事件、来源状态和离线状态
```

适配器映射当前真实字段 `eid/rdt/at/anm/acd/cod/mag/maxi/json`。`cod` 使用 JMAXML 同类坐标格式解析经纬度和米制深度；`json` 文件名作为稳定来源消息 ID。JMA 没有附带偏移量的时间按 JST 解释，已带 `Z` 或 `±HH:mm` 的时间保留原偏移量。JSON 列表目前只生成事件摘要，不伪造区域、市町村或观测点详情。

非成功 HTTP 不抛到 UI：429 为 `RateLimited`，其他状态为 `Disconnected`；网络异常为 `Disconnected`；JSON 和字段异常为 `ParseFailed`。仓储即使收到空失败结果也只持久化来源状态，继续发布原缓存事件。取消令牌仍向上抛出，用于窗口关闭和刷新取消。

### 10.8A JMA 详细 JSON 固定样例

JMA XML 数据目录已经清理 2026-07-28 的历史 XML，原始 XML 地址返回 404；JMA 仍提供同一事件的官方详细 JSON。`JmaQuakeDetailJsonParser` 位于 Core，只解析随应用发布的 `JmaJson/Official` 固定文件，不改变实时 `list.json` 摘要适配器。

固定 seed 包含事件 `20260728162718` 的 7 份报文：4 份 `VXSE51` 震度速報、2 份 `VXSE53` 震源・震度情報和 1 份 `VXSE61` 震源要素更新。解析器保留 JMA JSON 原文、官方文件名和 URI；`Pref/Area/City/IntensityStation` 映射到现有区域、市町村和观测点模型，观测点优先使用 `latlon`，缺失时使用 4,368 条目录补全。`Coordinate_WGS` 使用度分格式解析，因而保留最终 16 km 深度和精确震源坐标。

后续 `VXSE61` 仅包含震源更新、没有观测点数组时，`EarthquakeEvent.Summary`、地图和观测树沿用之前已经收到的有效最大震度、区域、市町村和观测点；当前报文的震源、震级和深度仍优先显示。这样符合详情页“字段收到后持续显示”的契约。

### 10.9 JMA XML 实时详情

`JmaXmlEarthquakeSource` 默认读取 `https://www.data.jma.go.jp/developer/xml/feed/eqvol.xml`。它使用 `System.Xml.Linq` 解析 Atom `entry`，从 `entry/id` 文件名筛选 `VXSE51`、`VXSE52`、`VXSE53`，再下载 `link[type=application/xml]` 指向的报文。每次最多处理 20 个条目，并把文件名作为 `SourceMessageId`、链接作为 `RawMessageUri`，把完整 XML 作为 `SourcePayload`。

从 `0.41.0` 起，该适配器同时实现 `IIncrementalEarthquakeSource`。SQLite 仓储刷新前按 `SourceId` 读取当前缓存中最大的 `IssuedAt`，对 JMA XML 使用 `FetchSinceAsync`；适配器从文件名的前 14 位按 JST 解析条目时间，只下载不早于增量起点的条目。来源状态的 `Detail` 会记录“Feed 总条数/增量命中条数/增量起点”，便于判断 Feed 是否覆盖离线期间。文件名无法解析时间的条目不会被过滤，以避免误删报文。

从 `0.42.0` 起，短 Feed 的最早条目晚于 `since` 时，适配器额外读取 JMA 官方长期 Feed `https://www.data.jma.go.jp/developer/xml/feed/eqvol_l.xml`，最多解析 100 条并按 `SourceMessageId` 跨 Feed 去重；短 Feed 仍承担正常实时刷新。长期 Feed 读取失败时保留短 Feed 已成功结果，并在来源状态记录失败原因。2026-08-24 已使用同一解析器将长期 Feed 中 42 条 8 月 21–24 日报文幂等写入本机 SQLite。

该机制只解决上游 Feed 当前窗口内的增量回补。JMA Feed 没有历史分页契约，若缓存起点早于 Feed 最早可见条目，应用只能显示覆盖诊断，不能声称已经恢复全部离线报文；后续需接入有授权的历史归档或本地 XML 导入。

详情报文复用 Core 的 `JmaXmlParser`，并注入 `FixedJmaXmlDataLoader.LoadStationCatalog()` 得到的完整站点目录，因此实时 XML 与固定 XML 具有相同的区域、市町村和观测点字段契约。坐标先按 `IntensityStation.Code` 精确匹配；代码未命中时仅按规范化后的唯一显示名称补全。适配器只依赖 Core 和 `HttpClient`，不访问 SQLite 或 WPF。

Feed 或详情 HTTP 429 映射为 `RateLimited`，其他网络/HTTP 失败映射为 `Disconnected`；Feed XML 格式错误或单条详情 XML 解析错误映射为 `ParseFailed`。单条详情失败只记录在 `SourceStatus.Detail`，同一 Feed 的其他成功报文继续写入仓储。仓储按来源分别保存状态，并在任何来源失败时保留已有 SQLite 事件。

`EarthquakeEventMerger` 在事件内排序时加入来源优先级：`p2pquake=5`、`jma-json=10`、`jma-xml=20`、其他来源 `0`。历史 JSON 仅保留排序兼容；当前 XML/P2P 报文满足关联阈值时先合并事件，再保留双方报文，JMA XML 事件 ID 作为规范 ID。`EarthquakeEvent.PreferredReport` 单独负责默认展示优先级，详情页仍可通过来源按钮切换当前报文。

### 10.9A JMA 海啸 XML 来源（0.45.0）

`JmaTsunamiXmlSource` 与地震 XML 来源分开实例化，来源 ID 固定为 `jma-xml-tsunami`，避免把独立海啸报文混入地震事件时间线。它读取同一组 JMA 高频/长期 Feed，只筛选文件名中的 `VTSE41`、`VTSE51`、`VTSE52`，然后下载 `application/xml` 链接并交给 Core 的 `JmaTsunamiXmlParser`。

该适配器已经实现 `IRealtimeTsunamiSource` 和 `IIncrementalTsunamiSource`。`FetchSinceAsync` 以 Feed 文件名前 14 位按 JST 解析发布时间；短 Feed 最早条目晚于增量起点时，额外读取长期 Feed，跨 Feed 按 `SourceMessageId` 去重。每条成功报文保留完整 XML、原始链接和文件名身份，单条失败只写入来源诊断，不清空其他成功结果。

当前来源层已完成传输、报头、`Kind/LastKind`、预报区、预计到达、预计高度、沿岸观测和近海推定字段解析；三份官方训练样例固定在 `tests/TestData/JmaTsunami/Official/`，由 `tools/validate_test_data.py` 检查哈希、事件 ID、训练标记和结构数量。`0.67.10` 起 App 启动时将样例复制到 `Assets/Data/Tsunami/`，并以 `sample-jma-tsunami` 来源写入本地 SQLite，供无网络、无缓存时展示；该来源不代表在线状态，移除 seed 调用和资源链接即可恢复纯缓存行为。`0.46.0` 已由独立 SQLite 海啸仓储提供持久化边界，`0.47.0` 起由 App 生命周期调用来源和仓储。

### 10.9B JMA 海啸 SQLite 持久化（0.46.0）

`ITsunamiReportRepository` 与 `SqliteTsunamiReportRepository` 独立于 `IEarthquakeEventRepository`，避免把独立 `VTSE*` 报文交给 `EarthquakeEventMerger`。仓储使用与地震缓存相同的数据库文件和 `tsunami_reports` 表，主键为 `event_id + source_id + source_message_id`；`report_code`、`issued_at`、`received_at` 作为查询列，所有结构化字段和完整 `SourcePayload` 由 `TsunamiReportPayloadDto` 显式序列化。

仓储提供初始化、全部报文读取、按事件 ID读取和批量 upsert。重复来源消息只更新原记录，不生成重复报文；读取时按发布时间、接收时间和来源身份稳定排序。高度对象保留 `Meters=null` 与 `Description`，因此 `NaN` 和“巨大”等 JMAXML 信息不会被误写成数字。

地震 SQLite schema 从 v2 升级到 v3，地震和海啸仓储使用独立的 schema key，避免共享数据库时互相误判版本。检测到旧地震缓存时删除 `jma-json` 报文和来源状态；未知版本仍抛出持久化格式错误，由地震仓储按既有固定 seed 回退策略处理；海啸仓储不伪造报文，直接向调用方报告错误。

`0.46.0` 只完成持久化边界；从 `0.47.0` 起由应用 ViewModel 实例化该仓储并负责生命周期调用。

### 10.9C 海啸来源应用生命周期（0.47.0）

`MainWindowViewModel` 在构造时为联网模式创建一个共享 `HttpClient` 上的 `JmaTsunamiXmlSource`，并将其传给 `SqliteTsunamiReportRepository`。初始化顺序为：初始化地震仓储、初始化海啸仓储、发布离线来源状态、加载地震页面、执行首次网络刷新。网络关闭时仍初始化海啸 schema；测试或其他宿主可以注入 `IRealtimeTsunamiSource` 验证链路。

海啸仓储刷新会读取 `jma-xml-tsunami` 来源在 `source_status` 中保存的最大 `LastReceivedAt`，对实现 `IIncrementalTsunamiSource` 的来源调用 `FetchSinceAsync`，写入报文并原子更新来源状态。首次运行没有时间点时完整读取高频 Feed；短 Feed 覆盖不足时由来源自行合并长期 Feed。刷新失败只更新来源状态，不删除已有 `tsunami_reports`。

自动刷新循环在地震来源或海啸来源任一存在时启动，退避只读取 `_realtimeSources` 中 JMA XML/P2PQuake HTTP 来源的状态；`p2pquake-ws` 只用于流式连接诊断，不会把 HTTP 轮询拉入指数退避。单轮未预期异常会更新失败状态并继续下一轮，取消令牌仍负责退出循环。海啸来源状态通过 `MainWindowViewModel.TsunamiSourceStatuses` 和 `PropertyChanged` 发布。关闭时先取消生命周期令牌并等待初始化、自动刷新和 WebSocket 循环，再释放海啸仓储、HTTP 客户端和其他资源；因此不会留下海啸刷新后台任务。

应用级回归测试使用注入假来源确认：海啸报文可以独立写入同一 SQLite 文件，地震事件列表数量不因海啸报文增加，`DisposeAsync` 完成后可重新打开仓储读取报文。

### 10.9D 海啸来源状态栏投影（0.48.0）

`MainWindowViewModel.TsunamiSourceStatusText` 将独立来源状态映射为短文本，供底部状态栏显示。没有海啸来源时显示“海啸：未启用”；单个来源按以下规则映射：`Online`→“海啸：在线”、`Delayed`→“海啸：延迟”、`RateLimited`→“海啸：限流”、`ParseFailed`→“海啸：解析失败”、`Disconnected`→“海啸：离线”、`Unknown`→“海啸：状态未知”、`Disabled`→“海啸：未启用”。多个来源时选择优先级最高的异常状态，优先级为解析失败、限流、离线、延迟、未知、在线、未启用。

主窗口 XAML 在地图状态旁显示该文本，复用现有低干扰状态栏样式，不改变顶部地震数据状态卡片和底部自动刷新布局。`UpdateTsunamiSourceStatuses()` 同时触发 `TsunamiSourceStatuses` 和 `TsunamiSourceStatusText` 的属性通知，确保首次初始化、每次刷新和失败状态都能更新界面。

### 10.9E 海啸专页只读状态层（0.49.0）

`TsunamiPageState` 只保存页面需要的报文快照、当前选择、来源状态、加载状态、刷新标记、离线标记和错误文案。`TsunamiPageViewModel.LoadAsync()` 只调用 `ListReportsAsync()`，不会触发网络；`RefreshAsync()` 才调用仓储 `RefreshAsync()`，随后重新读取快照，因此页面刷新按钮不会重复实现来源请求逻辑。

报文排序规则为 `IssuedAt` 降序、`ReceivedAt` 降序、`EventId`、`SourceId`、`SourceMessageId` 顺序比较。报文选择身份是三元组 `EventId + SourceId + SourceMessageId`；重新读取后按该身份恢复选择，找不到时选择排序后的第一条报文。没有报文时选择保持 `null`。

读取异常进入 `Error` 状态并保存 `ErrorMessage`，不伪造报文；来源连接是否在线由仓储的 `SourceStatuses` 独立决定，读取异常不会覆盖该状态。`Dispose()` 只释放页面刷新互斥量，不释放仓储，仓储生命周期仍由 `MainWindowViewModel` 统一管理。

### 10.9F 海啸报文查询页视图（0.50.0）

`TsunamiPageView` 是一个独立 WPF `UserControl`，由左侧报文列表和右侧当前报文摘要组成。列表绑定 `TsunamiPageViewModel.Reports` 和 `SelectedReport`，显示报文代码、类型、状态、发布时间和事件 ID；摘要显示报文代码、发布/订正状态、正式/训练场景、发布时间、接收时间、报文身份和预报区/观测/推定区域数量。

主窗口左侧导航通过 `IsEarthquakePageVisible`、`IsTsunamiPageVisible` 两个只读属性反映当前页面，点击事件调用 `ShowEarthquakePage()` 或 `ShowTsunamiPage()`。两个 `RadioButton` 使用 `OneWay` 绑定，避免 WPF 尝试写入只读属性；页面切换只改变两个内容网格的可见性，不释放或重建任何页面状态。

海啸页刷新按钮调用 `TsunamiPageViewModel.RefreshAsync()`，异常和空缓存由 ViewModel 状态投影到空状态区域。`0.51.0` 起视图显示预报区、沿岸观测和近海推定列表；原始 XML 和完整字段树仍留待后续视图切片。

### 10.9G 海啸详情列表和等级配色（0.51.0）

`TsunamiPageViewModel` 将当前报文的 `ForecastAreas`、`ObservationStations` 和 `EstimationAreas` 投影为三个只读显示数组。预报区等级只调用 `JmaTsunamiClassifier.Classify(KindName, KindCode)`，不使用 `LastKindName/LastKindCode` 代替当前等级；报告总等级从 `Items` 和预报区当前等级中取最高优先级，用于摘要文字。

显示格式保留空值边界：没有时间显示“未提供”，有到达条件但没有时间时只显示条件；高度优先显示有限 `Meters + Unit`，否则显示原始 `Description`，两者都没有时显示“未提供”。沿岸观测的 `Initial` 原文保留，不转换为数值。

XAML 样式按 `TsunamiLevel` 触发颜色：`MinorChange` 蓝色、`Advisory` 黄色、`Warning` 红色、`MajorWarning` 紫色、`NoConcern` 灰色；警报深色背景使用白字，`Investigating/Unknown` 使用中性灰色。颜色只作为报文等级辅助标识，不代表地图风险范围。

### 10.9H 信息项和原始 XML（0.52.0）

`TsunamiPageViewModel.InformationItems` 将 `JmaTsunamiReport.Items` 投影为只读显示项，保留当前等级、代码、上一状态和区域名称/代码。`RawXmlText` 直接读取当前报文 `Source.SourcePayload`，没有原文时隐藏原始 XML 区域；视图通过 `IsReadOnly=true` 的 `TextBox` 展示，复制按钮调用 `Clipboard.SetText`，然后由 ViewModel 记录“已复制原始 XML”反馈。

本版本修复的导航 Bug 根因是：`TsunamiPageView` 设置自身 `DataContext` 为 `TsunamiPageViewModel` 后，样式触发器使用 `RelativeSource AncestorType=Window` 直接查找 `IsTsunamiPageVisible`，实际该属性位于 `Window.DataContext`，条件永远为假。修复为 `DataContext.IsTsunamiPageVisible`，并用 STA WPF 测试实际触发 `RadioButton.Click` 后断言页面可见。

### 10.9I 海啸报文时间线和解除过程（0.53.0）

`TsunamiPageViewModel.TimelineReports` 是当前选择报文的派生只读集合：按 `EventId` 过滤，按 `IssuedAt`、`ReceivedAt` 和来源消息 ID 升序排列，因此同一海啸事件的发布、订正和解除报文会连续显示。切换 `SelectedReport` 只改变筛选事件和当前节点，不写回 `JmaTsunamiReport` 或 SQLite。

时间线显示项由 `TsunamiTimelineItemDisplay` 投影。发布/订正报文使用 `GetReportLevel()` 计算当前等级；取消报文强制使用 `Unknown` 等级并显示“解除”，防止取消报文携带的旧 `Items` 被误当成仍生效的警报。页面只读显示报文代码、状态、场景、发布时间、结构数量和等级徽标。

主窗口布局将工作区分成 68px 导航列和内容列：地震工作区跨两列，海啸页仅放在内容列，避免海啸页可见时遮挡地震/海啸导航。震度 4/5 弱色板在地图绘制和三个 XAML 徽标样式中保持一致。

### 10.9J 海啸报文逐字段差异（0.54.0）

`TsunamiPageViewModel.FindPreviousReport()` 先按当前 `EventId` 筛选报文，再按 `IssuedAt`、`ReceivedAt` 和来源消息 ID升序排列，定位当前报文的紧邻上一报。`ReportDifferences` 只投影发生变化的字段，不修改报文快照、事件身份或 SQLite。

当前比较字段包括报文代码、状态、场景、最高等级、标题、信息项数量、预报区数量、沿岸观测数量和近海推定数量。首报显示“首报，没有上一报可比较”；存在上一报但所有字段相同则显示“与上一报无字段差异”。取消报文在差异计算中强制使用 `Unknown` 等级，因此上一报的警报等级会明确变化为“解除”。

### 10.9K 海啸预报区沿岸线地图（0.55.0）

开发期脚本 `tools/convert_jma_tsunami_gis.py` 读取 JMA `20240520_AreaTsunami_GIS.zip` 的 PolyLine Shapefile，按 DBF `code` 聚合记录并以约 `0.01°` 容差简化，输出 67 个预报区 GeoJSON Feature。原始 ZIP 不进入发布包；运行时只读取约 5.8 MB 的派生资源。

`TsunamiMapGeometry` 只接受 `LineString` 和 `MultiLineString`，按 `forecastAreaCode` 建立沿岸线索引和经纬度包络。`TsunamiMapView` 将同一预报区的多条线合并到一个 `StreamGeometry`，未激活区域绘制为中性海岸线，当前报文中的预报区按 `JmaTsunamiClassifier` 等级着色。该地图显示的是 JMA 预报区沿岸线，不将线错误填充为面。

当前 JMAXML 海啸观测站的报文本身只有名称、代码、到达时间和高度等字段；页面使用独立海啸站点目录补充官方坐标，不复用地震站点目录，也不按名称或距离推测位置。观测点没有目录坐标时仍保留在表格中，但不绘制地图点。

### 10.9L 0.55.1 海啸地图、增量回补和站点目录边界

海啸页原先把 `TsunamiMapView` 放在 `HasSelectedReport` 控制的详情容器内，未选中报文时整个容器折叠，沿岸线地图也随之不可见。当前 XAML 将地图移到右侧滚动内容的外层，地图只由 `HasMapGeometry` 控制；`TsunamiMapView` 在没有选中报文时仍按中性颜色绘制全部 JMA 预报区沿岸线。

JMA `list.json` 的 `ser` 字段不是稳定的 JSON 类型，既可能是字符串也可能是数字。`JmaJsonEarthquakeSource` 现在用 `JsonElement` 兼容两种类型；否则列表中任意一条数字 `ser` 都会使整批列表反序列化失败，从而遗漏包括 `20260824125441` 在内的其他报文。

`JmaXmlEarthquakeSource.FetchSinceAsync()` 在增量模式先完整解析短 Feed，再按 `IssuedAt >= since` 筛选；短 Feed 覆盖不足时再完整合并长期 Feed。初次加载仍按 `_maxEntries` 限制，避免改变正常启动请求量。该策略保证离线回补不会因“先取前 N 条”漏掉起点之后的报文。

中精度地图的“刺”主要来自 WPF 默认斜接线在锐角处外扩，而非坐标数量不足。区域和市町村 `Path` 统一设置 `PenLineJoin.Round` 及圆端点，内存和几何数据量不变；若未来仍存在几何本身的尖角，再单独评估降低中精度简化容差。

官方站点目录调查确认 JMA 技术资料页及其代码表压缩包中的 `20250630_PointTidalLevel.xls` 是潮位/海啸站点坐标的首选候选。海啸报文的 `潮位観測点` 代码与地震观测点代码空间不同，禁止复用 `jma-intensity-stations.json`。

### 10.9O 海啸站点目录 SQLite 读写和观测点图层（0.67.1）

`JmaTsunamiStationCatalog` 是海啸站点目录的唯一 Core 查询对象，站点 code、近海发布 code 和预报区 code 全部按 `TEXT` 保存，保留前导零。目录资源 `jma-tsunami-catalog.json` 由 `tsunami_station_list.txt` 和代码表工作表 `35` 离线整理而成，当前包含 449 个唯一站点和 611 个近海发布点；表 35 的示例映射为 `00410 -> 10050`。

`ITsunamiStationCatalogRepository` 独立于 `ITsunamiReportRepository`，`SqliteTsunamiReportRepository` 在初始化时建立 `tsunami_station_catalog`、`tsunami_offshore_publication` 和 `tsunami_offshore_station_map` 三张表。应用启动先将固定目录种子写入 SQLite，再由 `TsunamiPageViewModel` 通过目录仓储读回；数据库目录为空、未实现目录接口或读取发生可恢复的格式/数据库异常时，才回退到固定 JSON 目录。目录读回按 code 排序，发布点与原始站点通过关联表恢复一对多关系，不做名称、距离或最近点推断。

观测点显示名称、经纬度和近海发布信息均按 `Observation/Station/Code` 精确查询。没有目录匹配的原始报文名称和 code 仍显示在观测表中，但不显示目录补充信息；没有完整经纬度的记录不生成地图标记。地图标记颜色使用观测高度的同一等级分级：`<0.2m` 浅蓝、`0.2-1m` 黄色、`1-3m` 红色、`>3m` 紫色；`微弱` 无数值时按浅蓝显示，`欠测` 和未知高度保持中性。

### 10.9P 海啸地图观测点选择（0.67.2）

`TsunamiPageViewModel` 以当前报文中可显示观测点的 `Code` 保存选择状态；`SelectObservationStation()` 只接受当前 `ObservationStations` 集合中的精确 code，未匹配或已过滤的站点返回 `false`。报文切换后如果原 code 不再存在，选择自动清空，不按名称、坐标或最近点恢复。

`TsunamiMapView` 只为同时具备有限纬度和经度的站点创建 `Ellipse`，点击标记调用 ViewModel 选择方法；选中标记增大并加粗白色描边，详情面板直接绑定 `SelectedObservationStation`，显示区域、站点名、原始 code、近海发布 code、状态、高度、首波和高潮时间。地图仍不负责定位、聚合或修改报文观测数据。

### 10.9Q 海啸页面布局和地图 LOD（0.67.4）

海啸详情工作区按“当前报文/震源摘要 → 地图 → 选中站点详情 → 时间线与发布区域/观测列表 → 近海推定和原始 XML”顺序排列，先呈现当前风险和震源，再呈现空间分布，避免默认把所有站点详情堆在地图前。观测列表使用 `ListBox` 选择状态，选中项通过站点 `Code` 与地图标记共享高亮状态。

海啸地图使用三级本地 LOD。`jma-tsunami-forecast-lines-low.geojson` 是由已审计的 JMA 沿岸线资源按步长 `2` 抽稀并去除连续重复点得到的低精度层；`jma-tsunami-forecast-lines-medium.geojson` 为保留完整点序列的中精度层；`jma-tsunami-forecast-lines-overview.geojson` 为详细层。`MapZoomLevel <= 2` 使用低精度，`2 < MapZoomLevel <= 12` 使用中精度，`MapZoomLevel > 12` 使用详细层。中/详细层在首次进入对应倍率后按需后台加载并缓存，加载期间保留当前层作为兜底；缩放范围为 `0.5–16`，滚轮和地图工具按钮共用同一 ViewModel 命令。

海啸地图滚轮期间使用 120ms 防抖的指针锚定 `ScaleTransform` 预览，保留当前沿岸线视觉缓存，停止滚轮后才恢复变换并执行一次完整绘制。沿岸线按预报区 code 合并到单个 `DrawingVisual`，观测点仍作为可命中的独立标记；投影线段超过 500px 或坐标非有限时断开当前图形，避免异常跨区长线形成尖刺。图例从预报区和已观测站点等级计算最高级别，按“海啸预报 → 海啸注意报 → 海啸警报 → 大海啸警报”连续显示。

观测点显示规则分离为“表格数据”和“地图数据”：表格沿用报文中除“未观测到海啸”外的记录，并允许选择 `欠测`、`微弱` 等状态；地图只绘制 `HasMeasuredTsunami` 为真的 `观测到海啸` 或 `微弱` 记录，且必须同时具有有限纬度和经度。没有实际观测、没有坐标或未知状态的记录不生成地图标记；用户选中表格行时仍可查看该记录详情。

时间线每个条目使用截至该报文的累计快照计算最高等级；因此仅包含“津波 调查中”的后续报文仍显示此前尚未解除的警报级别。详情页 Tab 使用全局蓝色选中模板，局部仅覆盖内容区 `Stretch` 对齐，保证右栏横向固定占满。

### 10.9T 海啸详情显示规则与绑定诊断（0.67.18）

`TsunamiPageViewModel.FormatTimestamp()` 将 `DateTimeOffset` 转换到 Windows `Tokyo Standard Time`，统一输出 `yyyy-MM-dd HH:mm:ss JST`；预报、观测、推定、时间线中的到达、高潮、实测和报文时间都复用该方法。注意报等级没有数值或描述高度时，预报高度显示“——”。

VTSE 解析器读取 `codeType="固定付加文"` 节点的 `Text`，按原文去重保存到 `JmaTsunamiReport.FixedAdditionalTexts`；ViewModel 在累计报文时保留此前附加文，并在摘要标签显示。震源区域的 `Description`、`NameFromMark` 或坐标描述作为 `Hypocenter.Description`，震源名为“不明/未知”时优先展示该描述。

预报/时间线使用通用等级样式，只有观测实测高度列使用带 `ObservationStatusText` 触发器的专用样式，消除了预报对象没有该属性却被绑定导致的 `BindingExpression path error`。地图按精度切换取消旧请求时记录的 `TaskCanceledException` 是并发请求的正常收敛，不应写入错误状态。

### 10.9U 海啸震级描述与观测时间列（0.67.19）

`JmaTsunamiXmlParser` 读取 `jmx_eb:Magnitude` 的 `description`，`MagnitudeDto` 在 SQLite JSON 往返中保留该字段。`TsunamiPageViewModel.EarthquakeMagnitudeText` 在有限数值缺失时使用描述，并通过 Unicode 兼容归一化和“を超える”短语规范化，将 JMA 的“Ｍ８を超える巨大地震”显示为“M8超巨大地震”。

海啸观测表的“首波”绑定 `FirstHeight/ArrivalTime`，“高潮”绑定观测 `MaxHeight/DateTime`（JMA 原文语义为最大波观测时刻），两列在详情页和主页面分别占用固定宽度。表格“区域”直接来自 `Observation/Item/Area/Name`；近海观测项经常为空，空值表示报文没有指定沿岸预报区，不根据站点名称或坐标推断区域。

### 10.9R 海啸观测表与地图双向联动（0.67.5）

`TsunamiPageViewModel.TryGetSelectedObservationCoordinate()` 只为当前选中且状态为“观测到海啸”或“微弱”的完整坐标站点提供定位坐标。`TsunamiMapView` 根据当前投影和缩放计算平移量，将该站点置于地图中心；选择欠测、无坐标或未知状态时不执行强制定位，清空选择时恢复默认中心。地图点点击和表格 `SelectedItem` 继续使用原始 `Station.Code` 精确匹配，因此不会因名称相同或目录缺失误选站点。

观测表 `ListBox` 在选择变化后通过 `DispatcherPriority.Loaded` 调用 `ScrollIntoView`，保证地图点点击后表格自动滚动到对应行；报文切换造成的失效选择仍由 ViewModel 清理。

### 10.9S 海啸地图独立可见性（0.67.6）

地图的 `Visibility` 只绑定 `HasMapGeometry`，不再继承包裹报文详情的 `HasSelectedReport` 条件。这样空报文状态仍可查看 JMA 沿岸线概览，报文详情隐藏不会误隐藏地图；资源缺失时才折叠地图组件。

### 10.9M 0.55.2 JMA 度分坐标与潮位站目录提取

`JmaJsonEarthquakeSource.ParseCoordinate()` 对 `cod` 坐标采用两段式规则：绝对值在纬度 `90` 或经度 `180` 范围内时按十进制度读取；超过范围时按 JMA 的 `DDMM.m / DDDMM.m` 度分格式拆分，要求分钟小于 `60`，转换结果再次交给 `GeoCoordinate` 做范围校验。这样 `+3559.9+14005.7-68000/` 会得到约 `35.998333, 140.095`，不会因为单条度分报文使整个列表失败。

本机缓存验证显示 `earthquake_reports` 和 `earthquake_events` 均已有 `20260824125441`；该事件来源为 `jma-json`，报文发布时间为 `2026-08-24T12:57:00+09:00`，摘要为釧路地方中南部、M3.3、深度 80 km、最大震度 1。该条是列表摘要，完整观测点明细仍需详情 JSON/XML。

`resources/20250630_PointTidalLevel.xls` 已离线提取为 `src/EarthquakeShow.App/Assets/Data/Stations/jma-tsunami-tidal-points.json`，并标记 `codeType=PointTidalLevel`。提取结果 311 条、唯一代码 311 条，其中 106 条同时有纬度和经度；源表缺失的 205 条记录保留 `null`，不按名称或附近站点猜测。与三份官方 `VTSE` 样例的 190 个 `Station/Code` 比对，代码交集为 0，说明该表不能直接作为当前海啸报文站点坐标目录。坐标单位为 WGS84 十进制度，运行时资源由 App 的 `Assets\Data\**\*` 内容规则复制，但暂不用于海啸地图点匹配。

### 10.9N 0.55.3 JMA JSON 生产禁用与 XML 主来源

JMA JSON 接入后会把摘要报文作为独立来源写入事件缓存，导致同一事件出现摘要节点、详情节点和重复列表项。该问题不是 JSON 解析失败，而是生产来源策略不适合当前页面的详情模型。`MainWindowViewModel` 从实时来源装配中移除 `JmaJsonEarthquakeSource`，只保留 `JmaXmlEarthquakeSource` 和 `P2pQuakeEarthquakeSource`；自动刷新条件改为检查实时来源列表，避免移除 JSON 后跳过 XML/P2P 刷新。

`JmaJsonEarthquakeSource` 类和固定 JSON 测试样本保留用于解析器回归；从 `0.55.3` 起不会再请求 `list.json`。`0.56.0` 的地震 SQLite schema v2→v3 迁移会删除历史 `jma-json` 报文和来源状态，之后每次初始化继续幂等清理，因此该来源不会再进入页面历史。XML 继续通过短 Feed、长期 Feed 和详情 XML 负责实时接收与离线回补。

### 10.10 P2PQuake HTTP 补充源

`P2pQuakeEarthquakeSource` 默认请求 `https://api.p2pquake.net/v2/jma/quake`，只实现 HTTP 列表读取，不建立 WebSocket。适配器把每个 JSON 数组元素转换为一个 `EarthquakeReport`：`id` 保存为 `SourceMessageId`，`issue` 映射报文时间/类型/订正状态，`earthquake.hypocenter` 映射震源、坐标、深度和震级，`maxScale` 映射 JMA 震度，`points` 映射为无坐标的来源内观测点。

P2PQuake `earthquake.domesticTsunami` 表示日本国内海啸状态，官方枚举为 `None`、`Unknown`、`Checking`、`NonEffective`、`Watch`、`Warning`；`foreignTsunami` 表示海外海啸可能性，官方枚举为 `None`、`Unknown`、`Checking`、`NonEffectiveNearby`、`WarningNearby`、`WarningPacific`、`WarningPacificWide`、`WarningIndian`、`WarningIndianWide`、`Potential`。解析时国内状态优先，`None` 显示“津波の心配なし”，`Checking/Unknown` 显示“津波 调查中”，`Warning` 按官方“津波予報（種類不明）”语义显示“津波预报”，不显示为津波警报或大津波警报；海外 `None/Unknown` 不覆盖国内结果，其余状态以“海外：”前缀作为补充。SQLite 读取历史 P2P 报文时，会从保存的 `SourcePayload` 重新生成该摘要，以修正旧缓存。该定义来源于 [P2PQuake JSON API v2 规范](https://github.com/p2pquake/epsp-specifications/blob/master/json-api-v2.yaml)。

P2PQuake 没有 JMA `EventID`，原始事件身份仍固定为 `p2pquake:{id}`；`EarthquakeEventMerger` 会先归并证据充分的远地 P2P 重复更新，再对有效的 XML/P2P 报文按 60 秒、80 km、震级差 0.5 的阈值合并，优先 JMA XML 事件 ID。`jma-intensity-regions.json` 保存都道府县、区域、市町村的正式父子关系和地址别名，P2P 命中后使用正式 `municipalityCode/areaCode`，因此可直接复用市町村地图面；未命中时保留来源内回退键。详情页来源切换按钮选择合并时间线中的 XML 或 P2P 报文，观测树统一为四层。

HTTP 429 返回 `RateLimited`，其他非成功 HTTP 和网络异常返回 `Disconnected`，JSON 或必需字段异常返回 `ParseFailed`。仓储把 P2PQuake 与 JMA 来源状态分别持久化；P2PQuake 失败时继续发布 JMA/SQLite 快照。来源优先级为 `p2pquake=5`、`jma-json=10`、`jma-xml=20`，其中 JSON 优先级仅服务于历史缓存排序；P2P 原始事件 ID 在合并阶段按明确阈值与 JMA XML 归并。

### 10.11 同事件来源差异投影

`EarthquakeDetailsViewModel` 在 `Rebuild()` 时基于当前 `SelectedEvent` 和 `ViewedReport` 构建 `SourceDifferences`。它按来源分组，每组选择发布时间最新、接收时间次新的报文，与当前快照比较状态、最大震度、震级、震源、深度和观测点数量。比较结果是只读的 `EarthquakeSourceDifferenceItemViewModel`，不回写领域对象、不改变 `LatestReport` 和事件排序。

摘要页的“来源差异”区域显示来源 ID、来源消息 ID、来源角色和差异文本。XML/P2P 成功合并后仍保留双方差异，用户通过摘要顶部来源切换按钮选择当前报文；无法合并的事件不再显示“可能关联来源”候选区块。

### 10.12 跨源事件关联（0.56.0 已替换候选展示）

`EarthquakeEventMerger` 在按 `EventId` 分组后，先对同一来源的远地 P2P 重复更新使用严格证据归并：所有报文必须是远地类型，远地类别明确且一致，时间差不超过 60 秒，球面距离不超过 80 km，双方震级都存在时差值不超过 0.5。随后对 `p2pquake` 与 `jma-xml` 使用相同的发生时间、震源坐标和震级证据；满足条件时合并报文时间线并优先采用 JMA XML 事件 ID，缺少坐标/发生时间或超出阈值时保持独立事件。详情页使用来源切换按钮而不显示候选关联列表。

### 10.13 自动刷新与退避

`MainWindowViewModel.InitializeAsync()` 完成缓存加载和首次网络刷新后，启动由生命周期取消令牌控制的后台刷新循环。循环继续调用 `EarthquakePageViewModel.RefreshAsync()`，因此自动刷新、列表刷新按钮和仓储来源顺序共用同一条数据路径。

`RefreshBackoffPolicy` 根据上一轮来源状态计算下一次等待时间：所有来源为 `Online` 时返回 60 秒并清零失败次数；普通 `Disconnected`/`ParseFailed` 从 30 秒开始按 2 倍递增；包含 `RateLimited` 时从 2 分钟开始按 2 倍递增；所有等待时间上限为 15 分钟。窗口关闭时取消生命周期令牌，循环不再发起新请求，状态栏显示“自动刷新：已停止”。

### 10.13A 0.66.14 XML 覆盖状态投影

`JmaXmlEarthquakeSource` 在短 Feed 和长期 Feed 都无法覆盖缓存 `since` 时返回 `SourceConnectionState.Delayed`，并在 `SourceStatus.Detail` 中保留 Feed 最早条目和命中数量。`EarthquakePageDisplayState.GetNetworkStatusText()` 将该状态优先投影为“网络：XML覆盖延迟”；它不表示 HTTP 断开，也不清空已有缓存。来源状态同时出现时，诊断优先级为 XML 覆盖延迟、限流、解析失败，最后才回退到已连接/不可用文本。自动刷新调度仍按 `Delayed` 的快速检查策略执行。

### 10.13B 0.66.15 JMA XML 覆盖审计

`tools\audit_jma_xml_feed.ps1` 是开发期只读审计工具，不参与正式应用运行。它从 Atom `entry/id` 提取文件名，按与 `JmaXmlEarthquakeSource.ParseMessageIssuedAt()` 相同的规则把前 14 位解释为 UTC，只保留 `VXSE51`、`VXSE52`、`VXSE53`，输出条目数量、类型分布、最早/最新时间和可选 `since` 命中数。运行示例：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\audit_jma_xml_feed.ps1 -Since 2026-08-21T00:00:00+09:00
```

2026-08-26 的真实只读核验结果为：短 Feed 8 条，最早 `2026-08-25T23:36:00Z`；长期 Feed 93 条，最早 `2026-08-19T11:47:27Z`。以 `2026-08-21T00:00:00+09:00` 为起点，短 Feed 命中 8 条但覆盖不足，长期 Feed 命中 75 条且覆盖正常。该结果证明当前 XML 回补适合近期离线窗口，但不能恢复早于长期 Feed 最早条目的历史报文；下一步需要本地 XML 导入或有授权的历史归档。

`EarthquakePageViewModel` 使用 `SemaphoreSlim` 串行化刷新调用，避免自动刷新与用户手动刷新并发写入 SQLite。该互斥只保护刷新过程，不改变事件选择、筛选或报文快照保持规则。

### 本地 JMA XML 导入批次持久化（0.66.19）

`JmaXmlLocalFileImporter` 位于 `src/EarthquakeShow.Infrastructure/Sources`，用于将用户保存的历史 JMA XML 转换为 `EarthquakeReport`。调用方传入目录后，导入器递归枚举 `.xml` 文件，只处理文件名中包含 `_VXSE51_`、`_VXSE52_` 或 `_VXSE53_` 的文件；其他 XML 放入 `SkippedFiles`。解析调用 Core 的 `JmaXmlParser`，并可注入与在线来源相同的观测点和区域目录。

本地报文使用来源 ID `jma-xml`，`SourceMessageId` 使用文件名，`RawMessageUri` 使用本地 `file` URI，`SourcePayload` 保留完整文本。`SqliteEarthquakeEventRepository.ImportLocalXmlAsync()` 在同一个事务中写入 `earthquake_reports`、`earthquake_events`、`local_xml_import_batches` 和 `local_xml_import_items`；任一写入失败时事务回滚。应用初始化时读取最近完成批次，设置页最多投影 100 条明细，避免大目录造成 UI 负担。导入成功后再读取完整报文和来源状态并发布事件快照；来源状态保存仍沿用现有独立流程。

### 10.14 P2PQuake WebSocket 消息流

`P2pQuakeWebSocketSource` 实现 `IStreamingEarthquakeSource`，默认连接 `wss://api.p2pquake.net/v2/ws`。连接通过 `IWebSocketConnection` 抽象注入，正式运行时由 `ClientWebSocket` 包装实现，测试使用本地假连接，不依赖真实网络。

每次读取使用固定缓冲区，按 `EndOfMessage` 重组完整 WebSocket 消息。仅文本消息进入 JSON 解析；顶层必须是单个对象。对象同时缺少 `id`、`issue` 和 `earthquake` 时，按非事件控制/状态消息处理：发布空报文的 `Online` 状态并记录 `LastMessageAt`，不进入 `ParseReport()`，继续读取后续消息；带有 `issue` 或 `earthquake` 结构但缺少 `id` 的对象仍按字段错误返回 `ParseFailed`。数组、二进制消息、分片类型变化和其他字段错误只影响当前消息，不丢弃后续消息。当前协议没有已确认的独立 heartbeat 帧，非事件消息也不被解释为 heartbeat，因此最近消息时间只表示消息活性。

连接失败、读取异常或服务端 Close 帧返回 `Disconnected` 后结束本次流；连接建立/读取异常附带一次连接异常计数，服务端 Close 帧和解析失败不计入该计数；取消令牌继续抛出 `OperationCanceledException`。本版本不负责重连、连接数限制、SQLite 写入、主窗口订阅或自动刷新调度，避免在连接契约尚未稳定时扩大生命周期范围。

### 10.15 WebSocket 重连与连接生命周期

`ReconnectingEarthquakeSource` 包装任意 `IStreamingEarthquakeSource`，每次只创建和消费一个底层异步枚举器。底层报告 `Disconnected`、正常结束或抛出 `WebSocketException`/`IOException` 后，包装器先释放当前枚举器，再等待退避时间并创建下一次会话，因此不会在应用内部并行占用多个 P2PQuake 连接。

`StreamingReconnectPolicy` 默认从 5 秒开始按 2 倍递增，最大 5 分钟；一个会话收到至少一条 `Online` 结果后，下一次断开的失败计数从初始间隔重新开始。单条 `ParseFailed` 仍由底层消息流继续读取，不触发额外连接。重连等待使用与接收循环相同的取消令牌，取消时不生成伪造的断开状态。

当前策略还限制单个连接最多持续 9 分钟。每个底层会话使用独立的链接取消令牌；达到时限后主动结束当前会话并发布预期断开，随后按原有退避策略创建下一会话。窗口生命周期令牌优先级更高，窗口关闭时仍直接取消接收和等待，不生成轮换状态。

`0.20.0` 中包装器尚未在 `MainWindowViewModel` 中创建；`0.21.0` 的具体接入路径见下一节。

### 10.16 WebSocket 仓储和页面接入

`MainWindowViewModel.InitializeAsync()` 在 SQLite 缓存加载和首次 HTTP 刷新完成后启动 `RunStreamingLoopAsync()`。正式来源由 `P2pQuakeWebSocketSource` 外包 `ReconnectingEarthquakeSource`；循环使用窗口生命周期令牌，窗口关闭后取消当前接收或退避等待，不再建立新连接。

每个 `EarthquakeSourceFetchResult` 交给 `SqliteEarthquakeEventRepository.ApplyStreamingResultAsync()`。仓储使用同一个 `_writeGate` 串行化 HTTP 刷新、流式结果和其他报文保存，随后在一个连接流程中写入报文、来源状态、重新读取完整报文并发布合并事件。WebSocket 与 HTTP 收到相同 `p2pquake + SourceMessageId` 时命中 SQLite 既有主键，不生成重复报文。

连接通道状态使用 `p2pquake-ws`，标准化报文的 `Source.SourceId` 保持 `p2pquake`。这样 UI 可以分别显示 HTTP 补取和 WebSocket 长连接状态，同时不改变事件身份、来源优先级和去重键。`EarthquakePageViewModel` 在仓储发布事件时同步读取 `SourceStatuses`，因此流式新报文会更新列表、详情、地图和离线状态。

### 10.17 WebSocket 重连诊断

`ReconnectingEarthquakeSource` 在每次退避等待前发布 `SourceConnectionState.Delayed`，并在 `SourceStatus` 中填入当前连续重连次数 `RetryAttempt` 和按 UTC 计算的 `NextRetryAt`。等待完成后继续创建下一条底层流；收到 `Online` 后下一次断开从第 1 次重连开始。时间由可注入时钟提供，测试不依赖系统当前时间。

`EarthquakePageDisplayState` 只读取通道状态 ID `p2pquake-ws`，把 `NextRetryAt` 转换为 JST 文本显示在底部状态栏；没有精确时间时显示“等待重连”，其他状态显示在线、断开、解析失败或未启用。连接持续时间和最近错误详情见下一节。

`RetryAttempt` 和 `NextRetryAt` 是进程内瞬时诊断字段，不加入 SQLite 表。仓储在写入 HTTP 刷新结果时只把当前内存中带这两个字段的 WebSocket 状态合并回数据库快照，避免诊断丢失；普通 JMA/P2PQuake HTTP 状态始终由本次刷新结果覆盖，避免旧内存状态覆盖新状态。地震 SQLite schema 为 v3、海啸 schema 为 v2，重启后不恢复诊断字段。

### 10.18 WebSocket 连接持续时间和最近错误

`SourceStatus.ConnectedAt` 记录当前或最近一次 WebSocket 会话开始时间，`ConnectionEndedAt` 记录最近一次会话结束时间。在线状态的持续时间由 `displayAt - ConnectedAt` 动态计算；断开或等待重连状态使用 `ConnectionEndedAt - ConnectedAt`，避免把退避等待时间误算为连接时长。

`SourceStatus.LastError` 保存最近一次断开或消息解析失败的详情。新连接建立后不清空该字段，页面仍可看到最近一次异常；没有错误时显示“最近错误：无”，没有 WebSocket 通道时显示“最近错误：--”。当前错误文本沿用来源 `Detail`，长文本由状态栏省略显示。

主窗口已有的 `DispatcherTimer` 每秒调用 `EarthquakePageViewModel.UpdateDisplayClock()`，只重新计算展示投影，不修改领域状态、事件列表或 SQLite。这样连接持续时间会实时增长，同时不会增加独立计时任务和取消边界。

连接时间和最近错误均不写入 SQLite；仓储只在 HTTP 刷新期间从当前内存状态合并 `p2pquake-ws` 的瞬时字段，普通 HTTP 来源仍以本次刷新结果为准。应用重启后不恢复这些字段。

### 10.19 WebSocket 消息活性和连接异常统计

`P2pQuakeWebSocketSource` 在每个完整消息结果中设置 `LastMessageAt`；解析失败也算收到消息，因此不会把“收到坏消息”和“完全没有数据”混为一谈。连接建立失败或读取异常设置一次 `ConnectionExceptionCount` 和 `LastConnectionExceptionAt`；服务端 Close 帧只表示正常连接结束，不增加异常计数。

`ReconnectingEarthquakeSource` 汇总底层来源的连接异常计数，并为包装器自身捕获的 `WebSocketException`/`IOException` 追加计数。计数在当前进程内累计，重连或在线状态不会清零；`LastError` 仍保存最近错误文本。页面把 `LastMessageAt` 与当前展示时刻的差值显示为“活性：最近消息 HH:MM:SS 前”，同时显示“异常 N 次”。

当前没有 P2PQuake 协议级 ping/pong 或 heartbeat 消息，也没有因为消息静默而强制断开的 watchdog；“活性”只用于观察最后一次收到消息的时间。协议级主动心跳仍需取得上游协议确认后再实现，连接轮换见下一节。

### 10.20 WebSocket keep-alive 和主动连接轮换

正式 `ClientWebSocket` 在连接前设置 30 秒 `KeepAliveInterval`，使用 .NET WebSocket 实现提供的传输层 keep-alive；该设置不改变 P2PQuake 文本消息格式，也不把 keep-alive 帧暴露为领域报文。当前没有应用层 ping/pong 回调，因此页面仍只显示最近消息活性。

`StreamingReconnectPolicy.MaxConnectionDuration` 默认是 9 分钟，低于 P2PQuake 文档所述的 10 分钟强制断开限制。轮换使用会话级 `CancellationTokenSource.CancelAfter()`，底层异步流因该令牌结束时，包装器发布 `IsExpectedDisconnect=true` 的 `Disconnected`，再进入标准退避。该状态不增加 `ConnectionExceptionCount`，也不覆盖 `LastError`。

轮换时只允许会话令牌取消；外部窗口令牌取消仍向上抛出 `OperationCanceledException`，保证关闭窗口不会重新建立连接。当前 keep-alive 间隔和轮换时长由独立设置文件提供，缺失或非法时回退 30 秒和 9 分钟默认值。

### 10.21 WebSocket 连接策略设置

`ApplicationSettingsStore` 读取 `%LOCALAPPDATA%\\EarthquakeShow\\settings.json`，当前 schema 为 `1`。设置只保存 WebSocket 的 `keepAliveSeconds` 和 `maxConnectionDurationMinutes`，范围分别为 10–120 秒和 1–9 分钟；文件损坏、版本不支持或字段越界时返回默认值和警告，不影响 SQLite 缓存启动。

`SettingsView` 是主窗口内切换的原生设置页，当前只开放“数据源”分类。`SettingsViewModel` 使用 ComboBox 提供受约束的数值选项，应用设置时先写入文件，再由 `MainWindowViewModel` 取消旧的流式会话、等待其退出、按新设置创建 `P2pQuakeWebSocketSource` 和 `StreamingReconnectPolicy`，最后启动单个新流。HTTP 刷新任务、SQLite 仓储、事件列表、地图和详情现场不重置。

设置重建使用独立的流会话取消令牌和串行重启闸门，避免应用设置期间并行占用两个 P2PQuake 连接。自定义注入流只用于测试；正式网络路径始终由设置工厂创建。

### 10.22 P2PQuake 真实网络验证工具

`tools/P2pQuakeNetworkProbe` 是开发期控制台项目，不加入 `EarthquakeShow.sln` 和默认 xUnit 测试。它先使用同样的 `ClientWebSocket` 参数验证 `wss://api.p2pquake.net/v2/ws` 握手，再复用正式 `P2pQuakeWebSocketSource` 与 `ReconnectingEarthquakeSource` 运行指定时长。工具输出每个来源状态、报文数量、预期轮换数量和累计连接异常；当运行时长覆盖轮换上限却没有预期断开时返回失败。传入 `--capture-messages PATH` 时，消息源在分片重组、文本类型确认后将每条完整文本 JSON 追加写入 JSONL 文件，仅用于开发期协议取证。

正式验证命令示例：

```powershell
dotnet restore tools\P2pQuakeNetworkProbe\P2pQuakeNetworkProbe.csproj
dotnet run --project tools\P2pQuakeNetworkProbe --configuration Release -- --duration-minutes 10
```

捕获原始文本消息的示例：

```powershell

```

`0.29.0` 的真实 10 分钟捕获结果为：握手成功；前两次生产升级 HTTP 429 正确映射为 `RateLimited` 且不增加连接异常；随后收到三条 `code=555` 网络节点统计，消息间隔为 28.888 秒和 241.817 秒；约 9 分钟时观察到 `IsExpectedDisconnect=true`。样本证明该消息是各区域 P2P 节点数量快照且周期不固定，不是可用于 watchdog 的 heartbeat。本次仍没有收到有效地震报文，不能证明事件报文长期吞吐。

### 10.23 nTool 数据源评估（0.29.1）

本版本只做只读调查，不在正式应用中建立 nTool 客户端。调查确认 `post_data.json` 提供的 VXSE51/52/53 事件字段与现有 JMA XML/JSON 和 P2PQuake 信息高度重叠；它不能降低当前正式链路的关键缺口。nTool 实时页面使用的 Yahoo edge storage `sitelist.json` 和逐秒 `RealTimeData` 在技术上可以提供连续逐站显示，但这些地址不是面向第三方的稳定 API，数据链路涉及 Yahoo/NIED，nTool 条款也没有明确授予复制、再发布或商业分发权。

因此 nTool 的当前边界是：保留需求文档中的独立研究模式设计，默认关闭且不提供发布版启用入口；研究样本只能放在开发期忽略目录，不能进入 `src/EarthquakeShow.App/Assets` 或正式资源包。若未来获得书面授权，必须重新确认字段、限流、站点表版本、数组长度和数据时间，再单独设计适配器与测试。

## 12. 技术决策记录

### ADR-001：放弃 Tauri/WebView 正式路线

- 日期：2026-08-19。
- 原方案：Tauri 2 + Vue 3 + TypeScript + Rust。
- 原因：用户明确要求不开发网站或 WebView 界面，而是使用应用自带的原生图形界面。
- 处理：`0.1.0` 原型停止开发；相关文件已按用户授权删除，不在其上继续实现地震功能。
- 后续：已在 `0.2.0` 使用清理后的 `src/` 路径建立 WPF 原生外壳。

### ADR-002：采用 C# + .NET 8 + WPF

- 日期：2026-08-19。
- 原因：首发 Windows 10/11；WPF 是成熟的 Windows 原生桌面技术；本机已有完整 .NET 8 SDK 和 Desktop Runtime；界面与后台可以统一使用 C#。
- 代价：正式版本只能运行于 Windows；若未来要求跨平台，需要另行评估 Avalonia，不能直接承诺迁移成本。

### ADR-003：地图使用原生渲染

- 日期：2026-08-19。
- 决策：步骤 8 先使用 WPF 原生 `Canvas`、`Polygon` 和 `Ellipse` 加载本地 GeoJSON；Mapsui WPF + SkiaSharp 保留为后续正式 GIS 资源的评估选项。
- 原因：当前只需展示少量轮廓和事件点，原生控件可在不新增依赖的情况下满足离线、缩放和选择联动。
- 验证门槛：正式引入 JMA 边界前必须验证渲染性能、中文字体、高 DPI、几何许可和行政区域精度。

### ADR-004：文档与实现同步

- 日期：2026-08-19。
- 决策：用户可见功能更新版本记录；工程结构、数据流、依赖或 Bug 修复更新本文档；范围和 UI 变化分别更新需求与 UI 文档。

### ADR-005：领域模型显式保留未知值、时区和来源

- 日期：2026-08-19。
- 决策：震度使用显式 `Unknown`；可缺失数值使用可空类型；时间使用 `DateTimeOffset`；来源原始标识和负载与标准化字段并存。
- 原因：避免未知震度或深度被默认值伪装成真实观测，避免时区转换后无法还原来源时间，并为多源冲突排查保留证据。
- 代价：适配器必须显式处理缺失和未知字段，持久化层必须验证 ISO 8601 往返序列化。

### ADR-006：页面通过仓储接口消费不可变快照

- 日期：2026-08-19。
- 决策：WPF 页面只依赖 `IEarthquakeEventRepository`，仓储返回已合并的不可变事件快照；开发阶段使用内存实现。
- 原因：把页面选择状态与 HTTP、XML、SQLite 生命周期分开，使后续替换数据实现时不重写 ViewModel，并确保所有来源复用同一合并规则。
- 代价：完整快照在大量历史数据下可能产生额外分配；真实缓存接入后必须测量，再决定是否增加分页或增量更新契约。

### ADR-007：SQLite 作为离线缓存而非领域层依赖

- 日期：2026-08-20。
- 决策：新增 `EarthquakeShow.Infrastructure`，使用 `Microsoft.Data.Sqlite` 保存报文、原始 XML 和来源状态；Core 保持纯领域模型，App 只通过 `IEarthquakeEventRepository` 访问缓存。
- 原因：应用必须支持无网络启动和后续历史查询，同时避免数据库类型污染领域层；统一由 `EarthquakeEventMerger` 从缓存报文派生事件，保证内存和 SQLite 行为一致。
- 代价：当前使用完整快照读取，schema 迁移、分页、清缓存和实时刷新需要后续单独设计与验证；缓存损坏时只能回退开发期固定 seed。

### ADR-008：先接入 JMA JSON 摘要，再接权威 XML

- 日期：2026-08-20。
- 决策：步骤 11 首个切片使用无需认证的 JMA `list.json` 打通真实 HTTP、来源状态、刷新和持久化链路；完整区域和观测点继续等待 JMA XML 实时 Feed。
- 原因：JSON 列表数据量小，适合先验证缓存优先启动和失败降级；不应根据摘要源伪造 XML 才提供的报文详情。
- 代价：同一事件仍可能同时存在 `jma-json` 摘要和 `jma-xml` 报文节点；逐字段差异展示尚未完成。

### ADR-009：JMA XML 作为同时间报文的高优先级来源

- 日期：2026-08-20。
- 决策：接入 JMA XML Atom Feed，支持 `VXSE51/52/53`；在事件时间线排序中将 `jma-xml` 排在 `jma-json` 之后，使同一事件、发布时间、报次和接收时间相同时 XML 成为 `LatestReport`。
- 原因：JMA JSON 只提供事件摘要，XML 才包含区域、市町村、观测点和完整原始报文；必须避免摘要覆盖详情。
- 代价：当前只选择来源，不做逐字段冲突可视化；XML Feed 每次逐条下载最多 20 个详情报文，自动轮询和退避留待后续版本。

### ADR-010：P2PQuake 先采用 HTTP 补充源，不做猜测式跨源合并

- 日期：2026-08-20。
- 决策：接入 P2PQuake `/v2/jma/quake` HTTP 列表作为低优先级补充源；使用 `p2pquake:{id}` 作为独立事件身份，不根据时间、坐标或名称推测 JMA `EventID`。
- 原因：P2PQuake 文档允许免费二次利用且提供观测点字段，但响应没有 JMA 事件 ID；错误合并会把订正、取消或不同事件混为一条时间线。
- 代价：当前可能出现 P2PQuake 与 JMA 的重复事件；WebSocket、重连、退避和跨源关联需要单独设计和真实数据回放验证。

### ADR-011：WebSocket 先定义消息边界，再接入生命周期

- 日期：2026-08-20。
- 决策：`0.19.0` 只建立 `IStreamingEarthquakeSource`、WebSocket 连接包装和 P2PQuake 文本消息边界；每条消息独立解析为一个标准报文，异常返回来源状态。
- 原因：P2PQuake WebSocket 有强制断开和同 IP 连接数限制，必须先验证分片、消息类型、取消和异常边界，再设计重连与应用生命周期，避免把长连接故障直接带入当前 HTTP 自动刷新。
- 代价：当前 WebSocket 不会更新 SQLite 或界面；连接关闭后需要下一版本的重连服务恢复数据流。

### ADR-012：重连包装器保持单连接并独立于 UI

- 日期：2026-08-20。
- 决策：使用 `ReconnectingEarthquakeSource` 顺序释放、等待和重建底层流；不在消息源内部启动不可观察的后台任务，也不在本版本接入 WPF 生命周期。
- 原因：P2PQuake 对同一 IP 的并发连接数有限制，顺序异步枚举可以从结构上保证应用当前只占用一个连接，并使取消和测试边界保持清晰。
- 代价：只有消费该异步流时才会实际建立连接；仓储、页面状态和连接诊断仍需下一版本显式接入。

### ADR-013：WebSocket 与 HTTP 共用报文身份、分离通道状态

- 日期：2026-08-20。
- 决策：P2PQuake WebSocket 报文继续使用来源 ID `p2pquake`，连接状态使用 `p2pquake-ws`；两个通道共用 SQLite 报文去重键，但分别保存状态。
- 原因：同一上游报文可能由 HTTP 补取和 WebSocket 实时到达，报文身份必须一致才能去重；两个通道的在线、断开和退避状态又不能互相覆盖。
- 代价：页面来源列表会同时出现 P2PQuake HTTP 和 WebSocket 通道，后续显示投影需要提供清晰的通道名称和重连诊断。

### ADR-014：重连诊断只保留在进程内

- 日期：2026-08-20。
- 决策：`RetryAttempt` 和 `NextRetryAt` 只作为 `SourceStatus` 的可选内存字段；SQLite 继续使用 schema v1，不新增诊断列。
- 原因：重连次数和下次重试时间描述的是当前连接生命周期，重启后恢复它们会造成过期信息；同时页面需要在 HTTP 刷新期间保持当前 WebSocket 等待状态。
- 实现：仓储只将带诊断字段的 WebSocket 内存状态合并回读取快照，HTTP 来源状态仍以本次刷新结果为准；页面把下次重试时间统一转换为 JST。
- 代价：应用重启后不会恢复上一次重连次数或下次重试时间；连接持续时间和最近错误详情需另行定义契约。

### ADR-015：用现有 UI 时钟刷新连接持续时间

- 日期：2026-08-20。
- 决策：不为 WebSocket 诊断新增计时后台任务；复用 `MainWindowViewModel` 已有的 1 秒 `DispatcherTimer`，调用页面 ViewModel 重新生成展示投影。
- 原因：连接持续时间是展示值，不应写入领域状态或触发 SQLite 写入；复用现有 UI 时钟可以实时更新，并保持窗口关闭时已有生命周期管理。
- 代价：只有主窗口运行时刷新显示；连接时间的权威起止点仍由 WebSocket 重连包装器记录。

### ADR-016：消息活性不冒充协议心跳

- 日期：2026-08-20。
- 决策：当前版本只显示最后收到完整消息的时间和消息年龄，不实现未经上游协议确认的 ping/pong 或 heartbeat 帧。
- 原因：现有 P2PQuake WebSocket 契约只定义文本消息、Close 帧和连接异常，没有独立 heartbeat 消息；主动发送未知帧可能导致连接被服务端关闭。
- 实现：完整消息和解析失败消息更新 `LastMessageAt`；连接/读取异常累计 `ConnectionExceptionCount`，正常 Close 和解析失败不计数。
- 代价：消息长时间静默时只能显示最近消息年龄，不能证明网络层仍然可达；主动心跳和静默 watchdog 留待协议确认后实现。

### ADR-017：传输层 keep-alive 与主动连接轮换

- 日期：2026-08-20。
- 决策：使用 `ClientWebSocketOptions.KeepAliveInterval=30s` 作为传输层保活，并在 9 分钟时主动轮换 P2PQuake 连接。
- 原因：P2PQuake 连接存在 10 分钟强制断开限制；传输层 keep-alive 不依赖未确认的应用层消息格式，提前轮换可以避免在强制断开边界等待服务端关闭。
- 实现：会话级取消令牌触发预期断开，预期断开不计为连接异常；外部生命周期取消保持原有直接终止语义。
- 代价：当前没有应用层 heartbeat 回调；设置值是否需要更细粒度的动态策略仍需真实网络长时间运行后评估。

### ADR-018：连接策略设置独立于事件缓存

- 日期：2026-08-20。
- 决策：将 WebSocket keep-alive 和连接轮换设置保存为 `%LOCALAPPDATA%\\EarthquakeShow\\settings.json`，不写入 SQLite 事件缓存。
- 原因：连接策略属于用户运行偏好，不是地震领域数据；独立文件可以在清除事件缓存时保留设置，也避免改变 SQLite schema v1。
- 实现：设置文件 schema 为 1，读取失败回退默认值；应用设置时串行取消旧流并按新参数重建一个流式来源。
- 代价：当前只开放数据源连接策略，其他设置分类仍未实现；设置文件本身尚未提供导入/导出功能。

### ADR-019：原始 WebSocket 捕获仅用于协议取证

- 日期：2026-08-20。
- 决策：为 `P2pQuakeNetworkProbe` 增加可选 `--capture-messages PATH`，在完整文本消息重组后以 UTF-8 JSONL 追加保存；正式应用不启用观察回调。
- 原因：当前没有可确认的 P2PQuake heartbeat 字段定义，必须先取得真实完整消息，不能根据缺少 `id` 或任意 `code` 猜测协议语义。
- 实现：`P2pQuakeWebSocketSource` 提供可选原始文本观察回调；探测工具负责创建目录和追加文件，默认路径为空，不产生捕获文件。
- 代价：捕获文件可能包含完整地震原文和其他敏感诊断信息，不写入 SQLite，不应纳入正式发布包或提交 Git；heartbeat 字段、方向、周期和 UI 展示仍待样本确认。

### ADR-020：`code=555` 网络节点统计不作为 heartbeat

- 日期：2026-08-20。
- 决策：只把同时满足 `code=555` 和 `areas` 为数组的对象分类为网络节点统计；返回 `Online` 空报文并更新 `LastMessageAt`，不新增 heartbeat 状态。
- 原因：真实三条样本的字段和用途均指向各区域 P2P 节点数量，消息间隔分别为 28.888 秒和 241.817 秒，不存在稳定周期或请求响应标识。
- 实现：消息源在通用非事件规则前检查 `code` 与 `areas`，使用明确详情文本；不解析、保存或展示 `areas[].peer`。
- 代价：页面只能表示最近收到服务端消息，不能显示协议 heartbeat 成功或用固定静默时长判定连接失效；传输保活继续由 .NET keep-alive 和 9 分钟轮换承担。

### ADR-021：nTool 只保留为隔离研究源

- 日期：2026-08-20。
- 决策：不把 nTool 事件 API 或其页面使用的 Yahoo/NIED 逐秒 JSON 接入正式生产链路；研究模式默认关闭，发布版不提供启用入口。
- 原因：事件 API 与已有 JMA/P2PQuake 信息重叠；逐站链路虽有技术补充价值，但端点未文档化、无 SLA，且未确认复制、再发布和商业分发授权。
- 实现：只维护需求和数据契约中的隔离适配设计，不新增运行时代码、SQLite schema、设置项或资源；开发样本不得进入正式资源包。
- 代价：当前版本不提供连续逐站实时震度；下一步必须寻找有明确授权和稳定接口的替代数据源，或取得 nTool/NIED 的书面许可。

### ADR-022：无站点代码目录只作为唯一名称坐标候选

- 日期：2026-08-21。
- 决策：接入 JMA 公开震度观测点的 4,368 条名称和坐标；有代码时严格按代码解析，代码未命中时只允许规范化后的唯一名称补全坐标，重复名称拒绝自动匹配。
- 原因：当前公开资源覆盖全国坐标，但没有 JMAXML `IntensityStation.Code` 和市町村父级；完全拒绝该资源会继续导致实时观测点缺坐标，而反推代码或父级会制造无法验证的官方关系。
- 实现：`JmaStationCoordinateCatalog` 保留所有记录和诊断，`FixedJmaXmlDataLoader` 为固定与实时 JMAXML 注入同一实例，并用 75 条固定代码坐标提供精确匹配和损坏回退。
- 代价：唯一名称匹配只证明当前目录中的名称无歧义，不等同官方代码映射；三层树必须等带代码和父级的真实数据，不能沿用名称猜测。

## 14. 故障排查

### `dotnet` 无法识别 WPF 模板

执行：

```powershell
dotnet new list wpf
dotnet --list-runtimes
```

确认存在 WPF 模板以及 `Microsoft.WindowsDesktop.App 8.x`。当前开发机已经检测到 Windows Desktop Runtime。

### 应用启动后出现控制台窗口

确认 WPF 项目使用 `Microsoft.NET.Sdk` 且 `OutputType` 为 `WinExe`，不要改为 `Exe`。

### 窗口关闭后进程仍然存在

先确认主窗口是否仍然打开或最小化。`dotnet test` 构建解决方案时若提示 `MSB3026` 且列出 `EarthquakeShow.App (PID)`，表示该进程仍在占用 App 输出目录中的 DLL；关闭应用后重试，不需要删除 `bin`、`obj` 或数据库。代码排查时检查后台 `CancellationTokenSource`、定时器、数据源连接和未释放线程；WPF `Application.ShutdownMode` 保持 `OnMainWindowClose`，除非未来明确实现系统托盘。`0.35.1` 起正常关闭会等待初始化、HTTP 刷新和 WebSocket 循环结束后再完成窗口关闭。

### UI 卡顿

检查是否在 Dispatcher 线程执行网络、XML/JSON 解析、SQLite 或大规模 GIS 处理。用固定样本复现后，将耗时工作移到异步服务，并记录修复前后的测量结果。

### 修改版本号后输出程序集仍显示旧版本

先确认 `Directory.Build.props` 和 `obj/<配置>/<目标框架>/*AssemblyInfo.cs` 已生成新版本号。如果生成文件已更新但 `bin/` 中的 DLL 仍为旧版本，执行一次非增量构建：

```powershell
dotnet build EarthquakeShow.sln --configuration Release --no-restore --no-incremental
```

然后通过文件 `VersionInfo` 或应用底部版本文本再次确认。不要手工修改 `obj/` 中的生成文件。

### BUG-004：JMA XML Feed 格式错误未映射为来源状态

- 发现日期：2026-08-20。

- 现象：JMA Atom Feed 或单条 XML 报文格式损坏时，适配器无法按预期返回 `ParseFailed`，可能把异常直接带到刷新调用方。
- 复现步骤：使用本地假的 HTTP 响应返回未闭合的 `<feed>` 或 XML 报文，并调用 `JmaXmlEarthquakeSource.FetchAsync()`。

- 关联版本：`0.14.0`。

### BUG-005：HTTP 刷新覆盖 WebSocket 诊断并回退 HTTP 状态

- 发现日期：2026-08-20。
- 影响版本：`0.21.0` WebSocket 仓储接入实现。
- 现象：HTTP 刷新重新读取 SQLite 后，旧的内存来源状态可能覆盖本次 HTTP 返回的最新状态；WebSocket 等待重连状态也可能丢失。
- 复现步骤：先写入 WebSocket `Delayed` 状态，再让 HTTP 来源返回 `Online`，调用仓储 `RefreshAsync()` 并检查两个通道状态。
- 根因：仓储把全部内存状态无条件合并到持久化状态，未区分瞬时 WebSocket 诊断和普通 HTTP 状态。
- 修改位置：`src/EarthquakeShow.Infrastructure/Persistence/SqliteEarthquakeEventRepository.cs`。
- 修复方法：只合并带 `RetryAttempt` 或 `NextRetryAt` 的当前状态；HTTP 刷新结果随后覆盖同一来源的状态。
- 回归验证：Infrastructure 集成测试验证 WebSocket 诊断保持且 `jma-json` 在线状态不回退；全套 149 个测试通过。
- 关联版本：`0.22.0`。

### BUG-006：WebSocket 非事件消息和升级限流被误分类

- 发现日期：2026-08-20。
- 影响版本：`0.26.1` 真实网络验证工具运行期间。
- 现象：P2PQuake 发送没有 `id` 的非事件 JSON 时，消息被记录为 `ParseFailed`；WebSocket 升级返回 HTTP `429` 时，被记录为连接异常并增加异常计数。
- 复现步骤：向 `P2pQuakeWebSocketSource` 注入只含控制字段的 JSON，或让连接建立抛出“status code '429' ... expected”的 `WebSocketException`。
- 根因：消息源此前把所有对象直接交给地震报文解析器，连接异常也没有区分服务端限流和真正的网络故障。
- 修改位置：`src/EarthquakeShow.Infrastructure/Sources/P2pQuakeWebSocketSource.cs`、`src/EarthquakeShow.Infrastructure/Sources/ReconnectingEarthquakeSource.cs`。
- 修复方法：同时缺少 `id`、`issue`、`earthquake` 的对象返回 `Online` 空报文并记录活性；带事件结构但缺少 `id` 仍失败。明确的升级 `429` 返回 `RateLimited`，不增加连接异常，重连仍使用退避策略。
- 回归验证：新增非事件恢复、事件结构缺少 `id`、握手 `429` 和限流状态保留测试；全套 167 个测试、Release 构建和固定数据校验通过。
- 关联版本：`0.27.0`。

### ADR-007：事件跟随使用震源中心与包络适配

- 日期：2026-08-25。
- 决策：跟随按钮执行一次性事件视野定位；中心优先使用震源坐标，缩放范围使用震源、观测点和命中行政区几何的包络，围绕中心重建对称包络并保留约 6% 视口留白，对点事件设置最小包络；自动事件视野优先加载中精度几何。
- 调研依据：Leaflet `fitBounds`、Mapbox GL JS `cameraForBounds/fitBounds`、OpenLayers `View.fit` 均采用范围 + padding，并提供最大缩放或最小分辨率约束。
- 原因：中心与范围职责分离，可以保证震源严格居中，同时尽量铺满地图并避免小范围事件过度放大；一次性按钮不会持续抢回用户手动视角。
- 代价：极小范围事件受最小包络和现有最大缩放约束，可能显示比实际区域略大的周边范围；没有坐标的观测点不参与包络计算。

- 根因：`_viewportCenter` 在拖动过程中更新时仍保留 `_panOffset`，没有形成明确的提交边界；`RenderMap()` 又只使用一次性 `_pendingViewportCenter`，该值被首次渲染清除后，后续普通图层通知再次按 `FocusedCoordinate` 使用震源。改为持久中心后仍存在一处竞态：异步 LOD 请求携带的旧中心曾优先于几何替换瞬间从画布反算出的实际中心，加载期间继续拖动时仍会被旧请求拉回。
- 修改位置：`src/EarthquakeShow.App/Views/EarthquakeMapView.xaml.cs`、`src/EarthquakeShow.App/ViewModels/EarthquakeMapViewModel.cs`。
- 修复方法：拖动中只修改 `_panOffset`；鼠标松开、失去捕获或滚轮锚点换算完成时反算画布中心并提交到 `_viewportCenter`，随后清零偏移。`CreateProjection()` 和 `RenderMap()` 始终使用已提交中心；LOD 几何替换前用旧几何反算当前画布中心并提交，异步请求中心仅保留在日志中对照，不再参与中心优先级。临时 `[MapDebug]` 同时输出交互、LOD、请求中心和最终投影中心。
- 回归验证：投影测试覆盖不同几何范围替换时当前画布中心不变；中/高精度顺序、上一范围缓存和 generation 测试继续通过。全量 285 项测试和 Release 构建通过；完整人工拖动仍需结合临时日志在实际窗口复核。
- 关联版本：`0.63.0`。

### BUG-034：并发高精度重载覆盖最新地图中心

- 发现日期：2026-08-25。
- 影响版本：`0.62.3` 及更早版本。
- 现象：高精度加载完成后仍可能回到震源或旧位置。
- 根因：多个 View 入口可同时发起 LOD 检查；旧请求在中精度兜底阶段抢先触发几何通知，旧 pending 中心又优先于新请求中心。
- 修改位置：`src/EarthquakeShow.App/ViewModels/EarthquakeMapViewModel.cs`、`src/EarthquakeShow.App/Views/EarthquakeMapView.xaml.cs`。
- 修复方法：中精度提交前后检查 generation/取消状态；`ResolvePendingViewportCenter` 规定新请求中心优先于旧 pending 中心。
- 回归验证：专项地图测试 34 项，全量测试和 Release 构建通过。
- 关联版本：`0.62.4`。

### BUG-033：高精度重载三阶段行为不可观察

- 发现日期：2026-08-25。
- 影响版本：`0.62.2` 及更早版本。
- 现象：高精度越界时中精度过渡不稳定或不可见，加载完成后的中心仍可能回到震源，回拖上一范围无法确认是否命中缓存。
- 根因：中精度切换和高精度加载在同一异步调用中没有明确的 UI 交接点；中心仍主要依赖 `GeometryChanging` 时刻反算；缓存恢复没有运行时可观察状态。
- 修改位置：`src/EarthquakeShow.App/ViewModels/EarthquakeMapViewModel.cs`、`src/EarthquakeShow.App/Views/EarthquakeMapView.xaml.cs`、`tests/EarthquakeShow.App.Tests/EarthquakeMapViewModelTests.cs`。
- 修复方法：高精度请求先提交中精度并让出 UI 调度周期；从请求开始显式传递 `viewportCenter` 到几何替换事件；缓存命中设置 `LastHighLoadUsedCache` 并在状态栏显示。
- 回归验证：测试确认越界替换顺序包含 `High → Medium → High`，回拖后 `LastHighLoadUsedCache=true`；全量 278 项测试和 Release 构建通过。
- 关联版本：`0.62.3`。

### BUG-032：高精度视野重载时地图中心回到震源

- 发现日期：2026-08-25。
- 影响版本：`0.62.1` 及更早版本。
- 现象：高精度地图拖出已加载范围后触发重新加载，加载完成地图中心回到震源；拖动期间未加载区域没有稳定的中精度兜底。
- 复现步骤：选择事件并放大到高精度，拖动到当前高精度范围外，松开鼠标并等待高精度加载完成。
- 根因：高精度资源按整套 `MapGeometrySet` 替换，异步加载期间没有独立的显示兜底；中心保存依赖几何通知时序，普通缩放和 LOD 重载都可能重复应用 pending 中心；旧异步请求也没有 generation 校验。
- 修改位置：`src/EarthquakeShow.App/ViewModels/EarthquakeMapViewModel.cs`、`src/EarthquakeShow.App/Views/EarthquakeMapView.xaml.cs`。
- 修复方法：常驻缓存中精度几何，越界时先切换中精度再加载新高精度；保存当前/上一高精度范围用于回拖恢复；每次加载增加 generation 校验；仅在确认会发生几何变化时保存地理中心，普通缩放不重复应用平移。
- 回归验证：高精度越界判定、上一范围恢复、重复中心策略和全量地图测试通过。
- 关联版本：`0.62.2`。
