# Earthquake Show 工程实现文档

## 1. 文档用途

本文档长期记录正式原生桌面工程如何运行、关键代码位于哪里、重要技术决策以及 Bug 的原因和修复方法。后续排查回归问题时，应先按版本记录确定功能引入时间，再在本文档中查找对应实现和故障记录。

维护要求：

- 工程结构、启动流程、依赖或配置变化时同步更新。
- 新增数据流或跨模块约定时，在实现变更中同步更新相应章节。
- 每次 Bug 修复记录现象、影响版本、根因、修改位置和回归验证。
- 不记录猜测；尚未实现或尚未验证的信息必须明确标记。

## 3. 正式技术栈

| 层级 | 技术 | 职责 |
| --- | --- | --- |
| 桌面界面 | .NET 8 + WPF | 原生窗口、控件、布局、键盘和可访问性 |
| 应用语言 | C# | 界面、领域模型、数据源、缓存和后台任务 |
| 架构 | MVVM | 分离 View、页面状态和业务逻辑 |
| MVVM 辅助 | CommunityToolkit.Mvvm | 后续减少通知属性和命令样板代码 |
| 地图 | Mapsui WPF + SkiaSharp | 不依赖 WebView 的地图、区域和点图层渲染 |
| GIS | NetTopologySuite | GeoJSON、几何计算和空间数据处理 |
| 数据库 | Microsoft.Data.Sqlite | 事件、报文版本、原始响应和来源状态缓存 |
| 网络 | HttpClient | JMA、P2PQuake 和其他 HTTP 数据源 |
| JSON/XML | System.Text.Json + System.Xml | 数据解析和固定样本契约 |
| 日志 | Microsoft.Extensions.Logging | 结构化运行日志和故障诊断 |
| 测试 | xUnit | 领域逻辑、解析器、仓储和回归测试 |
| 开发脚本 | Python | 仅用于 GIS 和固定样本的离线预处理 |

正式运行时不得依赖 Node.js、npm、Rust、浏览器、WebView、HTML/CSS 或本地 HTTP 服务。

## 5. 目标解决方案结构

```text
EarthquakeShow.sln
Directory.Build.props                 # 统一版本、语言和分析器设置
src/
  EarthquakeShow.App/
    App.xaml                          # WPF 应用入口和全局资源
    MainWindow.xaml                   # 主窗口外壳
    Views/                            # 页面和可复用 UserControl
    ViewModels/                       # 页面状态和命令
    Controls/                         # 震度、状态等自定义控件
    Resources/                        # 主题、颜色、图标和静态 GIS
  EarthquakeShow.Core/
    Models/                           # 地震事件和报文领域模型
    Services/                         # 事件合并、排序和查询逻辑
    Abstractions/                     # 仓储、时钟和数据源接口
  EarthquakeShow.Infrastructure/
    Adapters/                         # JMA/P2PQuake 等数据源适配器
    Persistence/                      # SQLite 实现和迁移
    Networking/                       # HttpClient、重试和限流
tests/
  EarthquakeShow.Core.Tests/
  EarthquakeShow.Infrastructure.Tests/
tools/                                # Python GIS/样本预处理脚本
```

目录只在对应职责开始实现时创建，避免预先建立空层和空接口。

## 6. 目标依赖方向

```text
EarthquakeShow.App
  ├─> EarthquakeShow.Core
  └─> EarthquakeShow.Infrastructure

EarthquakeShow.Infrastructure
  └─> EarthquakeShow.Core

EarthquakeShow.Core
  └─> 不依赖 UI、数据库或具体网络库
```

约束：

- WPF View 不直接发送 HTTP 请求或执行 SQL。
- Core 不引用 WPF，领域逻辑可以在无窗口环境中测试。
- Infrastructure 实现 Core 定义的仓储和数据源接口。
- View 的 code-behind 只处理纯显示行为；业务状态和命令放入 ViewModel。

## 7. 原生窗口实现规划

### 7.1 启动流程

```text
EarthquakeShow.App.exe
  → App.xaml 启动
  → 建立应用服务和 MainWindowViewModel
  → 创建 MainWindow
  → 加载地震情报工作区
  → 后续先读 SQLite 缓存，再异步连接数据源
```

基础外壳阶段没有网络、数据库和长期后台任务，关闭主窗口后进程必须直接退出。

### 7.2 主窗口区域

`MainWindow.xaml` 使用 WPF `Grid` 建立固定区域：

- 顶部状态栏：当前时间、数据状态和最后接收时间。
- 左侧导航：首版只显示已经实现的地震入口。
- 事件列表：最近事件和历史地震共用一个列表。
- 地图区域：后续承载 Mapsui 原生地图控件。
- 右侧详情：摘要、观测点、时间线和原始数据标签。
- 底部状态栏：网络、缓存、来源和版本。

目标默认窗口为 `1440 × 900`，最小窗口为 `1180 × 720`。不得通过启动浏览器或托管网页完成任何区域。

### 7.3 UI 线程规则

- 网络、XML/JSON 解析和 SQLite 操作不得阻塞 WPF Dispatcher。
- 后台结果通过 ViewModel 更新，必要时使用 Dispatcher 切回 UI 线程。
- 不使用 `async void`，事件处理器和 WPF 生命周期入口除外。
- 所有长期任务必须支持取消，应用退出时停止连接和定时器。

## 8. 地图方案

地图使用 Mapsui WPF 控件和 SkiaSharp 原生绘制，不使用在线网页地图组件。

计划图层：

1. 随应用打包的日本/JMA 简化边界。
2. 区域最大观测震度填充。
3. 震源符号。
4. 观测点符号。
5. 图例和标签。

GIS 原始文件在开发阶段由 Python 脚本预处理为简化 GeoJSON 或后续确认的本地格式，运行时不下载大体积 Shapefile。地图依赖版本和许可证必须在实际引入时记录。

## 10. 技术决策记录

### ADR-001：放弃 Tauri/WebView 正式路线

- 日期：2026-08-19。
- 原方案：Tauri 2 + Vue 3 + TypeScript + Rust。
- 原因：用户明确要求不开发网站或 WebView 界面，而是使用应用自带的原生图形界面。
- 处理：`0.1.0` 原型停止开发；相关文件已按用户授权删除，不在其上继续实现地震功能。
- 后续：`0.2.0` 在干净的 `src/` 路径建立 WPF 原生外壳。

### ADR-002：采用 C# + .NET 8 + WPF

- 日期：2026-08-19。
- 原因：首发 Windows 10/11；WPF 是成熟的 Windows 原生桌面技术；本机已有完整 .NET 8 SDK 和 Desktop Runtime；界面与后台可以统一使用 C#。
- 代价：正式版本只能运行于 Windows；若未来要求跨平台，需要另行评估 Avalonia，不能直接承诺迁移成本。

### ADR-003：地图使用原生渲染

- 日期：2026-08-19。
- 决策：优先评估 Mapsui WPF + SkiaSharp，并使用本地 GIS 数据。
- 原因：满足无浏览器/WebView要求，同时支持区域多边形、点图层、缩放和离线显示。
- 验证门槛：正式引入前用日本边界 GeoJSON 验证渲染性能、中文字体、高 DPI 和许可证。

### ADR-004：文档与实现同步

- 日期：2026-08-19。
- 决策：用户可见功能更新版本记录；工程结构、数据流、依赖或 Bug 修复更新本文档；范围和 UI 变化分别更新需求与 UI 文档。

## 12. 故障排查

### `dotnet` 无法识别 WPF 模板

执行：

```powershell
dotnet new list wpf
dotnet --list-runtimes
```

确认存在 WPF 模板以及 `Microsoft.WindowsDesktop.App 8.x`。当前开发机已经检测到 Windows Desktop Runtime。

### 应用启动后出现控制台窗口

确认 WPF 项目使用 `Microsoft.NET.Sdk` 且 `OutputType` 为 `WinExe`，不要改为 `Exe`。

### 窗口关闭后进程仍然存在

检查后台 `CancellationTokenSource`、定时器、数据源连接和未释放线程。WPF `Application.ShutdownMode` 应保持主窗口关闭时退出，除非未来明确实现系统托盘。

### UI 卡顿

检查是否在 Dispatcher 线程执行网络、XML/JSON 解析、SQLite 或大规模 GIS 处理。用固定样本复现后，将耗时工作移到异步服务，并记录修复前后的测量结果。
