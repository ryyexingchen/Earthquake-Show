# Earthquake Show 工程实现文档

## 1. 文档用途

本文档长期记录正式原生桌面工程如何运行、关键代码位于哪里、重要技术决策以及 Bug 的原因和修复方法。后续排查回归问题时，应先按版本记录确定功能引入时间，再在本文档中查找对应实现和故障记录。

维护要求：

- 工程结构、启动流程、依赖或配置变化时同步更新。
- 新增数据流或跨模块约定时，在实现变更中同步更新相应章节。
- 每次 Bug 修复记录现象、影响版本、根因、修改位置和回归验证。
- 不记录猜测；尚未实现或尚未验证的信息必须明确标记。

- Windows 10/11 x64。
- .NET SDK 8.x。
- Microsoft Windows Desktop Runtime 8.x。
- 不需要单独安装 SQLite；`Microsoft.Data.Sqlite` 随应用依赖提供托管和原生运行库。

## 7. 原生窗口实现

### 7.1 启动流程

```text
EarthquakeShow.App.exe
  → App.xaml 启动
  → 创建 MainWindow
  → MainWindow 创建 MainWindowViewModel 并设为 DataContext
  → FixedJmaXmlDataLoader 读取站点 CSV 和四份固定 JMAXML
  → 创建 SQLite 仓储并初始化 schema v1
  → 优先读取缓存；缓存为空时写入固定 seed
  → SqliteEarthquakeEventRepository 使用 EarthquakeEventMerger 合并事件
  → 设置离线来源状态并加载页面快照
  → 依次请求 JMA list.json 摘要和 JMA XML Atom Feed 详情
  → 成功报文写入 SQLite；失败来源只更新来源状态
  → ViewModel 初始化版本、页面状态、地图和 JST 时钟
  → 窗口首次显示后异步加载仓储事件快照
  → 关闭窗口时调用 ViewModel.Dispose() 停止 DispatcherTimer
```

`0.14.0` 仍没有依赖注入容器或长期轮询任务。固定样本在 ViewModel 创建阶段解析，SQLite 缓存先加载到页面，随后用同一个 `HttpClient` 以 15 秒超时依次请求 JMA JSON 和 JMA XML；用户点击刷新时复用相同路径。HTTP、XML/JSON 处理和 SQLite 操作均在异步流程中执行，不阻塞 WPF Dispatcher。

### 7.2 主窗口区域

`MainWindow.xaml` 使用 WPF `Grid` 建立以下固定区域：

- 顶部状态栏：当前时间、数据状态和最后接收时间。
- 左侧导航：首版只显示已经实现的地震入口。
- 事件列表：最近事件和历史地震共用一个列表。
- 地图区域：承载 WPF 原生 `EarthquakeMapView`，绘制离线轮廓和当前事件图层。
- 右侧详情：摘要、观测点、时间线和原始数据标签。
- 底部状态栏：网络、缓存、来源和版本。

默认窗口为 `1440 × 900`，最小窗口为 `1180 × 720`。宽度不低于 `1280 px` 时，右侧详情栏固定为 `380 px`；低于该阈值时详情列宽归零，详情面板覆盖在地图右侧并可开关。顶部搜索按钮聚焦事件搜索框；地图工具提供缩放、复位、定位和跟随选择，设置按钮仍禁用。所有区域均由 WPF 原生控件构成，不通过浏览器或托管网页实现。

### 7.3 UI 线程规则

- 当前 JST 时钟使用 UI 线程上的 `DispatcherTimer`，每秒只更新一个文本属性，并在窗口关闭时停止和解除事件订阅。
- 网络、XML/JSON 解析和 SQLite 操作不得阻塞 WPF Dispatcher。
- 后台结果通过 ViewModel 更新，必要时使用 Dispatcher 切回 UI 线程。
- 不使用 `async void`，事件处理器和 WPF 生命周期入口除外。
- 所有长期任务必须支持取消，应用退出时停止连接和定时器。

### 7.4 地震情报页面状态

`EarthquakePageViewModel` 只依赖 `IEarthquakeEventRepository`，通过不可变 `EarthquakePageState` 快照统一发布页面状态。主窗口只负责在首次显示时调用 `LoadAsync()`，不直接读取事件或管理选择。

```text
IEarthquakeEventRepository
  → ListEventsAsync / EventsChanged
  → EarthquakePageViewModel
  → EarthquakePageState
  → 后续事件列表、地图和详情绑定
```

首次非空加载选择事件列表第一项及其最后一报。仓储发布新快照时，先按 `EventId` 恢复当前事件，再按 `SourceId + SourceMessageId` 恢复当前报文；只有原选择已不存在时才回退到第一项或最后一报。因此新事件到达不会强制打断历史浏览。

页面状态同时保存搜索文字、筛选快照、排序选项、地图焦点、来源状态、加载、刷新、离线和错误状态。`0.11.0` 由列表 ViewModel 执行搜索、筛选和排序，由详情 ViewModel 投影 `ViewedReport`，由地图 ViewModel 消费同一快照并投影当前报文图层。

`EarthquakeDetailsViewModel` 不创建第二份事件选择。摘要字段、区域/市町村/观测点列表、时间线和原始负载均从 `EarthquakePageState.ViewedReport` 重建；时间线选择通过 `EarthquakePageViewModel.SelectReport()` 修改页面快照。上一报和下一报在边界处禁用，返回最新直接选择时间线最后一报。观测点选择有坐标时调用地图 `FocusLocation()`，无坐标项仍可选但不会生成地图标记。

仓储更新可能来自后台线程。ViewModel 在创建时捕获 `SynchronizationContext`，收到更新后切回该上下文再替换状态；测试环境没有同步上下文时同步执行。窗口关闭时取消初始化令牌，并由 `Dispose()` 解除仓储事件订阅。

### 7.5 显示投影与响应式布局

`EarthquakePageDisplayState.Create()` 将领域和页面状态转换为可直接绑定的界面文字和布尔状态。加载、错误、空数据、来源连接、最后接收和当前选择的判断集中在该投影中；XAML 只使用绑定和 `BooleanToVisibilityConverter`，不重复业务判断。

`WindowLayoutViewModel` 只管理窗口宽度等级和详情抽屉开关。`MainWindow` 的 `SizeChanged` code-behind 属于纯显示行为：它把实际宽度交给布局 ViewModel，并在紧凑模式把 `DetailsColumn` 设置为 `0`。详情面板跨越地图与详情列并右对齐，因此桌面模式占用预留列，紧凑模式则覆盖地图右侧。

顶部状态字段使用固定列宽，底部来源字段使用最大宽度和文字省略，防止网络状态、来源名称和时间变化影响地图区域。响应阈值和抽屉状态有独立单元测试；窗口尺寸、标签切换和抽屉操作使用原生窗口截图与 UI Automation 验证。

### 7.6 事件列表投影与选择

`EarthquakeEventListViewModel` 订阅 `EarthquakePageViewModel.PropertyChanged`，只把页面事件快照投影为当前可见卡片，不持有第二份仓储或独立选择。筛选或排序改变后计算目标顺序，再按 `EventId` 对同一个 `ObservableCollection` 执行插入、移动、替换和删除；未变化卡片保留实例，避免重置整个数据源和滚动位置。100 条事件场景由单元测试验证，WPF `ListBox` 使用回收式 `VirtualizingStackPanel` 创建可见容器。

搜索覆盖事件 ID、震源名称/代码、报文代码和来源 ID。时间筛选使用最新发布时间；震度和震级未知值不会被当作零值参与最低值比较；区域筛选检查最新有效报文的震源、区域、市町村和观测点。确定性排序和字段细节维护于[数据契约与格式](./数据契约与格式.md)。

列表 `SelectedItem` 调用页面 `SelectEvent()`，因此地图和详情后续可复用同一选择状态。仓储快照变化时列表按 `EventId` 恢复卡片选择，并比较前后事件 ID 标记新事件；首次加载的数据不标为新事件。刷新入口调用页面已有仓储边界，并在任务完成前拒绝第二次刷新。

筛选区域当前在固定 `280 px` 左栏内折叠并即时应用，没有引入筛选草稿对象或独立抽屉 ViewModel。当前仓储一次返回全部事件，不存在分页游标；“加载更早记录”将在 SQLite 仓储定义分页契约后实现。

### 7.7 地图状态与图层

`EarthquakeMapViewModel` 只依赖现有 `EarthquakePageViewModel` 和不可变 `OfflineMapGeometry`。页面状态变化时重新投影 `ViewedReport`：区域通过 `areaCode` 匹配本地 GeoJSON，震源只在存在合法坐标时生成一个标记，观测点只为有坐标的记录生成标记。无坐标观测点不丢失，详情页仍可显示。没有手动报文快照时，页面首次选择事件仍把 `ViewedReport` 设置为最新报文。

`EarthquakeMapView` 使用 WPF `Canvas` 和 `Polygon`/`Ellipse` 原生图形，按固定 EPSG:4326 范围进行经纬度到屏幕坐标转换；有效焦点在“跟随选择”开启且存在当前事件时为 `SelectedEvent`，使用可绘制标记的平均坐标，否则使用 `JapanOverview` 的日本全图中心。缩放范围为 `1.0` 到 `4.0`，并且不改变页面选择状态；点击日本全图会关闭跟随，避免刚复位就被当前选择重新拉回。

应用资源 `Assets/japan-overview.geojson` 在 `.csproj` 中配置为输出和发布复制。该资源只提供非官方示意轮廓，应用状态栏显示“离线示意”；不得用于行政边界、区域归属或空间查询。真正 JMA GIS 数据接入前不引入在线底图。

## 8. 地图方案

步骤 8 使用 WPF 原生 `Canvas`、`Polygon` 和 `Ellipse` 绘制，不使用浏览器、WebView、在线底图或 Mapsui 运行时依赖；Mapsui/SkiaSharp 仍保留为后续大规模 GIS 场景的评估选项。

当前图层：

1. 随应用打包的非官方日本示意轮廓。
2. 与 `areaCode` 匹配的区域最大观测震度填充。
3. 有坐标的震源符号。
4. 有坐标的观测点符号和工具提示。
5. 震度图例、缩放、复位、定位和跟随选择控件。

GIS 原始文件在开发阶段由 Python 脚本预处理为简化 GeoJSON 或后续确认的本地格式，运行时不下载大体积 Shapefile。当前应用轮廓是手工维护的 UI 示意资源，不能替代正式 JMA GIS 边界。地图依赖版本和许可证必须在实际引入时记录。

## 9. 固定测试数据

`0.3.0` 在 `tests/TestData/` 建立后续解析、事件合并和地图测试的固定输入：

```text
tests/TestData/
  manifest.json                       # 来源、SHA-256 和预期解析结果
  README.md                           # 数据用途、来源和限制
  JmaXml/
    Official/                         # JMA 官方 VXSE51/52/53 原文
    Synthetic/                        # 订正和字段缺失夹具
  JmaStations.csv                     # 详情报中 75 个观测点的坐标
  Gis/jma-area-test-envelopes.geojson # 7 个非官方区域测试包络
  Definitions/intensity-scale.json    # 震度、排序和显示颜色定义
```

数据约束：

- `Official/` 文件保持下载原文，不得为方便解析而修改。
- `Synthetic/` 文件必须在 `manifest.json` 中标明派生来源、改动或测试目的，不能伪装成官方报文。
- `JmaStations.csv` 的名称和坐标来自 JMA 官方观测点 JSON，观测点编码来自固定 `VXSE53`；两者按去除名称末尾 `＊` 后的名称关联。
- 区域测试包络由区域内观测点的经纬度范围生成，不是官方边界；正式地图不得使用该几何判断行政或预报区归属。
- `manifest.json` 是固定数据契约。修改任何受管文件时，必须同步更新哈希和预期结果。
- 校验器仅使用 Python 标准库并且不访问网络：`python tools\validate_test_data.py`。

JMA 官方来源和下载日期记录在固定数据 README 与清单中。全国细分区域 Shapefile 约 110 MB，未直接纳入仓库；正式地图阶段应生成经过简化、精度和许可检查的派生资源。

## 10. 领域模型

Core 只表达跨来源公共语义和纯领域计算，不引用 WPF、HttpClient、SQLite 或具体 XML 类型。

### 10.1 核心对象

| 类型 | 约定 |
| --- | --- |
| `EarthquakeEvent` | 使用来源事件 ID 标识事件，保存不可变报文时间线，并派生当前报文、最后有效报文和事件摘要 |
| `EarthquakeReport` | 保存报文代码、类型、状态、上下文、时间、震源、震级、震度集合和来源 |
| `Hypocenter` | 名称、代码和坐标可未知；深度为 `int?`，`0` 与 `null` 含义不同 |
| `Magnitude` | 值可未知；拒绝 `NaN` 和正负无穷，保留类型和来源条件文字 |
| `IntensityArea` | 保存都道府县、细分区域和该区域最大观测震度 |
| `IntensityMunicipality` | 使用 `AreaCode` 关联区域，保存市町村最大观测震度 |
| `IntensityStation` | 使用 `MunicipalityCode` 关联市町村，坐标可未知 |
| `SourceReference` | 保留来源 ID、原始消息 ID、原文 URL 和来源原始负载 |
| `SourceStatus` | 表达在线、延迟、断开、限流、解析失败和停用等适配器状态 |

### 10.2 未知值与时间

- 震度未知统一使用 `JmaIntensity.Unknown`；枚举顺序只用于稳定排序，不能把底层数值直接显示给用户。
- 标准震度代码由 `ToCode`/`TryParseCode` 转换，未知输入返回失败和 `Unknown`，不静默映射为普通震度。
- 震源深度未知使用 `null`，地表或极浅震源可使用 `0`。
- 震级未知使用 `Magnitude.Value = null`；非有限浮点数在构造时拒绝。
- 领域时间使用 `DateTimeOffset`。写入 JSON 或 SQLite 时使用 `ToString("O")` 等价的 ISO 8601 往返格式，读取后必须保留原偏移量。

### 10.3 集合与来源字段

报文的区域、市町村、观测点以及事件的报文时间线使用 `ImmutableArray<T>`。Core 不把 XML 节点直接暴露给 UI；无法统一的源字段保存在 `SourceReference.SourcePayload`，同时保留原始报文代码和消息 ID，便于排查标准化差异。

### 10.4 事件合并与摘要

`EarthquakeEventMerger.Merge()` 接受已标准化的报文集合并返回不可变事件集合。它不保存状态、不读取数据库，也不依赖输入顺序，后续内存仓储和 SQLite 仓储应复用这一入口，不能在各数据源适配器中复制合并规则。

```text
标准化报文
  → 校验 EventId / SourceId / SourceMessageId
  → 按 EventId 分组
  → 按 SourceId + SourceMessageId 去重并保留最早接收记录
  → 事件内稳定排序
  → 按最新发布时间排列事件
  → EarthquakeEvent 派生当前状态和最后有效报文摘要
```

事件内排序键依次为 `IssuedAt`、`Serial`、`ReceivedAt`、`SourceId`、`SourceMessageId`，其中 `Serial = null` 排在数字报次之前。事件集合按各事件最后报文的 `IssuedAt` 降序排列，时间相同使用 `EventId` 升序兜底。

`LatestReport` 是时间线最后一份报文，包含取消状态；`LatestEffectiveReport` 只接受 `Issued` 或 `Correction`。`EarthquakeEventSummary.Status`、`Context` 和 `UpdatedAt` 来自 `LatestReport`，报文代码、发生时间、震源、震级和最大震度来自 `LatestEffectiveReport`。因此取消报可以结束事件，同时不会让列表摘要丢失最后确认的地震数据。

输入标识为空时合并服务抛出 `ArgumentException`。该检查只保护归并身份；字段级合法性仍由值对象和后续解析器负责。

### 10.5 固定 JMAXML 解析与应用装配

`JmaXmlParser` 使用禁用 DTD 和外部解析器的 `XmlReader` 加载 XML，再按节点本地名称读取 JMAXML 命名空间中的固定字段。解析器只依赖 Core 领域模型，不知道 WPF、输出目录或测试路径；报文代码、稳定来源消息 ID 和可选接收时间由调用方通过 `JmaXmlParseOptions` 提供。

```text
App 输出 Assets/JmaXml + JmaStations.csv
  → FixedJmaXmlDataLoader 组装文件路径和稳定消息 ID
  → JmaStationCatalog 按 station_code 建立坐标字典
  → JmaXmlParser.LoadFixtures 读取并标准化四份报文
  → EarthquakeEventMerger 按 EventID 合并时间线
  → InMemoryEarthquakeEventRepository
  → EarthquakePageViewModel → 列表和地图
```

App 的 `.csproj` 从 `tests/TestData` 链接三份官方报文、订正夹具和站点 CSV，并配置输出、发布复制。字段缺失夹具不复制到 App，防止测试事件出现在用户界面。`SourceId` 固定为 `jma-xml`，`SourceMessageId` 使用文件名，原始 XML 保存于 `SourcePayload`，便于解析差异排查。

解析失败不会生成部分事件：文件访问、权限或格式异常由 App 装配器包装为带资源提示的 `InvalidOperationException`，当前固定资源缺失会阻止窗口创建。网络适配器接入后不得沿用这个启动失败策略，应把单份报文失败映射为来源状态并继续显示缓存。

完整字段映射、未知值和错误边界维护于[数据契约与格式](./数据契约与格式.md)。Core 测试直接使用仓库固定夹具，覆盖官方三报文、订正、字段缺失、坐标补齐、事件合并和 XML 安全边界。

### 10.6 仓储边界与内存实现

`IEarthquakeEventRepository` 定义异步事件列表、按 ID 查询、完整快照更新通知和主动刷新。WPF 页面不能绕过该接口直接访问 HTTP、XML 或 SQLite。具体字段和方法契约长期维护于[数据契约与格式](./数据契约与格式.md)。

`InMemoryEarthquakeEventRepository` 用于开发和单元测试。它在线程锁内保存原始标准化报文和合并后的事件快照，`ApplyReports()` 追加报文后统一调用 `EarthquakeEventMerger`，在锁外发布不可变完整快照，避免订阅者回调阻塞仓储锁。当前没有外部来源，所以 `RefreshAsync()` 只检查取消令牌，不产生数据。

### 10.7 SQLite 缓存实现

`SqliteEarthquakeEventRepository` 位于 `EarthquakeShow.Infrastructure/Persistence`，只依赖 Core。它使用 `Microsoft.Data.Sqlite`，连接字符串关闭连接池以避免 Windows 进程退出后残留数据库文件句柄。默认路径为 `%LOCALAPPDATA%\\EarthquakeShow\\earthquake-cache.db`，测试通过构造函数传入临时路径隔离文件。

数据流固定为：

```text
seed 报文 → 初始化 schema v1 → 读取 earthquake_reports
                         ↘ 空缓存时写入 seed
所有报文 → EarthquakeEventMerger → 事件快照 → EventsChanged / 页面
source_status → 离线 Disabled 状态 → EarthquakePageState.SourceStatuses
```

每份报文的标准列用于查询和审计，完整领域字段保存在显式 `ReportPayloadDto` JSON 中；DTO 明确映射时间、枚举、坐标、震度集合和来源原文，不直接序列化领域 record。写入使用事件 ID、来源 ID和来源消息 ID作为主键，重复初始化通过 upsert 保持幂等。

数据库无法打开、schema 版本不支持、JSON 损坏或权限/格式异常时，仓储捕获可预期持久化异常，使用传入的固定 seed 构建内存事件快照，并把失败原因写入 `CacheStatus`；不会让 WPF 启动直接退出，也不会清空已有内存事件。取消令牌仍按异步 API 约定向上抛出。

当前没有 schema 迁移脚本。版本不为 `1` 时先记录不支持状态并回退 seed；新增字段或表时必须提高 schema 版本、补迁移策略和独立测试，不能静默复用旧格式。

### 10.8 JMA JSON 实时摘要

`JmaJsonEarthquakeSource` 实现 `IRealtimeEarthquakeSource`，默认读取 `https://www.jma.go.jp/bosai/quake/data/list.json`。适配器只负责 HTTP 获取、真实字段解析和标准化，不引用 SQLite 或 WPF。`MainWindowViewModel` 持有应用生命周期 `HttpClient`，设置 15 秒超时和应用 User-Agent，并把适配器注入 SQLite 仓储。

启动和刷新数据流：

```text
页面先加载 SQLite 缓存
  → JmaJsonEarthquakeSource.FetchAsync
  → EarthquakeSourceFetchResult（报文 + SourceStatus）
  → SqliteEarthquakeEventRepository upsert
  → EarthquakeEventMerger 重新派生快照
  → 页面同步事件、来源状态和离线状态
```

适配器映射当前真实字段 `eid/rdt/at/anm/acd/cod/mag/maxi/json`。`cod` 使用 JMAXML 同类坐标格式解析经纬度和米制深度；`json` 文件名作为稳定来源消息 ID。JMA 没有附带偏移量的时间按 JST 解释，已带 `Z` 或 `±HH:mm` 的时间保留原偏移量。JSON 列表目前只生成事件摘要，不伪造区域、市町村或观测点详情。

非成功 HTTP 不抛到 UI：429 为 `RateLimited`，其他状态为 `Disconnected`；网络异常为 `Disconnected`；JSON 和字段异常为 `ParseFailed`。仓储即使收到空失败结果也只持久化来源状态，继续发布原缓存事件。取消令牌仍向上抛出，用于窗口关闭和刷新取消。

### 10.9 JMA XML 实时详情

`JmaXmlEarthquakeSource` 默认读取 `https://www.data.jma.go.jp/developer/xml/feed/eqvol.xml`。它使用 `System.Xml.Linq` 解析 Atom `entry`，从 `entry/id` 文件名筛选 `VXSE51`、`VXSE52`、`VXSE53`，再下载 `link[type=application/xml]` 指向的报文。每次最多处理 20 个条目，并把文件名作为 `SourceMessageId`、链接作为 `RawMessageUri`，把完整 XML 作为 `SourcePayload`。

详情报文复用 Core 的 `JmaXmlParser`，并注入 `FixedJmaXmlDataLoader.LoadStationCoordinates()` 得到的站点坐标表，因此实时 XML 与固定 XML 具有相同的区域、市町村和观测点字段契约。适配器只依赖 Core 接口和 `HttpClient`，不访问 SQLite 或 WPF。

Feed 或详情 HTTP 429 映射为 `RateLimited`，其他网络/HTTP 失败映射为 `Disconnected`；Feed XML 格式错误或单条详情 XML 解析错误映射为 `ParseFailed`。单条详情失败只记录在 `SourceStatus.Detail`，同一 Feed 的其他成功报文继续写入仓储。仓储按来源分别保存状态，并在任何来源失败时保留已有 SQLite 事件。

`EarthquakeEventMerger` 在事件内排序时加入来源优先级：`jma-json=10`、`jma-xml=20`、其他来源 `0`。因此两个来源在 `IssuedAt`、`Serial` 和 `ReceivedAt` 都相同的情况下，XML 报文成为 `LatestReport`；两个来源的原始报文仍分别保留，逐字段冲突比较留待后续 UI 功能。

## 12. 技术决策记录

### ADR-001：放弃 Tauri/WebView 正式路线

- 日期：2026-08-19。
- 原方案：Tauri 2 + Vue 3 + TypeScript + Rust。
- 原因：用户明确要求不开发网站或 WebView 界面，而是使用应用自带的原生图形界面。
- 处理：`0.1.0` 原型停止开发；相关文件已按用户授权删除，不在其上继续实现地震功能。
- 后续：已在 `0.2.0` 使用清理后的 `src/` 路径建立 WPF 原生外壳。

### ADR-002：采用 C# + .NET 8 + WPF

- 日期：2026-08-19。
- 原因：首发 Windows 10/11；WPF 是成熟的 Windows 原生桌面技术；本机已有完整 .NET 8 SDK 和 Desktop Runtime；界面与后台可以统一使用 C#。
- 代价：正式版本只能运行于 Windows；若未来要求跨平台，需要另行评估 Avalonia，不能直接承诺迁移成本。

### ADR-003：地图使用原生渲染

- 日期：2026-08-19。
- 决策：步骤 8 先使用 WPF 原生 `Canvas`、`Polygon` 和 `Ellipse` 加载本地 GeoJSON；Mapsui WPF + SkiaSharp 保留为后续正式 GIS 资源的评估选项。
- 原因：当前只需展示少量轮廓和事件点，原生控件可在不新增依赖的情况下满足离线、缩放和选择联动。
- 验证门槛：正式引入 JMA 边界前必须验证渲染性能、中文字体、高 DPI、几何许可和行政区域精度。

### ADR-004：文档与实现同步

- 日期：2026-08-19。
- 决策：用户可见功能更新版本记录；工程结构、数据流、依赖或 Bug 修复更新本文档；范围和 UI 变化分别更新需求与 UI 文档。

### ADR-005：领域模型显式保留未知值、时区和来源

- 日期：2026-08-19。
- 决策：震度使用显式 `Unknown`；可缺失数值使用可空类型；时间使用 `DateTimeOffset`；来源原始标识和负载与标准化字段并存。
- 原因：避免未知震度或深度被默认值伪装成真实观测，避免时区转换后无法还原来源时间，并为多源冲突排查保留证据。
- 代价：适配器必须显式处理缺失和未知字段，持久化层必须验证 ISO 8601 往返序列化。

### ADR-006：页面通过仓储接口消费不可变快照

- 日期：2026-08-19。
- 决策：WPF 页面只依赖 `IEarthquakeEventRepository`，仓储返回已合并的不可变事件快照；开发阶段使用内存实现。
- 原因：把页面选择状态与 HTTP、XML、SQLite 生命周期分开，使后续替换数据实现时不重写 ViewModel，并确保所有来源复用同一合并规则。
- 代价：完整快照在大量历史数据下可能产生额外分配；真实缓存接入后必须测量，再决定是否增加分页或增量更新契约。

### ADR-007：SQLite 作为离线缓存而非领域层依赖

- 日期：2026-08-20。
- 决策：新增 `EarthquakeShow.Infrastructure`，使用 `Microsoft.Data.Sqlite` 保存报文、原始 XML 和来源状态；Core 保持纯领域模型，App 只通过 `IEarthquakeEventRepository` 访问缓存。
- 原因：应用必须支持无网络启动和后续历史查询，同时避免数据库类型污染领域层；统一由 `EarthquakeEventMerger` 从缓存报文派生事件，保证内存和 SQLite 行为一致。
- 代价：当前使用完整快照读取，schema 迁移、分页、清缓存和实时刷新需要后续单独设计与验证；缓存损坏时只能回退开发期固定 seed。

### ADR-008：先接入 JMA JSON 摘要，再接权威 XML

- 日期：2026-08-20。
- 决策：步骤 11 首个切片使用无需认证的 JMA `list.json` 打通真实 HTTP、来源状态、刷新和持久化链路；完整区域和观测点继续等待 JMA XML 实时 Feed。
- 原因：JSON 列表数据量小，适合先验证缓存优先启动和失败降级；不应根据摘要源伪造 XML 才提供的报文详情。
- 代价：同一事件仍可能同时存在 `jma-json` 摘要和 `jma-xml` 报文节点；逐字段差异展示尚未完成。

### ADR-009：JMA XML 作为同时间报文的高优先级来源

- 日期：2026-08-20。
- 决策：接入 JMA XML Atom Feed，支持 `VXSE51/52/53`；在事件时间线排序中将 `jma-xml` 排在 `jma-json` 之后，使同一事件、发布时间、报次和接收时间相同时 XML 成为 `LatestReport`。
- 原因：JMA JSON 只提供事件摘要，XML 才包含区域、市町村、观测点和完整原始报文；必须避免摘要覆盖详情。
- 代价：当前只选择来源，不做逐字段冲突可视化；XML Feed 每次逐条下载最多 20 个详情报文，自动轮询和退避留待后续版本。

## 14. 故障排查

### `dotnet` 无法识别 WPF 模板

执行：

```powershell
dotnet new list wpf
dotnet --list-runtimes
```

确认存在 WPF 模板以及 `Microsoft.WindowsDesktop.App 8.x`。当前开发机已经检测到 Windows Desktop Runtime。

### 应用启动后出现控制台窗口

确认 WPF 项目使用 `Microsoft.NET.Sdk` 且 `OutputType` 为 `WinExe`，不要改为 `Exe`。

### 窗口关闭后进程仍然存在

检查后台 `CancellationTokenSource`、定时器、数据源连接和未释放线程。WPF `Application.ShutdownMode` 应保持主窗口关闭时退出，除非未来明确实现系统托盘。

### UI 卡顿

检查是否在 Dispatcher 线程执行网络、XML/JSON 解析、SQLite 或大规模 GIS 处理。用固定样本复现后，将耗时工作移到异步服务，并记录修复前后的测量结果。

### 修改版本号后输出程序集仍显示旧版本

先确认 `Directory.Build.props` 和 `obj/<配置>/<目标框架>/*AssemblyInfo.cs` 已生成新版本号。如果生成文件已更新但 `bin/` 中的 DLL 仍为旧版本，执行一次非增量构建：

```powershell
dotnet build EarthquakeShow.sln --configuration Release --no-restore --no-incremental
```

然后通过文件 `VersionInfo` 或应用底部版本文本再次确认。不要手工修改 `obj/` 中的生成文件。

## 15. Bug 修复记录

### BUG-001：版本文本绑定导致应用启动退出

- 发现日期：2026-08-19。
- 影响版本：`0.2.0` 初始实现。
- 现象：Release 构建成功，但应用在创建主窗口期间抛出绑定异常并终止进程。
- 复现步骤：执行 `dotnet run --project src\EarthquakeShow.App`，加载主窗口底部版本文本时发生异常。
- 根因：WPF `Run.Text` 的默认绑定尝试把目标值回写到只读的 `MainWindowViewModel.AppVersion` 属性。
- 修改位置：`src/EarthquakeShow.App/MainWindow.xaml`。
- 修复方法：将版本绑定显式设为 `{Binding AppVersion, Mode=OneWay}`。
- 回归验证：Release 构建通过；原生窗口成功显示；通过 UI Automation 切换详情标签；关闭窗口后进程正常退出，`dotnet run` 返回代码 `0`。
- 关联版本：`0.2.0`。

### BUG-002：震级 NaN 未被识别为未知值

- 发现日期：2026-08-19。
- 影响版本：`0.3.0` 固定数据校验器初始实现。
- 现象：字段缺失夹具期望震级为未知，但首次校验得到浮点 `nan`，导致预期结果不匹配。
- 复现步骤：在合成 XML 的 `Magnitude` 中使用 `NaN`，执行 `python tools\validate_test_data.py`。
- 根因：Python `float("NaN")` 会成功返回非有限浮点数，不会触发 `ValueError`。
- 修改位置：`tools/validate_test_data.py`。
- 修复方法：数值转换后使用 `math.isfinite()` 检查；非有限值统一转为 `None`。
- 回归验证：离线校验通过，并正确验证缺字段夹具的震级为未知。
- 关联版本：`0.3.0`。

### BUG-003：事件列表转换器资源作用域导致启动失败

- 发现日期：2026-08-19。
- 影响版本：`0.8.0` 事件列表初始实现。
- 现象：解决方案可以编译并通过单元测试，但原生应用加载 `EarthquakeEventListView` 时抛出 `XamlParseException` 并退出。
- 复现步骤：执行 `dotnet run --project src\EarthquakeShow.App --configuration Release --no-build`。
- 根因：独立加载的 `UserControl` 使用 `StaticResource BooleanToVisibilityConverter`，但转换器只定义在父窗口资源中，控件初始化阶段无法解析父级资源。
- 修改位置：`src/EarthquakeShow.App/Views/EarthquakeEventListView.xaml`。
- 修复方法：在事件列表控件自己的资源字典中定义 `BooleanToVisibilityConverter`，使 BAML 独立加载时即可解析。
- 回归验证：Release 构建和 84 个测试通过；原生应用可以启动并显示事件列表空状态。
- 关联版本：`0.8.0`。

### BUG-004：JMA XML Feed 格式错误未映射为来源状态

- 发现日期：2026-08-20。
- 影响版本：`0.14.0` 接入实现期间。
- 现象：JMA Atom Feed 或单条 XML 报文格式损坏时，适配器无法按预期返回 `ParseFailed`，可能把异常直接带到刷新调用方。
- 复现步骤：使用本地假的 HTTP 响应返回未闭合的 `<feed>` 或 XML 报文，并调用 `JmaXmlEarthquakeSource.FetchAsync()`。
- 根因：异常处理沿用了 JSON 适配器的 `System.Text.Json.JsonException`，没有捕获 `System.Xml.XmlException`。
- 修改位置：`src/EarthquakeShow.Infrastructure/Sources/JmaXmlEarthquakeSource.cs`。
- 修复方法：Feed 级别捕获 `XmlException` 并返回 `ParseFailed`；单条报文捕获 `XmlException` 并继续处理同一 Feed 的其他条目。
- 回归验证：新增损坏 Feed 和详情限流测试；Infrastructure 15 个测试全部通过，解决方案 Release 构建无警告。
- 关联版本：`0.14.0`。
