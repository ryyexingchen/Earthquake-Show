# 日本地震信息桌面应用 UI 设计文档

## 1. 文档信息

- 文档状态：Draft 0.2
- 编写日期：2026-08-19
- 依据文档：[日本地震信息桌面应用需求文档](./日本地震信息桌面应用需求文档.md)
- 目标平台：Windows 10/11 优先
- 产品形态：单窗口桌面应用
- 实现技术：C# + .NET 8 + WPF；地图采用原生 Mapsui/SkiaSharp 渲染

## 2. 设计前提

### 2.1 当前假设

1. 首版界面使用简体中文，JMA 地名和原始报文可保留日文原文。
2. 应用以单窗口运行，不为地震、EEW 或海啸分别创建独立系统窗口。
3. MVP 先完整实现地震情报；EEW 和海啸完成后再启用对应导航，不在正式版本中展示无法使用的空入口。
4. NIED/Yahoo 连续逐站震度仅属于研究功能，未完成数据授权评审前不得作为正式实时数据展示。
5. 系统托盘、开机启动和声音提醒不属于当前需求文档中的 MVP，界面中可以预留所属设置分组，但不能默认承诺实现。

### 2.2 设计目标

- 用户打开应用后可以立即看到日本地图、最近事件和数据连接状态。
- 一次选择即可在同一窗口中完成“找到事件、查看地图、核对详情、追踪报文演进”。
- 官方观测、EEW 预测、本地计算和研究推测在文字和视觉上始终可区分。
- 数据断开、字段未知或离线启动时，界面仍然可用且不会显示误导性默认值。
- 常用监看操作保持在主界面，低频配置集中到设置界面。

## 3. 界面数量与导航

完整版本包含 4 个一级界面和 4 类辅助界面。历史事件列表直接属于各业务界面；历史回放是低优先级的独立辅助页面，不占用一级导航。

### 3.1 一级界面

| 编号 | 界面 | 作用 | 计划版本 |
| --- | --- | --- | --- |
| P-01 | 地震情报 | 查看地震事件、区域震度、观测点和报文演进 | MVP |
| P-02 | 实时 / EEW | 查看 EEW 报次、预测区域及 P/S 波估计 | V1 |
| P-03 | 海啸 | 查看海啸警报、预报区、到达时间和观测信息 | V1 |
| P-04 | 设置 | 管理显示、通知、数据源、存储、日志和应用信息 | 分阶段 |

### 3.2 辅助界面

| 编号 | 界面 | 展现方式 |
| --- | --- | --- |
| A-01 | 事件详情 | 主界面右侧固定面板，不跳离地图 |
| A-02 | 搜索与筛选 | 从当前业务界面的事件列表打开的抽屉 |
| A-03 | 历史回放 | 从具体历史事件进入的独立页面，不放入一级导航；低优先级实现 |
| A-04 | 确认与错误详情 | 模态对话框，仅用于清缓存等危险操作或查看完整错误 |

### 3.3 导航规则

- 左侧业务导航依次为：地震、EEW、海啸；只显示当前版本已经可用的业务界面。
- 设置使用左下角齿轮按钮进入，进入后显示独立设置页面。
- 设置页面左上角提供“返回”按钮，返回后恢复进入设置前的页面、事件选择和地图位置。
- 各业务界面的左侧列表同时承载最近事件和本地历史，不额外提供“历史记录”一级页面。
- 历史回放只能从具体事件的报文时间线进入，返回后恢复原事件和地图状态。
- 收到高级别 EEW 或海啸信息时，顶部全局警报条可以引导用户进入对应界面，但不能强制打断用户正在查看的历史事件或历史回放。

## 4. 应用外壳

### 4.1 主窗口布局

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 应用名称 │ 日本时间 │ 数据状态 │ 最后接收 │ 全局警报 │ 搜索 │ 设置 │
├──────────┬────────────────────────────────────┬─────────────────────┤
│ 一级导航 │                                    │                     │
│          │                                    │ 事件摘要 / 区域列表 │
│ 事件列表 │              日本地图               │ 观测点 / 报文时间线 │
│          │                                    │                     │
├──────────┴────────────────────────────────────┴─────────────────────┤
│ 网络/缓存状态 │ 当前来源 │ 地图数据版本 │ 状态说明                  │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.2 尺寸与响应规则

- 推荐默认窗口尺寸：`1440 × 900`。
- 建议最小窗口尺寸：`1180 × 720`。
- 左侧栏建议宽度：`280 px`；右侧详情栏建议宽度：`380 px`。
- 地图始终获得剩余空间，不因列表文本变化而跳动。
- 窗口较窄时，右侧详情收为可展开抽屉；左侧仅在用户主动操作后收起。
- 地图图例、工具栏和状态标签不得互相覆盖。
- 后续可以实现窗口大小可调节，地图缩放，以及地图可以跟着窗口大小自动调节缩放等功能

### 4.3 顶部状态栏

#### 显示内容

- 当前时间，默认格式为 `YYYY-MM-DD HH:mm:ss JST`；用户选择本地时间时必须同步显示时区标识。
- 总体数据状态：在线、部分可用、离线、使用缓存。
- 最近成功接收时间。
- 当前最高全局警报状态。

布局要求：数据状态使用带状态点的紧凑卡片，卡片内以小标题和状态文字两行显示；最近接收时间独立于数据状态卡片；当前时间使用固定高度的时间卡片，避免动态文本挤压搜索和设置按钮。

#### 按钮

| 按钮 | 行为 | 状态要求 |
| --- | --- | --- |
| 搜索 | 打开搜索与筛选抽屉 | 所有业务页面可用 |
| 数据状态 | 打开数据源状态摘要 | 有异常时显示数量标记 |
| 设置 | 进入设置界面 | 返回时恢复现场 |
| 全局警报 | 跳转到对应的 EEW 或海啸事件 | 无警报时不可点击或仅显示“当前无警报” |

### 4.4 底部状态栏

显示网络状态、缓存状态、当前页面使用的数据源、最后同步时间、地图边界数据版本和 WebSocket 通道状态。WebSocket 状态至少显示在线、断开、解析失败和等待重连；等待重连时显示连续重连次数及 JST 下次重试时间，在线或断开时显示连接持续时间，并保留最近错误详情、最近消息活性和累计连接异常次数。当前协议没有独立 heartbeat 时，活性文案必须明确是最近消息年龄。正常状态下保持简洁，错误详情通过点击状态项展开。

布局要求：WebSocket 错误详情使用弹性列并省略显示；自动刷新状态和版本信息使用独立固定宽度列，两者之间保留可视间距，任何状态文本不得覆盖版本文本。

## 5. P-01 地震情报界面

### 5.1 页面目标

让用户快速确认地震发生位置、规模、最大震度、受影响区域、具体观测点以及同一事件的报文演进。

### 5.2 事件列表（最近事件与历史记录）

事件列表同时承担实时更新和历史浏览，交互参考 SREV、JQuake 等常驻监看应用。默认先显示最新事件，并可在同一列表中向下浏览本地缓存的历史事件，不要求用户切换页面。

应用首次启动使用随应用发布的固定样例；已有 SQLite 缓存升级时，按报文身份补入缺失的官方熊本样例报文，避免缓存不为空时页面完全看不到该回归事件。该样例与实时来源事件一样进入事件列表、摘要、地图和报文时间线。

#### 每条事件显示

- 最大震度标记。
- 震源区域名称。
- 震级；未知时显示 `M 不明`。
- 发生时间。
- 海啸状态摘要。
- 最新报文类型和状态，例如“震源・震度情报”“订正”。
- 未读更新标记。

同一 `EventID` 的 `VXSE51`、`VXSE52`、`VXSE53` 必须合并成一个事件，不得因新报文生成重复事件项。

#### 列表按钮

| 按钮 | 行为 |
| --- | --- |
| 刷新 | 请求允许主动刷新的数据源；请求期间防止重复点击 |
| 筛选 | 打开搜索与筛选抽屉 |
| 排序 | 在“最新发生”“最新发布”“最大震度”中选择 |
| 加载更早记录 | 从本地缓存读取更早事件；没有更多缓存时隐藏或禁用 |

#### 列表交互

- 单击事件：选中事件，更新地图和右侧详情。
- 键盘上/下键：切换事件；Enter：聚焦详情。
- 新报文到达时更新原事件，并保持用户当前选择；除非用户开启“跟随最新事件”。
- 用户正在查看历史事件时，新事件只增加列表标记和全局提示，不自动改变地图和详情。

### 5.3 地图

#### 地图图层

1. 日本行政或 JMA 区域边界。
2. 按区域最大观测震度着色的区域层。
3. 震源标记。
4. 观测点标记：只显示当前报文中实际观测到震度且有坐标的观测点，使用震度颜色。
5. 地名和必要的海岸线底图。

区域配色只使用已经发布的观测震度，不根据震级自行推测。十档震度使用统一高饱和度色板；浅色等级使用深色边框和文字，深色等级使用浅色边框和白字。

`0.32.0` 在 `0.31.5` 的基础上将观测点详情实现为 `区域 → 市町村 → 观测点` TreeView，按代码挂接并保留未映射节点；支持递归搜索、最高震度筛选、展开全部、折叠全部和地图定位。`0.33.0` 接入 JMA 市町村概览边界，市町村节点和地图市町村震度面使用同一代码匹配和包络中心。震度速報即使当前报文没有震源和观测点，只要有区域或市町村图层，地图也会定位到事件范围中间。当前报文没有坐标的观测点不绘制，地图不因完整目录增加数千个标记；完整目录仅用于 JMAXML 解析和旧缓存坐标补全。观测点边框根据震度颜色亮度选择深灰或白色，保证浅色和深色点在地图底图上都清晰可见。

`0.34.0` 已将区域面填充改为拓扑去重后的区域边界：共享边界按相邻区域最大震度取色，外边界按唯一相邻区域取色；区域内部由市町村震度填充，未知市町村不填充。市町村有震度时使用深色/黑色边界，无震度时恢复中性边界。`0.34.1` 关闭正式拓扑边界存在时区域 Polygon 的重复 Stroke，区域边界线宽调整为 `1.8`，并加深震度 1/3 配色，减少错位双线和低震度边界不清的问题。`0.33.1` 已完成从 JMA 原始 ZIP 生成带 `areaCode1/areaCode2` 相邻代码的 LineString 候选资源，`0.33.2` 已确认开放端点全部是正常三叉交汇节点，`0.33.3` 已完成 App 解析和区域索引，`0.33.4` 已完成 ViewModel 的边界震度分组，`0.33.5` 已完成按震度组的 WPF 边界线绘制，`0.34.0` 已完成区域面移除和市町村有效震度填色；真实启动性能和人工截图验证仍待完成。

#### 地图按钮

| 按钮 | 行为 |
| --- | --- |
| 放大 | 放大一级 |
| 缩小 | 缩小一级 |
| 日本全图 | 恢复默认中心和缩放级别 |
| 定位震源 | 将当前事件震源置于地图中心 |
| 图层 | 打开图层菜单 |
| 全屏地图 | 暂时收起左右栏；再次点击或按 Esc 恢复 |

`0.37.0` 起，地图支持在画布上按住鼠标左键拖动平移，使用鼠标滚轮以指针所在地图坐标为中心缩放。手动平移或缩放后暂停自动跟随；点击跟随所选事件按钮、点击日本全图或定位震源时恢复相应的地图视角。跟随视角以震源为中心，围绕震源保留约 6% 边距，并按事件图层包络自适应缩放。

`0.38.0` 起，摘要栏底部提供与时间线一致的“上一报”“下一报”和“返回最新”按钮。按钮只切换当前事件的报文快照，不创建独立选择；摘要、时间线、地图和观测点树必须同步更新。首报禁用上一报，最新报禁用下一报，查看非最新报文时启用返回最新。

`0.38.1` 起，时间线中的报文卡片默认横向占满详情栏可用宽度；卡片不因事件字段长度不同而缩短或撑宽，横向滚动被关闭，长文本继续按字段规则省略或换行。

`0.39.0` 起，地图根据缩放级别切换显示几何：启动和 `ZoomLevel <= 2` 使用低内存概览层，放大到 `ZoomLevel > 2` 后异步加载同源 `0.003°` 中精度区域、市町村和区域边界；加载期间保留当前地图，缩回时恢复概览，失败时不清空地图。该切换只改变显示细节，不改变事件、报文、区域代码和观测点数据。高精度全量资源暂不在运行时加载。

步骤 8 的首版实现使用随应用打包的非官方示意轮廓和 WPF 原生 Canvas；状态栏明确显示“离线示意”。该资源仅用于确认页面布局、事件图层和交互，不用于行政边界或区域归属判断。正式 JMA GIS 边界接入前，地图按钮不提供在线底图或空间查询。`0.29.7` 已完成原始包用途审计，具体图层选择见 [JMA GIS 地图资源清单](./JMA%20GIS地图资源清单.md)。

#### 图层菜单

- 区域震度：默认开启。
- 观测点：有观测点数据时默认开启。
- 震源：默认开启，不能与观测点使用相同图标。
- 地名：默认开启。
- 震度图例：默认开启，使用紧凑竖向十档：不明、1、2、3、4、5-、5+、6-、6+、7。标签使用 `5-`、`5+`、`6-`、`6+`，颜色沿用项目震度定义，不采用中国烈度分级。

#### 地图点选

- 点选震源：打开震源摘要。
- 点选区域：显示区域最大震度及包含的市町村数量。
- 点选观测点：显示名称、编码、所属区域、震度、来源和发布时间。
- 多个点重叠时显示可选择列表，不允许随机选择其中一个。

### 5.4 右侧事件详情

右侧使用 4 个标签页。

#### 摘要

- 最大震度。
- 震源名称。
- 发生时间、发布时间、接收时间。
- 经纬度、深度、震级和震级类型。
- 海啸评论。
- 发布机构、当前显示值的来源。
- 同一事件存在多个来源时，在摘要下方显示来源差异：来源 ID、来源角色、消息 ID，以及状态、震度、震级、震源、深度和观测点数量差异。
- 订正、取消、训练、测试等状态。

按钮：

- `定位震源`：地图居中到震源。
- `复制事件 ID`：复制统一事件 ID。
- `打开原始电文`：使用系统浏览器打开来源链接，并用外部链接图标表明将离开应用。

#### 区域与观测点

- 使用三层树结构：`区域 → 市町村 → 观测点`；区域和市町村节点显示最大震度与子项数量，观测点节点显示具体震度、编码和坐标状态。
- 默认展开有观测结果的区域，其他节点可折叠；同一观测点只能出现在一个代码确定的父级路径下。
- 支持在当前事件内按都道府县、区域、市町村、观测点名称或代码递归搜索；父节点保留匹配后代的上下文。
- 无坐标的观测点仍保留在树中，并显示“地图位置未知”；区域或市町村无法匹配地图几何时显示“地图区域未知”。
- 选择区域或市町村时定位真实地图几何，选择观测点时定位站点；无坐标或无几何时定位按钮禁用并说明原因。
- 无法通过代码挂接的记录进入“未映射”分组，不根据名称或数组顺序猜测父级。

按钮：

- `展开全部` / `折叠全部`。
- `仅看最高震度`。
- `定位所选项`，无坐标时禁用并说明原因。

#### 报文时间线

每条报文显示报文类型、报次、发布时间、接收时间、状态、来源和相对上一报的字段变化。

变化规则：缺失字段不显示变化，也不能把已收到的值变成“不明”；首次收到字段时只显示当前值，实际值变化时显示 `旧值 → 新值`，相同值或当前报文缺失时继续显示累计原值，不显示箭头；从未收到的非海啸字段不显示，海啸行保留“津波 调查中”。震度更新报如果此前已经收到震源情报，继续显示累计的震级、深度、震源地和海啸状态。摘要查看某一报时沿用从首报到当前报已收到的字段，海外地震只显示可用要素。

摘要中的关键字段逐行显示，顺序为最大震度、震源地、震级、深度、海啸；震度速报在最大震度后显示“震源・规模 调查中”。最大震度和时间线最大震度变化使用与地图图例一致的十档颜色，深色等级使用白字。时间线按最大震度一行、震级/震源地/深度一行、海啸一行排版。没有海啸说明时显示“津波 调查中”；收到后显示“津波の心配なし”（灰/透明）、“若干の海面変動”（蓝）、“津波注意報”（黄）、“津波警報”（红）或“大津波警報”（紫）。

按钮：

- `上一报`、`下一报`：切换当前事件的地图和详情快照；摘要栏和时间线共用同一组 ViewModel 状态。
- `返回最新`：退出历史快照并显示最新报文。
- `查看原始数据`：切换到原始数据标签。

### 9.5 数据源设置与诊断

MVP 不向用户提供随意填写未知 API 地址的功能，避免引入不受支持的数据格式和安全风险。页面只管理应用内置适配器。

#### 数据源列表字段

- 数据源名称和用途。
- 官方/第三方属性。
- 当前角色：主源、补充源、降级源、研究源。
- 当前状态：在线、延迟、断开、限流、解析失败、已停用。
- 最近成功时间。
- 最近错误摘要。
- 当前重连次数或下次重试时间。

#### 每个数据源的操作

| 按钮 | 行为 |
| --- | --- |
| 立即检查 | 执行一次轻量健康检查，防止连续重复点击 |
| 重新连接 | 仅对 WebSocket 等长连接显示 |
| 查看详情 | 显示地址类别、限流、用途、最近错误和条款链接 |
| 查看来源条款 | 使用系统浏览器打开条款页面，并显示外部链接图标 |

MVP 的数据源状态页以诊断为主，不提供启用、停用或调整优先级的控件。后续只有在出现明确的可选数据源使用场景时，才为可选补充源增加开关；必要主源始终由应用按降级策略管理。

#### P2PQuake WebSocket 连接策略

当前版本在数据源设置中提供两个受约束的选项：传输层 keep-alive 为 `10–120` 秒，单连接最大持续时间为 `1–9` 分钟，默认分别为 `30` 秒和 `9` 分钟。点击“应用并重新连接”后立即写入独立设置文件并重建当前 WebSocket 流；HTTP 刷新、SQLite 缓存和当前地震情报页面现场不重置。设置文件损坏或超出范围时回退默认值并显示警告。应用层 heartbeat 仍不在设置页提供。

#### 数据源优先级

- 官方 JMA 值优先于第三方转发值。
- 当前 JMA 内部优先级为：XML 详情（`jma-xml`）高于 JSON 摘要（`jma-json`）；同时间同报次时显示 XML，并在时间线保留 JSON 节点。
- P2PQuake 作为补充/降级源（`p2pquake`），低于所有 JMA 来源；其独立事件标识和非官方属性必须在来源栏显示。
- 用户可以查看优先级，但 MVP 不允许自由拖拽改写冲突规则。
- 发生冲突时不取平均值或最大值，详情中保留来源差异。

#### 研究数据源

NIED/Yahoo 研究源放在独立折叠区，默认停用，并显示“研究用途・非正式数据”。没有完成许可评审的发布版本不提供启用入口。

#### 显示信息

- 已缓存事件数量。
- 原始响应占用空间。
- 日志占用空间。
- 缓存目录和日志目录。
- 最早/最新缓存时间。

#### 设置项与按钮

| 项目 | 行为 |
| --- | --- |
| 打开缓存目录 | 使用系统文件管理器打开应用缓存目录 |
| 打开日志目录 | 使用系统文件管理器打开日志目录 |
| 清除事件缓存 | 二次确认；说明事件和原始响应将被删除 |
| 清除日志 | 二次确认；不影响事件缓存和设置 |
| 导出诊断信息 | 导出不包含账号、位置或密钥的状态与错误摘要 |

清除操作结束后显示实际删除内容和释放空间；失败时说明哪些内容未删除。应用设置不能随着事件缓存一起被清除。

MVP 固定保存最近 100 个事件，不把尚未支持修改的上限伪装成设置项。清除事件缓存后，如果当前正在查看缓存事件，界面返回无事件状态并保留地图和数据源状态。

### 10.1 使用场景

- 在当前业务页面过滤同一列表中的最近事件和本地历史记录。
- 筛选只影响当前业务类型；跨类型查找通过切换地震、EEW 或海啸界面完成。

### 10.2 快速筛选字段

筛选项根据当前业务界面变化，不显示对当前类型无意义的输入框。

| 适用界面 | 筛选字段 |
| --- | --- |
| 全部业务界面 | 时间范围、关键字、数据来源、事件状态 |
| 地震情报 | 最低最大震度、最低震级、震源区域 |
| EEW | 预报/警报、是否最终报、是否取消、是否训练 |
| 海啸 | 最低警报级别、是否解除、预报区 |

### 10.3 按钮

- `应用`：刷新当前事件列表。
- `重置`：清除快速筛选。
- `关闭`：不修改当前筛选。

## 11. 全局状态与反馈

### 11.1 数据类型标识

| 数据性质 | 固定文字标识 | 要求 |
| --- | --- | --- |
| 官方观测 | JMA 官方观测 | 地震和海啸正式值优先使用 |
| 上游预测 | EEW 预测 | 不得写成已经观测到的震度 |
| 本地计算 | 本地计算估计 | 用于 P/S 波圈等计算结果 |
| 研究推测 | 非官方推测 | 与正式信息分层且默认关闭 |

颜色只作为辅助编码，所有状态必须同时有文字或图标。

### 11.2 通用状态

- `加载中`：使用不改变布局尺寸的占位内容。
- `无数据`：说明是没有事件、筛选无结果还是来源未返回数据。
- `离线`：显示缓存时间和当前仍可进行的操作。
- `限流`：显示下一次允许重试时间，不提供连续刷新按钮。
- `解析失败`：保留上一份有效数据，并允许查看错误详情。
- `未知字段`：显示“不明”。
- `操作成功`：使用短暂状态提示，不阻塞地图操作。
- `危险操作`：使用确认对话框，并明确影响范围。

### 11.3 全局警报条

- 普通状态不占用大面积空间。
- 新 EEW 警报或海啸警报到达时显示事件类型、区域、级别和发布时间。
- 提供 `查看详情` 和 `收起`。
- 收起只折叠横幅详情；顶部必须继续保留当前警报级别和未解除状态，直到警报解除或失效。
- 训练和测试报必须使用不同样式，且文案包含“训练”或“测试”。

## 12. 可访问性与键盘操作

- 所有按钮具有可见焦点和名称；图标按钮提供工具提示。
- 状态不能只依赖颜色，震度和警报级别同时显示文字。
- 地图信息在区域/观测点列表中提供等价内容。
- `Ctrl+F` 打开搜索抽屉，`Esc` 关闭抽屉或退出地图全屏。
- 上/下键切换事件，Enter 打开详情。
- 不全局占用操作系统或辅助技术常用快捷键。
- 动画遵循系统减少动态效果设置；用户可以暂停波前动画。

## 14. UI 验收检查表

1. 应用启动后无需打开浏览器即可看到日本地图、最近事件和数据状态。
2. 完整版本可以在一个窗口内切换地震、EEW、海啸和设置 4 个一级界面；未实现的业务入口不会显示为可用导航。
3. 同一事件的多份报文只生成一个事件项，并能在时间线逐份查看。
4. 震源、区域震度和观测点可以在地图与等价列表中查看。
5. 离线启动时能查看缓存，并明确显示缓存时间和离线状态。
6. EEW 的预测、本地波前计算和 JMA 正式观测具有不同文字标识。
7. 取消 EEW 后波前动画停止，历史报文仍可查看。
8. 海啸更新和解除修改原事件，时间线保留此前状态。
9. 数据源异常时页面保留上一份有效数据，并显示降级状态。
10. 未知字段显示“不明”，训练、测试、订正、取消和最终报均有显式标签。
11. 清除缓存和日志等操作有明确范围和二次确认。
12. 所有主要地图信息都有列表替代，键盘可以完成事件选择和详情查看。
13. 最近事件和历史地震可在地震情报页面的同一列表中浏览，不需要切换到独立历史页面。
14. 用户查看历史事件时，新事件不会自动替换当前地图和详情，除非主动开启跟随最新事件。

## 15. 首个 UI 实现切片

为控制首轮实现复杂度，建议第一个可运行版本只完成以下闭环：

1. 单窗口外壳、顶部状态栏和左侧导航。
2. 使用固定样本显示最近地震事件列表。
3. 在日本地图显示震源、区域震度和观测点。
4. 在右侧显示摘要、观测点和报文时间线。
5. 设置页面先实现主题、时间显示、数据源状态和关于信息。
6. 覆盖加载、无事件、选中事件和离线缓存四种界面状态。

该切片可以验证核心信息架构和地图交互，同时不会提前依赖实时 API、通知系统或尚未获授权的连续逐站数据。
