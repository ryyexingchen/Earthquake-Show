# 实时地震监测页面功能需求

## 1. 文档信息

- 文档状态：Draft 0.1
- 编写日期：2026-09-01
- 适用页面：P-02 实时 / EEW
- 依据文档：[日本地震信息桌面应用需求文档](./日本地震信息桌面应用需求文档.md)、[日本地震信息桌面应用UI设计文档](./日本地震信息桌面应用UI设计文档.md)、[数据契约与格式](./数据契约与格式.md)
- 目标平台：Windows 10/11 桌面应用
- 术语说明：本文的“实时”指收到上游报文后尽快更新页面，不表示上游数据零延迟；“EEW”指紧急地震速報预测报文；“观测”指 JMA 发布后的震度结果。

本文是实时监测页面的长期功能基线。实现、测试或发现缺陷后，应优先更新本文对应章节，再更新工程实现文档和数据契约；不能只修改界面而不记录行为变化。

## 2. 目标与边界

### 2.1 页面目标

用户打开页面后，应在一个窗口内完成以下任务：

1. 判断当前是否存在有效的 EEW、最高警戒级别和最新报次；
2. 查看当前预测震源、预测震度和警报区域；
3. 观察 P 波、S 波传播估计的当前范围，并知道其为本地计算结果；
4. 查看同一事件的报文演进、订正、最终报和取消报；
5. 在实时事件和已缓存事件之间切换，不丢失当前查看上下文；
6. 判断数据来自哪个来源、是否延迟、是否处于离线或降级状态。

### 2.2 与其他页面的边界

| 页面 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 地震情报 P-01 | JMA 震度速報、震源情报、震源/震度情报及事后观测 | 连续逐站实时加速度、EEW 波前动画 |
| 实时 / EEW P-02 | EEW 报次、预测震度、警报区域和波前估计；连续全国逐站震度 | 用事后观测替代缺失的 EEW |
| 海啸 P-03 | 海啸预报、注意报、警报、观测和解除 | 将海啸等级推断为地震预测结果 |
| 设置 P-04 | 来源、刷新、显示、缓存和通知策略 | 直接修改事件或报文数据 |

### 2.3 明确不承诺的能力

- 没有获得稳定、合法、全国覆盖的逐站实时数据前，不显示“连续实时震度”作为正式功能。
- 不使用 P-01 的事后观测填充 P-02 的预测字段。
- 不把本地计算的波前、震源或预测震度标为 JMA 官方值。
- 不提供生命安全、避难、交通控制或设备控制的唯一决策依据。

## 3. 使用场景

| 场景 | 用户操作 | 必须得到的结果 |
| --- | --- | --- |
| 正常监看 | 打开应用并停留在 P-02 | 自动显示最新 EEW 事件和报次，页面持续更新 |
| 新报到达 | 收到同一事件的新 Serial | 原事件更新，不产生重复事件；地图、摘要、时间线同步 |
| 高级别预警 | 收到警报或高预测震度 | 顶部全局警报条和事件列表立即突出，但不强制抢走用户正在看的历史事件 |
| 查看旧报 | 点击时间线中的旧报 | 地图、预测区域和摘要切换到该报快照，波前保持静态 |
| 断线 | EEW WebSocket 断开 | 显示来源异常、重连倒计时，并保留最后快照 |
| 离线启动 | 无网络启动 | 显示本地缓存的 EEW 历史，明确标注缓存时间和离线状态 |
| 恢复连接 | 网络恢复 | 先补取缺失报文，再恢复实时订阅；按身份去重，不重复弹出事件 |
| 取消/最终报 | 收到取消或最终报 | 停止相关动画，保留完整时间线并显示最终状态 |
| 训练/假定 | 收到训练或假定震源 | 使用独立标签和视觉样式，不触发正式警报样式或通知 |

### 4.1 主窗口结构

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 应用名称 │ 日本时间 │ EEW来源状态 │ 最近接收 │ 全局警报 │ 搜索 │ 设置 │
├──────────┬────────────────────────────────────┬─────────────────────┤
│ 一级导航 │                                    │                     │
│ 地震     │                                    │ 当前报摘要          │
│ 实时/EEW │             实时 EEW 地图           │ 预测区域 / 警报区域  │
│ 海啸     │                                    │ 报文时间线 / 原始数据│
│          │                                    │                     │
│ EEW事件列表                                    │                     │
├──────────┴────────────────────────────────────┴─────────────────────┤
```

### 4.2 尺寸和响应

- 默认窗口尺寸 `1440 × 900`，最小尺寸 `1180 × 720`。
- 左侧事件列表建议 `280 px`，右侧详情建议 `380 px`；地图占据剩余宽度。
- 地图、列表和详情的宽度不能因动态文本改变；长文本在详情栏内换行或省略。
- 窗口较窄时，右侧详情收为抽屉；实时状态栏和全局警报条仍保持可见。
- 全局警报条不得遮挡地图控制、图例或详情标签。

## 5. 顶部和底部状态栏

### 5.1 顶部状态

必须显示：

- 当前时间，默认 `YYYY-MM-DD HH:mm:ss JST`；切换本地时区时必须带时区标识；
- EEW 来源状态：在线、延迟、断开、等待重连、限流、解析失败、已停用；
- 最近成功接收时间和消息年龄；
- 当前最高有效 EEW 状态：无警报、预报、警报、训练、假定、已取消；
- 当前页面是否跟随最新事件。

状态只用颜色是不充分的，必须同时显示文字和状态点。状态项可点击打开来源诊断抽屉。

### 5.2 底部状态

- WebSocket 当前状态、连续重连次数、下次重试时间；
- HTTP 补取状态和最近一次补取范围；
- 当前波前动画状态：运行、暂停、已取消、历史静态、计算不可用；
- 本地缓存状态、最新缓存时间和地图数据版本；
- 最近错误摘要；完整异常通过诊断抽屉查看。

## 6. EEW 事件列表

### 6.1 事件身份和排序

- 事件主键为上游 `EventID`，报次由 `Serial` 表示；事件列表只能出现一条事件代表项。
- 同一事件收到新报时更新代表项，完整报次进入该事件的时间线。
- 默认按“最新发布时间”倒序；可切换“发生时间”“最大预测震度”“状态优先级”。
- 旧报不得覆盖新报；Serial 相同但来源不同的消息按来源身份去重。
- 用户查看历史事件时，新事件只更新未读标记和全局提示；开启“跟随最新事件”后才切换选择。

### 6.2 事件卡片字段

每条事件至少显示：

- 状态标签：预报、警报、最终、取消、训练、假定；
- 当前报次，如 `第 3 报`；
- 震源地、发生时间；
- 最大预测震度；未知显示“不明”；
- 是否最终报、是否取消；
- 发布时间、接收时间或消息年龄；
- 数据来源标识；多来源合并时显示“多源”。

最大预测震度使用与 P-01 一致的十档震度色板；深色背景使用白字，浅色背景使用深色字，并同时显示文字等级。

### 6.3 列表操作

| 操作 | 行为 |
| --- | --- |
| 单击事件 | 选中事件，更新地图和详情 |
| 上/下键 | 切换事件；选择变化不启动历史波前动画 |
| Enter | 将焦点移入右侧详情 |
| 刷新 | 请求允许主动刷新的来源；期间禁用重复点击 |
| 筛选 | 按状态、时间、预测震度、震源区域、来源筛选 |
| 排序 | 在发生时间、发布时间、预测震度、状态优先级间切换 |
| 返回最新 | 选择最新有效报次并恢复自动跟随 |
| 加载更早记录 | 从 SQLite 读取更早的缓存事件 |

## 7. 实时 EEW 地图

### 7.1 图层顺序

从底到顶固定为：

1. 日本及周边海域底图；
2. 行政/预报区域边界；
3. EEW 警报区域；
4. 区域预测震度面；
5. P 波估计波前；
6. S 波估计波前；
7. 官方预测震源；
8. 本地推测图层（默认关闭）；
9. 选中对象高亮和标签。

图层顺序必须保证震源和选中高亮不被区域填充遮挡；预测和推测使用不同线型、颜色和图例。

### 7.2 图层语义

- 警报区域：来自上游 EEW 报文，不根据震级或距离自行扩大。
- 区域预测震度：来自上游预测值；未知区域不着色，不使用事后实测值替换。
- P/S 波前：本地计算的传播估计，必须在图例和详情中标注“计算估计”。
- 震源：使用独立图标；官方预测震源与本地推测震源不可使用相同图标。
- 观测点：P-02 默认不显示连续逐站观测点；若未来启用实验图层，必须显示“研究数据/非官方”标签并默认关闭。

### 7.3 地图交互

- 鼠标左键拖动平移，滚轮以指针位置为锚点缩放；缩放和拖动不改变事件选择。
- `放大`、`缩小`、`日本全图`、`定位震源`、`跟随最新`、`图层`、`全屏地图`按钮与 P-01 保持一致。
- 点击警报区域显示区域名称、警报级别、预测震度、报次和来源；点击震源显示震源详情。
- 波前动画运行时地图视角默认跟随当前事件包络；用户手动拖动/缩放后暂停自动跟随。
- 无有效震源坐标时不绘制波前，地图保留区域预测图层并说明“震源坐标未知”。
- 当前报文切换、地图精度异步切换和刷新不得重置用户视口，除非用户主动点击定位或日本全图。

### 7.4 波前计算规则

- 输入至少包括震源经纬度、深度、发生时间、当前时间和选定走时模型。
- P 波和 S 波使用独立传播速度/模型参数；参数版本和计算基准时间必须可见。
- 波前只表示估计到达范围，不表示实际地震动强度或安全边界。
- 发生时间、震源或深度更新时重新计算；仅状态字段变化时不重复计算。
- 计算必须在后台线程执行，取消、切换事件或报次时取消旧任务。
- 暂停页面动画不停止数据接收；切回最新时以当前时间重新计算。
- 取消报、最终报或切换到历史报时停止动画计时器，保留最后一帧或静态波前。

## 8. 右侧详情

右侧详情使用固定宽度的标签页：`摘要`、`预测区域`、`时间线`、`原始数据`。

### 8.1 摘要

按以下顺序逐行显示：

1. 状态和报次；
2. 最大预测震度；
3. 震源地；
4. 震级；
5. 深度；
6. 经纬度；
7. 发布时间、发生时间、接收时间；
8. 最终/取消/训练/假定/精度标记；
9. 数据来源和原始消息身份。

字段缺失时显示“不明”或隐藏，具体按数据契约；不能显示 `0`、空字符串或把缺失预测值当成观测值。摘要底部提供 `上一报`、`下一报`、`返回最新`，与时间线共用同一选择状态。

### 8.2 预测区域

每行显示：区域名称、预测震度、是否警报区域、预测到达状态（如有）、报次和来源。支持按预测震度、警报状态筛选和按震度降序排序。选择行后地图定位并高亮；无地图几何时保留列表并说明“地图区域未知”。

### 8.3 时间线

每个节点显示：报文类型、报次、状态、发布时间、接收时间、来源和相对上一报的变化。

- 首次出现的字段只显示当前值；
- 值发生变化显示 `旧值 → 新值`；
- 相同值、缺失值或未变化值不显示箭头；
- 不能把已收到的值重置为“不明”；
- 报次按 `IssuedAt → Serial → ReceivedAt → Source` 稳定排序；
- 用户主动点击旧报后，摘要、预测区域、地图和波前全部切换到该报快照；
- 历史报文不运行动画，只显示静态计算结果或“未计算”。

### 8.4 原始数据

- 默认显示结构化摘要；可切换原始 XML/JSON 和标准化 JSON；
- 原始数据只读，不执行脚本；
- 支持复制、自动换行和打开来源链接；
- 显示来源、消息 ID、抓取时间和校验/解析状态；
- 原文缺失时显示“原始内容未缓存”，不能伪造空 JSON。

## 9. 报文处理和事件状态机

### 9.1 接收类型

正式接入的 EEW 适配器以 Wolfx JMA EEW WebSocket 为主，HTTP 用于启动和断线补取；具体字段以数据契约定义为准。至少兼容：预报、警报、最终、取消、训练、假定震源和未知扩展字段。

### 9.2 状态优先级

事件状态按以下规则解释：

1. 取消报优先显示“已取消”，但不删除此前预测；
2. 最终报显示“最终报”，停止波前动画；
3. 训练/假定始终保留独立标签，不升级为正式警报；
4. 警报高于普通预报；
5. 未知状态保留原始值并显示“未知状态”，不得静默归入普通预报。

### 9.3 旧报保护

- 以 `EventID + Serial` 作为事件内排序身份；
- 同一身份重复收到时只更新接收时间/来源状态，不新增时间线节点；
- Serial 较小的迟到报文不能覆盖当前最新快照；
- 跨来源合并须同时满足事件时间、坐标和震级阈值；无法确认时保留独立来源记录并在详情显示差异。

## 10. 实时刷新、离线与恢复

### 10.1 正常刷新

- WebSocket 接收线程只负责读取、校验和发布标准化报文；
- UI 线程消费不可变快照，单次批量更新列表、地图和详情；
- 收到报文后目标是 1 秒内完成页面更新；
- 同一报文重复推送不得造成列表闪烁、重复声音或重复时间线节点。

### 10.2 断线和限流

- WebSocket 断开后使用指数退避并显示重连次数和下次重试时间；
- HTTP 补取和 WebSocket 连接必须遵守来源限流，禁止并发建立多个生产连接；
- 429、超时、DNS/网络错误、TLS 错误和解析错误分别记录诊断原因；
- 单一来源失败不得清空已有事件或阻断其他来源；
- 连续失败达到阈值后显示“来源不可用”，仍保留缓存页面。

### 10.3 离线启动和回补

- 启动顺序：读取本地快照 → 显示缓存页面 → 后台连接来源；
- 以 SQLite 中各来源最新 `IssuedAt` 为增量起点；
- 恢复后优先补取起点之后的所有可用报文，再切换到实时订阅；
- 补报按消息身份去重并保持原始发布时间；
- 上游覆盖不足时在来源状态中说明“无法保证完整回补”，不能假装没有缺报；
- 网络恢复不强制改变用户正在查看的历史事件，除非开启自动跟随。

## 11. 设置项

设置页按以下分组提供选项，所有设置都持久化到独立 settings 文件：

### 11.1 数据源

- 启用/停用 Wolfx EEW WebSocket；
- 启用/停用 HTTP 补取；
- P2PQuake 是否作为补充源（默认按全局策略关闭或只读）；
- 连接超时、重试上限和轮换周期（提供推荐值，普通用户不必修改）；
- 来源和地图数据版本查看。

### 11.2 显示和跟随

- 默认打开页面；
- 自动跟随最新事件；
- 是否显示 P 波、S 波、预测区域、警报区域和标签；
- 波前动画开关和帧率档位；
- 时间显示时区；
- 地图默认缩放和低内存模式。

### 11.3 通知

- 是否显示桌面通知；
- 触发级别（警报、预测震度阈值、仅状态变化）；
- 训练/假定事件是否通知（默认关闭）；
- 声音资源和音量（资源缺失时不阻塞页面）。

### 11.4 缓存和诊断

- 保留事件数量和原始报文开关；
- 查看缓存目录、日志目录和来源诊断；
- 清除缓存前必须二次确认，并明确设置文件不会被删除；
- 导出诊断包时去除用户本地路径之外的个人信息。

## 12. 异常、可访问性与合规

- 任何状态不能只依赖颜色；每个等级必须同时有文字、图标或纹理差异。
- 支持键盘导航、事件列表上下移动、时间线切换和 Esc 关闭抽屉。
- 地图中的信息必须能在预测区域表格和摘要中等价获取。
- 来源异常、字段缺失、坐标未知、计算失败和缓存过期必须分别表述。
- 页面及“关于”中显示 JMA、Wolfx、P2PQuake 和地图数据来源、使用条件及免责声明。
- XML/JSON 只作为数据解析，不执行其中脚本或动态内容；来源链接使用外部浏览器打开前明确提示。

## 13. 性能、资源和生命周期

- 常驻监测时 UI 线程不得执行网络、XML 解析、数据库写入或波前计算。
- 默认只绘制当前事件和当前报次图层，历史报文按需加载；
- 地图继续使用现有低/中精度 LOD 和可取消异步加载；实时页面不得强制加载高精度全量地图；
- 波前动画在窗口最小化、页面不可见或用户暂停时降低或停止绘制，但后台接收继续；
- 单次刷新必须释放旧的取消令牌、计时器、事件订阅和临时几何，防止后台任务挂起和内存增长；
- 目标基线：空闲页面内存增长趋近于零；连续监测 30 分钟无持续线性增长；收到重复报文不造成集合无限增长；
- 列表、时间线和地图使用不可变快照替换，避免 UI 线程与后台线程共享可变集合。

## 14. 数据存储和日志

- SQLite 保存事件、报文、标准化字段、原始内容（按设置决定）和来源身份；
- 事件与报次必须支持按 `EventID + Serial + SourceId + SourceMessageId` 查询；
- 诊断日志记录连接状态变化、重连、限流、解析失败、补报范围、去重结果和波前计算失败；
- 日志不得记录 API 密钥（当前不需要）或无关个人信息；
- 版本升级先更新数据契约，再实现迁移；未知 schema 版本不得静默读取。

## 15. 测试需求

### 15.1 单元测试

- EventID/Serial 身份和重复报去重；
- 旧报不能覆盖新报；
- 预报、警报、最终、取消、训练、假定状态映射；
- 缺失字段、未知枚举和扩展字段处理；
- 跨报次累计字段和变化箭头；

- 预测震度颜色、深浅色文字和未知值显示；
- 增量补报起点、回补去重和排序；
- 来源状态到页面文案的映射。

### 15.2 集成测试

- Wolfx WebSocket 报文进入仓储、事件合并和 ViewModel；
- WebSocket 断线后 HTTP 补取再恢复订阅；
- 同一事件多来源到达不产生重复列表项；
- 取消/最终报停止动画且时间线完整；
- 离线启动、恢复连接和缓存回补；
- 页面刷新期间保持事件、报次和地图视口选择。

### 15.3 手动验收

- 使用固定发布、警报、最终、取消、训练、假定样例逐项确认视觉标签；
- 连续拖动/缩放地图，确认波前和区域不越界、视口不乱跳；
- 运行 30 分钟并观察进程、句柄、线程和内存趋势；
- 断网、限流、解析错误和恢复场景均能继续查看缓存；
- 窄窗口、键盘操作、深色等级白字和无障碍等价信息均可用。

## 16. 验收标准

1. 页面可在不打开浏览器或本地 Web 服务的情况下启动并显示缓存/实时状态。
2. 同一 `EventID` 的所有 Serial 只形成一条事件卡片，时间线完整且顺序稳定。
3. 新报到达后 1 秒内同步更新列表、摘要、预测区域、地图和状态栏。
4. 预测值、观测值、本地波前计算和研究推测在文字、颜色、图例和原始来源上均可区分。
5. 旧报、最终报和取消报不会被迟到消息覆盖；取消/最终后动画停止。
6. WebSocket 断线、429、超时和解析错误不会导致应用退出或清空现有数据。
7. 网络恢复后能够按最新缓存时间补取可用报文，并对覆盖不足给出明确提示。
8. 手动拖动/缩放后不会自动抢回视角；点击跟随或定位按钮后恢复预期视角。
9. 页面在 30 分钟连续运行中无可观察的任务、计时器、订阅或内存持续泄漏。
10. 所有关键行为有固定样例测试或可重复的手动验收记录。

## 18. 依赖、真实数据和未决事项

- 需要至少一组 Wolfx JMA EEW 的真实或脱敏固定报文，覆盖预报、警报、最终、取消、训练和假定字段；如果无法提供，应从公开样例或已授权抓包中建立固定测试样例。
