# Earthquake Show 数据契约与格式

## 1. 文档用途

本文档长期记录应用内部领域数据、页面状态、仓储接口和仓库内固定数据文件的当前契约，供解析器、缓存、界面和测试实现时查询。

维护规则：

- 修改领域字段、枚举、未知值、事件身份、排序、去重或仓储行为时，必须在同一次变更中更新本文档。
- 修改 `tests/TestData/` 中受 `manifest.json` 管理的文件时，必须同步更新清单哈希、预期结果和本文件对应格式说明。
- 新增 SQLite、JSON API 或其他持久化格式时，先在本文档定义版本、字段、空值和迁移规则，再实现读写代码。
- 本文档只记录应用采用的契约，不复制完整 JMAXML 或 GeoJSON 标准；上游原始格式以官方规范为准。
- 尚未实现的外部格式必须明确标为“未定义”，不能把设计建议当成已生效契约。

当前适用应用版本：`0.61.1`。固定测试数据集版本独立维护，当前为 `0.5.0`。`0.61.1` 仅修复地图焦点状态、LOD 中心切换时序并增加高精度 Feature 索引，不改变地震报文、来源或 SQLite 数据契约；`0.60.0` 的按视野裁剪以及 `0.59.0` 的地图缩放边界继续适用。

## 2. 通用约定

### 2.1 命名与文本

- C# 公共字段和属性使用 `PascalCase`。
- 当前固定 JSON 使用 `camelCase`，固定 CSV 使用 `snake_case`；后续格式必须在本文件单独列出字段名，不能仅依赖命名策略推断。
- ID 和代码按区分大小写的序号规则比较，不做区域性排序。
- `EventId`、`SourceId` 和 `SourceMessageId` 是归并身份，不能为 `null`、空字符串或纯空白；合并时不自动修剪或改写。
- JMA 地名和原始报文允许保留日文；应用显示文本与稳定代码必须分开保存。

### 2.2 时间

- 内存时间统一使用 `DateTimeOffset`，不得先转换为无时区的 `DateTime`。
- 后续 JSON 或 SQLite 持久化统一使用 ISO 8601 往返格式 `O`，例如 `2026-08-19T07:14:00.0000000+09:00`。
- `OriginTime` 可以未知；`IssuedAt` 和 `ReceivedAt` 必须存在。
- 显示层可以转换为 JST 或用户本地时区，但必须同时显示时区标识，不能覆盖原始偏移量。

### 2.3 空值和未知值

- 可缺失对象和数值使用 `null`，不使用空字符串、`0`、`NaN` 或无穷值代替未知。
- 震度未知使用 `JmaIntensity.Unknown`，稳定外部代码为 `unknown`。
- 深度 `0` 表示真实的 `0 km`，深度未知使用 `null`；负深度无效。
- 震级未知使用 `Magnitude.Value = null`；`NaN` 和正负无穷不能进入领域模型。
- 坐标未知使用 `null`；已知坐标必须是有限值，纬度范围为 `[-90, 90]`，经度范围为 `[-180, 180]`。
- 集合使用 `ImmutableArray<T>`；无数据使用空数组，不使用 `null`。

## 3. 领域对象契约

### 3.1 `EarthquakeEvent`

| 字段 | 类型 | 必需 | 含义 |
| --- | --- | --- | --- |
| `EventId` | `string` | 是 | 来源事件 ID，也是事件聚合键 |
| `Reports` | `ImmutableArray<EarthquakeReport>` | 是 | 已去重并稳定排序的完整报文时间线 |
| `LatestReport` | `EarthquakeReport?` | 派生 | 时间线最后一报，包含取消报 |
| `PreferredReport` | `EarthquakeReport?` | 派生 | 默认展示报文；优先最新 `jma-xml`，其次最新 `p2pquake`，最后回退 `LatestReport` |
| `LatestEffectiveReport` | `EarthquakeReport?` | 派生 | 最后的发布或订正报 |
| `Summary` | `EarthquakeEventSummary?` | 派生 | 供列表和当前状态使用的摘要；空时间线时为 `null` |

### 3.2 `EarthquakeEventSummary`

| 字段 | 来源 | 含义 |
| --- | --- | --- |
| `EventId` | 事件 | 事件 ID |
| `Status` | `PreferredReport` | 默认来源的发布、订正、取消或未知状态 |
| `Context` | `PreferredReport` | 默认来源的正常、训练、测试或未知上下文 |
| `UpdatedAt` | `PreferredReport.IssuedAt` | 默认来源的最后发布时间 |
| `ReportCode` | `LatestEffectiveReport` | 最后有效报文代码；没有有效报文时为 `null` |
| `OriginTime` | `LatestEffectiveReport` | 地震发生时间 |
| `Hypocenter` | `LatestEffectiveReport` | 震源信息 |
| `Magnitude` | `LatestEffectiveReport` | 震级信息 |
| `MaxIntensity` | `LatestEffectiveReport` | 最大观测震度；没有有效报文时为 `Unknown` |

取消报决定 `Status`、`Context` 和 `UpdatedAt`，但不会清空最后有效报文提供的地震摘要。

### 3.3 `EarthquakeReport`

| 字段 | 类型 | 必需 | 含义 |
| --- | --- | --- | --- |
| `EventId` | `string` | 是 | 所属事件 ID |
| `ReportCode` | `string` | 是 | 原始报文代码，例如 `VXSE51/52/53` |
| `ReportType` | `EarthquakeReportType` | 是 | 标准化报文类型 |
| `Status` | `ReportStatus` | 是 | 发布、订正、取消或未知 |
| `Context` | `ReportContext` | 是 | 正常、训练、测试或未知 |
| `Serial` | `int?` | 否 | 报次；缺失与 `0` 不同 |
| `OriginTime` | `DateTimeOffset?` | 否 | 地震发生时间 |
| `IssuedAt` | `DateTimeOffset` | 是 | 来源发布时间 |
| `ReceivedAt` | `DateTimeOffset` | 是 | 应用接收时间 |
| `Hypocenter` | `Hypocenter?` | 否 | 震源名称、代码、坐标和深度 |
| `Magnitude` | `Magnitude?` | 否 | 震级值、类型和来源条件文字 |
| `MaxIntensity` | `JmaIntensity` | 是 | 最大观测震度，默认 `Unknown` |
| `IntensityAreas` | `ImmutableArray<IntensityArea>` | 是 | 区域最大观测震度 |
| `IntensityMunicipalities` | `ImmutableArray<IntensityMunicipality>` | 是 | 市町村最大观测震度 |
| `IntensityStations` | `ImmutableArray<IntensityStation>` | 是 | 观测点震度和可选坐标 |
| `TsunamiComment` | `string?` | 否 | 来源报文中的海啸相关说明 |
| `TsunamiCommentCode` | `string?` | 否 | 与含海啸文本对应的 JMAXML `ForecastComment/Code`；原样保存，不按全局数字规则解释 |
| `Source` | `SourceReference` | 是 | 来源身份、原文链接和可选原始负载 |

### 3.4 值对象和关联字段

| 类型 | 字段 | 约定 |
| --- | --- | --- |
| `Hypocenter` | `Name`, `Code`, `Coordinate`, `DepthKm` | 各来源字段可以未知；深度单位为 km |
| `Magnitude` | `Value`, `Type`, `Condition` | `Value` 必须为有限值或 `null` |
| `GeoCoordinate` | `Latitude`, `Longitude` | 使用十进制度；顺序固定为纬度、经度 |
| `IntensityArea` | `Code`, `Name`, `PrefectureCode`, `PrefectureName`, `MaxIntensity` | 区域代码关联市町村和 GIS 要素 |
| `IntensityMunicipality` | `Code`, `Name`, `AreaCode`, `MaxIntensity` | `AreaCode` 必须引用所属区域代码 |
| `IntensityStation` | `Code`, `Name`, `MunicipalityCode`, `Intensity`, `Coordinate` | 无坐标观测点仍必须保留 |
| `SourceReference` | `SourceId`, `SourceMessageId`, `RawMessageUri`, `SourcePayload` | 前两项组成来源消息身份 |
| `SourceStatus` | `SourceId`, `State`, `CheckedAt`, `LastReceivedAt`, `Detail`; WebSocket 可选 `RetryAttempt`, `NextRetryAt`, `ConnectedAt`, `ConnectionEndedAt`, `LastError`, `LastMessageAt`, `ConnectionExceptionCount`, `LastConnectionExceptionAt`, `IsExpectedDisconnect` | 描述适配器状态，不代表单份报文状态；连接诊断字段只在进程内生效。JMA XML 增量刷新在 `Detail` 中记录缓存增量起点、Feed 总条数和命中条数 |

## 4. 枚举和稳定代码

### 4.1 JMA 震度

| C# 值 | 稳定代码 | 显示文本 |
| --- | --- | --- |
| `Unknown` | `unknown` | 不明 |
| `One` | `1` | 1 |
| `Two` | `2` | 2 |
| `Three` | `3` | 3 |
| `Four` | `4` | 4 |
| `FiveLower` | `5-lower` | 5弱 |
| `FiveUpper` | `5-upper` | 5強 |
| `SixLower` | `6-lower` | 6弱 |
| `SixUpper` | `6-upper` | 6強 |
| `Seven` | `7` | 7 |

枚举底层整数只用于进程内稳定排序，不能直接写入界面或外部数据格式。

### 4.2 其他枚举

- `EarthquakeReportType`：`Unknown`、`SeismicIntensity`、`Hypocenter`、`HypocenterAndIntensity`。
- `ReportStatus`：`Unknown`、`Issued`、`Correction`、`Cancelled`。
- `ReportContext`：`Unknown`、`Normal`、`Training`、`Test`。
- `SourceConnectionState`：`Unknown`、`Online`、`Delayed`、`Disconnected`、`RateLimited`、`ParseFailed`、`Disabled`。
- `TsunamiLevel`：`Unknown`、`NoConcern`、`MinorChange`、`Advisory`、`Warning`、`MajorWarning`、`Investigating`。当前已验证代码 `0215 -> NoConcern`；通用模板和未知代码不得直接推断为警报。

### 4.3 JMAXML 海啸字段

- 地震/震源/震度报文的固定评论位于 `Body/Comments/ForecastComment` 或 `VarComment`，文本为 `Text`，官方代码为同一节点下的 `Code`。
- JMA 官方代码管理表 `code.TsunamiWarning` 还规定独立海啸报文的 `Head/Headline/Information/Item/Kind/Code` 和上一状态 `LastKind/Code`；独立 `VTSE*` 报文接入前不得把这两个路径与地震固定评论代码混用。
- 分类优先级固定为：同节点官方代码映射 -> 明确文本等级 -> 通用模板/未知文本显示“津波 调查中”。

独立海啸解析契约当前已完成真实样例字段验收，但尚未接入持久化：

| 类型 | 字段 | 规则 |
| --- | --- | --- |
| `JmaTsunamiReport` | `EventId`、`ReportCode`、`InfoKind`、`Status`、`Context`、`Serial`、`IssuedAt`、`ReceivedAt`、`HeadlineText`、`Items`、`ForecastAreas`、`ObservationStations`、`EstimationAreas` | 只接受 `VTSE*` 报文；`Control/Status=訓練` 映射为 `ReportContext.Training`；原始来源通过 `Source` 保存；四个集合无数据时为空数组 |
| `JmaTsunamiInformationItem` | `KindName`、`KindCode`、`LastKindName`、`LastKindCode`、`Areas` | 当前和上一状态分开保存；代码未知时保留原文，不按编号推断 |
| `JmaTsunamiArea` | `Name`、`Code` | 来自 `Head/Headline/Information/Item` 内的预报区 `Area` |
| `JmaTsunamiHeight` | `Meters`、`Description`、`Condition`、`Unit`、`Type` | 高度数字可为空；JMAXML 的 `NaN` 映射为 `Meters=null`，同时保留 `description`（例如“巨大”）和其他原文属性 |
| `JmaTsunamiForecastArea` | `Name`、`Code`、`KindName/Code`、`LastKindName/Code`、`FirstArrivalTime/Condition`、`MaximumHeight`、`Stations` | 来自 `Body/Tsunami/Forecast/Item`；当前状态与上一状态分开保存，站点数组允许为空 |
| `JmaTsunamiStationForecast` | `Name`、`Code`、`HighTideTime`、`FirstArrivalTime`、`FirstArrivalCondition` | 来自预报区内 `Station`，缺失时间使用 `null` |
| `JmaTsunamiObservationStation` | `AreaName/Code`、`Name/Code`、`Sensor`、`FirstArrivalTime/Condition`、`Initial`、`MaximumHeightTime/Condition`、`MaximumHeight` | 来自 `Body/Tsunami/Observation/Item/Station`，支持 GPS 波浪计、水压计等原始传感器文本 |
| `JmaTsunamiEstimationArea` | `Name`、`Code`、`FirstArrivalTime/Condition`、`MaximumHeight` | 来自 `Body/Tsunami/Estimation/Item`，高度未知时保留 `description` |

固定真实样例位于 `tests/TestData/JmaTsunami/Official/`：三份报文来自 `jmaxml_20260723_Samples.zip`，`EventID=20160901071000`，`Control/Status=訓練`。`VTSE41` 和 `VTSE51` 各含 66 个预报区，`VTSE51` 另含 182 个沿岸站点；`VTSE52` 含 8 个近海观测站和 5 个推定区域。校验器通过 `manifest.json` 固定哈希和数量，禁止联网更新这些夹具。

解析器和 SQLite 仓储只负责结构化读取与保存，不代表已完成海啸等级展示或海啸页面；持久化仍保持原文和可空语义。

SQLite/JSON 持久化使用枚举名称文本，例如 `Correction`、`Normal`、`Disabled`；不得写入底层整数。读取未知文本时视为格式错误并触发缓存回退。`JmaIntensity` 使用既有稳定代码 `unknown`、`1`、`2`、`3`、`4`、`5-lower`、`5-upper`、`6-lower`、`6-upper`、`7`。

## 5. 事件身份、去重和排序

- 事件聚合键：`EventId`。
- 来源消息去重键：`SourceId + SourceMessageId`，仅在同一事件内生效。
- `p2pquake` 与 `jma-xml` 初始事件 ID 不同；当有效报文发生时间差不超过 60 秒、震源距离不超过 80 km，且双方震级已知时差不超过 0.5 时，合并为同一事件。合并保留两边报文，规范事件 ID 优先采用 JMA XML 震源报文的 `EventId`。
- 同一来源消息重复到达时保留最早 `ReceivedAt` 的记录。
- 事件内排序：`IssuedAt` 升序、`Serial` 升序、`ReceivedAt` 升序、来源优先级升序、`SourceId` 升序、`SourceMessageId` 升序；`Serial = null` 排在数字报次之前。来源优先级为 `p2pquake=5`、`jma-json=10`、`jma-xml=20`、其他来源 `0`，因此同一事件、发布时间、报次和接收时间相同时 JMA XML 成为 `LatestReport`。`jma-json=10` 从 `0.55.3` 起仅用于历史缓存排序，不代表生产网络来源已启用。
- 事件列表排序：最后报文 `IssuedAt` 降序，时间相同按 `EventId` 升序。
- 订正和取消均保留原报，不覆盖或删除时间线节点。

## 6. 仓储契约

`IEarthquakeEventRepository` 是页面可见事件数据的唯一访问边界：

| 成员 | 输入 | 输出/行为 |
| --- | --- | --- |
| `ListEventsAsync` | 可取消令牌 | 返回已合并、去重并按事件顺序排列的不可变快照 |
| `GetEventAsync` | 非空 `eventId`、可取消令牌 | 返回指定事件或 `null` |
| `EventsChanged` | 无 | 发布完整事件快照；消费者不能修改快照 |
| `RefreshAsync` | 可取消令牌 | 请求具体实现刷新；不保证一定产生数据变化 |

页面和 ViewModel 不得直接调用 HTTP 或 SQLite。仓储事件可能由非 UI 线程发布，WPF 消费者必须切回创建页面状态时捕获的同步上下文。

`IEarthquakeSourceStatusProvider` 是可选状态接口，只暴露不可变 `SourceStatuses` 快照。页面在仓储实现该接口时，于加载和刷新后同步来源状态；至少一个来源为 `Online` 时 `IsOffline=false`，否则保持离线/缓存模式。未实现该接口的测试或内存仓储不伪造来源状态。

`IIncrementalEarthquakeSource` 是可选实时源接口，提供 `FetchSinceAsync(DateTimeOffset? since, CancellationToken)`。SQLite 仓储按来源从已缓存报文计算最大 `IssuedAt`，实现该接口的源必须返回不早于 `since` 的报文；`since=null` 表示首次全量 Feed。接口只约束应用内增量边界，不承诺上游具备历史分页或完整离线覆盖。

`InMemoryEarthquakeEventRepository` 只用于开发和测试：

- 构造时可以接收标准化报文。
- `ApplyReports` 追加报文后统一调用 `EarthquakeEventMerger`，再发布完整快照。
- `RefreshAsync` 没有外部数据源，因此是可取消的空操作。
- 它不负责 XML 解析、磁盘持久化或网络访问。

### 6.2 SQLite 缓存契约（schema v3）

SQLite 数据库默认路径为 `%LOCALAPPDATA%\\EarthquakeShow\\earthquake-cache.db`；测试必须传入独立临时路径。所有时间列和 JSON 时间字段使用 ISO 8601 往返格式 `O`，保留 `DateTimeOffset` 原始偏移量。地震和海啸仓储使用 `schema_info` 中独立的 `earthquake_schema_version` 与 `tsunami_schema_version` 键，当前值分别为整数文本 `3` 和 `2`；旧数据库没有专用键时兼容读取旧 `schema_version`。

| 表 | 主键 | 字段 | 规则 |
| --- | --- | --- | --- |
| `schema_info` | `key` | `key`, `value` | 保存 schema 版本；未知版本不能静默读取 |
| `earthquake_events` | `event_id` | `updated_at`, `report_count` | 事件索引和审计信息；事件内容由报文重新合并 |
| `earthquake_reports` | `event_id + source_id + source_message_id` | `report_code`, `issued_at`, `received_at`, `payload_json` | 报文身份去重键；标准列用于查询，完整字段在 JSON DTO |
| `source_status` | `source_id` | `state`, `checked_at`, `last_received_at`, `detail` | 状态使用枚举名称文本；离线启动写入 `Disabled` |
| `tsunami_reports` | `event_id + source_id + source_message_id` | `report_code`, `issued_at`, `received_at`, `payload_json` | 独立海啸报文身份去重键；不参与 `EarthquakeEventMerger`，按事件 ID单独查询 |

`ITsunamiReportRepository` 只提供 `InitializeAsync`、`ListReportsAsync`、`ListReportsForEventAsync(eventId)` 和 `SaveReportsAsync`；它不负责 HTTP、Feed 增量、来源状态或地震事件合并。调用方先使用 `IRealtimeTsunamiSource` 获取 `JmaTsunamiReport`，再显式提交成功报文；空数组不会删除已有海啸报文。

地震仓储初始化时如果 `earthquake_reports` 已有记录，不再只读取缓存；传入的固定 seed 会按 `(event_id, source_id, source_message_id)` 检查缺失身份并补写缺少的报文。schema v2→v3 迁移会删除 `source_id=jma-json` 的历史报文和来源状态，v3 每次初始化也会重复执行幂等清理。海啸仓储通过 `ITsunamiReportRepository` 独立初始化和保存，不接收地震 seed，也不发布地震事件快照。重复启动和重复保存均使用 upsert，不生成重复报文。

`payload_json` 使用显式 `ReportPayloadDto` 格式，字段如下：

- `eventId`、`reportCode`、`reportType`、`status`、`context`、`serial`。
- `originTime`、`issuedAt`、`receivedAt`，时间为 `O` 格式字符串；`originTime` 可为 `null`。
- `hypocenter`（`name`、`code`、`coordinate`、`depthKm`）和 `magnitude`（`value`、`type`、`condition`），对象可为 `null`。
- `maxIntensity` 使用稳定震度代码；`intensityAreas`、`intensityMunicipalities`、`intensityStations` 使用数组，空集合写 `[]`。
- `tsunamiComment` 可为 `null`。
- `source` 包含 `sourceId`、`sourceMessageId`、`rawMessageUri` 和 `sourcePayload`；原始 XML 不做清洗或执行。

`tsunami_reports.payload_json` 使用显式 `TsunamiReportPayloadDto`，字段为：

- `eventId`、`reportCode`、`infoKind`、`status`、`context`、`serial`。
- `issuedAt`、`receivedAt`，时间为 `O` 格式字符串；`status` 和 `context` 使用枚举名称文本。
- `headlineText`、`items`、`forecastAreas`、`observationStations`、`estimationAreas`；集合无数据时写 `[]`。
- `forecastAreas` 内保存当前/上一 `Kind`、预计到达时间/条件、`maximumHeight` 和沿岸站点；`observationStations` 保存传感器、初动、实测高度时间/条件；高度对象保存 `meters`、`description`、`condition`、`unit`、`type`，`NaN` 对应 `meters=null`。
- `source` 包含 `sourceId`、`sourceMessageId`、`rawMessageUri` 和完整 `sourcePayload`。

坐标 DTO 使用 `Latitude`/`Longitude` 数字；空坐标为 `null`。读取 JSON 时必须重新构造领域值类型，使无效枚举和时间继续触发格式错误。地震仓储遇到数据库损坏、权限错误、schema 不支持或 JSON 格式错误时回退到固定 seed；海啸仓储不伪造 seed，直接向调用方报告持久化错误。取消令牌不回退而是继续抛出取消异常。当前未定义分页和清缓存契约，已定义 v1→v2 的一次性 schema 迁移。

## 7. 地震情报页面状态

`EarthquakePageState` 是不可变快照，更新时整体替换：

| 字段 | 含义 |
| --- | --- |
| `Events` | 当前事件列表快照 |
| `SelectedEvent` | 当前选中事件；首次非空加载默认选择列表第一项 |
| `ViewedReport` | 当前查看的报文版本；切换事件时默认最后一报 |
| `SearchText` | 搜索条件；去除首尾空白后保存 |
| `SortOrder` | 最新发布、最新发生或最大震度 |
| `Filters` | 时间、最低震度、最低震级、区域和来源筛选快照 |
| `Map` | 日本全图或所选事件焦点，以及是否跟随选择 |
| `SourceStatuses` | 各数据源状态快照 |
| `LoadState` | `NotLoaded`、`Loading`、`Ready` 或 `Error` |
| `IsRefreshing` | 主动刷新是否进行中 |
| `IsOffline` | 页面是否处于离线/缓存模式 |
| `ErrorMessage` | 最近一次加载或刷新错误；无错误时为 `null` |

仓储更新时保留当前 `EventId` 和当前报文的来源消息身份。新事件不得抢走用户正在查看的历史事件；当前报文不存在时才回退到该事件最后一报。

`EarthquakeEventFilterState` 字段：

| 字段 | 类型与规则 |
| --- | --- |
| `TimeRange` | `All`、`Last24Hours`、`Last7Days` 或 `Last30Days`；使用事件最新发布时间与当前时间比较 |
| `MinimumIntensity` | `JmaIntensity`；`Unknown` 表示不限，未知事件不能匹配任何已知最低震度 |
| `MinimumMagnitude` | `double?`；`null` 表示不限，非有限值被拒绝，震级未知的事件不能匹配最低震级 |
| `RegionText` | 去除首尾空白；匹配震源、区域、都道府县、市町村和观测点名称或代码 |
| `SourceId` | 去除首尾空白；按稳定来源 ID 精确筛选，界面显示名称不参与契约 |

详情快照契约：

- `EarthquakePageState.ViewedReport` 是右侧详情、报文时间线和地图图层的共同报文快照；切换时间线只能修改它，不修改事件列表摘要的当前状态规则。
- 首次选择事件时 `ViewedReport = PreferredReport`；选择时间线节点后必须使用该节点的 `SourceId + SourceMessageId` 精确恢复。
- “上一报”或“下一报”到达时间线边界时保持当前报文，不循环切换；“返回最新”选择 `PreferredReport`，取消报仍保留在时间线中。
- 详情显示时间、坐标、深度、震级、海啸和状态均来自 `ViewedReport`，未知值按本文件 2.3 规则显示为“不明”。
- 地图区域、震源和观测点图层读取 `ViewedReport`；观测点无坐标时仍在详情集合中，地图不生成标记。
- 详情中的原始文本来自 `ViewedReport.Source.SourcePayload`，只读展示；应用不得把 XML 当作可执行内容，也不得自动打开其中的链接。

列表投影规则：

- 搜索不区分拉丁字母大小写，匹配 `EventId`、震源名称/代码、任一报文代码和任一 `SourceId`。
- 最新发布按摘要 `UpdatedAt` 降序；最新发生将未知 `OriginTime` 排在已知值之后；最大震度将 `Unknown` 排在已知值之后。
- 三种排序最终均按区分大小写的 `EventId` 升序兜底，保证结果可重复。
- 过滤只改变可见列表，不修改页面当前事件；当前选择被过滤时详情状态继续保留。
- 当前仓储返回完整事件快照，尚未定义分页游标或“更多记录”格式；SQLite 已实现但本版本不伪造分页契约。

地图状态和资源契约：

| 项目 | 规则 |
| --- | --- |
| `EarthquakeMapViewState.FocusMode` | `JapanOverview` 或 `SelectedEvent`；只控制视图焦点，不修改当前事件选择 |
| `EarthquakeMapViewState.FollowSelection` | `true` 且存在当前事件时地图有效焦点为 `SelectedEvent`；手动平移/缩放会关闭，跟随所选事件按钮会重新开启，点击日本全图会同时关闭 |
| 坐标顺序 | 领域 `GeoCoordinate` 使用 `Latitude/Longitude`；GeoJSON 使用标准 `[longitude, latitude]` |
| 区域匹配 | 使用 `IntensityArea.Code` 与 GeoJSON `properties.areaCode`/`code` 的区分大小写字符串匹配 |
| 区域颜色 | 只使用 `JmaIntensity`，`Unknown` 为中性颜色；不从震级推导区域颜色 |
| 观测点绘制 | `IntensityStation.Coordinate` 为 `null` 时不生成地图标记，但不得从事件详情中删除 |
| 轮廓资源 | 运行时读取 `src/EarthquakeShow.App/Assets/Data/Map/jma-earthquake-areas-overview.geojson`，随应用复制，`officialBoundary=true`；高精度 `jma-earthquake-areas.geojson` 保留作后续按需加载输入 |
| 地图 LOD | `ZoomLevel <= 2` 使用概览；`ZoomLevel > 2` 异步读取同源 `0.003°` 中精度区域、市町村和边界资源；高精度视野重载前保留当前画布中心；LOD 只改变显示几何，不修改报文、震度、区域代码或 SQLite |
| LOD 失败策略 | 中精度读取取消或失败时保留当前已显示几何，并通过 `DetailLoadError` 和“中精度加载失败”状态文本提供诊断；缩回概览时恢复启动几何 |
| 几何读取 | `Polygon` 和 `MultiPolygon` 的每个 Feature 保留全部环；MultiPolygon 的所有部件合并到同一 Feature 几何，环集合使用 EvenOdd 规则绘制 |
| 地图范围 | 全国视图使用 `OfflineMapGeometry.Bounds`；事件视图使用震源、已解析观测点和命中区域/市町村几何包络，围绕焦点重建对称范围，投影使用中心纬度修正经度比例并保留约 6% 视口留白 |
| 解析诊断 | `OfflineMapGeometry.InvalidGeometryCount` 记录无有效环的要素数；`EarthquakeMapViewModel.UnmappedAreaCount` 记录报文区域没有匹配 `areaCode` 的数量 |
| 概览过滤 | `simplificationToleranceDegrees=0.015`、`minPolygonAreaDegreesSquared=0.0002`；只影响显示几何，不改变区域代码和事件字段 |

当 `FollowSelection=true` 且当前事件存在可绘制的区域或标记时，地图优先使用 `Hypocenter.Coordinate` 作为 `SelectedEvent` 中心，并用事件图层包络自适应缩放；震度速報没有震源时回退到区域/观测点包络中心。点事件使用最小包络防止过度放大，没有任何事件图层时才使用全国地图范围。

正式地图资源不是测试数据集的一部分，不加入 `tests/TestData/manifest.json`；它不参与固定样本哈希校验。GeoJSON 的领域坐标仍使用 `Latitude/Longitude`，文件坐标必须使用 `[longitude, latitude]`。地图边界只用于显示和代码匹配，不执行未定义的空间归属推断。

## 8. 固定测试数据格式

### 8.1 `manifest.json`

- 顶层 `schemaVersion` 当前必须为整数 `1`。
- `datasetVersion` 是固定数据集版本，不等同于应用版本。
- `fixtures[]` 记录 `id`、`reportCode`、相对 `path`、`origin`、SHA-256 和 `expected`。
- `assets[]` 记录固定资源 ID、相对路径、SHA-256、来源和预期记录数。
- `origin.kind` 只能明确区分官方原文和合成夹具；合成夹具必须记录基础文件、改动或测试目的。
- 修改受管文件后必须重新计算 SHA-256，并通过离线校验器。

### 8.2 `JmaStations.csv`

文件使用 UTF-8 CSV，首行字段固定为：

```text
station_code,report_name,coordinate_name,prefecture_code,affiliation,latitude,longitude
```

- `station_code` 必须唯一。
- `affiliation` 当前允许 `JMA`、`LocalGovernment`、`NIED`。
- `latitude`、`longitude` 使用十进制度和点号小数。
- `report_name` 保留报文名称，`coordinate_name` 保存用于坐标匹配的名称。

### 8.3 `Definitions/intensity-scale.json`

- 顶层 `schemaVersion` 当前为 `1`。
- `levels` 必须按 `unknown` 到 `7` 的稳定代码顺序包含 10 项。
- 每项包含 `code`、`jmaText`、`sortRank`、`color`、`textColor`。
- `sortRank` 必须从 `0` 连续到 `9`；颜色使用大写六位 `#RRGGBB`。
- 当前颜色是应用显示定义，不是 JMA 官方配色，界面必须同时显示文字。

### 8.4 `Gis/jma-area-test-envelopes.geojson`

- 顶层类型为 `FeatureCollection`，坐标系为 `EPSG:4326`。
- 当前要素几何类型为 `Polygon`，坐标顺序遵循 GeoJSON 的经度、纬度。
- 属性包含 `areaCode`、`name`、`maxIntensity`、`geometryKind`、`officialBoundary`。
- `officialBoundary` 必须为 `false`；该文件仅用于测试，不得作为正式地图边界。

### 8.5 应用离线轮廓 `Assets/japan-overview.geojson`

- 顶层类型为 `FeatureCollection`，坐标顺序为经度、纬度。
- 每个要素使用 `Polygon`，当前只提供日本列岛的 UI 示意外轮廓；解析器同时接受 `MultiPolygon` 外环以便后续替换资源。
- `properties` 至少包含 `code`、`name` 和 `officialBoundary`；当前所有要素的 `officialBoundary` 必须为 `false`。
- `metadata.source` 记录资源来源说明；资源不得声称是 JMA 官方边界。
- 该文件随 WPF App 输出和发布复制，不访问网络，不加入固定测试数据 `manifest.json`。

### 8.6 正式 JMA 地震区域地图 `Assets/Data/Map/jma-earthquake-areas.geojson`

- 顶层类型为 `FeatureCollection`；当前生成 194 个 Feature，几何类型为 `Polygon` 或 `MultiPolygon`。
- `metadata` 必须包含 `source`、`sourceUrl`、`sourceVersion`、`acquiredAt`、`coordinateSystem`、`officialBoundary=true`、`sourceLayer`、`simplificationToleranceDegrees` 和 `sourceArchive`。
- Feature 属性至少包含 `areaCode`、`name` 和 `sourceLayer`；`areaCode` 与 `IntensityArea.Code` 采用区分大小写的字符串精确匹配。
- Polygon 坐标结构为 `coordinates[ring][position][longitude,latitude]`；MultiPolygon 坐标结构为 `coordinates[polygon][ring][position][longitude,latitude]`。所有外环和内环必须保留，不能只取第一个环。
- 转换器按 `0.0005` 度显示容差生成派生资源；该容差只影响显示几何，不改变代码、名称或领域事件字段。原始 ZIP 保留在开发期资源目录，不进入发布输出。
- 当前资源范围约为经度 `122.9337486–153.9868386`、纬度 `20.4227464–45.5569332`；运行时不得再写死固定地图范围。

### 8.7 JMA 地震区域概览地图 `Assets/Data/Map/jma-earthquake-areas-overview.geojson`

- 这是运行时默认加载的低内存概览层，来源和代码字段与高精度地震区域资源一致。
- 当前生成 194 个 Feature、435 个多边形部件，使用 `0.015` 度简化容差和 `0.0002` 平方度最小多边形面积过滤，文件约 3.2 MB。
- 过滤会忽略极小岛屿和碎片，只用于全国概览、事件区域着色和定位，不得用于精确行政归属、面积计算或空间分析。
- 高精度 `jma-earthquake-areas.geojson` 不在启动时解析；`ZoomLevel > 12` 时通过对应 `.index.json` 按视野需要加载。

### 8.7.1 地图多级 LOD（0.61.1 当前生效范围）

- 当前生效为三级：区域、市町村和区域拓扑边界的 `0.015°` 概览层、同一原始 JMA ZIP 生成的 `0.003°` 中精度层，以及 `0.0005°` 高精度区域/市町村层。中精度文件分别约 `1.03 MB`、`2.77 MB`、`0.86 MB`，高精度区域和市町村文件约 `62.94 MB`、`69.31 MB`。
- 中精度资源沿用同一原始 JMA ZIP、代码字段、坐标顺序和 `officialBoundary=true`，只改变 `simplificationToleranceDegrees` 和经审计的碎片过滤参数。
- `ZoomLevel <= 2` 保持概览；`ZoomLevel > 2` 由 `MapLodResourceProvider` 在后台读取中精度，三类几何成功读取后一起替换；缩回时恢复概览。
- LOD 切换不得修改 `EarthquakeReport`、区域代码、震度值或 SQLite；它只改变地图显示几何。
- 运行时同一时间只让当前 LOD 参与地图图层；后台读取完成后才替换 ViewModel 几何，取消或失败时保留上一层，不清空地图。
- `ZoomLevel > 12` 时，高精度资源按当前视野加 20% 缓冲加载；随高精度 GeoJSON 发布的 `.index.json` 保存源文件长度、Feature 字节偏移、字节长度和经纬度包络。索引源文件长度不匹配时必须回退完整解析，不能读取过期偏移；高精度区域轮廓由命中的区域 Polygon 派生。

### 8.6 JMAXML 固定报文

- `JmaXml/Official/` 保存下载原文，禁止为了方便解析而修改。
- `JmaXml/Synthetic/` 是边界测试夹具，不得作为真实事件展示。
- 当前固定链为同一 `EventID` 的 `VXSE51 → VXSE52 → VXSE53`，另有订正和字段缺失夹具。
- `JmaXmlParser` 当前支持 `VXSE51`、`VXSE52` 和 `VXSE53` 使用到的字段子集，不代表完整 JMAXML Schema 实现；报文代码由调用方从 Feed 元数据或固定清单提供。

字段映射：

| JMAXML | 领域字段 | 规则 |
| --- | --- | --- |
| `Head/EventID` | `EventId` | 必需，空值拒绝 |
| `Head/ReportDateTime` | `IssuedAt` | 必需，保留来源时区 |
| `Control/DateTime` | `ReceivedAt` | 调用方未提供接收时间时使用 |
| `Head/InfoType` | `Status` | `発表`、`訂正`、`取消/取り消し` 分别映射为发布、订正、取消 |
| `Control/Status` | `Context` | `通常`、`訓練`、`試験/テスト` 分别映射为正常、训练、测试 |
| `Head/Serial` | `Serial` | 空值或非法整数映射为 `null` |
| `Earthquake/OriginTime` | `OriginTime` | 可缺失，保留来源时区 |
| `Hypocenter/Area` | `Hypocenter` | 读取名称、代码和坐标 |
| `jmx_eb:Coordinate` | `Coordinate`, `DepthKm` | 读取纬度、经度和米制深度；深度换算为 km |
| `jmx_eb:Magnitude` | `Magnitude` | 有限数字写入 `Value`；`NaN` 或非法值为 `null`，保留 `type` 和 `condition` |
| `Observation/MaxInt` | `MaxIntensity` | 支持 JMA 的 `5-/5+/6-/6+` 以及 `5弱/5強/6弱/6強` 写法；其他未知代码映射为 `Unknown` |
| `Pref/Area/City/IntensityStation` | 三类震度集合 | 按原层级展开；空集合不使用 `null` |
| `Comments` 中含“津波”的文字 | `TsunamiComment` | 去重后使用中文分号连接 |
| XML 原文 | `Source.SourcePayload` | 调用方未提供负载时保留完整原文 |

观测点坐标不在详情报中提供。`JmaStationCatalog` 读取 `JmaStations.csv`，按 `station_code` 与 `IntensityStation/Code` 精确匹配；未匹配记录仍进入 `IntensityStations`，其 `Coordinate` 为 `null`。

解析边界：

- XML 禁止 DTD 和外部实体解析，单文档字符上限为 1000 万。
- 根元素、`EventID`、`ReportDateTime` 或默认接收时间缺失时抛出 `FormatException`。
- 报文代码、来源 ID 或来源消息 ID 为空时抛出 `ArgumentException`。
- 非空但不符合当前 JMAXML 坐标格式的字段抛出 `FormatException`；缺少坐标则保留震源并使用 `null`。
- 订正和取消报不会覆盖原报；解析后继续由 `EarthquakeEventMerger` 保留完整时间线并生成当前摘要。
- 未识别的可选 XML 节点当前忽略，但完整原文继续保留，后续增加字段时必须先扩展本文档和测试。

### 8.7 JMA JSON 实时摘要

默认端点：`https://www.jma.go.jp/bosai/quake/data/list.json`，来源 ID 固定为 `jma-json`，不需要 API Key。当前字段契约于 2026-08-20 使用真实公共响应只读核验：

| JMA JSON | 领域字段 | 规则 |
| --- | --- | --- |
| `eid` | `EventId` | 必需；空值使本次响应进入 `ParseFailed` |
| `rdt` | `IssuedAt` | 必需；显式偏移保留，无偏移时按 JST |
| `at` | `OriginTime` | 可缺失；时间规则同 `rdt` |
| `ttl` | `ReportType` | `震度速報`、`震源情報`、`震源・震度情報` 映射到对应类型 |
| `ift` | `Status` | `発表`、`訂正`、`取消/取り消し` 映射到稳定状态 |
| `ser` | `Serial` | 非法或缺失值为 `null` |
| `anm` | `Hypocenter.Name` | `-`、`不明` 或空值为 `null` |
| `acd` | `Hypocenter.Code` | 区域代码，可缺失 |
| `cod` | `Coordinate`, `DepthKm` | JMA JSON 的 `+lat+lon-depth/`；纬度/经度优先按十进制度读取，超出 `[-90,90]`/`[-180,180]` 时按 `DDMM.m` / `DDDMM.m` 度分格式转换；米制深度取绝对值后换算 km |
| `mag` | `Magnitude.Value` | 有限数字写入；`-`、`不明` 或非法值为未知 |
| `maxi` | `MaxIntensity` | 支持稳定代码及 `5弱/5強/6弱/6強`，其他值为 `Unknown` |
| `json` | `SourceMessageId` | 优先作为稳定去重身份；缺失时使用 `ctt + eid` |
| 完整列表响应 | `SourcePayload` | 只读保存，不执行其中的内容或链接 |

JMA JSON 当前只建立事件摘要，`IntensityAreas`、`IntensityMunicipalities` 和 `IntensityStations` 保持空数组；不得根据 `int` 中只有代码和最大震度的摘要伪造名称或观测点。`RawMessageUri` 保存公共端点 URI，`ReportCode` 固定为 `JMA-JSON`。从 `0.56.0` 起该契约仅适用于解析器测试和离线诊断；生产 SQLite 初始化会删除历史 `jma-json` 报文，实时仓储不再请求或写入该来源。

获取结果使用 `EarthquakeSourceFetchResult`：`Reports` 是本次规范化报文，`Status` 是同一来源的检查结果。HTTP 429 为 `RateLimited`，其他非成功 HTTP 和网络异常为 `Disconnected`，JSON/必填字段/坐标错误为 `ParseFailed`。失败结果的 `Reports=[]`，仓储必须保留已有事件并只更新来源状态。

### 8.7B 四层震度关系目录与 P2PQuake 观测层级

`src/EarthquakeShow.App/Assets/Data/Intensity/jma-intensity-regions.json` 是随应用发布的轻量关系目录，保存 `prefectureCode → areaCode → municipalityCode` 及市町村地址别名。目录由 `tools/generate_jma_intensity_catalog.py` 根据 JMA 都道府县、区域和市町村 GeoJSON 生成；`diagnostics` 保存资源版本、记录数量和未匹配代码，便于更新时校验。

`P2pQuakeEarthquakeSource` 从 `points[].pref` 保存都道府县名称，并从 `points[].addr` 去除都道府县前缀后使用目录别名最长匹配市町村。命中目录时，`IntensityArea.Code`、`IntensityMunicipality.Code` 和 `IntensityStation.MunicipalityCode` 分别使用正式 JMA 区域码、市町村码和市町村码，区域的 `PrefectureCode/PrefectureName` 也来自目录；震度取所含观测点的最大值。未命中目录时才使用 `p2p-area:{prefecture}`、`p2p-municipality:{prefecture}:{name}` 和 `p2p-pref:{prefecture}` 回退键，名称为 `unknown` 的观测点仍保留。

详情树统一为“都道府县 → 区域 → 市町村 → 观测点”。XML 先按区域代码/名称从目录反查都道府县，P2P 和 XML 最终都通过 `municipalityCode` 与地图 GeoJSON 精确匹配；没有正式代码或几何的记录只计入未映射诊断，不按坐标猜测。

### 8.7A JMA 详细 JSON 固定报文

JMA XML 数据目录已清理 2026-07-28 的历史 XML；对应 XML 地址返回 404。项目保存 JMA 当前仍公开的等价详细 JSON，来源 ID 固定为 `jma-json-detail`，只作为随应用发布的离线 seed；它不参与网络刷新，也不代表实时 `jma-json` 摘要来源已启用。

| --- | --- | --- |
| `Head.EventID` | `EventId` | 必需；当前固定事件为 `20260728162718` |
| `Head.ReportDateTime` | `IssuedAt` | 必需；保留 JMA 显式时区 |

### 8.8 JMA XML 实时 Feed

默认 Feed：`https://www.data.jma.go.jp/developer/xml/feed/eqvol.xml`，来源 ID 固定为 `jma-xml`，不需要 API Key。Feed 使用 Atom 命名空间，应用只读取 `entry` 中的 `id` 和 `link[type=application/xml][href]`：

| Atom 字段 | 领域字段 | 规则 |
| --- | --- | --- |
| `entry/id` | `SourceMessageId` | 必须是绝对 URI；取 URI 最后一个文件名，保留 `.xml` |
| `entry/id` 文件名中的 `VXSE51/VXSE52/VXSE53` | `ReportCode` | 只接入这三类地震情报，其他代码忽略 |
| `entry/link/@href` | `RawMessageUri` | 优先选择 `type=application/xml`；没有 type 时也接受绝对 HTTP/HTTPS URI，用于下载详情和打开来源 |
| 下载得到的 XML 原文 | `SourcePayload` | 交给 `JmaXmlParser` 解析并原样保存；站点坐标来自随应用复制的 `JmaStations.csv` |

每次首次刷新默认最多处理 20 个 Feed 条目；增量刷新先完整解析短 Feed，再按来源 `since` 筛选。Feed 成功后逐条下载报文；单条 HTTP、超时或 XML 解析失败只计入该来源详情，其他成功报文仍返回。Feed 本身格式错误为 `ParseFailed`；HTTP 429 为 `RateLimited`，其他非成功 HTTP、网络异常和超时为 `Disconnected`。空 Feed 或最早条目晚于来源 `since` 时尝试长期 Feed；任何失败结果的 `Reports=[]` 都不能清空 SQLite 中已有报文，且不会阻断其他来源。

地震 XML 的海啸说明位于 `Body/Comments/ForecastComment`，通常包含 `<Text>` 和 `<Code>`；固定样例 `0215` 对应“この地震による津波の心配はありません。”。当前 `JmaXmlParser` 保存含“津波”评论及其同节点 `Code`，App 先按已验证代码、再按明确文本归一化。`JmaXmlEarthquakeSource` 当前只接入 `VXSE51`、`VXSE52`、`VXSE53`，独立海啸 XML 报文和完整代码表尚未接入，因此不能宣称当前版本已覆盖全部海啸代码。

从 `0.41.0` 起，JMA XML 源实现 `IIncrementalEarthquakeSource`。仓储刷新前按 `SourceId` 从已缓存报文计算最大 `IssuedAt` 作为 `since`，P2PQuake 的时间不会推进 XML 起点；Feed 文件名前 14 位按 UTC 解析为条目时间，早于 `since` 的条目不下载，等于 `since` 的条目仍保留以覆盖同秒多报文情况。空 Feed 也视为覆盖不足并额外读取长期 `eqvol_l.xml`，最多保留 100 条并按 `SourceMessageId` 去重。每个实时来源独立处理超时和网络异常，单来源失败不阻断后续来源。`SourceStatus.Detail` 记录 `增量起点`、Feed 总条数、命中条数和是否使用长期 Feed。长期 Feed 没有历史分页，起点早于长期 Feed 最早条目时仍只提供覆盖诊断，不保证离线期间完整回补。

JMA XML 与 P2PQuake 可能使用不同事件 ID 描述同一地震。`EarthquakeEventMerger` 使用发生时间、震源坐标和震级阈值合并两者，时间线仍保留各来源报文；JMA XML 震源报文优先作为规范事件 ID。无法满足阈值时保持独立事件。`0.56.0` 起历史 `jma-json` 报文在 SQLite 初始化迁移中删除，详情页不再显示“可能关联来源”候选区块。

### 8.8A JMA 海啸接口调研（2026-08-24）

JMA 官方 XML 页面确认，公开 XML 仅提供 PULL 型 Atom Feed，不再提供官方 PUSH/WebSocket。海啸报文与地震、火山报文同属“地震火山”分类，正式接入应复用以下两个 Feed：

| 接口 | 更新/保留 | 适用范围 | 结论 |
| --- | --- | --- | --- |
| `https://www.data.jma.go.jp/developer/xml/feed/eqvol.xml` | 每分钟更新，至少保留最近约 10 分钟入电 | 实时轮询 | 首选实时源；从 Atom `entry/link`（XML 类型优先）下载完整 XML |
| `https://www.data.jma.go.jp/developer/xml/feed/eqvol_l.xml` | 每小时更新，保留数天入电 | 启动回补、短 Feed 覆盖不足 | 首选回补源；无历史分页，不能保证更早缺口 |

需要从 Feed 详情中接收的海啸报文代码至少包括：

- `VTSE41`：津波警報・注意報・予報（警报、注意报、预报及其状态变化）。
- `VTSE51`：津波情報（沿岸预报/观测相关信息）。
- `VTSE52`：沖合の津波観測に関する情報（近海观测及基于观测的推定信息）。

这些代码名称由 JMA 技术资料和公开的 JMAXML 相关资料交叉核对。当前版本已用 JMA 官方训练样例验收独立海啸 XML 的稳定路径：`Head/Headline/Information/Item/Kind`、同节点 `LastKind`，以及 `Body` 中的预报区、预计到达/高度和观测数据；不能把地震报文的 `ForecastComment/Code` 当作独立海啸等级代码。

JMA 官网还提供海啸页面使用的 JSON：

- 列表：`https://www.jma.go.jp/bosai/tsunami/data/list.json`
- 详情：`https://www.jma.go.jp/bosai/tsunami/data/{list.json 中的 json 字段}`

公开索引可确认列表项包含 `eid`、`rdt`、`ttl`、`ift` 等摘要字段，并通过 `json` 字段指向详情文件；详情文件名示例为 `20260728181010_20260728162718_VTSE41_0.json`。但 JMA 未在 XML 技术资料页为这组 JSON 发布稳定版本化契约，字段可能随官网改版变化，因此当前只将其定义为补充源，不能替代 XML 原文链路。首次实现必须保存完整 JSON 原文，并对缺失或新增字段保持向后兼容。

第三方可选接口：P2PQuake JSON API v2 提供 `GET https://api.p2pquake.net/v2/jma/tsunami` 和 `GET https://api.p2pquake.net/v2/jma/tsunami/{id}`。它转发 JMA 海啸预报，便于快速验证，但不是 JMA 官方源，存在独立事件 ID、限流和字段延迟风险，只能作为非官方补充/降级源，不能覆盖或改写 JMA XML。

正式商用或需要 PUSH/低延迟保障时，应联系 JMA 页面指向的（一財）気象業務支援センター或获得许可的预报业务许可运营商签订配信服务；这类服务通常需要合同或费用，本项目当前不默认依赖。

当前状态：XML 接口地址和官方获取规则已确认，三份官方训练 XML 已完成结构验收并固定到测试数据；官网 JSON 的实时响应字段仍未形成稳定契约，因此继续只作为补充源调研记录。

`0.45.0` 来源层契约：

| 类型/成员 | 规则 |
| --- | --- |
| `IRealtimeTsunamiSource.FetchAsync()` | 首次或手动刷新读取高频 Feed，返回 `ImmutableArray<JmaTsunamiReport>` 和不可变 `SourceStatus` |

`0.49.0` 页面状态契约：`TsunamiPageState.Reports` 是按 `IssuedAt`、`ReceivedAt` 和身份稳定排序的不可变快照；`SelectedReport` 使用 `EventId + Source.SourceId + Source.SourceMessageId` 恢复。`LoadState` 的 `Error` 只表示本地快照读取失败，`IsOffline` 只根据 `SourceStatuses` 是否存在在线来源计算；两者不可互相替代。页面层不修改 `JmaTsunamiReport` 和 SQLite 数据。

`0.50.0` 视图契约：`TsunamiPageView` 只绑定 `TsunamiPageViewModel` 的公开状态属性和 `JmaTsunamiReport` 只读字段；刷新按钮调用 `RefreshAsync()`，报文选择写回 `SelectedReport`。列表不修改报文数组，不在视图层推断海啸等级；预报区、沿岸站点和近海推定结构数量仅作为摘要计数显示。

`0.51.0` 详情投影契约：`ForecastAreas` 的等级来源为当前 `KindName/KindCode`，`ObservationStations` 和 `EstimationAreas` 不虚构等级。高度使用有限 `Meters`，否则使用 `Description`；时间和条件保持可空。显示数组是派生数据，不写回领域模型或 SQLite。

`0.52.0` 原文契约：`RawXmlText` 只读映射 `Source.SourcePayload`，空值不显示原文区域；复制操作不修改 `JmaTsunamiReport`、`SourcePayload` 或 SQLite。`InformationItems` 只显示 `Items` 中实际存在的区域和等级字段，空区域显示“无区域”，不从预报区反向补写信息项。

`0.53.0` 时间线契约：`TimelineReports` 只从页面快照中筛选与当前 `SelectedReport.EventId` 相同的报文，按 `IssuedAt`、`ReceivedAt` 和 `SourceMessageId` 升序排列；不改变仓储报文身份或数据库结构。发布和订正节点使用当前报文等级，`ReportStatus.Cancelled` 节点固定显示“解除”并使用 `Unknown` 中性色，不从取消报文中推断仍然有效的警报等级。时间线项同时显示报文代码、状态、场景、发布时间和结构数量。

`0.54.0` 差异契约：`ReportDifferences` 只比较当前选择报文与同一 `EventId` 时间线中紧邻的上一报。比较字段为报文代码、状态、场景、最高等级、标题、信息项数量、预报区数量、沿岸观测数量和近海推定数量；只输出发生变化的字段。首报不生成差异项，无变化时不生成差异项；取消报文最高等级固定按 `Unknown` 计算，因此解除过程会显示等级变化为“解除”。

`0.55.0` 海啸地图契约：`jma-tsunami-forecast-lines-overview.geojson` 来源为 JMA `20240520_AreaTsunami_GIS.zip`，几何为按 `forecastAreaCode` 分组的 `LineString/MultiLineString` 沿岸线，不是可填充行政面。页面按 `JmaTsunamiForecastArea.Code` 建立等级索引；无当前报文等级的线使用中性颜色，已收到等级的线使用海啸等级颜色。该资源不包含观测站坐标；`JmaTsunamiObservationStation` 没有经纬度时必须保留列表记录但不创建地图标记，禁止使用地震 `JmaStations.csv` 猜测海啸站位置。

### 8.9 P2PQuake JSON API v2 补充源

默认端点：`https://api.p2pquake.net/v2/jma/quake`，来源 ID 固定为 `p2pquake`。当前字段契约于 2026-08-20 使用真实公共响应只读核验：

| P2PQuake JSON | 领域字段 | 规则 |
| --- | --- | --- |
| `id` | `SourceMessageId` | 必需；报文事件身份使用 `p2pquake:{id}`，不猜测 JMA `EventID` |
| `code` | `ReportCode` | 保存为 `P2P-{code}` |
| `issue.time` | `IssuedAt` | 必需；无时区的 `yyyy/MM/dd HH:mm:ss[.fff]` 按 JST 解释 |
| `issue.type` | `ReportType` | `DetailScale`→`HypocenterAndIntensity`，`ScalePrompt`→`SeismicIntensity`，`Destination`→`Hypocenter`，其他为 `Unknown` |
| `issue.correct` | `Status` | `None`→`Issued`，`Correction/訂正`→`Correction`，取消值→`Cancelled` |
| `earthquake.time` | `OriginTime` | 可缺失；时间规则同 `issue.time` |
| `earthquake.hypocenter` | `Hypocenter`、`Magnitude` | 坐标是必需有限值；深度单位为 km；震级缺失保留 `null` |
| `earthquake.maxScale` | `MaxIntensity` | `10/20/30/40/45/50/55/60/70` 映射为 `1/2/3/4/5弱/5強/6弱/6強/7`，其他值为 `Unknown` |
| `points[]` | `IntensityStations` | `addr/pref/scale` 转为来源内合成编码和地址；不声称是 JMA 官方观测点编码，缺地址的项忽略 |
| `earthquake.domesticTsunami/foreignTsunami` | `TsunamiComment` | `None/Unknown` 不展示，其他原文以分号连接 |
| 单条数组元素原文 | `SourcePayload` | 只读保存；`RawMessageUri` 为列表端点 URI |

P2PQuake HTTP 失败状态规则与其他 HTTP 来源一致：HTTP 429 为 `RateLimited`，其他非成功 HTTP 和网络异常为 `Disconnected`，JSON/必填字段/坐标错误为 `ParseFailed`。失败结果的 `Reports=[]`，仓储必须保留已有 JMA 与 SQLite 事件。HTTP 源不负责 WebSocket 生命周期和自动重连；P2P 报文的独立事件 ID 是刻意的安全边界，而不是完整去重契约。

### 8.10 来源差异展示契约

来源差异属于 App 层详情投影，不改变 Core 领域报文和 SQLite schema。对当前 `EarthquakeEvent` 内每个不同 `SourceId`，选取该来源按 `IssuedAt`、`ReceivedAt` 降序排列的最新报文，与当前 `ViewedReport` 比较：

| 比较项 | 显示规则 |
| --- | --- |
| `Status` | 使用稳定中文状态文本比较 |
| `MaxIntensity` | 使用震度显示文本比较 |
| `Magnitude` | 使用 `M x.x` 或“不明”比较 |
| `Hypocenter.Name` | 空值显示“不明” |
| `Hypocenter.DepthKm` | 使用 `n km` 或“不明”比较 |
| `IntensityStations.Length` | 只比较数量，不声称观测点编码可跨来源等价 |

差异项保留来源 ID、来源消息 ID、来源角色和合并后的文本；没有差异时显示“无字段差异”。来源差异只在同一 `EarthquakeEvent` 内计算，不依据时间、坐标或名称猜测跨事件关系。P2PQuake 使用独立事件 ID，因此当前不会出现在 JMA 事件的差异列表中。后续若定义跨源关联，必须先新增稳定关联键、置信度、人工复核边界和单独测试。

#### 8.10.1 详情累计显示投影（App 层）

该规则不改变 `EarthquakeReport` 原始字段，只规定 `EarthquakeDetailsViewModel` 如何把多份报文投影到摘要和时间线：

| 项目 | 规则 |
| --- | --- |
| 最大震度 | 只有非 `Unknown` 值覆盖累计值；缺失值不会生成“已知 → 不明”，相同值不显示变化 |
| 震源、震级、深度、发生时间 | 收到非空值后保留到后续报文；后续报文缺失时继续显示最近已知值 |
| 海啸说明 | 收到非空原文后保留；摘要和时间线归一化为五种状态或保留未识别原文；无任何说明或仅包含 JMA“津波警报等（…）”通用模板时显示“津波 调查中” |
| 海外地震 | 不根据缺失字段推断内容，只显示当前累计快照中实际存在的要素 |
| 时间线变化 | 首次收到字段显示当前值，已知字段变化显示 `旧值 → 新值`；已知字段在后续报文缺失或无变化时继续显示累计原值；从未收到的非海啸字段不生成变化文本，海啸行保留“津波 调查中” |

海啸状态的显示等级为：`津波の心配なし`（中性灰）、`若干の海面変動`（蓝）、`津波注意報`（黄）、`津波警報`（红）、`大津波警報`（紫）。未识别但非空的文本和通用模板统一显示 `津波 调查中`，不再回退为“津波の心配なし”；该归一化只影响界面文字和颜色，不覆盖 `TsunamiComment` 原文。

海啸等级判断的依据和优先级如下：

1. 仅在报文路径为 `Body/Comments/ForecastComment` 且代码已由 JMA 关联代码表逐项核实后，使用 `Code` 精确映射；当前已核实 `0215 -> NoConcern`。
2. 代码未知时，再匹配明确文本：`津波なし`/“津波の心配はありません”→`NoConcern`；“若干の海面変動”或“若干の潮位変化”→`MinorChange`；明确的“大津波警報”→`MajorWarning`；明确的“津波警報”→`Warning`；明确的“津波注意報”→`Advisory`。
3. 文本包含“津波警報等（…）”等列举模板，或包含“解除”时，不从括号内或历史状态推断当前等级，统一为 `Investigating`。
4. 其他非空文本和缺失字段分别保留原文并归类为 `Investigating`，不得按数字顺序猜测代码含义。

官方依据：JMA [JMAXML 资料](https://xml.kishou.go.jp/)、[技术资料](https://xml.kishou.go.jp/tec_material.html)、[格式规范](https://xml.kishou.go.jp/jmaxml_20221209_format_v1_3.pdf) 和 [2026-08-06 代码表](https://xml.kishou.go.jp/jmaxml_20260806_code.xlsx)。独立海啸报文的结构化等级位于 `Head/Headline/Information/Item/Kind/Code`，上一状态位于同节点 `LastKind/Code`；这部分属于 `VTSE*` 报文，当前尚未接入，不能与地震 `ForecastComment/Code` 混用。

最大震度的摘要和时间线徽标复用地图图例的十档颜色：不明、1、2、3、4、5弱、5强、6弱、6强、7。当前显示色板为：不明 `#E6EBEF`、1 `#78C7D8`、2 `#70D6C1`、3 `#F0C943`、4 `#E89A3C`、5弱 `#E85E3F`、5强 `#F04438`、6弱 `#B51255`、6强 `#8E24AA`、7 `#4A148C`。颜色只属于 App 显示层，不写回领域字段；5强、6弱、6强、7 使用白字和白边框，其余等级使用深色字和深灰边框。

### 8.11 跨源事件关联契约

页面当前使用 `EarthquakeEventMerger` 在事件派生阶段合并 `p2pquake` 与 `jma-xml`；`EarthquakeEventAssociator` 保留为通用诊断 API，但不再驱动详情页候选展示。合并只取每个来源事件最新的 `Issued` 或 `Correction` 报文，且要求双方 `EventId` 和 `SourceId` 不同：

| 条件 | 阈值/规则 |
| --- | --- |
| `OriginTime` | 两侧必须存在，绝对差不超过 60 秒 |
| 震源坐标 | 两侧必须存在，球面距离不超过 80 km |
| `Magnitude` | 两侧都有值时，绝对差不超过 0.5；一侧缺失不直接否决 |
| `Confidence=High` | 时间差不超过 10 秒、距离不超过 30 km，且震级差缺失或不超过 0.2 |
| `Confidence=Medium` | 满足基本阈值但不满足高置信度阈值 |

`EarthquakeEventMerger` 满足基本阈值时合并报文时间线，优先 JMA XML 事件 ID；不满足阈值时保留独立事件。详情页通过来源切换按钮选择已合并时间线中的来源报文，不显示“可能关联来源”区块。缺少发生时间/坐标、超出阈值、同事件或同来源的组合不合并。

### 8.12 自动刷新与退避状态契约

自动刷新调度不改变报文格式和仓储 schema，只读取上一轮 `SourceStatus`：

| 状态 | 下一次基础间隔 | 退避规则 |
| --- | --- | --- |
| 所有来源 `Online` | 60 秒 | 失败次数清零 |
| 包含 `Disconnected` 或 `ParseFailed` | 30 秒 | 每次连续失败乘 2 |
| 包含 `RateLimited` | 2 分钟 | 每次连续限流乘 2 |
| 任一失败类型 | 最大 15 分钟 | 超过上限固定为 15 分钟 |

`RefreshBackoffPolicy` 只在内存中保存连续失败次数；应用重启后从在线基础间隔重新开始。空来源状态不视为在线成功。自动刷新和手动刷新共用 `EarthquakePageViewModel.RefreshAsync()` 的异步互斥，取消令牌触发后不得再发起 HTTP 请求。

### 8.13 P2PQuake WebSocket 消息流契约

默认端点为 `wss://api.p2pquake.net/v2/ws`。连接通道和 `SourceStatus.SourceId` 使用 `p2pquake-ws`，标准化报文的 `Source.SourceId` 仍为 `p2pquake`。`IStreamingEarthquakeSource.StreamAsync()` 是可取消的异步消息流；每个 `EarthquakeSourceFetchResult` 最多包含一条报文。

| WebSocket 输入 | 结果 | 规则 |
| --- | --- | --- |
| 完整或分片的文本消息 | `Reports=[EarthquakeReport]`、`Online` | 分片按 `EndOfMessage` 重组；顶层必须是单个 JSON 对象；字段映射与 P2PQuake HTTP JSON 共用；`Source.RawMessageUri` 为 WebSocket 端点 |
| 顶层 JSON 数组、损坏 JSON、带事件结构但缺少必填字段/坐标错误 | `Reports=[]`、`ParseFailed` | 只影响当前消息，流继续读取下一条消息；带 `issue` 或 `earthquake` 结构但缺少 `id` 不得静默忽略 |
| 同时缺少 `id`、`issue` 和 `earthquake` 的 JSON 对象 | `Reports=[]`、`Online` | 视为非事件控制/状态消息；记录 `LastMessageAt`，不生成事件、不触发重连、不计连接异常；不赋予 heartbeat 或其他具体协议语义 |
| `code=555` 且 `areas` 为数组 | `Reports=[]`、`Online` | 网络节点统计消息；详情显示“网络节点统计（code 555）”，只记录 `LastMessageAt`，不保存节点数、不作为 heartbeat |
| 二进制消息或同一消息内类型变化 | `Reports=[]`、`ParseFailed` | 当前版本不把二进制当作 JSON 解析 |
| WebSocket 升级 HTTP `429` | `Reports=[]`、`RateLimited` | 不计入连接异常；结束本次流并由重连包装器按退避策略重新连接 |
| 其他连接失败、读取异常或 Close 帧 | `Reports=[]`、`Disconnected` | 输出一次状态后结束本次流 |
| 取消令牌触发 | 不输出失败结果 | 必须向上抛出 `OperationCanceledException`，由应用生命周期负责停止消费 |

消息身份仍使用 `p2pquake:{id}` 作为 `EventId`，`id` 作为 `SourceMessageId`；WebSocket 和 HTTP 收到相同消息时由仓储按既有报文来源 `p2pquake + SourceMessageId` 规则去重。消息源本身不负责重连、协议级心跳、SQLite 写入或 UI 订阅；消息活性字段由消息源记录，重连由下节包装契约负责。

开发期可通过 `P2pQuakeWebSocketSource` 的可选原始文本观察回调，或探测工具的 `--capture-messages PATH`，在分片重组和文本类型确认后取得每条完整原始 JSON。观察回调默认为空；正式应用不启用该回调，不把捕获内容写入 SQLite 或用户日志。捕获文件使用 UTF-8 JSONL，每行一条完整文本消息，可能包含完整地震原文，必须按诊断数据处理并避免提交。

### 8.14 WebSocket 重连契约

`ReconnectingEarthquakeSource` 顺序消费一个 `IStreamingEarthquakeSource`，任何时刻最多存在一个底层异步枚举器：

| 条件 | 行为 |
| --- | --- |
| 底层返回 `Disconnected` | 释放本次流，等待退避后创建下一次流 |
| 底层正常结束 | 视为连接结束，等待退避后创建下一次流 |
| 底层抛出 `WebSocketException` 或 `IOException` | 输出一个 `Disconnected` 状态，释放本次流后重连 |
| 收到至少一个 `Online` 结果 | 当前连续失败次数清零；后续断开重新使用初始间隔 |
| 达到 `MaxConnectionDuration` | 使用会话取消令牌结束当前连接，输出 `Disconnected(IsExpectedDisconnect=true)` 后按退避重连 |
| 收到 `ParseFailed` | 原样输出，由底层继续读取当前连接，不单独触发重连 |
| 取消令牌触发 | 终止接收或等待并向上抛出取消；不输出伪造失败状态 |

默认重连间隔为 5 秒，连续失败时按 2 倍递增，最大 5 分钟；`MaxConnectionDuration` 默认 9 分钟。重连等待次数、连接异常统计只保存在当前进程内，不写入 SQLite；应用重启后重新从初始间隔和零异常计数开始。当前没有协议级 heartbeat 或静默 watchdog；主动轮换用于避开 P2PQuake 10 分钟强制断开边界。

### 8.16 流式结果持久化契约

`SqliteEarthquakeEventRepository.ApplyStreamingResultAsync()` 接收一个完整 `EarthquakeSourceFetchResult`，在同一个串行化写入流程中处理：

1. 按既有 SQLite 主键 upsert `Reports`；空报文数组不删除已有数据。
2. 按 `SourceStatus.SourceId` upsert当前通道状态。
3. 保留没有参与本次更新的其他来源和通道状态。
4. 重新读取全部报文，调用 `EarthquakeEventMerger` 派生事件快照并发布 `EventsChanged`。

HTTP 刷新、WebSocket 流和显式报文保存共用一个进程内 `SemaphoreSlim` 写入互斥。SQLite schema 当前为 v2；`p2pquake-ws` 只用于连接状态，新增的 `tsunami_reports` 不参与地震报文去重。持久化地震报文仍使用 `source_id=p2pquake`，因此 HTTP/WS 相同消息不会重复。取消令牌在等待写锁、SQLite 操作或上游流中触发时必须继续向上抛出。

### 8.17 WebSocket 重连诊断字段

`SourceStatus` 的以下字段只用于当前进程内的 WebSocket 连接诊断：

| 字段 | 类型 | 生效条件 | 含义 |
| --- | --- | --- | --- |
| `RetryAttempt` | `int?` | `State=Delayed` | 当前连续重连等待次数，从 `1` 开始；收到 `Online` 后下一次断开重新计数 |
| `NextRetryAt` | `DateTimeOffset?` | `State=Delayed` | 预计结束当前退避等待的 UTC 时刻，显示层转换为 JST |
| `ConnectedAt` | `DateTimeOffset?` | WebSocket 已连接过 | 当前或最近一次连接会话的开始时间 |
| `ConnectionEndedAt` | `DateTimeOffset?` | 最近会话已结束 | 最近一次连接会话的结束时间；在线状态为 `null` |
| `LastError` | `string?` | 断开或解析失败后 | 最近一次连接错误或消息解析错误详情；新连接不会自动清空 |
| `LastMessageAt` | `DateTimeOffset?` | 收到完整消息或解析失败消息 | 最近一次收到完整 WebSocket 消息的时间；不表示协议 heartbeat |
| `ConnectionExceptionCount` | `int?` | 连接建立/读取异常后 | 当前进程累计连接异常次数；正常 Close 和解析失败不计入 |
| `LastConnectionExceptionAt` | `DateTimeOffset?` | `ConnectionExceptionCount > 0` | 最近一次连接异常发生时间 |
| `IsExpectedDisconnect` | `bool` | 主动连接轮换 | `true` 表示达到最大连接时长的预期断开，不增加异常次数、不覆盖最近错误 |

只有 `p2pquake-ws` 通道填充上述字段。退避等待前先发布 `Delayed` 状态；精确时间不可用时，页面显示“等待重连”。收到 `Online`、`Disconnected` 或 `ParseFailed` 时，状态按对应来源结果更新，解析失败不会触发额外重连。

这些字段不写入 SQLite `source_status` 表，也不改变 schema 版本；SQLite 读取出的诊断字段始终为 `null`。HTTP 刷新时，仓储只从当前内存状态合并带有这些字段的 `p2pquake-ws` 状态，随后使用本次 HTTP 结果覆盖对应 HTTP 来源状态，避免旧内存状态回退新状态。应用重启后不恢复上一次连接时间、重连次数、下次重试时间或最近错误详情。

在线连接持续时间由展示时刻减 `ConnectedAt` 计算；断开或等待重连时由 `ConnectionEndedAt - ConnectedAt` 计算，不包含退避等待时间。主窗口每秒刷新展示投影，不改变领域状态或持久化数据。

消息活性由展示时刻减 `LastMessageAt` 计算，页面显示为最近消息年龄；不存在独立协议 heartbeat 时，不得把该年龄显示为“心跳已确认”。连接异常统计只在进程内累计，不能用于跨进程或历史可靠性分析。

### 8.18 WebSocket keep-alive 与连接轮换契约

正式 `ClientWebSocket` 使用传输层 `KeepAliveInterval=30s`。该 keep-alive 由 .NET WebSocket 实现处理，不生成 `EarthquakeReport`，也不改变 P2PQuake 文本消息格式；当前没有应用层 ping/pong 结果字段。原始消息捕获仅为开发期取证能力，不改变正式连接策略。

`StreamingReconnectPolicy.MaxConnectionDuration` 默认 9 分钟，必须大于零。达到时限时，重连包装器取消当前会话令牌并输出：

| 字段 | 值 |
| --- | --- |
| `State` | `Disconnected` |
| `IsExpectedDisconnect` | `true` |
| `Detail` | 包含“单连接轮换时间” |
| `ConnectionExceptionCount` | 保持当前累计值，不因轮换增加 |
| `LastError` | 保持最近错误，不写入轮换原因 |

窗口生命周期取消优先于轮换；外部取消不得输出预期断开或重新建立连接。轮换后的新会话继续使用原有指数退避、在线重置和单连接约束。

### 8.19 WebSocket 连接策略设置契约

设置文件固定保存于 `%LOCALAPPDATA%\\EarthquakeShow\\settings.json`，与 SQLite 事件缓存分离。当前设置 schema 版本为 `1`，JSON 使用 camelCase：

```json
{
  "schemaVersion": 1,
  "webSocket": {
    "keepAliveSeconds": 30,
    "maxConnectionDurationMinutes": 9
  }
}
```

| 字段 | 类型 | 默认值 | 约束 |
| --- | --- | --- | --- |
| `schemaVersion` | `int` | `1` | 不是 `1` 时整份设置回退默认值 |
| `webSocket.keepAliveSeconds` | `int` | `30` | `10–120`；映射为 `ClientWebSocketOptions.KeepAliveInterval` |
| `webSocket.maxConnectionDurationMinutes` | `int` | `9` | `1–9`；映射为 `StreamingReconnectPolicy.MaxConnectionDuration` |

设置文件缺失、无法读取、JSON 损坏、schema 不支持或字段越界时，应用使用默认设置并向设置页提供警告文本；不得因为设置错误阻止读取 SQLite 缓存。点击应用后先校验并写入文件，再重建当前 WebSocket 流；HTTP 刷新、SQLite schema、事件选择和页面现场不受影响。设置不是地震报文，不写入 SQLite，也不参与事件去重。

### 8.20 P2PQuake `code=555` 网络节点统计契约

`0.29.0` 的真实 10 分钟捕获取得三条 `code=555` 消息，顶层字段均为 `_id`、`areas`、`code`、`created_at`、`expire`、`hop`、`time`、`uid`、`ver`。`areas[]` 包含数值 `id` 和 `peer`，三条数组长度分别为 114、114、112；消息时间间隔为 28.888 秒和 241.817 秒。

当前只使用 `code=555` 和 `areas` 数组存在性识别网络节点统计，不解析区域编码、不持久化节点数、不生成 `EarthquakeReport`。消息只更新通道 `LastMessageAt` 并返回 `Online`。由于真实间隔不固定，且没有独立 ping/pong 响应标识，`code=555` 不得显示为 heartbeat 成功，也不得用作静默 watchdog 的固定周期。

其他同时缺少 `id`、`issue`、`earthquake` 的对象仍按通用非事件消息返回 `Online` 空报文；若带 `issue` 或 `earthquake` 结构但缺少 `id`，仍返回 `ParseFailed`。

### 8.21 nTool 研究数据边界（非生效契约）

| 项目 | 计划契约 |
| --- | --- |

### 8.35 JMA JSON `cod` 度分坐标契约（0.55.2）

JMA `list.json` 的 `cod` 可能使用十进制度或度分格式：

| 输入示例 | 解释 | 标准化结果 |
| --- | --- | --- |
| `+43.2+145.0-80000/` | 纬度/经度为十进制度 | `43.2`, `145.0`, 深度 `80 km` |
| `+3559.9+14005.7-68000/` | `35°59.9′`, `140°05.7′` | `35.998333...`, `140.095`, 深度 `68 km` |

转换规则只在原始绝对值超出对应十进制度上限时触发；度分格式的分钟必须小于 `60`，转换后再次执行领域经纬度范围校验。无法满足规则的报文返回 `ParseFailed`，仓储保留已有快照；合法度分报文不得影响同一列表中其他报文的解析。
