# Earthquake Show 数据契约与格式

## 1. 文档用途

本文档长期记录应用内部领域数据、页面状态、仓储接口和仓库内固定数据文件的当前契约，供解析器、缓存、界面和测试实现时查询。

维护规则：

- 修改领域字段、枚举、未知值、事件身份、排序、去重或仓储行为时，必须在同一次变更中更新本文档。
- 修改 `tests/TestData/` 中受 `manifest.json` 管理的文件时，必须同步更新清单哈希、预期结果和本文件对应格式说明。
- 新增 SQLite、JSON API 或其他持久化格式时，先在本文档定义版本、字段、空值和迁移规则，再实现读写代码。
- 本文档只记录应用采用的契约，不复制完整 JMAXML 或 GeoJSON 标准；上游原始格式以官方规范为准。
- 尚未实现的外部格式必须明确标为“未定义”，不能把设计建议当成已生效契约。

当前适用应用版本：`0.9.0`。固定测试数据集版本独立维护，当前为 `0.3.0`。

## 2. 通用约定

### 2.1 命名与文本

- C# 公共字段和属性使用 `PascalCase`。
- 当前固定 JSON 使用 `camelCase`，固定 CSV 使用 `snake_case`；后续格式必须在本文件单独列出字段名，不能仅依赖命名策略推断。
- ID 和代码按区分大小写的序号规则比较，不做区域性排序。
- `EventId`、`SourceId` 和 `SourceMessageId` 是归并身份，不能为 `null`、空字符串或纯空白；合并时不自动修剪或改写。
- JMA 地名和原始报文允许保留日文；应用显示文本与稳定代码必须分开保存。

### 2.2 时间

- 内存时间统一使用 `DateTimeOffset`，不得先转换为无时区的 `DateTime`。
- 后续 JSON 或 SQLite 持久化统一使用 ISO 8601 往返格式 `O`，例如 `2026-08-19T07:14:00.0000000+09:00`。
- `OriginTime` 可以未知；`IssuedAt` 和 `ReceivedAt` 必须存在。
- 显示层可以转换为 JST 或用户本地时区，但必须同时显示时区标识，不能覆盖原始偏移量。

### 2.3 空值和未知值

- 可缺失对象和数值使用 `null`，不使用空字符串、`0`、`NaN` 或无穷值代替未知。
- 震度未知使用 `JmaIntensity.Unknown`，稳定外部代码为 `unknown`。
- 深度 `0` 表示真实的 `0 km`，深度未知使用 `null`；负深度无效。
- 震级未知使用 `Magnitude.Value = null`；`NaN` 和正负无穷不能进入领域模型。
- 坐标未知使用 `null`；已知坐标必须是有限值，纬度范围为 `[-90, 90]`，经度范围为 `[-180, 180]`。
- 集合使用 `ImmutableArray<T>`；无数据使用空数组，不使用 `null`。

## 3. 领域对象契约

### 3.1 `EarthquakeEvent`

| 字段 | 类型 | 必需 | 含义 |
| --- | --- | --- | --- |
| `EventId` | `string` | 是 | 来源事件 ID，也是事件聚合键 |
| `Reports` | `ImmutableArray<EarthquakeReport>` | 是 | 已去重并稳定排序的完整报文时间线 |
| `LatestReport` | `EarthquakeReport?` | 派生 | 时间线最后一报，包含取消报 |
| `LatestEffectiveReport` | `EarthquakeReport?` | 派生 | 最后的发布或订正报 |
| `Summary` | `EarthquakeEventSummary?` | 派生 | 供列表和当前状态使用的摘要；空时间线时为 `null` |

### 3.2 `EarthquakeEventSummary`

| 字段 | 来源 | 含义 |
| --- | --- | --- |
| `EventId` | 事件 | 事件 ID |
| `Status` | `LatestReport` | 当前发布、订正、取消或未知状态 |
| `Context` | `LatestReport` | 当前正常、训练、测试或未知上下文 |
| `UpdatedAt` | `LatestReport.IssuedAt` | 当前状态的最后发布时间 |
| `ReportCode` | `LatestEffectiveReport` | 最后有效报文代码；没有有效报文时为 `null` |
| `OriginTime` | `LatestEffectiveReport` | 地震发生时间 |
| `Hypocenter` | `LatestEffectiveReport` | 震源信息 |
| `Magnitude` | `LatestEffectiveReport` | 震级信息 |
| `MaxIntensity` | `LatestEffectiveReport` | 最大观测震度；没有有效报文时为 `Unknown` |

取消报决定 `Status`、`Context` 和 `UpdatedAt`，但不会清空最后有效报文提供的地震摘要。

### 3.3 `EarthquakeReport`

| 字段 | 类型 | 必需 | 含义 |
| --- | --- | --- | --- |
| `EventId` | `string` | 是 | 所属事件 ID |
| `ReportCode` | `string` | 是 | 原始报文代码，例如 `VXSE51/52/53` |
| `ReportType` | `EarthquakeReportType` | 是 | 标准化报文类型 |
| `Status` | `ReportStatus` | 是 | 发布、订正、取消或未知 |
| `Context` | `ReportContext` | 是 | 正常、训练、测试或未知 |
| `Serial` | `int?` | 否 | 报次；缺失与 `0` 不同 |
| `OriginTime` | `DateTimeOffset?` | 否 | 地震发生时间 |
| `IssuedAt` | `DateTimeOffset` | 是 | 来源发布时间 |
| `ReceivedAt` | `DateTimeOffset` | 是 | 应用接收时间 |
| `Hypocenter` | `Hypocenter?` | 否 | 震源名称、代码、坐标和深度 |
| `Magnitude` | `Magnitude?` | 否 | 震级值、类型和来源条件文字 |
| `MaxIntensity` | `JmaIntensity` | 是 | 最大观测震度，默认 `Unknown` |
| `IntensityAreas` | `ImmutableArray<IntensityArea>` | 是 | 区域最大观测震度 |
| `IntensityMunicipalities` | `ImmutableArray<IntensityMunicipality>` | 是 | 市町村最大观测震度 |
| `IntensityStations` | `ImmutableArray<IntensityStation>` | 是 | 观测点震度和可选坐标 |
| `TsunamiComment` | `string?` | 否 | 来源报文中的海啸相关说明 |
| `Source` | `SourceReference` | 是 | 来源身份、原文链接和可选原始负载 |

### 3.4 值对象和关联字段

| 类型 | 字段 | 约定 |
| --- | --- | --- |
| `Hypocenter` | `Name`, `Code`, `Coordinate`, `DepthKm` | 各来源字段可以未知；深度单位为 km |
| `Magnitude` | `Value`, `Type`, `Condition` | `Value` 必须为有限值或 `null` |
| `GeoCoordinate` | `Latitude`, `Longitude` | 使用十进制度；顺序固定为纬度、经度 |
| `IntensityArea` | `Code`, `Name`, `PrefectureCode`, `PrefectureName`, `MaxIntensity` | 区域代码关联市町村和 GIS 要素 |
| `IntensityMunicipality` | `Code`, `Name`, `AreaCode`, `MaxIntensity` | `AreaCode` 必须引用所属区域代码 |
| `IntensityStation` | `Code`, `Name`, `MunicipalityCode`, `Intensity`, `Coordinate` | 无坐标观测点仍必须保留 |
| `SourceReference` | `SourceId`, `SourceMessageId`, `RawMessageUri`, `SourcePayload` | 前两项组成来源消息身份 |
| `SourceStatus` | `SourceId`, `State`, `CheckedAt`, `LastReceivedAt`, `Detail` | 描述适配器状态，不代表单份报文状态 |

## 4. 枚举和稳定代码

### 4.1 JMA 震度

| C# 值 | 稳定代码 | 显示文本 |
| --- | --- | --- |
| `Unknown` | `unknown` | 不明 |
| `One` | `1` | 1 |
| `Two` | `2` | 2 |
| `Three` | `3` | 3 |
| `Four` | `4` | 4 |
| `FiveLower` | `5-lower` | 5弱 |
| `FiveUpper` | `5-upper` | 5強 |
| `SixLower` | `6-lower` | 6弱 |
| `SixUpper` | `6-upper` | 6強 |
| `Seven` | `7` | 7 |

枚举底层整数只用于进程内稳定排序，不能直接写入界面或外部数据格式。

### 4.2 其他枚举

- `EarthquakeReportType`：`Unknown`、`SeismicIntensity`、`Hypocenter`、`HypocenterAndIntensity`。
- `ReportStatus`：`Unknown`、`Issued`、`Correction`、`Cancelled`。
- `ReportContext`：`Unknown`、`Normal`、`Training`、`Test`。
- `SourceConnectionState`：`Unknown`、`Online`、`Delayed`、`Disconnected`、`RateLimited`、`ParseFailed`、`Disabled`。

这些枚举目前只有 C# 进程内契约，尚未定义 SQLite 或 JSON 稳定编码。实现持久化前必须在本文档新增外部代码映射，不能直接依赖枚举整数。

## 5. 事件身份、去重和排序

- 事件聚合键：`EventId`。
- 来源消息去重键：`SourceId + SourceMessageId`，仅在同一事件内生效。
- 同一来源消息重复到达时保留最早 `ReceivedAt` 的记录。
- 事件内排序：`IssuedAt` 升序、`Serial` 升序、`ReceivedAt` 升序、`SourceId` 升序、`SourceMessageId` 升序；`Serial = null` 排在数字报次之前。
- 事件列表排序：最后报文 `IssuedAt` 降序，时间相同按 `EventId` 升序。
- 订正和取消均保留原报，不覆盖或删除时间线节点。

## 6. 仓储契约

`IEarthquakeEventRepository` 是页面可见事件数据的唯一访问边界：

| 成员 | 输入 | 输出/行为 |
| --- | --- | --- |
| `ListEventsAsync` | 可取消令牌 | 返回已合并、去重并按事件顺序排列的不可变快照 |
| `GetEventAsync` | 非空 `eventId`、可取消令牌 | 返回指定事件或 `null` |
| `EventsChanged` | 无 | 发布完整事件快照；消费者不能修改快照 |
| `RefreshAsync` | 可取消令牌 | 请求具体实现刷新；不保证一定产生数据变化 |

页面和 ViewModel 不得直接调用 HTTP 或 SQLite。仓储事件可能由非 UI 线程发布，WPF 消费者必须切回创建页面状态时捕获的同步上下文。

`InMemoryEarthquakeEventRepository` 只用于开发和测试：

- 构造时可以接收标准化报文。
- `ApplyReports` 追加报文后统一调用 `EarthquakeEventMerger`，再发布完整快照。
- `RefreshAsync` 没有外部数据源，因此是可取消的空操作。
- 它不负责 XML 解析、磁盘持久化或网络访问。

## 7. 地震情报页面状态

`EarthquakePageState` 是不可变快照，更新时整体替换：

| 字段 | 含义 |
| --- | --- |
| `Events` | 当前事件列表快照 |
| `SelectedEvent` | 当前选中事件；首次非空加载默认选择列表第一项 |
| `ViewedReport` | 当前查看的报文版本；切换事件时默认最后一报 |
| `SearchText` | 搜索条件；去除首尾空白后保存 |
| `SortOrder` | 最新发布、最新发生或最大震度 |
| `Filters` | 时间、最低震度、最低震级、区域和来源筛选快照 |
| `Map` | 日本全图或所选事件焦点，以及是否跟随选择 |
| `SourceStatuses` | 各数据源状态快照 |
| `LoadState` | `NotLoaded`、`Loading`、`Ready` 或 `Error` |
| `IsRefreshing` | 主动刷新是否进行中 |
| `IsOffline` | 页面是否处于离线/缓存模式 |
| `ErrorMessage` | 最近一次加载或刷新错误；无错误时为 `null` |

仓储更新时保留当前 `EventId` 和当前报文的来源消息身份。新事件不得抢走用户正在查看的历史事件；当前报文不存在时才回退到该事件最后一报。

`EarthquakeEventFilterState` 字段：

| 字段 | 类型与规则 |
| --- | --- |
| `TimeRange` | `All`、`Last24Hours`、`Last7Days` 或 `Last30Days`；使用事件最新发布时间与当前时间比较 |
| `MinimumIntensity` | `JmaIntensity`；`Unknown` 表示不限，未知事件不能匹配任何已知最低震度 |
| `MinimumMagnitude` | `double?`；`null` 表示不限，非有限值被拒绝，震级未知的事件不能匹配最低震级 |
| `RegionText` | 去除首尾空白；匹配震源、区域、都道府县、市町村和观测点名称或代码 |
| `SourceId` | 去除首尾空白；按稳定来源 ID 精确筛选，界面显示名称不参与契约 |

列表投影规则：

- 搜索不区分拉丁字母大小写，匹配 `EventId`、震源名称/代码、任一报文代码和任一 `SourceId`。
- 最新发布按摘要 `UpdatedAt` 降序；最新发生将未知 `OriginTime` 排在已知值之后；最大震度将 `Unknown` 排在已知值之后。
- 三种排序最终均按区分大小写的 `EventId` 升序兜底，保证结果可重复。
- 过滤只改变可见列表，不修改页面当前事件；当前选择被过滤时详情状态继续保留。
- 当前仓储返回完整事件快照，尚未定义分页游标或“更多记录”格式；SQLite 缓存实现前不得伪造分页契约。

地图状态和资源契约：

| 项目 | 规则 |
| --- | --- |
| `EarthquakeMapViewState.FocusMode` | `JapanOverview` 或 `SelectedEvent`；只控制视图焦点，不修改当前事件选择 |
| `EarthquakeMapViewState.FollowSelection` | `true` 且存在当前事件时地图有效焦点为 `SelectedEvent`；关闭后保留 `FocusMode`，点击日本全图会同时关闭跟随 |
| 坐标顺序 | 领域 `GeoCoordinate` 使用 `Latitude/Longitude`；GeoJSON 使用标准 `[longitude, latitude]` |
| 区域匹配 | 使用 `IntensityArea.Code` 与 GeoJSON `properties.areaCode`/`code` 的区分大小写字符串匹配 |
| 区域颜色 | 只使用 `JmaIntensity`，`Unknown` 为中性颜色；不从震级推导区域颜色 |
| 观测点绘制 | `IntensityStation.Coordinate` 为 `null` 时不生成地图标记，但不得从事件详情中删除 |
| 轮廓资源 | `src/EarthquakeShow.App/Assets/japan-overview.geojson`，随应用复制，必须声明 `officialBoundary=false`；当前仅为 UI 示意轮廓 |

步骤 8 的地图资源不是测试数据集的一部分，不加入 `tests/TestData/manifest.json`；它不参与固定样本哈希校验。正式 JMA 边界资源建立前，不得使用当前示意轮廓执行行政归属或空间查询。

## 8. 固定测试数据格式

### 8.1 `manifest.json`

- 顶层 `schemaVersion` 当前必须为整数 `1`。
- `datasetVersion` 是固定数据集版本，不等同于应用版本。
- `fixtures[]` 记录 `id`、`reportCode`、相对 `path`、`origin`、SHA-256 和 `expected`。
- `assets[]` 记录固定资源 ID、相对路径、SHA-256、来源和预期记录数。
- `origin.kind` 只能明确区分官方原文和合成夹具；合成夹具必须记录基础文件、改动或测试目的。
- 修改受管文件后必须重新计算 SHA-256，并通过离线校验器。

### 8.2 `JmaStations.csv`

文件使用 UTF-8 CSV，首行字段固定为：

```text
station_code,report_name,coordinate_name,prefecture_code,affiliation,latitude,longitude
```

- `station_code` 必须唯一。
- `affiliation` 当前允许 `JMA`、`LocalGovernment`、`NIED`。
- `latitude`、`longitude` 使用十进制度和点号小数。
- `report_name` 保留报文名称，`coordinate_name` 保存用于坐标匹配的名称。

### 8.3 `Definitions/intensity-scale.json`

- 顶层 `schemaVersion` 当前为 `1`。
- `levels` 必须按 `unknown` 到 `7` 的稳定代码顺序包含 10 项。
- 每项包含 `code`、`jmaText`、`sortRank`、`color`、`textColor`。
- `sortRank` 必须从 `0` 连续到 `9`；颜色使用大写六位 `#RRGGBB`。
- 当前颜色是应用显示定义，不是 JMA 官方配色，界面必须同时显示文字。

### 8.4 `Gis/jma-area-test-envelopes.geojson`

- 顶层类型为 `FeatureCollection`，坐标系为 `EPSG:4326`。
- 当前要素几何类型为 `Polygon`，坐标顺序遵循 GeoJSON 的经度、纬度。
- 属性包含 `areaCode`、`name`、`maxIntensity`、`geometryKind`、`officialBoundary`。
- `officialBoundary` 必须为 `false`；该文件仅用于测试，不得作为正式地图边界。

### 8.5 应用离线轮廓 `Assets/japan-overview.geojson`

- 顶层类型为 `FeatureCollection`，坐标顺序为经度、纬度。
- 每个要素使用 `Polygon`，当前只提供日本列岛的 UI 示意外轮廓；解析器同时接受 `MultiPolygon` 外环以便后续替换资源。
- `properties` 至少包含 `code`、`name` 和 `officialBoundary`；当前所有要素的 `officialBoundary` 必须为 `false`。
- `metadata.source` 记录资源来源说明；资源不得声称是 JMA 官方边界。
- 该文件随 WPF App 输出和发布复制，不访问网络，不加入固定测试数据 `manifest.json`。

### 8.5 JMAXML 固定报文

- `JmaXml/Official/` 保存下载原文，禁止为了方便解析而修改。
- `JmaXml/Synthetic/` 是边界测试夹具，不得作为真实事件展示。
- 当前固定链为同一 `EventID` 的 `VXSE51 → VXSE52 → VXSE53`，另有订正和字段缺失夹具。
- 当前尚未实现完整 JMAXML 到领域模型的解析契约；解析器实现时必须在本文档增加字段映射和无法识别字段的处理规则。

## 9. 变更检查清单

数据相关变更至少检查：

1. 领域模型、仓储接口和本文档字段是否一致。
2. 新枚举是否定义未知值和稳定外部代码。
3. 新时间字段是否保留时区并定义持久化格式。
4. 新数值和对象是否明确 `null`、`0`、空数组的差异。
5. 身份、去重、排序或选择保持规则是否有单元测试。
6. 固定数据变更是否更新 `manifest.json` 哈希和预期结果。
7. SQLite/JSON Schema 变更是否有独立版本和迁移/兼容规则。
8. `dotnet test EarthquakeShow.sln --configuration Release` 和 `python -X utf8 tools\validate_test_data.py` 是否通过。
