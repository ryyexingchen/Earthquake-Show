# Earthquake Show 数据契约与格式

## 1. 文档用途

本文档长期记录应用内部领域数据、页面状态、仓储接口和仓库内固定数据文件的当前契约，供解析器、缓存、界面和测试实现时查询。

维护规则：

- 修改领域字段、枚举、未知值、事件身份、排序、去重或仓储行为时，必须在同一次变更中更新本文档。
- 修改 `tests/TestData/` 中受 `manifest.json` 管理的文件时，必须同步更新清单哈希、预期结果和本文件对应格式说明。
- 新增 SQLite、JSON API 或其他持久化格式时，先在本文档定义版本、字段、空值和迁移规则，再实现读写代码。
- 本文档只记录应用采用的契约，不复制完整 JMAXML 或 GeoJSON 标准；上游原始格式以官方规范为准。
- 尚未实现的外部格式必须明确标为“未定义”，不能把设计建议当成已生效契约。

当前适用应用版本：`0.26.1`。固定测试数据集版本独立维护，当前为 `0.3.0`。

## 2. 通用约定

### 2.1 命名与文本

- C# 公共字段和属性使用 `PascalCase`。
- 当前固定 JSON 使用 `camelCase`，固定 CSV 使用 `snake_case`；后续格式必须在本文件单独列出字段名，不能仅依赖命名策略推断。
- ID 和代码按区分大小写的序号规则比较，不做区域性排序。
- `EventId`、`SourceId` 和 `SourceMessageId` 是归并身份，不能为 `null`、空字符串或纯空白；合并时不自动修剪或改写。
- JMA 地名和原始报文允许保留日文；应用显示文本与稳定代码必须分开保存。

### 2.2 时间

- 内存时间统一使用 `DateTimeOffset`，不得先转换为无时区的 `DateTime`。
- 后续 JSON 或 SQLite 持久化统一使用 ISO 8601 往返格式 `O`，例如 `2026-08-19T07:14:00.0000000+09:00`。
- `OriginTime` 可以未知；`IssuedAt` 和 `ReceivedAt` 必须存在。
- 显示层可以转换为 JST 或用户本地时区，但必须同时显示时区标识，不能覆盖原始偏移量。

### 2.3 空值和未知值

- 可缺失对象和数值使用 `null`，不使用空字符串、`0`、`NaN` 或无穷值代替未知。
- 震度未知使用 `JmaIntensity.Unknown`，稳定外部代码为 `unknown`。
- 深度 `0` 表示真实的 `0 km`，深度未知使用 `null`；负深度无效。
- 震级未知使用 `Magnitude.Value = null`；`NaN` 和正负无穷不能进入领域模型。
- 坐标未知使用 `null`；已知坐标必须是有限值，纬度范围为 `[-90, 90]`，经度范围为 `[-180, 180]`。
- 集合使用 `ImmutableArray<T>`；无数据使用空数组，不使用 `null`。

## 3. 领域对象契约

### 3.1 `EarthquakeEvent`

| 字段 | 类型 | 必需 | 含义 |
| --- | --- | --- | --- |
| `EventId` | `string` | 是 | 来源事件 ID，也是事件聚合键 |
| `Reports` | `ImmutableArray<EarthquakeReport>` | 是 | 已去重并稳定排序的完整报文时间线 |
| `LatestReport` | `EarthquakeReport?` | 派生 | 时间线最后一报，包含取消报 |
| `LatestEffectiveReport` | `EarthquakeReport?` | 派生 | 最后的发布或订正报 |
| `Summary` | `EarthquakeEventSummary?` | 派生 | 供列表和当前状态使用的摘要；空时间线时为 `null` |

### 3.2 `EarthquakeEventSummary`

| 字段 | 来源 | 含义 |
| --- | --- | --- |
| `EventId` | 事件 | 事件 ID |
| `Status` | `LatestReport` | 当前发布、订正、取消或未知状态 |
| `Context` | `LatestReport` | 当前正常、训练、测试或未知上下文 |
| `UpdatedAt` | `LatestReport.IssuedAt` | 当前状态的最后发布时间 |
| `ReportCode` | `LatestEffectiveReport` | 最后有效报文代码；没有有效报文时为 `null` |
| `OriginTime` | `LatestEffectiveReport` | 地震发生时间 |
| `Hypocenter` | `LatestEffectiveReport` | 震源信息 |
| `Magnitude` | `LatestEffectiveReport` | 震级信息 |
| `MaxIntensity` | `LatestEffectiveReport` | 最大观测震度；没有有效报文时为 `Unknown` |

取消报决定 `Status`、`Context` 和 `UpdatedAt`，但不会清空最后有效报文提供的地震摘要。

### 3.3 `EarthquakeReport`

| 字段 | 类型 | 必需 | 含义 |
| --- | --- | --- | --- |
| `EventId` | `string` | 是 | 所属事件 ID |
| `ReportCode` | `string` | 是 | 原始报文代码，例如 `VXSE51/52/53` |
| `ReportType` | `EarthquakeReportType` | 是 | 标准化报文类型 |
| `Status` | `ReportStatus` | 是 | 发布、订正、取消或未知 |
| `Context` | `ReportContext` | 是 | 正常、训练、测试或未知 |
| `Serial` | `int?` | 否 | 报次；缺失与 `0` 不同 |
| `OriginTime` | `DateTimeOffset?` | 否 | 地震发生时间 |
| `IssuedAt` | `DateTimeOffset` | 是 | 来源发布时间 |
| `ReceivedAt` | `DateTimeOffset` | 是 | 应用接收时间 |
| `Hypocenter` | `Hypocenter?` | 否 | 震源名称、代码、坐标和深度 |
| `Magnitude` | `Magnitude?` | 否 | 震级值、类型和来源条件文字 |
| `MaxIntensity` | `JmaIntensity` | 是 | 最大观测震度，默认 `Unknown` |
| `IntensityAreas` | `ImmutableArray<IntensityArea>` | 是 | 区域最大观测震度 |
| `IntensityMunicipalities` | `ImmutableArray<IntensityMunicipality>` | 是 | 市町村最大观测震度 |
| `IntensityStations` | `ImmutableArray<IntensityStation>` | 是 | 观测点震度和可选坐标 |
| `TsunamiComment` | `string?` | 否 | 来源报文中的海啸相关说明 |
| `Source` | `SourceReference` | 是 | 来源身份、原文链接和可选原始负载 |

### 3.4 值对象和关联字段

| 类型 | 字段 | 约定 |
| --- | --- | --- |
| `Hypocenter` | `Name`, `Code`, `Coordinate`, `DepthKm` | 各来源字段可以未知；深度单位为 km |
| `Magnitude` | `Value`, `Type`, `Condition` | `Value` 必须为有限值或 `null` |
| `GeoCoordinate` | `Latitude`, `Longitude` | 使用十进制度；顺序固定为纬度、经度 |
| `IntensityArea` | `Code`, `Name`, `PrefectureCode`, `PrefectureName`, `MaxIntensity` | 区域代码关联市町村和 GIS 要素 |
| `IntensityMunicipality` | `Code`, `Name`, `AreaCode`, `MaxIntensity` | `AreaCode` 必须引用所属区域代码 |
| `IntensityStation` | `Code`, `Name`, `MunicipalityCode`, `Intensity`, `Coordinate` | 无坐标观测点仍必须保留 |
| `SourceReference` | `SourceId`, `SourceMessageId`, `RawMessageUri`, `SourcePayload` | 前两项组成来源消息身份 |
| `SourceStatus` | `SourceId`, `State`, `CheckedAt`, `LastReceivedAt`, `Detail`; WebSocket 可选 `RetryAttempt`, `NextRetryAt`, `ConnectedAt`, `ConnectionEndedAt`, `LastError`, `LastMessageAt`, `ConnectionExceptionCount`, `LastConnectionExceptionAt`, `IsExpectedDisconnect` | 描述适配器状态，不代表单份报文状态；连接诊断字段只在进程内生效 |

## 4. 枚举和稳定代码

### 4.1 JMA 震度

| C# 值 | 稳定代码 | 显示文本 |
| --- | --- | --- |
| `Unknown` | `unknown` | 不明 |
| `One` | `1` | 1 |
| `Two` | `2` | 2 |
| `Three` | `3` | 3 |
| `Four` | `4` | 4 |
| `FiveLower` | `5-lower` | 5弱 |
| `FiveUpper` | `5-upper` | 5強 |
| `SixLower` | `6-lower` | 6弱 |
| `SixUpper` | `6-upper` | 6強 |
| `Seven` | `7` | 7 |

枚举底层整数只用于进程内稳定排序，不能直接写入界面或外部数据格式。

### 4.2 其他枚举

- `EarthquakeReportType`：`Unknown`、`SeismicIntensity`、`Hypocenter`、`HypocenterAndIntensity`。
- `ReportStatus`：`Unknown`、`Issued`、`Correction`、`Cancelled`。
- `ReportContext`：`Unknown`、`Normal`、`Training`、`Test`。
- `SourceConnectionState`：`Unknown`、`Online`、`Delayed`、`Disconnected`、`RateLimited`、`ParseFailed`、`Disabled`。

SQLite/JSON 持久化使用枚举名称文本，例如 `Correction`、`Normal`、`Disabled`；不得写入底层整数。读取未知文本时视为格式错误并触发缓存回退。`JmaIntensity` 使用既有稳定代码 `unknown`、`1`、`2`、`3`、`4`、`5-lower`、`5-upper`、`6-lower`、`6-upper`、`7`。

## 5. 事件身份、去重和排序

- 事件聚合键：`EventId`。
- 来源消息去重键：`SourceId + SourceMessageId`，仅在同一事件内生效。
- 同一来源消息重复到达时保留最早 `ReceivedAt` 的记录。
- 事件内排序：`IssuedAt` 升序、`Serial` 升序、`ReceivedAt` 升序、来源优先级升序、`SourceId` 升序、`SourceMessageId` 升序；`Serial = null` 排在数字报次之前。来源优先级为 `p2pquake=5`、`jma-json=10`、`jma-xml=20`、其他来源 `0`，因此同一事件、发布时间、报次和接收时间相同时 JMA XML 成为 `LatestReport`。
- 事件列表排序：最后报文 `IssuedAt` 降序，时间相同按 `EventId` 升序。
- 订正和取消均保留原报，不覆盖或删除时间线节点。

## 6. 仓储契约

`IEarthquakeEventRepository` 是页面可见事件数据的唯一访问边界：

| 成员 | 输入 | 输出/行为 |
| --- | --- | --- |
| `ListEventsAsync` | 可取消令牌 | 返回已合并、去重并按事件顺序排列的不可变快照 |
| `GetEventAsync` | 非空 `eventId`、可取消令牌 | 返回指定事件或 `null` |
| `EventsChanged` | 无 | 发布完整事件快照；消费者不能修改快照 |
| `RefreshAsync` | 可取消令牌 | 请求具体实现刷新；不保证一定产生数据变化 |

页面和 ViewModel 不得直接调用 HTTP 或 SQLite。仓储事件可能由非 UI 线程发布，WPF 消费者必须切回创建页面状态时捕获的同步上下文。

`IEarthquakeSourceStatusProvider` 是可选状态接口，只暴露不可变 `SourceStatuses` 快照。页面在仓储实现该接口时，于加载和刷新后同步来源状态；至少一个来源为 `Online` 时 `IsOffline=false`，否则保持离线/缓存模式。未实现该接口的测试或内存仓储不伪造来源状态。

`InMemoryEarthquakeEventRepository` 只用于开发和测试：

- 构造时可以接收标准化报文。
- `ApplyReports` 追加报文后统一调用 `EarthquakeEventMerger`，再发布完整快照。
- `RefreshAsync` 没有外部数据源，因此是可取消的空操作。
- 它不负责 XML 解析、磁盘持久化或网络访问。

### 6.2 SQLite 缓存契约（schema v1）

SQLite 数据库默认路径为 `%LOCALAPPDATA%\\EarthquakeShow\\earthquake-cache.db`；测试必须传入独立临时路径。所有时间列和 JSON 时间字段使用 ISO 8601 往返格式 `O`，保留 `DateTimeOffset` 原始偏移量。数据库 schema 版本保存在 `schema_info` 的 `schema_version` 键，当前值为整数文本 `1`。

| 表 | 主键 | 字段 | 规则 |
| --- | --- | --- | --- |
| `schema_info` | `key` | `key`, `value` | 保存 schema 版本；未知版本不能静默读取 |
| `earthquake_events` | `event_id` | `updated_at`, `report_count` | 事件索引和审计信息；事件内容由报文重新合并 |
| `earthquake_reports` | `event_id + source_id + source_message_id` | `report_code`, `issued_at`, `received_at`, `payload_json` | 报文身份去重键；标准列用于查询，完整字段在 JSON DTO |
| `source_status` | `source_id` | `state`, `checked_at`, `last_received_at`, `detail` | 状态使用枚举名称文本；离线启动写入 `Disabled` |

`payload_json` 使用显式 `ReportPayloadDto` 格式，字段如下：

- `eventId`、`reportCode`、`reportType`、`status`、`context`、`serial`。
- `originTime`、`issuedAt`、`receivedAt`，时间为 `O` 格式字符串；`originTime` 可为 `null`。
- `hypocenter`（`name`、`code`、`coordinate`、`depthKm`）和 `magnitude`（`value`、`type`、`condition`），对象可为 `null`。
- `maxIntensity` 使用稳定震度代码；`intensityAreas`、`intensityMunicipalities`、`intensityStations` 使用数组，空集合写 `[]`。
- `tsunamiComment` 可为 `null`。
- `source` 包含 `sourceId`、`sourceMessageId`、`rawMessageUri` 和 `sourcePayload`；原始 XML 不做清洗或执行。

坐标 DTO 使用 `Latitude`/`Longitude` 数字；空坐标为 `null`。读取 JSON 时必须重新构造领域值类型，使越界坐标、负深度、非有限震级和无效枚举继续触发格式错误。初始化遇到数据库损坏、权限错误、schema 不支持或 JSON 格式错误时，仓储回退到固定 seed，并更新页面缓存失败状态；取消令牌不回退而是继续抛出取消异常。当前没有分页、清缓存或 schema 迁移契约。

## 7. 地震情报页面状态

`EarthquakePageState` 是不可变快照，更新时整体替换：

| 字段 | 含义 |
| --- | --- |
| `Events` | 当前事件列表快照 |
| `SelectedEvent` | 当前选中事件；首次非空加载默认选择列表第一项 |
| `ViewedReport` | 当前查看的报文版本；切换事件时默认最后一报 |
| `SearchText` | 搜索条件；去除首尾空白后保存 |
| `SortOrder` | 最新发布、最新发生或最大震度 |
| `Filters` | 时间、最低震度、最低震级、区域和来源筛选快照 |
| `Map` | 日本全图或所选事件焦点，以及是否跟随选择 |
| `SourceStatuses` | 各数据源状态快照 |
| `LoadState` | `NotLoaded`、`Loading`、`Ready` 或 `Error` |
| `IsRefreshing` | 主动刷新是否进行中 |
| `IsOffline` | 页面是否处于离线/缓存模式 |
| `ErrorMessage` | 最近一次加载或刷新错误；无错误时为 `null` |

仓储更新时保留当前 `EventId` 和当前报文的来源消息身份。新事件不得抢走用户正在查看的历史事件；当前报文不存在时才回退到该事件最后一报。

`EarthquakeEventFilterState` 字段：

| 字段 | 类型与规则 |
| --- | --- |
| `TimeRange` | `All`、`Last24Hours`、`Last7Days` 或 `Last30Days`；使用事件最新发布时间与当前时间比较 |
| `MinimumIntensity` | `JmaIntensity`；`Unknown` 表示不限，未知事件不能匹配任何已知最低震度 |
| `MinimumMagnitude` | `double?`；`null` 表示不限，非有限值被拒绝，震级未知的事件不能匹配最低震级 |
| `RegionText` | 去除首尾空白；匹配震源、区域、都道府县、市町村和观测点名称或代码 |
| `SourceId` | 去除首尾空白；按稳定来源 ID 精确筛选，界面显示名称不参与契约 |

详情快照契约：

- `EarthquakePageState.ViewedReport` 是右侧详情、报文时间线和地图图层的共同报文快照；切换时间线只能修改它，不修改事件列表摘要的当前状态规则。
- 首次选择事件时 `ViewedReport = LatestReport`；选择时间线节点后必须使用该节点的 `SourceId + SourceMessageId` 精确恢复。
- “上一报”或“下一报”到达时间线边界时保持当前报文，不循环切换；“返回最新”选择 `LatestReport`，取消报也属于最新报。
- 详情显示时间、坐标、深度、震级、海啸和状态均来自 `ViewedReport`，未知值按本文件 2.3 规则显示为“不明”。
- 地图区域、震源和观测点图层读取 `ViewedReport`；观测点无坐标时仍在详情集合中，地图不生成标记。
- 详情中的原始文本来自 `ViewedReport.Source.SourcePayload`，只读展示；应用不得把 XML 当作可执行内容，也不得自动打开其中的链接。

列表投影规则：

- 搜索不区分拉丁字母大小写，匹配 `EventId`、震源名称/代码、任一报文代码和任一 `SourceId`。
- 最新发布按摘要 `UpdatedAt` 降序；最新发生将未知 `OriginTime` 排在已知值之后；最大震度将 `Unknown` 排在已知值之后。
- 三种排序最终均按区分大小写的 `EventId` 升序兜底，保证结果可重复。
- 过滤只改变可见列表，不修改页面当前事件；当前选择被过滤时详情状态继续保留。
- 当前仓储返回完整事件快照，尚未定义分页游标或“更多记录”格式；SQLite 已实现但本版本不伪造分页契约。

地图状态和资源契约：

| 项目 | 规则 |
| --- | --- |
| `EarthquakeMapViewState.FocusMode` | `JapanOverview` 或 `SelectedEvent`；只控制视图焦点，不修改当前事件选择 |
| `EarthquakeMapViewState.FollowSelection` | `true` 且存在当前事件时地图有效焦点为 `SelectedEvent`；关闭后保留 `FocusMode`，点击日本全图会同时关闭跟随 |
| 坐标顺序 | 领域 `GeoCoordinate` 使用 `Latitude/Longitude`；GeoJSON 使用标准 `[longitude, latitude]` |
| 区域匹配 | 使用 `IntensityArea.Code` 与 GeoJSON `properties.areaCode`/`code` 的区分大小写字符串匹配 |
| 区域颜色 | 只使用 `JmaIntensity`，`Unknown` 为中性颜色；不从震级推导区域颜色 |
| 观测点绘制 | `IntensityStation.Coordinate` 为 `null` 时不生成地图标记，但不得从事件详情中删除 |
| 轮廓资源 | `src/EarthquakeShow.App/Assets/japan-overview.geojson`，随应用复制，必须声明 `officialBoundary=false`；当前仅为 UI 示意轮廓 |

步骤 8 的地图资源不是测试数据集的一部分，不加入 `tests/TestData/manifest.json`；它不参与固定样本哈希校验。正式 JMA 边界资源建立前，不得使用当前示意轮廓执行行政归属或空间查询。

## 8. 固定测试数据格式

### 8.1 `manifest.json`

- 顶层 `schemaVersion` 当前必须为整数 `1`。
- `datasetVersion` 是固定数据集版本，不等同于应用版本。
- `fixtures[]` 记录 `id`、`reportCode`、相对 `path`、`origin`、SHA-256 和 `expected`。
- `assets[]` 记录固定资源 ID、相对路径、SHA-256、来源和预期记录数。
- `origin.kind` 只能明确区分官方原文和合成夹具；合成夹具必须记录基础文件、改动或测试目的。
- 修改受管文件后必须重新计算 SHA-256，并通过离线校验器。

### 8.2 `JmaStations.csv`

文件使用 UTF-8 CSV，首行字段固定为：

```text
station_code,report_name,coordinate_name,prefecture_code,affiliation,latitude,longitude
```

- `station_code` 必须唯一。
- `affiliation` 当前允许 `JMA`、`LocalGovernment`、`NIED`。
- `latitude`、`longitude` 使用十进制度和点号小数。
- `report_name` 保留报文名称，`coordinate_name` 保存用于坐标匹配的名称。

### 8.3 `Definitions/intensity-scale.json`

- 顶层 `schemaVersion` 当前为 `1`。
- `levels` 必须按 `unknown` 到 `7` 的稳定代码顺序包含 10 项。
- 每项包含 `code`、`jmaText`、`sortRank`、`color`、`textColor`。
- `sortRank` 必须从 `0` 连续到 `9`；颜色使用大写六位 `#RRGGBB`。
- 当前颜色是应用显示定义，不是 JMA 官方配色，界面必须同时显示文字。

### 8.6 JMAXML 固定报文

- `JmaXml/Official/` 保存下载原文，禁止为了方便解析而修改。
- `JmaXml/Synthetic/` 是边界测试夹具，不得作为真实事件展示。
- 当前固定链为同一 `EventID` 的 `VXSE51 → VXSE52 → VXSE53`，另有订正和字段缺失夹具。
- `JmaXmlParser` 当前支持 `VXSE51`、`VXSE52` 和 `VXSE53` 使用到的字段子集，不代表完整 JMAXML Schema 实现；报文代码由调用方从 Feed 元数据或固定清单提供。

字段映射：

| JMAXML | 领域字段 | 规则 |
| --- | --- | --- |
| `Head/EventID` | `EventId` | 必需，空值拒绝 |
| `Head/ReportDateTime` | `IssuedAt` | 必需，保留来源时区 |
| `Control/DateTime` | `ReceivedAt` | 调用方未提供接收时间时使用 |
| `Head/InfoType` | `Status` | `発表`、`訂正`、`取消/取り消し` 分别映射为发布、订正、取消 |
| `Control/Status` | `Context` | `通常`、`訓練`、`試験/テスト` 分别映射为正常、训练、测试 |
| `Head/Serial` | `Serial` | 空值或非法整数映射为 `null` |
| `Earthquake/OriginTime` | `OriginTime` | 可缺失，保留来源时区 |
| `Hypocenter/Area` | `Hypocenter` | 读取名称、代码和坐标 |
| `jmx_eb:Coordinate` | `Coordinate`, `DepthKm` | 读取纬度、经度和米制深度；深度换算为 km |
| `jmx_eb:Magnitude` | `Magnitude` | 有限数字写入 `Value`；`NaN` 或非法值为 `null`，保留 `type` 和 `condition` |
| `Observation/MaxInt` | `MaxIntensity` | 未知代码映射为 `Unknown` |
| `Pref/Area/City/IntensityStation` | 三类震度集合 | 按原层级展开；空集合不使用 `null` |
| `Comments` 中含“津波”的文字 | `TsunamiComment` | 去重后使用中文分号连接 |
| XML 原文 | `Source.SourcePayload` | 调用方未提供负载时保留完整原文 |

观测点坐标不在详情报中提供。`JmaStationCatalog` 读取 `JmaStations.csv`，按 `station_code` 与 `IntensityStation/Code` 精确匹配；未匹配记录仍进入 `IntensityStations`，其 `Coordinate` 为 `null`。

解析边界：

- XML 禁止 DTD 和外部实体解析，单文档字符上限为 1000 万。
- 根元素、`EventID`、`ReportDateTime` 或默认接收时间缺失时抛出 `FormatException`。
- 报文代码、来源 ID 或来源消息 ID 为空时抛出 `ArgumentException`。
- 非空但不符合当前 JMAXML 坐标格式的字段抛出 `FormatException`；缺少坐标则保留震源并使用 `null`。
- 订正和取消报不会覆盖原报；解析后继续由 `EarthquakeEventMerger` 保留完整时间线并生成当前摘要。
- 未识别的可选 XML 节点当前忽略，但完整原文继续保留，后续增加字段时必须先扩展本文档和测试。

### 8.7 JMA JSON 实时摘要

默认端点：`https://www.jma.go.jp/bosai/quake/data/list.json`，来源 ID 固定为 `jma-json`，不需要 API Key。当前字段契约于 2026-08-20 使用真实公共响应只读核验：

| JMA JSON | 领域字段 | 规则 |
| --- | --- | --- |
| `eid` | `EventId` | 必需；空值使本次响应进入 `ParseFailed` |
| `rdt` | `IssuedAt` | 必需；显式偏移保留，无偏移时按 JST |
| `at` | `OriginTime` | 可缺失；时间规则同 `rdt` |
| `ttl` | `ReportType` | `震度速報`、`震源情報`、`震源・震度情報` 映射到对应类型 |
| `ift` | `Status` | `発表`、`訂正`、`取消/取り消し` 映射到稳定状态 |
| `ser` | `Serial` | 非法或缺失值为 `null` |
| `anm` | `Hypocenter.Name` | `-`、`不明` 或空值为 `null` |
| `acd` | `Hypocenter.Code` | 区域代码，可缺失 |
| `cod` | `Coordinate`, `DepthKm` | JMAXML 同类坐标格式；米制深度取绝对值后换算 km |
| `mag` | `Magnitude.Value` | 有限数字写入；`-`、`不明` 或非法值为未知 |
| `maxi` | `MaxIntensity` | 支持稳定代码及 `5弱/5強/6弱/6強`，其他值为 `Unknown` |
| `json` | `SourceMessageId` | 优先作为稳定去重身份；缺失时使用 `ctt + eid` |
| 完整列表响应 | `SourcePayload` | 只读保存，不执行其中的内容或链接 |

JMA JSON 当前只建立事件摘要，`IntensityAreas`、`IntensityMunicipalities` 和 `IntensityStations` 保持空数组；不得根据 `int` 中只有代码和最大震度的摘要伪造名称或观测点。`RawMessageUri` 保存公共端点 URI，`ReportCode` 固定为 `JMA-JSON`。

获取结果使用 `EarthquakeSourceFetchResult`：`Reports` 是本次规范化报文，`Status` 是同一来源的检查结果。HTTP 429 为 `RateLimited`，其他非成功 HTTP 和网络异常为 `Disconnected`，JSON/必填字段/坐标错误为 `ParseFailed`。失败结果的 `Reports=[]`，仓储必须保留已有事件并只更新来源状态。

### 8.8 JMA XML 实时 Feed

默认 Feed：`https://www.data.jma.go.jp/developer/xml/feed/eqvol.xml`，来源 ID 固定为 `jma-xml`，不需要 API Key。Feed 使用 Atom 命名空间，应用只读取 `entry` 中的 `id` 和 `link[type=application/xml][href]`：

| Atom 字段 | 领域字段 | 规则 |
| --- | --- | --- |
| `entry/id` | `SourceMessageId` | 必须是绝对 URI；取 URI 最后一个文件名，保留 `.xml` |
| `entry/id` 文件名中的 `VXSE51/VXSE52/VXSE53` | `ReportCode` | 只接入这三类地震情报，其他代码忽略 |
| `entry/link[type=application/xml]/@href` | `RawMessageUri` | 必须是绝对 HTTP/HTTPS URI，用于下载详情和打开来源 |
| 下载得到的 XML 原文 | `SourcePayload` | 交给 `JmaXmlParser` 解析并原样保存；站点坐标来自随应用复制的 `JmaStations.csv` |

每次刷新默认最多处理 20 个 Feed 条目。Feed 成功后逐条下载报文；单条 HTTP 或 XML 解析失败只计入该来源的 `ParseFailed` 详情，其他成功报文仍返回。Feed 本身格式错误为 `ParseFailed`；HTTP 429 为 `RateLimited`，其他非成功 HTTP 和网络异常为 `Disconnected`。任何失败结果的 `Reports=[]` 都不能清空 SQLite 中已有报文。

JMA XML 与 JMA JSON 可能同时描述同一事件。两者的标准化字段都保留在时间线中，不做逐字段合并；仅在时间线排序中使用来源优先级，使满足相同 `IssuedAt`、`Serial`、`ReceivedAt` 条件时 XML 报文作为 `LatestReport`。详情界面的逐字段差异展示尚未定义。

### 8.9 P2PQuake JSON API v2 补充源

默认端点：`https://api.p2pquake.net/v2/jma/quake`，来源 ID 固定为 `p2pquake`。当前字段契约于 2026-08-20 使用真实公共响应只读核验：

| P2PQuake JSON | 领域字段 | 规则 |
| --- | --- | --- |
| `id` | `SourceMessageId` | 必需；报文事件身份使用 `p2pquake:{id}`，不猜测 JMA `EventID` |
| `code` | `ReportCode` | 保存为 `P2P-{code}` |
| `issue.time` | `IssuedAt` | 必需；无时区的 `yyyy/MM/dd HH:mm:ss[.fff]` 按 JST 解释 |
| `issue.type` | `ReportType` | `DetailScale`→`HypocenterAndIntensity`，`ScalePrompt`→`SeismicIntensity`，`Destination`→`Hypocenter`，其他为 `Unknown` |
| `issue.correct` | `Status` | `None`→`Issued`，`Correction/訂正`→`Correction`，取消值→`Cancelled` |
| `earthquake.time` | `OriginTime` | 可缺失；时间规则同 `issue.time` |
| `earthquake.hypocenter` | `Hypocenter`、`Magnitude` | 坐标是必需有限值；深度单位为 km；震级缺失保留 `null` |
| `earthquake.maxScale` | `MaxIntensity` | `10/20/30/40/45/50/55/60/70` 映射为 `1/2/3/4/5弱/5強/6弱/6強/7`，其他值为 `Unknown` |
| `points[]` | `IntensityStations` | `addr/pref/scale` 转为来源内合成编码和地址；不声称是 JMA 官方观测点编码，缺地址的项忽略 |
| `earthquake.domesticTsunami/foreignTsunami` | `TsunamiComment` | `None/Unknown` 不展示，其他原文以分号连接 |
| 单条数组元素原文 | `SourcePayload` | 只读保存；`RawMessageUri` 为列表端点 URI |

P2PQuake HTTP 失败状态规则与其他 HTTP 来源一致：HTTP 429 为 `RateLimited`，其他非成功 HTTP 和网络异常为 `Disconnected`，JSON/必填字段/坐标错误为 `ParseFailed`。失败结果的 `Reports=[]`，仓储必须保留已有 JMA 与 SQLite 事件。HTTP 源不负责 WebSocket 生命周期和自动重连；P2P 报文的独立事件 ID 是刻意的安全边界，而不是完整去重契约。

### 8.10 来源差异展示契约

来源差异属于 App 层详情投影，不改变 Core 领域报文和 SQLite schema。对当前 `EarthquakeEvent` 内每个不同 `SourceId`，选取该来源按 `IssuedAt`、`ReceivedAt` 降序排列的最新报文，与当前 `ViewedReport` 比较：

| 比较项 | 显示规则 |
| --- | --- |
| `Status` | 使用稳定中文状态文本比较 |
| `MaxIntensity` | 使用震度显示文本比较 |
| `Magnitude` | 使用 `M x.x` 或“不明”比较 |
| `Hypocenter.Name` | 空值显示“不明” |
| `Hypocenter.DepthKm` | 使用 `n km` 或“不明”比较 |
| `IntensityStations.Length` | 只比较数量，不声称观测点编码可跨来源等价 |

差异项保留来源 ID、来源消息 ID、来源角色和合并后的文本；没有差异时显示“无字段差异”。来源差异只在同一 `EarthquakeEvent` 内计算，不依据时间、坐标或名称猜测跨事件关系。P2PQuake 使用独立事件 ID，因此当前不会出现在 JMA 事件的差异列表中。后续若定义跨源关联，必须先新增稳定关联键、置信度、人工复核边界和单独测试。

### 8.11 跨源事件候选关联契约

候选关联是 Core 层的只读结果，不是事件合并。`EarthquakeEventAssociator.Associate()` 只取每个事件最新的 `Issued` 或 `Correction` 报文，且要求双方 `EventId` 和 `SourceId` 不同：

| 条件 | 阈值/规则 |
| --- | --- |
| `OriginTime` | 两侧必须存在，绝对差不超过 60 秒 |
| 震源坐标 | 两侧必须存在，球面距离不超过 80 km |
| `Magnitude` | 两侧都有值时，绝对差不超过 0.5；一侧缺失不直接否决 |
| `Confidence=High` | 时间差不超过 10 秒、距离不超过 30 km，且震级差缺失或不超过 0.2 |
| `Confidence=Medium` | 满足基本阈值但不满足高置信度阈值 |

结果保存双方事件 ID、来源 ID、来源消息 ID、时间差、距离、可空震级差和置信度。App 只显示“可能关联来源”，不自动合并、删除、重排或持久化事件。缺少发生时间/坐标、超出阈值、同事件或同来源的组合返回空结果。后续若允许人工确认，必须新增关联状态、用户操作审计和撤销规则。

### 8.12 自动刷新与退避状态契约

自动刷新调度不改变报文格式和仓储 schema，只读取上一轮 `SourceStatus`：

| 状态 | 下一次基础间隔 | 退避规则 |
| --- | --- | --- |
| 所有来源 `Online` | 60 秒 | 失败次数清零 |
| 包含 `Disconnected` 或 `ParseFailed` | 30 秒 | 每次连续失败乘 2 |
| 包含 `RateLimited` | 2 分钟 | 每次连续限流乘 2 |
| 任一失败类型 | 最大 15 分钟 | 超过上限固定为 15 分钟 |

`RefreshBackoffPolicy` 只在内存中保存连续失败次数；应用重启后从在线基础间隔重新开始。空来源状态不视为在线成功。自动刷新和手动刷新共用 `EarthquakePageViewModel.RefreshAsync()` 的异步互斥，取消令牌触发后不得再发起 HTTP 请求。

### 8.13 P2PQuake WebSocket 消息流契约

默认端点为 `wss://api.p2pquake.net/v2/ws`。连接通道和 `SourceStatus.SourceId` 使用 `p2pquake-ws`，标准化报文的 `Source.SourceId` 仍为 `p2pquake`。`IStreamingEarthquakeSource.StreamAsync()` 是可取消的异步消息流；每个 `EarthquakeSourceFetchResult` 最多包含一条报文。

| WebSocket 输入 | 结果 | 规则 |
| --- | --- | --- |
| 完整或分片的文本消息 | `Reports=[EarthquakeReport]`、`Online` | 分片按 `EndOfMessage` 重组；顶层必须是单个 JSON 对象；字段映射与 P2PQuake HTTP JSON 共用；`Source.RawMessageUri` 为 WebSocket 端点 |
| 顶层 JSON 数组、损坏 JSON、必填字段/坐标错误 | `Reports=[]`、`ParseFailed` | 只影响当前消息，流继续读取下一条消息 |
| 二进制消息或同一消息内类型变化 | `Reports=[]`、`ParseFailed` | 当前版本不把二进制当作 JSON 解析 |
| 连接失败、读取异常或 Close 帧 | `Reports=[]`、`Disconnected` | 输出一次状态后结束本次流 |
| 取消令牌触发 | 不输出失败结果 | 必须向上抛出 `OperationCanceledException`，由应用生命周期负责停止消费 |

消息身份仍使用 `p2pquake:{id}` 作为 `EventId`，`id` 作为 `SourceMessageId`；WebSocket 和 HTTP 收到相同消息时由仓储按既有报文来源 `p2pquake + SourceMessageId` 规则去重。消息源本身不负责重连、协议级心跳、SQLite 写入或 UI 订阅；消息活性字段由消息源记录，重连由下节包装契约负责。

### 8.14 WebSocket 重连契约

`ReconnectingEarthquakeSource` 顺序消费一个 `IStreamingEarthquakeSource`，任何时刻最多存在一个底层异步枚举器：

| 条件 | 行为 |
| --- | --- |
| 底层返回 `Disconnected` | 释放本次流，等待退避后创建下一次流 |
| 底层正常结束 | 视为连接结束，等待退避后创建下一次流 |
| 底层抛出 `WebSocketException` 或 `IOException` | 输出一个 `Disconnected` 状态，释放本次流后重连 |
| 收到至少一个 `Online` 结果 | 当前连续失败次数清零；后续断开重新使用初始间隔 |
| 达到 `MaxConnectionDuration` | 使用会话取消令牌结束当前连接，输出 `Disconnected(IsExpectedDisconnect=true)` 后按退避重连 |
| 收到 `ParseFailed` | 原样输出，由底层继续读取当前连接，不单独触发重连 |
| 取消令牌触发 | 终止接收或等待并向上抛出取消；不输出伪造失败状态 |

默认重连间隔为 5 秒，连续失败时按 2 倍递增，最大 5 分钟；`MaxConnectionDuration` 默认 9 分钟。重连等待次数、连接异常统计只保存在当前进程内，不写入 SQLite；应用重启后重新从初始间隔和零异常计数开始。当前没有协议级 heartbeat 或静默 watchdog；主动轮换用于避开 P2PQuake 10 分钟强制断开边界。

### 8.15 `Lee2025VpVs.txt` 初步格式

文件当前位于 `resources/Lee2025VpVs.txt`，来自 Equake 资源且没有表头。`0.20.0` 只完成格式抽样和全文件范围统计，尚未实现解析器或把它加入发布输出。

| 列 | 初步含义 | 统计范围 | 备注 |
| --- | --- | --- | --- |
| 1 | 经度 | `118.90–123.26` | 110 个规则采样点，间隔约 `0.04°` |
| 2 | 纬度 | `20.98–25.98` | 126 个规则采样点，间隔约 `0.04°` |
| 3 | 深度或模型 Z 坐标 | `-4–120` | 32 层，间隔 `4`；按地震速度模型惯例推测单位为 km，负值含义需原始说明确认 |

### 8.16 流式结果持久化契约

`SqliteEarthquakeEventRepository.ApplyStreamingResultAsync()` 接收一个完整 `EarthquakeSourceFetchResult`，在同一个串行化写入流程中处理：

1. 按既有 SQLite 主键 upsert `Reports`；空报文数组不删除已有数据。
2. 按 `SourceStatus.SourceId` upsert当前通道状态。
3. 保留没有参与本次更新的其他来源和通道状态。
4. 重新读取全部报文，调用 `EarthquakeEventMerger` 派生事件快照并发布 `EventsChanged`。

HTTP 刷新、WebSocket 流和显式报文保存共用一个进程内 `SemaphoreSlim` 写入互斥。SQLite schema 仍为 v1，没有新增表或字段。`p2pquake-ws` 只用于连接状态；持久化报文仍使用 `source_id=p2pquake`，因此 HTTP/WS 相同消息不会重复。取消令牌在等待写锁、SQLite 操作或上游流中触发时必须继续向上抛出。

### 8.17 WebSocket 重连诊断字段

`SourceStatus` 的以下字段只用于当前进程内的 WebSocket 连接诊断：

| 字段 | 类型 | 生效条件 | 含义 |
| --- | --- | --- | --- |
| `RetryAttempt` | `int?` | `State=Delayed` | 当前连续重连等待次数，从 `1` 开始；收到 `Online` 后下一次断开重新计数 |
| `NextRetryAt` | `DateTimeOffset?` | `State=Delayed` | 预计结束当前退避等待的 UTC 时刻，显示层转换为 JST |
| `ConnectedAt` | `DateTimeOffset?` | WebSocket 已连接过 | 当前或最近一次连接会话的开始时间 |
| `ConnectionEndedAt` | `DateTimeOffset?` | 最近会话已结束 | 最近一次连接会话的结束时间；在线状态为 `null` |
| `LastError` | `string?` | 断开或解析失败后 | 最近一次连接错误或消息解析错误详情；新连接不会自动清空 |
| `LastMessageAt` | `DateTimeOffset?` | 收到完整消息或解析失败消息 | 最近一次收到完整 WebSocket 消息的时间；不表示协议 heartbeat |
| `ConnectionExceptionCount` | `int?` | 连接建立/读取异常后 | 当前进程累计连接异常次数；正常 Close 和解析失败不计入 |
| `LastConnectionExceptionAt` | `DateTimeOffset?` | `ConnectionExceptionCount > 0` | 最近一次连接异常发生时间 |
| `IsExpectedDisconnect` | `bool` | 主动连接轮换 | `true` 表示达到最大连接时长的预期断开，不增加异常次数、不覆盖最近错误 |

只有 `p2pquake-ws` 通道填充上述字段。退避等待前先发布 `Delayed` 状态；精确时间不可用时，页面显示“等待重连”。收到 `Online`、`Disconnected` 或 `ParseFailed` 时，状态按对应来源结果更新，解析失败不会触发额外重连。

这些字段不写入 SQLite `source_status` 表，也不改变 schema 版本；SQLite 读取出的诊断字段始终为 `null`。HTTP 刷新时，仓储只从当前内存状态合并带有这些字段的 `p2pquake-ws` 状态，随后使用本次 HTTP 结果覆盖对应 HTTP 来源状态，避免旧内存状态回退新状态。应用重启后不恢复上一次连接时间、重连次数、下次重试时间或最近错误详情。

在线连接持续时间由展示时刻减 `ConnectedAt` 计算；断开或等待重连时由 `ConnectionEndedAt - ConnectedAt` 计算，不包含退避等待时间。主窗口每秒刷新展示投影，不改变领域状态或持久化数据。

消息活性由展示时刻减 `LastMessageAt` 计算，页面显示为最近消息年龄；不存在独立协议 heartbeat 时，不得把该年龄显示为“心跳已确认”。连接异常统计只在进程内累计，不能用于跨进程或历史可靠性分析。

### 8.18 WebSocket keep-alive 与连接轮换契约

正式 `ClientWebSocket` 使用传输层 `KeepAliveInterval=30s`。该 keep-alive 由 .NET WebSocket 实现处理，不生成 `EarthquakeReport`，也不改变 P2PQuake 文本消息格式；当前没有应用层 ping/pong 结果字段。

`StreamingReconnectPolicy.MaxConnectionDuration` 默认 9 分钟，必须大于零。达到时限时，重连包装器取消当前会话令牌并输出：

| 字段 | 值 |
| --- | --- |
| `State` | `Disconnected` |
| `IsExpectedDisconnect` | `true` |
| `Detail` | 包含“单连接轮换时间” |
| `ConnectionExceptionCount` | 保持当前累计值，不因轮换增加 |
| `LastError` | 保持最近错误，不写入轮换原因 |

窗口生命周期取消优先于轮换；外部取消不得输出预期断开或重新建立连接。轮换后的新会话继续使用原有指数退避、在线重置和单连接约束。

### 8.19 WebSocket 连接策略设置契约

设置文件固定保存于 `%LOCALAPPDATA%\\EarthquakeShow\\settings.json`，与 SQLite 事件缓存分离。当前设置 schema 版本为 `1`，JSON 使用 camelCase：

```json
{
  "schemaVersion": 1,
  "webSocket": {
    "keepAliveSeconds": 30,
    "maxConnectionDurationMinutes": 9
  }
}
```

| 字段 | 类型 | 默认值 | 约束 |
| --- | --- | --- | --- |
| `schemaVersion` | `int` | `1` | 不是 `1` 时整份设置回退默认值 |
| `webSocket.keepAliveSeconds` | `int` | `30` | `10–120`；映射为 `ClientWebSocketOptions.KeepAliveInterval` |
| `webSocket.maxConnectionDurationMinutes` | `int` | `9` | `1–9`；映射为 `StreamingReconnectPolicy.MaxConnectionDuration` |

设置文件缺失、无法读取、JSON 损坏、schema 不支持或字段越界时，应用使用默认设置并向设置页提供警告文本；不得因为设置错误阻止读取 SQLite 缓存。点击应用后先校验并写入文件，再重建当前 WebSocket 流；HTTP 刷新、SQLite schema、事件选择和页面现场不受影响。设置不是地震报文，不写入 SQLite，也不参与事件去重。

真实网络验证曾收到缺少 `id` 的 WebSocket JSON。当前该类消息按字段错误映射为 `ParseFailed` 并继续读取；由于尚未取得稳定原始样本和上游定义，暂不为其新增领域类型或 heartbeat 语义。

## 9. 变更检查清单

数据相关变更至少检查：

1. 领域模型、仓储接口和本文档字段是否一致。
2. 新枚举是否定义未知值和稳定外部代码。
3. 新时间字段是否保留时区并定义持久化格式。

5. 身份、去重、排序或选择保持规则是否有单元测试。
6. 固定数据变更是否更新 `manifest.json` 哈希和预期结果。
7. SQLite/JSON Schema 变更是否有独立版本和迁移/兼容规则。
8. `dotnet test EarthquakeShow.sln --configuration Release` 和 `python -X utf8 tools\validate_test_data.py` 是否通过。
