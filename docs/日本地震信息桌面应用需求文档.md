# 日本地震信息桌面应用需求文档

## 1. 文档信息

- 文档状态：Draft 0.4
- 调研日期：2026-08-19
- 产品形态：桌面应用程序，不是需要浏览器访问的网页
- 首发平台假设：Windows 优先；是否同时支持 macOS/Linux 在技术设计阶段确认
- 目标区域：日本及其周边海域
- 数据范围：暂时只处理日本气象厅（JMA）相关地震、紧急地震速報（EEW）和海啸信息
- 成本约束：仅使用无需付费订阅的 API 或公开数据

本文中的“免费可访问”不等于“允许任意复制和再分发”。数据源必须同时满足可访问、用途允许、能力足够三个条件，才能进入正式版本。

## 2. 产品定位

应用用于持续展示日本地震信息，帮助用户快速了解：

1. 地震发生在哪里、震级和深度是多少；
2. 哪些区域和观测点记录到何种震度；
3. EEW 当前是第几报、预报或警报、最终报还是取消报；
4. P 波、S 波估计传播到哪里，哪些区域可能出现何种震度；
5. 是否发布海啸预报、注意报、警报或大海啸警报，沿岸和海上观测情况如何；
6. 当前数据来自哪里、是否延迟、是否为预测/观测/推测值。

本产品是信息展示和研究工具，不替代 JMA、地方政府或经过许可的预警服务，不作为生命安全、避难、交通或设备控制的唯一依据。

### 3.1 连续实时逐站震度的实际实现路线

公开资料显示，同类桌面软件实现“连续逐站”主要有以下两条路线：

1. **强震监视器图像解析（JQuake、KyoshinEewViewer、EQuake 参考路线）**
   - 每 1 秒左右按时间戳请求 NIED 强震监视器的 GIF/PNG 图像；图像中的每个观测点用固定像素颜色编码实时震度、PGA、PGV 或 PGD。
   - 应用内置观测点坐标/像素映射表，读取每个站点像素，再把 RGB 转 HSV，通过分段多项式或颜色表换算为数值。
   - JQuake 作者公开的算法文章明确指出：NIED 当时未提供包含这些数值的 JSON API，因此第三方软件依赖图像解析；KyoshinEewViewer 的源码也直接调用 `WebApiUrlGenerator.RealtimeImg` 并执行 `ProcessImage`。
   - 这种路线技术上能够得到“连续逐站”，但数据仍属于 NIED 强震监视器展示内容，不等于获得了可自由再发布的官方数值 API。
   - 本次调研对按当前时间生成的 KMONI 图像地址做了只读验证，服务器返回 `200 image/gif`；这只能证明端点可访问，不能证明允许第三方持续抓取、解析或再发布。

2. **NIED/强震监视器 JSON（历史或手机应用接口）**
   - KyoshinMonitorLib 记录过 `ts.qtmoni.bosai.go.jp` 的 `RealTimeData`、站点列表和 EEW JSON 地址，可直接返回站点数值或网格数据。
   - 该库 README 同时注明手机应用 API “大部分当前不可用”，且没有给出面向第三方的稳定 SLA、注册流程或再分发授权。
   - 因此不能把源码中出现的 URL 视为当前可用、合规的公共 API；必须逐项实测并取得 NIED 明确许可后才能考虑。

3. **第三方网页转存 JSON（nTool 当前实现）**
   - nTool 的公开页面脚本每秒读取 `https://weather-kyoshin.east.edge.storage-yahoo.jp/SiteList/sitelist.json`，再按时间读取 `RealTimeData/{日期}/{时间}.json`。
   - `realTimeData.intensity[i]` 与站点列表按数组下标关联，同时还读取 `psWave` 和 `hypoInfo`，因此能够在网页上连续显示逐站震度、P/S 波圈和强震监视器 EEW。
   - 这是目前最接近用户目标的“免费可访问”案例，但地址属于 Yahoo/NIED 的未文档化存储，页面脚本的可见性不等于授权；格式、可用性、跨域策略和再分发权均未得到保证。

**结论**：连续逐站并不是“找一个免费 JSON API”即可完成，而是“获取监视器数据 + 观测点映射 + 图像数值化 + 授权审查”的整体方案。现阶段本项目只能把图像解析列为研究验证路线，不能列入免费正式版承诺。

## 4. 免费 API 与公开数据调研

### 4.1 调研范围

以下清单覆盖截至 2026-08-19 能公开发现、与日本/JMA 地震展示直接相关的主要免费接口。私人接口、需要邀请的接口、没有公开说明的抓包地址不视为可正式使用的 API。

2026-08-19 的一次性只读检查中，JMA XML、JMA 地震 JSON、Wolfx JMA EEW/地震列表、P2PQuake、USGS 和 EMSC 查询均返回 HTTP 200。该结果只说明调研时可访问，不构成可用性、延迟或长期 SLA 证明。

### 4.2 推荐使用的数据源

#### A. JMA 防灾信息 XML Feed

- 文档/入口：[JMA 高频地震火山 Feed](https://www.data.jma.go.jp/developer/xml/feed/eqvol.xml)
- 类型：公开 Atom Feed，条目链接至 JMA XML 电文
- 认证/费用：无需认证，免费公开访问
- 适合：权威地震情报、震度情报和海啸电文
- 已核对的地震电文：
  - `VXSE51`：震度速報
  - `VXSE52`：震源に関する情報
  - `VXSE53`：震源・震度に関する情報
- 海啸相关电文按 `VTSE*` 处理，至少包括警报/注意报/预报、到达时间和观测信息。
- 已核对字段：`EventID`、`InfoType`、`Serial`、`OriginTime`、震源区域和坐标、深度、震级、最大震度、省/区域/市町村/观测点震度、海啸评论。
- 优点：官方来源、字段完整、可以保留原始电文。
- 限制：XML 解析复杂；基于 Feed 轮询而非低延迟推送；不能将其当作免费 EEW 预报流的唯一来源。
- 接入要求：使用 `ETag`/`Last-Modified` 或内容 ID 去重，避免高频重复下载；遵守 [JMA 使用条款](https://www.jma.go.jp/jma/kishou/info/coment.html)。

结论：**MVP 权威主源**，用于地震情报和海啸信息。

#### B. JMA 官网公开 JSON 数据

- 地震列表：`https://www.jma.go.jp/bosai/quake/data/list.json`
- 地震详情：`https://www.jma.go.jp/bosai/quake/data/{list.json 中的 json 字段}`
- 海啸列表：`https://www.jma.go.jp/bosai/tsunami/data/list.json`
- 海啸详情：`https://www.jma.go.jp/bosai/tsunami/data/{list.json 中的 json 字段}`
- 认证/费用：无需认证，公开可访问
- 已核对能力：
  - 地震列表含 `eid`、报告时间、标题、震源、坐标、震级、最大震度、省/市町村编码；
  - 地震详情含省、细分区域、市町村、观测点名称/编码、具体震度以及部分观测点坐标；
  - 海啸详情含预报区、警报类别、当前/上一状态、关联地震和评论。
- 优点：JSON 易解析，详情能够直接支持观测点地图。
- 限制：这是 JMA 官网前端使用的数据文件，没有独立的稳定 API 版本或 SLA；路径、字段和保留窗口可能变化。

结论：**MVP 实用主源/补充源**。应用必须同时保留 JMA XML 适配器，避免官网 JSON 变化后完全不可用。

#### C. Wolfx Open API

- 文档：[Wolfx Open API](https://wolfx.jp/zh/docs/open-api)
- 服务性质：非官方公益项目，条款允许依照文档合理、免费使用；无 SLA
- JMA EEW HTTP：`https://api.wolfx.jp/jma_eew.json`
- JMA EEW WebSocket：`wss://ws-api.wolfx.jp/jma_eew`
- JMA 最近地震 HTTP：`https://api.wolfx.jp/jma_eqlist.json`
- JMA 最近地震 WebSocket：`wss://ws-api.wolfx.jp/jma_eqlist`
- 全部 EEW WebSocket：`wss://ws-api.wolfx.jp/all_eew`，本项目不需要订阅中国等非 JMA 数据。
- WebSocket 机制：服务端在连接后和每分钟发送 `heartbeat`；客户端建议发送 `ping`；支持 `query_jmaeew`、`query_jmaeqlist` 手动查询。
- JMA EEW 已核对字段：
  - `EventID`、`Serial`、`AnnouncedTime`、`OriginTime`；
  - `Hypocenter`、`Latitude`、`Longitude`、`Depth`、`Magunitude`（上游字段拼写如此）；
  - `MaxIntensity`、`WarnArea`、`Accuracy`；
  - `isWarn`、`isFinal`、`isCancel`、`isTraining`、`isAssumption`、`isSea`。
- 最近地震列表：固定返回最近 50 条摘要，含震源、震级、深度、最大震度、时间和 `md5`；不包含完整观测点明细。
- 限制：文档未给出固定数值限流，服务条款要求合理请求并允许运营方动态调整限制；非官方、可能延迟/中断/改格式。

结论：**免费 EEW 首选源**。WebSocket 为主，HTTP 用于启动时补取和断线校验；不得作为唯一生命安全信息源。

#### D. P2PQuake JSON API v2

- 文档：[P2PQuake JSON API v2](https://www.p2pquake.net/develop/json_api_v2/)
- HTTP 基址：`https://api.p2pquake.net/v2`
- WebSocket：`wss://api.p2pquake.net/v2/ws`
- 相关路径：
  - `GET /history`
  - `GET /jma/quake`
  - `GET /jma/quake/{id}`
  - `GET /jma/tsunami`
  - `GET /jma/tsunami/{id}`
  - `GET /ws` 升级为 WebSocket
- 已核对字段：震源名称/坐标/深度/震级、最大震度编码、各观测点地址与震度、海啸状态、报文类型和发布时间。
- 官方文档限制：
  - 商用和非商用均可免费使用，允许二次利用；旧 JMA 数据和地图等内容仍需按页面说明署名；
  - `/history`：每 IP 每分钟 60 次；
  - `/jma`：每 IP 每分钟 10 次；
  - `/ws`：每 IP 同时 2 个连接；
  - WebSocket 每 10 分钟强制断开，需要主动重连；
  - 文档给出的处理延迟约为 WebSocket 70 ms、JSON API 1000 ms，高负载时可能更高。
- `maxScale` 是编码，不是直接显示值：常见 `10/20/30/40/45/50/55/60/70` 对应 `1/2/3/4/5弱/5強/6弱/6強/7`。

结论：**MVP 低延迟地震/海啸补充和降级源**。必须按限制实现缓存、去重和定时重连。

#### E. nTool / Narikakun API

- 最新地震：`https://dev.narikakun.net/webapi/earthquake/post_data.json`
- 按类型取最近一条：
  - `.../last/震度速報.json`
  - `.../last/震源に関する情報.json`
  - `.../last/震源・震度に関する情報.json`
- 历史搜索：`https://earthquake-api-v2.nakn.jp/api/v2/list`
- 历史搜索能力：支持震度、震源编码、时间范围和数量；默认 100 条，最多 3000 条。
- EEW：`https://api.narikakun.net/eew/v1.json`
- 认证/费用：公开文档未要求 API Key 或付费。
- 数据来源：文档说明其数据由 DM-D.S.S 接收后重新整理。
- 风险：服务可无预告停止；无 SLA；2026-08-18 实测 EEW 端点仍返回 2022-12-16 的事件，不能判断为实时可用。

结论：最新地震和历史搜索可作为**补充/开发源**；EEW 端点因实测陈旧，**不进入运行时来源**。

#### 4.3.2 nTool 转存 JSON 的接入方法（研究模式）

如果暂时接受“技术验证、不承诺稳定性和再分发权”的前提，可以按以下方式实现一个独立适配器。该适配器必须默认关闭，并与 JMA 官方数据适配器分开。需要特别注意：这些地址不是 nTool 官方 API，而是 nTool 网页脚本当前直接读取的 Yahoo edge storage 上游文件。

**接口地址和时间格式**

```text
站点表：
https://weather-kyoshin.east.edge.storage-yahoo.jp/SiteList/sitelist.json

逐秒数据：
https://weather-kyoshin.east.edge.storage-yahoo.jp/RealTimeData/YYYYMMDD/YYYYMMDDHHmmss.json
```

时间使用日本标准时间（JST，UTC+09:00），月份、日期、时分秒均需要两位补零。响应中的 `dataTime` 是上游数据时间，不能用本机接收时间替代。

**启动流程**

1. 获取 `sitelist.json`，保存 `siteConfigId`、站点数组和响应版本。
2. 校验每个站点是否为 `[latitude, longitude]`，坐标范围是否合理，并记录站点数组长度。
3. 以当前 JST 时间减去 1-3 秒作为首个查询时间，避免 CDN 尚未生成最新文件。
4. 每秒最多发起一个串行请求；请求超时、404、403 或 JSON 解析失败时，不并发堆积请求。
5. 当响应中的 `siteConfigId` 变化、`intensity` 长度与站点数组不一致，或时间倒退时，暂停绘制并重新获取站点表。

**逐站震度解码**

`realTimeData.intensity` 是与站点数组按下标对应的字符字符串。nTool 页面使用 `字符 ASCII 码 - 100` 解码，并将小于 0 的结果视为缺测；例如 `d` 对应 0、`e` 对应 1、`f` 对应 2。该数值属于 nTool/NIED 强震监视器的实时显示编码，不能直接标记为 JMA 正式震度或计测震度。

应用内部建议保存为：

```json
{
  "source": "ntool-relay",
  "sourceTime": "2026-08-18T21:09:21+09:00",
  "siteConfigId": "20260123000000",
  "stations": [
    {
      "index": 0,
      "latitude": 35.3,
      "longitude": 136.8,
      "rawCode": "g",
      "displayLevel": 3,
      "quality": "unverified"
    }
  ]
}
```

必须同时保存原始字符、解码值、站点表版本和接收时间，方便发现上游编码变化。界面标签使用“实时显示值（nTool 转存）”或“强震监视器相当值”，不得写成“JMA 观测震度”。

**可选字段**

- `psWave.items`：解析 `latitude`、`longitude`、`pRadius`、`sRadius`，显示为上游估计的 P/S 波圈。
- `hypoInfo.items`：解析 `regionName`、`depth`、`magnitude`、`calcintensity`、`reportNum`、`reportTime`、`originTime` 等 EEW 字段。
- 坐标字符串可能包含 `N/S/E/W`，需要转换为带正负号的十进制度；这些字段仍标记为上游转存预测，不覆盖 Wolfx/JMA EEW。

**断线、缺帧和缓存策略**

- 维护最近 5 秒的请求窗口；当前秒失败时按时间顺序补取，最多补 3 秒，超过则标记缺帧，不无限追赶。
- 连续 3 次失败进入 `degraded`，停止高频轮询并退避到 5 秒；连续 60 秒失败进入 `disabled`，等待用户重新启用。
- 不把上一帧数值伪装成当前帧；界面显示“最后成功时间”和“数据延迟”。
- 本地可缓存最近 60 秒用于诊断和回放，但不能把缓存数据当成官方历史档案。
- 每次请求记录 HTTP 状态、响应时间、数据时间、站点表版本和缺测比例；禁止把上游响应转发成公共 API。

**验收条件（研究适配器）**

1. 固定样本能正确验证 `siteConfigId`、数组长度、JST 时间和字符解码。
2. 站点表变化时不会把旧站点坐标套到新强度字符串上。
3. 404、403、超时、缺字段和长度不一致均进入可见降级状态。
4. 同一时刻不会出现两个并发请求；应用退出时停止轮询。
5. UI 明确区分 nTool 转存值、JMA 事后观测值、Wolfx EEW 预测值和本地计算结果。

#### 4.3.3 NIED JSON 直连的可行范围

NIED/强震监视器相关 JSON 不能统一视为“逐站实时 API”，应拆成两组：

| 接口组 | 典型地址 | 能力 | 当前结论 |
| --- | --- | --- | --- |
| 强震监视器 Web API | `http://www.kmoni.bosai.go.jp/webservice/hypo/eew/{YYYYMMDDHHmmss}.json` | 强震监视器侧 EEW 震源、报数、震级、深度和预测信息 | 可作为研究补充；不提供完整全国逐站实时震度 |

#### 4.3.4 免费与友好程度分级

本项目把“友好”定义为：有公开文档、无需付费、用途和二次利用条件明确、无需抓包、具备合理限流说明。它与“数据能力是否适合日本”分开判断。

| 等级 | 数据源 | 免费/授权判断 | 日本 MVP 适用性 |
| --- | --- | --- | --- |
| A：优先 | JMA XML Feed、JMA GIS | 官方公开、无需密钥；按 JMA 条款署名和合理访问 | 地震、海啸和静态边界主源；不是连续逐站或完整免费 EEW 推送 |
| A：优先 | P2PQuake API v2 | 明确允许商用/非商用免费二次利用，并公开限流和协议 | 地震、海啸、JMA EEW 警报补充；不是连续逐站 |
| B：可用但需降级 | Wolfx Open API | 条款允许合理免费使用，文档公开；非官方、无 SLA，第三方源权利仍需遵守 | 当前免费 JMA EEW 首选，但必须显示来源并准备断线降级 |
| B：范围不匹配 | USGS、EMSC FDSN Event API | 文档成熟；EMSC 明确 CC BY 4.0 | 仅全球事件补充/交叉核对，缺少 JMA 震度、EEW、海啸和连续逐站 |
| C：条件式 | JMA 官网 JSON、nTool 事件 API | 当前免费可访问；前者未独立版本化，后者为第三方整理且无 SLA | 可补充和开发验证，不得成为唯一主源 |
| C：研究下载 | K-NET/KiK-net 等 NIED 正式波形 | 注册可取得研究数据，但不是实时 API，并限制再分发 | 仅事件后算法研究、训练和回放 |
| C：不适配 | FAN Studio FSSN、Wolfx SeisJS、TREM-Net | 可公开访问或申请使用，但限学术/社区站、覆盖不匹配或权利边界不足 | 不作为日本全国正式数据源 |

## 5. 产品范围与版本计划

### 5.1 MVP：地震情报桌面应用

- 打包为可安装/可运行的桌面程序，用户不需要启动浏览器或自建 Web 服务。
- 日本地图显示震源、分区震度配色和观测点具体震度。
- 展示并串联 `VXSE51 → VXSE52 → VXSE53`：震度速報、震源情报、震源/震度情报。
- 展示震源名称、经纬度、深度、震级、发生时间、最大震度和海啸评论。
- 支持最近事件列表、事件详情、报文时间线和本地历史缓存。
- 接入 JMA XML/JMA JSON，P2PQuake 和 nTool 作为降级或补充。
- 显示数据源连接状态、最后更新时间、缓存状态和错误。

### 5.2 V1：EEW 与海啸

- 接入 Wolfx JMA EEW WebSocket，HTTP 作为断线补取。
- 展示震源、第 N 报、最终报、预报/警报/取消报、训练/假定震源和精度信息。
- 显示 P 波和 S 波估计波前；清楚标注“计算估计”，不能伪装成观测值。
- 显示最大预测震度和各预报区域预测震度；未知值明确显示“不明”。
- 接入海啸预报、注意报、警报、大海啸警报、解除和观测信息。
- 海啸信息同时提供列表和地图视图。

### 5.3 后期研究功能

- 在获得合法、稳定、全国覆盖的逐站实时数据后，显示连续实时震度。
- 在逐站数据中增加 PGA/三轴加速度。
- 基于多站触发进行摇晃检测，推断震源、深度、震级和可信度。
- 推测震度分布。

连续逐站功能的研究路线按优先级划分：

| 路线 | 前置条件 | 可获得能力 | 费用 | 风险/结论 |
| --- | --- | --- | --- | --- |
| A. NIED 监视器图像解析 | NIED 书面许可、稳定的图像访问和观测点表 | 全国站点实时震度、PGA 等相当值 | 访问本身可能免费 | 技术验证价值最高；未获许可不得上线或对外再发布 |
| B. NIED 数值接口/数据授权 | NIED 开放接口或研究/再利用授权 | 可直接获得站点数值，质量和字段更稳定 | 需确认是否免费 | 一旦授权明确，优先于图像解析；当前未找到无条件公开版本 |
| C. Wolfx SeisJS/社区站 | 选择日本境内有稳定上报的站点 | 少量社区站的 PGA、计测震度和加速度 | 免费公益服务 | 覆盖不完整、非官方，不得宣称日本全国逐站；仅作实验图层 |
| D. 自建传感器网络 | 用户设备、站点部署、校准和联网 | 自建站连续加速度/震度，可做摇晃检测 | 硬件和运维成本 | 不属于“免费 API”，但最可控；应作为独立研究项目评估 |
| E. 仅使用 JMA 事后逐站 + EEW 预测 | 无新增授权 | 事件后逐站观测、EEW 预测和波前估计 | 免费 | 当前唯一可直接进入正式免费版本的稳妥范围 |

这些功能必须与官方 JMA 信息分栏显示，并标注算法版本、输入来源、置信度和“非官方推测”。如结果对外发布，还需评估日本《气象业务法》关于地震动预测业务的限制。

TREM-Net 可作为路线 D 的参考实现：社区站持续上传速度或加速度数据，服务端完成授时、质量控制、事件检测和分发。但日本版不能直接复用台湾站网，需要重新解决硬件成本、站点密度、传感器标定、网络抖动、站点授权和异常数据剔除。

## 6. 功能需求

### FR-01 桌面应用外壳

- 应生成桌面可执行程序和安装包；不得要求用户在浏览器中打开页面。
- 数据抓取、解析、缓存和重连应运行在应用后台进程，界面只消费标准化事件。
- 本地数据存储于应用数据目录；卸载、清除缓存和日志位置应可说明。
- 连接策略设置独立保存于 `%LOCALAPPDATA%\\EarthquakeShow\\settings.json`，不得随事件缓存清除。
- MVP 以单窗口为主，不增加账号、云同步、社区或无关灾害功能。

### FR-02 主界面布局

- 顶部：当前时间、主/备用数据源状态、最后接收时间和全局警报状态。
- 左侧：地震、实时/EEW、海啸三个视图入口及最近事件列表。
- 中间：日本地图，是主要信息区。
- 右侧：当前事件详情、地区/观测点列表和报文时间线。
- 无事件时仍展示地图、连接状态和最近历史，不显示空白窗口。

### FR-03 地震情报

- 接收并识别震度速報、震源情报、震源/震度情报。
- 同一 `EventID` 的不同报文组成一个事件，不重复创建事件卡片。
- 地图按 JMA 区域编码为分区着色，按日本震度 `1/2/3/4/5弱/5強/6弱/6強/7` 显示。
- 观测点显示名称和具体震度；点选后显示所属都道府县、区域、市町村、观测点编码和来源。
- 震源使用独立图标，并显示震中名称、经纬度、深度、震级和发生时间。
- 详情显示最大震度、海啸评论、发布时间、发布机构和原始电文链接。
- 对订正、取消、训练、测试和未知字段使用显式状态，不以默认 0 代替未知值。

### FR-04 EEW

- 按 `EventID + Serial` 处理更新，旧报不得覆盖新报。
- 显示：预报/警报、取消、训练、假定震源、第 N 报、最终报和发布时间。
- 显示：震源、经纬度、深度、震级、最大预测震度、精度和警报区域。
- 最大/区域预测震度支持“不明、1、2、3、4、5弱、5強、6弱、6強、7”。
- P/S 波圈根据震源、深度、发生时间和选定走时模型本地计算；界面显示算法名称和计算基准时间。
- 报文取消后立即停止波前动画，并保留带“已取消”标签的历史记录。
- 官方/上游预测与本地推测震源必须使用不同名称、颜色和图层开关。

### FR-05 事后观测点震度

- 地震详情加载 JMA/P2PQuake 观测点数据后，在地图上显示具体震度。
- 观测点不包含坐标时，通过随应用打包的 JMA 观测点编码表补齐；仍无法定位时仅在列表展示。
- 分区着色取该区域已观测的最大震度，不根据震级自行推测。
- 必须明确这是 JMA 发布后的观测信息，不是连续实时监测值。

### FR-06 连续实时震度与摇晃检测（后期）

- 只有当数据源许可、覆盖和 SLA 通过评审后才能启用。
- 逐站记录至少包含：站点 ID、坐标、采样时间、JMA 震度/计测震度、质量标记和来源；加速度后续增加。
- 摇晃检测必须要求多个空间分离的观测点满足时空阈值，过滤单站噪声和设备故障。
- 推断结果至少包含震源、深度、震级、参与站数、残差、可信度、算法版本和更新时间。
- 推断结果始终标注“本地推测”，不得覆盖 JMA EEW 或正式地震情报。

### FR-07 海啸信息

- 接收并区分海啸预报、海啸注意报、海啸警报、大海啸警报和解除。
- 列表显示：预报区、警报级别、预计到达时间、满潮时间、预计高度、观测时间和观测高度。
- 地图按 JMA 海啸预报区边界着色，沿岸区域与海上观测点分层显示。
- 对海上观测信息显示观测站名称、位置、观测高度和“距沿岸约 N 千米”等上游提供的信息。
- 上游未提供距岸距离时显示“未知”，不得通过简单直线距离伪造官方值。
- 更新和解除必须修改既有海啸事件，时间线保留此前状态。

### FR-08 搜索、缓存与回放

- 默认在本地保存最近 100 个事件及其全部报文版本和原始响应。
- 支持按时间、震级、最大震度、震源区域、报文类型和来源筛选。
- 支持选中历史事件后静态回放报文时间线；连续实时数据回放属于后期功能。
- 离线启动时显示本地缓存，并突出显示缓存时间和“离线”状态。

### FR-09 数据源状态与降级

- 每个适配器显示在线、延迟、断开、限流、解析失败和已停用状态。
- Wolfx WebSocket 失联后递增退避重连，并以 HTTP 拉取当前 EEW 校验状态。
- P2PQuake WebSocket 使用传输层 keep-alive，并在服务端 10 分钟强制断线前默认于 9 分钟主动轮换连接；轮换后自动重连，保持至多一个生产连接。
- P2PQuake WebSocket 等待重连时显示当前连续重连次数和下次重试时间，诊断字段只作为进程内状态，不写入历史缓存。
- P2PQuake WebSocket 显示当前或最近一次连接持续时间，并保留最近一次断开或解析失败的错误详情。
- P2PQuake WebSocket 显示最近收到消息的时间年龄和当前进程累计连接异常次数；没有独立 heartbeat 协议时不得伪造心跳确认。
- 达到最大连接时长产生的主动轮换属于预期断开，不增加连接异常次数、不覆盖最近错误；窗口关闭或应用生命周期取消不得触发重连。
- 设置页面允许调整 P2PQuake 传输层 keep-alive（10–120 秒）和单连接最大持续时间（1–9 分钟）；应用后立即重建 WebSocket，HTTP 刷新和 SQLite 缓存不重置。
- 设置文件缺失、损坏、版本不支持或参数越界时使用默认值并提示用户；不提供未经协议支持的应用层 heartbeat 设置。
- JMA/P2P/Wolfx/nTool 的重复事件按来源 ID、JMA `EventID`、时间和报文序号去重。
- 多源参数冲突时优先显示 JMA 官方值，并保留来源差异，不取平均值或最大值。

## 7. 数据模型

```json
{
  "eventId": "20260818183610",
  "source": "jma-xml",
  "sourceMessageId": "20260818093832_0_VXSE53_270000",
  "reportCode": "VXSE53",
  "reportType": "earthquake-detail",
  "status": "issued",
  "serial": 1,
  "originTime": "2026-08-18T18:36:00+09:00",
  "issuedAt": "2026-08-18T18:38:32+09:00",
  "receivedAt": "2026-08-18T18:38:33+09:00",
  "hypocenter": {
    "name": "熊本県熊本地方",
    "code": "741",
    "latitude": 32.5,
    "longitude": 130.6,
    "depthKm": 0
  },
  "magnitude": { "value": 2.6, "type": "Mj" },
  "maxIntensity": "1",
  "intensityAreas": [],
  "intensityStations": [],
  "tsunami": null,
  "rawReference": "https://example.invalid/raw-message"

```

统一字段只表达跨源公共语义；各源特有字段保存在 `sourcePayload` 或独立扩展对象中，避免为了统一而丢失原始信息。所有时间以带时区的 ISO 8601 字符串保存，禁止解析库静默转换时区后再当作原值写回。

## 8. 推荐应用架构

```text
JMA XML/JSON ─┐
Wolfx WS/HTTP ├─> 数据源适配器 ─> 校验/去重/标准化 ─> 本地 SQLite
P2PQuake WS ──┤                                      │
nTool HTTP ───┘                                      ↓
                                               桌面事件总线
                                                      ↓
                                 地图 / 列表 / 详情 / 时间线 / 设置
```

- 应用内置后台运行时直接访问免费 API，不需要自建云端服务。
- GIS 边界和代码表随版本打包，启动时不重复下载数百 MB 的原始 Shapefile。
- 数据适配器、标准化模型和界面解耦，单个免费 API 停止时可以替换。
- 正式技术选型采用 C# + .NET 8 + WPF。界面、业务模型、数据适配、标准化、缓存和后台任务统一使用 C#；地图使用 Mapsui/SkiaSharp 等原生渲染方案，不使用浏览器、WebView、本地 Web 服务或 HTML/CSS 界面；Python 只用于 GIS 和固定样本等开发期预处理脚本。首发明确支持 Windows 10/11，若未来要求 macOS/Linux，需要单独评估 Avalonia 等原生跨平台方案，不能假定 WPF 代码可直接跨平台。

## 9. 非功能需求

- 实时性：应用收到 WebSocket 报文后 1 秒内更新状态和详情；不对上游端到端延迟作虚假承诺。
- 正确性：所有适配器使用真实固定样本做契约测试，覆盖发布、订正、取消、最终报、训练和字段缺失。
- 稳定性：任一 API 失败不导致应用退出；恢复后自动补取和去重。
- 启动：先加载本地缓存，再异步连接网络；网络不可用时仍可查看历史。
- 资源使用：地图动画暂停或窗口最小化时降低刷新率；连续波前动画不得阻塞数据接收。
- 安全：MVP 不需要用户 API Key；远端 XML/JSON 仅作为数据解析，不能执行其中脚本或代码。
- 隐私：MVP 不采集用户位置、账号或个人信息。
- 可访问性：状态不只依赖颜色；地图内容有等价列表；支持键盘选择事件和观测点。
- 合规：在“关于”页面列出 JMA、Wolfx、P2PQuake、nTool 和地图数据来源、条款链接及免责声明。

## 10. MVP 验收标准

1. Windows 用户可以通过桌面可执行程序启动应用，不需要浏览器或本地 Web 服务。
2. 给定 `VXSE51`、`VXSE52`、`VXSE53` 固定样本，同一 `EventID` 形成一条事件及按时间排列的三类报文。
3. `VXSE53` 详情能在地图上显示震源、区域配色和观测点具体震度。
4. JMA 官网 JSON 结构变化或访问失败时，应用显示源故障并改用 JMA XML/P2PQuake，不崩溃。
5. 给定一组 Wolfx EEW 报文，界面正确显示第 N 报、最终报、警报/预报、取消、震源和最大预测震度。
6. P/S 波圈随时间推进；暂停、取消或切换历史事件后不会继续错误动画。
7. 给定 JMA 海啸预报和观测样本，列表和地图正确显示警报等级、预报区、到达时间、高度、观测站及解除状态。
8. P2PQuake 达到限流或 WebSocket 断开时，应用退避重连且不超过连接数限制。
9. 断网启动时可以查看缓存，且清楚显示离线和最后更新时间。
10. 官方观测、EEW 预测、本地计算波前和后期算法推测在文字和视觉上均可区分。

## 11. 风险与未决事项

- **连续实时震度数据缺口**：目前没有确认可用于第三方桌面应用的免费、日本全国逐站实时 API。此项不能通过抓取 NIED/Yahoo 未文档化地址绕过。
- **监视器图像解析风险**：同类软件通常从 NIED GIF/PNG 的像素颜色反推数值；这不是官方数值接口，图像尺寸、颜色表、时间戳或站点布局变化都会造成系统性误差。NIED 使用条件还可能限制复制、改编、发送和单独使用，因此只能在取得书面许可后产品化。
- **历史 NIED JSON 风险**：KyoshinMonitorLib 记录的手机应用 `RealTimeData`/站点列表端点并不等于当前公开 API，项目文档已注明大部分 API 当前不可用。未完成可用性、认证、限流和授权核验前，不得把这些 URL 写入生产配置。
- **EEW 上游风险**：免费 EEW 依赖 Wolfx 非官方转发；服务中断时只能显示“EEW 数据不可用”，不能用事后地震情报伪装成 EEW。
- **JMA JSON 稳定性**：官网 JSON 易用但未独立版本化；XML 必须保留为权威回退。
- **预测业务合规**：P/S 波圈是传播估计；自研震源和预测震度分布可能触及日本地震动预测业务规范，公开发布前需要法律/许可评审。
- **免费服务持续性**：Wolfx、P2PQuake、nTool 都可能调整条款、限流或停止服务，应用必须展示源状态并可替换适配器。
- **转发不等于授权**：开源客户端或第三方网站能读取某个上游，只能证明技术路径存在；进入正式版本前仍要分别核对转发方条款和 JMA/NIED 等原始数据权利。
- **地图数据体积**：JMA 原始 GIS 文件较大，需要预处理和版本化，不能每次启动在线下载。

待确认：

- 首发是否只支持 Windows 10/11，还是从第一版就要求 macOS/Linux；
- UI 是否以中文为主并保留 JMA 日文原文；
- 是否接受 JMA 官网未文档化 JSON 作为主读取路径，并以 XML 回退；
- 是否需要系统托盘、开机启动和声音提醒；这些不在当前 MVP 中；
- 连续实时震度功能是等待合法免费源，还是未来接受自建测站/获得授权。
