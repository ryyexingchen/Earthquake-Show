项目按 `C# + .NET 8 + WPF + Mapsui/SkiaSharp + SQLite` 推进。应用使用 Windows 原生窗口和控件，地图在本地原生画布中渲染，不使用浏览器、WebView、HTML/CSS 或本地 Web 服务。

首轮不接入 NIED/Yahoo 实时 Demo，也不直接从实时 API 开始。先用固定报文把页面闭环跑通，再接后台数据源。

**完成标准**

地震情报页面完成后，应满足：

1. 桌面程序可启动，不依赖浏览器。
2. `VXSE51/52/53` 同一 `EventID` 合并为一个事件。
3. 最近事件和历史记录在同一个列表中浏览。
4. 选择事件后，列表、地图和右侧详情同步更新。
5. 地图显示震源、区域震度和有坐标的观测点。
6. 时间线可以切换上一报、下一报和最新报。

8. 未知、订正、取消、训练和测试状态不会被错误显示成普通值。

## 具体步骤

### 1. 确定工程技术栈并创建桌面外壳

状态：已于 `0.2.0` 实现并验证。

建立 .NET 解决方案和 WPF 应用工程，先生成一个真正的 Windows 桌面窗口。运行时不得启动 HTTP 服务，也不得依赖浏览器或 WebView。

第一步只使用 WPF 和 .NET 8 自带能力：

- WPF `Window`、`Grid`、`ListBox`、`TabControl` 等原生控件建立三栏外壳。
- C# ViewModel 管理 JST 时钟、当前标签和基础页面状态。
- Windows `Segoe Fluent Icons` 或矢量资源提供工具栏图标。

`CommunityToolkit.Mvvm`、Mapsui、SQLite 和 xUnit 在对应职责真正出现时再引入，避免第一步保留未使用依赖。

验证：

- [x] Windows 下能够启动开发版本。
- [x] 启动时不出现控制台、浏览器或本地服务器窗口。
- [x] 窗口默认 `1440 × 900`，最小 `1180 × 720`。
- [x] 四个详情标签可以正常切换。
- [x] 关闭窗口后后台进程正常退出。

本步骤只包含页面外壳和基础 ViewModel 状态，没有领域解析或事件合并逻辑，因此未建立单元测试工程。验证采用 Release 构建、原生窗口启动、Windows UI Automation 交互和截图检查；单元测试从步骤 3/4 的可测试领域逻辑开始加入。

同时准备：

- JMA 观测点编码和坐标表。
- 震度颜色及排序定义。

验证：

- [x] 样本可以离线加载。
- [x] 每份样本都有明确来源、SHA-256 和预期解析结果。
- [x] 官方 `VXSE51/52/53` 使用同一 `EventID`，详情报包含多个区域和观测点。

### 3. 定义前后端统一数据模型

状态：已于 `0.4.0` 实现并验证。

先定义领域模型，再写页面组件。核心模型至少包括：

```text
EarthquakeEvent
EarthquakeReport
Hypocenter
IntensityArea
IntensityMunicipality
IntensityStation
SourceReference
SourceStatus
```

震度不能直接使用普通数字，建议定义明确枚举：

```text
unknown, 1, 2, 3, 4, 5-lower, 5-upper, 6-lower, 6-upper, 7
```

所有时间保存为带时区 ISO 8601 字符串，显示时再转换。

验证：

- [x] 未知震度使用 `JmaIntensity.Unknown`，不会变成震度 `1` 或普通数字 `0`。
- [x] 深度使用 `int?`，`0 km` 与深度未知可以区分。
- [x] 震级未知使用 `null`，`NaN` 和无穷值不能进入领域模型。
- [x] 经纬度必须是合法范围内的有限值，观测点坐标可以为未知。
- [x] 内存时间使用 `DateTimeOffset` 保留原始偏移量，后续持久化使用 ISO 8601 `O` 格式。
- [x] 原始报文代码、来源 ID、来源消息 ID、原文 URL 和 `SourcePayload` 不会因标准化而丢失。

模型位于 `src/EarthquakeShow.Core/Models/`，测试位于 `tests/EarthquakeShow.Core.Tests/`。本步骤只定义数据契约，不解析固定 XML，也不检查事件内报文顺序；解析属于数据源适配器，合并和排序属于步骤 4。

### 4. 实现事件合并与报文排序

状态：已于 `0.5.0` 实现并验证。

实现纯函数形式的事件归并逻辑：

- 按 `EventID` 聚合报文。
- 按发布时间、报次和接收时间稳定排序。
- 新报更新已有事件，不新增重复列表项。
- 旧报不得覆盖新报。
- 订正和取消保留之前的版本。
- 根据最新有效报文生成列表摘要。

实际实现规则：

- 先检查 `EventId`、`SourceId` 和 `SourceMessageId`，空标识直接拒绝。
- 按 `EventId` 聚合，使用 `SourceId + SourceMessageId` 识别同一来源消息。
- 同一来源消息重复到达时保留最早的 `ReceivedAt` 记录。
- 事件内按 `IssuedAt → Serial → ReceivedAt → SourceId → SourceMessageId` 升序排列；无报次排在有报次之前。
- 事件列表按最后报文 `IssuedAt` 降序排列，时间相同时按 `EventId` 稳定排列。
- `LatestReport` 表示当前最后一报，取消报可以成为当前状态。
- `LatestEffectiveReport` 只接受发布或订正报；取消后的摘要继续沿用最后有效报文的震源、震级和最大震度。
- 订正和取消报均保留在不可变时间线中，不覆盖或删除原报。

这部分应先写测试，再接 UI。

验证：

- 输入 `VXSE51 → 52 → 53` 后只有一个事件。
- 打乱输入顺序后结果仍然一致。
- 重复输入同一报文不会生成重复时间线节点。
- 订正报可以更新最新值，但旧值仍可查看。

验证结果：上述场景以及取消报、旧报、同时间排序、多事件排序、空输入、空时间线和无效标识均已有单元测试；Core 测试共 `46` 个，全部通过。

### 5. 建立页面状态和数据访问边界

建议将状态分成：

- 事件列表。
- 当前选中事件。
- 当前查看的报文版本。
- 搜索和排序条件。
- 地图视图状态。
- 数据源状态。
- 加载、离线和错误状态。

页面不应直接调用 HTTP 或 SQLite。建立一个简单的数据仓库接口：

```text
listEvents()
getEvent(eventId)
subscribeUpdates()
refresh()
```

开发初期由内存中的固定样本仓储实现，后期替换为 Infrastructure 项目中的 SQLite 和数据源适配器。

### 6. 实现主窗口三栏布局

先完成无地图业务逻辑的稳定布局：

- 顶部：时间、数据状态、最后接收时间、搜索和设置。
- 左侧：业务导航和地震事件列表。
- 中间：地图容器。
- 右侧：摘要、区域与观测点、时间线、原始数据。
- 底部：网络、缓存、来源和地图数据版本。

验证：

- 动态文本不会改变地图尺寸。
- 窄窗口下右侧栏可以收为抽屉。
- 无事件时地图和数据状态仍然可见。

### 7. 实现地震事件列表

拆分为 WPF `UserControl` 和 ViewModel：

EarthquakeEventListView / EarthquakeEventListViewModel
EarthquakeEventItemView
EarthquakeFilterView / EarthquakeFilterViewModel
IntensityBadgeControl
EventStatusBadgeControl

- 单击选择事件。
- 键盘上下键切换。

验证：

- 事件更新后列表项原地更新。
- 当前选择不会因列表更新丢失。

按以下顺序添加图层：

1. 日本轮廓和 JMA 区域边界。
2. 区域最大观测震度配色。
3. 震源标记。
4. 观测点标记。
5. 图例和地图工具栏。

不要一开始接在线底图。先用随应用打包的简化 GeoJSON，保证离线可用。

验证：

- 切换事件时旧图层被正确清理。
- 区域颜色来自观测结果，不根据震级推测。
- 无坐标观测点只显示在右侧列表。
- 重叠观测点能够弹出选择列表。
- 日本全图、定位震源、缩放和全屏按钮有效。

### 9. 实现右侧详情和报文时间线

四个标签依次实现：

- 摘要。
- 区域与观测点。
- 报文时间线。
- 原始数据。

时间线切换报文时，地图和详情都必须显示该版本的快照，而不是继续使用最新值。

验证：

- `上一报/下一报/返回最新` 行为正确。
- 观测点列表点击后可定位地图。
- 未知字段统一显示“不明”。
- 原始报文只读，不能执行其中的链接或代码。
- 未实现历史回放时不显示“进入历史回放”按钮。

### 10. 实现缓存和离线启动

SQLite 至少需要保存：

- 标准化事件。
- 每份报文版本。
- 原始响应。
- 来源信息。
- 接收时间。
- 当前数据源状态。

启动顺序固定为：

```text
打开数据库 → 加载缓存 → 显示页面 → 后台连接网络 → 合并更新
```

验证：

- 断网后重新启动仍可查看缓存事件。
- 页面明确显示“离线・缓存数据”和缓存时间。
- 清除缓存不删除设置。
- 数据库损坏时应用显示错误，不直接退出。

### 11. 分阶段接入真实数据源

推荐接入顺序：

1. JMA JSON：先打通列表和详情。
2. JMA XML：支持 `VXSE51/52/53`，作为权威来源。
3. P2PQuake：用于补充和降级。
4. nTool：仅在确有字段补充价值时接入。

每个适配器只负责“获取、解析、转成统一模型”，不得直接操作页面。

验证：

- API 失败不会清空已有内容。
- 重复来源不会生成重复事件。
- 来源冲突时显示 JMA 官方值，并保留差异。
- 限流和解析错误反映到数据源状态。
