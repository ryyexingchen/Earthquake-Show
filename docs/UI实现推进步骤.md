项目按 `C# + .NET 8 + WPF + Mapsui/SkiaSharp + SQLite` 推进。应用使用 Windows 原生窗口和控件，地图在本地原生画布中渲染，不使用浏览器、WebView、HTML/CSS 或本地 Web 服务。

首轮不接入 NIED/Yahoo 实时 Demo，也不直接从实时 API 开始。先用固定报文把页面闭环跑通，再接后台数据源。

- 功能范围变化同步更新需求文档，页面结构或交互变化同步更新 UI 设计文档。
- 文档与代码必须在同一次变更中更新，不能留到版本结束后集中补写。

**完成标准**

地震情报页面完成后，应满足：

1. 桌面程序可启动，不依赖浏览器。
2. `VXSE51/52/53` 同一 `EventID` 合并为一个事件。
3. 最近事件和历史记录在同一个列表中浏览。
4. 选择事件后，列表、地图和右侧详情同步更新。
5. 地图显示震源、区域震度和有坐标的观测点。
6. 时间线可以切换上一报、下一报和最新报。
7. 离线启动可以读取缓存。
8. 未知、订正、取消、训练和测试状态不会被错误显示成普通值。

正式发布使用 Windows x64 自包含构建，最终用户不需要另行安装 .NET Runtime；该项在发布阶段验证，不属于桌面外壳的首轮任务。

## 具体步骤

### 1. 确定工程技术栈并创建桌面外壳

状态：已于 `0.2.0` 实现并验证。

建立 .NET 解决方案和 WPF 应用工程，先生成一个真正的 Windows 桌面窗口。运行时不得启动 HTTP 服务，也不得依赖浏览器或 WebView。

第一步只使用 WPF 和 .NET 8 自带能力：

### 4. 实现事件合并与报文排序

状态：已于 `0.5.0` 实现并验证。

实现纯函数形式的事件归并逻辑：

- 按 `EventID` 聚合报文。
- 按发布时间、报次和接收时间稳定排序。
- 新报更新已有事件，不新增重复列表项。
- 旧报不得覆盖新报。
- 订正和取消保留之前的版本。
- 根据最新有效报文生成列表摘要。

实际实现规则：

- 先检查 `EventId`、`SourceId` 和 `SourceMessageId`，空标识直接拒绝。
- 按 `EventId` 聚合，使用 `SourceId + SourceMessageId` 识别同一来源消息。
- 同一来源消息重复到达时保留最早的 `ReceivedAt` 记录。
- 事件内按 `IssuedAt → Serial → ReceivedAt → SourceId → SourceMessageId` 升序排列；无报次排在有报次之前。
- 事件列表按最后报文 `IssuedAt` 降序排列，时间相同时按 `EventId` 稳定排列。
- `LatestReport` 表示当前最后一报，取消报可以成为当前状态。
- `LatestEffectiveReport` 只接受发布或订正报；取消后的摘要继续沿用最后有效报文的震源、震级和最大震度。
- 订正和取消报均保留在不可变时间线中，不覆盖或删除原报。

这部分应先写测试，再接 UI。

验证：

- 输入 `VXSE51 → 52 → 53` 后只有一个事件。
- 打乱输入顺序后结果仍然一致。
- 重复输入同一报文不会生成重复时间线节点。
- 订正报可以更新最新值，但旧值仍可查看。

验证结果：上述场景以及取消报、旧报、同时间排序、多事件排序、空输入、空时间线和无效标识均已有单元测试；Core 测试共 `46` 个，全部通过。

#### 9A-6. 区域边界与市町村填色重构（计划 `0.34.0`）

目标：消除区域面色与市町村面色重叠造成的视觉混浊，同时保留区域震度边界和市町村震度分布。

视觉规则（`0.34.0` 代码已实现，真实启动性能和人工截图验证待完成）：

1. 区域不再绘制最大震度填充，只绘制统一去重后的区域边界。
2. 共享边界的颜色取相邻区域最大震度；只有一侧区域的海岸/外边界取该区域震度；两侧都没有有效震度时使用中性边界色。
3. 区域边界按低震度到高震度绘制，高震度作为后绘制层；统一边界资源正常情况下每条边只绘制一次，此排序用于处理残留重叠和退化几何。
4. 市町村有有效震度时填充对应震度色，并使用深色/黑色边界；没有有效震度时不填充，边界恢复底图中性样式。
5. 观测点和震源图层保持现有规则，仍位于区域和市町村边界之上。

实现步骤：

1. 在开发期从未简化的 JMA 地震细分区域 Polygon/MultiPolygon 生成拓扑边界资源，规范化端点、拆分交点、合并连续线段，并保存相邻区域代码；不能直接对已经分别简化的 Polygon 做字符串端点去重，否则会留下缝隙或短重叠线。
2. 为边界资源定义 `LineString` 契约和无方向相邻代码集合 `areaCode1`、`areaCode2`；外边界的 `areaCode2` 为空。生成报告必须包含原始线段数、去重后线段数、共享边界数、开放链端点数和几何异常数。

### 10. 实现缓存和离线启动

状态：已于 `0.12.0` 实现并验证。

SQLite 至少需要保存：

- 标准化事件。
- 每份报文版本。
- 原始响应。
- 来源信息。
- 接收时间。
- 当前数据源状态。

当前启动顺序固定为：

```text
创建 SQLite 仓储 → 初始化地震 schema v3（兼容 v1/v2 迁移并清理 jma-json）→ 优先加载缓存
缓存为空时写入固定 seed → 设置离线来源状态 → 显示页面
```

验证：

- [x] 断网后重新启动仍可查看缓存事件。
- [x] 页面明确显示离线和缓存状态；缓存失败显示回退原因。
- [x] 数据库损坏、schema 不支持或 JSON 损坏时应用回退固定样本，不直接退出。
- [x] 标准字段、原始 XML、来源身份、接收时间和来源状态均有 SQLite 集成测试。
- [ ] 清除事件缓存不删除设置（清除缓存操作本身留待后续版本）。

实现边界：当前 `RefreshAsync` 不连接网络，缓存读取返回完整事件快照，不提供分页；固定样本是开发期 seed，不作为实时数据源。

### 11. 分阶段接入真实数据源

状态：第十四阶段连接策略设置已于 `0.26.0` 实现，第十四阶段真实网络验证已于 `0.26.1` 完成一轮，第十五阶段非事件消息契约已于 `0.27.0` 实现，第十六阶段原始消息捕获已于 `0.28.0` 实现，第十七阶段 `code=555` 网络状态契约已于 `0.29.0` 实现，第十八阶段 nTool 合规与补充价值评估已于 `0.29.1` 完成；P2PQuake 没有可确认的应用层 heartbeat，nTool 正式适配、人工关联确认和历史回放尚未实现。

推荐接入顺序：

1. JMA JSON：先打通列表和详情。（已完成摘要、刷新、缓存和状态）
2. JMA XML：支持 `VXSE51/52/53`，作为权威来源。（已完成 Feed、详情下载、缓存和状态）
3. P2PQuake：用于补充和降级。（已完成 HTTP 列表源、WebSocket 消息边界、重连以及仓储/UI 数据接入）
4. nTool：仅在确有字段补充价值时接入。

每个适配器只负责“获取、解析、转成统一模型”，不得直接操作页面。

`JmaXmlEarthquakeSource` 使用 `https://www.data.jma.go.jp/developer/xml/feed/eqvol.xml` 的 Atom `entry/id` 和 `link[type=application/xml]`，默认最多下载 20 条 `VXSE51/52/53` 详情，并复用 `JmaXmlParser` 和随应用复制的 `JmaStations.csv`。Feed 或单条报文失败只更新 `jma-xml` 来源状态；成功报文与 JSON 摘要一起写入 SQLite，由 `EarthquakeEventMerger` 按来源优先级派生页面快照。

`P2pQuakeEarthquakeSource` 使用 `https://api.p2pquake.net/v2/jma/quake` 的 JSON 列表，映射震源、震级、最大震度、都道府县、从地址前缀提取的市町村和观测点；原始报文以 `p2pquake:{id}` 保存，事件合并阶段按 60 秒/80 km/震级差 0.5 阈值与 JMA XML 合并。它是非官方补充/降级源，HTTP 429、网络错误和解析错误只更新 `p2pquake` 来源状态。

验证：

- [x] JMA JSON API 失败不会清空已有内容。
- [x] 相同 `json` 来源消息重复刷新不会生成重复报文。
- [x] HTTP 429、断开和解析错误反映到数据源状态。
- [x] 启动先显示 SQLite 缓存，再依次请求 JSON 摘要和 XML 详情；手动刷新复用同一路径。
- [x] 同一事件、发布时间、报次和接收时间相同时，JMA XML 按来源优先级成为最新报文。
- [x] XML Feed/详情失败不会清空已有内容；单条详情失败不阻止其他条目入库。
- [ ] 来源冲突时显示 JMA 官方 XML 值，并逐字段保留差异。
- [x] P2PQuake HTTP JSON 补充适配器失败不会清空 JMA/SQLite 内容。
- [x] P2PQuake 观测点按都道府县 → 市町村 → 观测点生成详情树，市町村最大震度由观测点聚合。
- [x] 满足时间、坐标和震级阈值的 XML/P2P 报文合并为单一事件，并通过详情来源切换按钮查看不同来源。
